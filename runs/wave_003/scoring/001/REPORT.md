## 3. Diagnostic patterns

- **Affective vs functional:** both leaked heavily. Functional whys scored 8.0/34.0; affective whys scored 12.0/58.0. Accessibility affective whys were the main exception.
- **Weight-3 vs weight-2:** high-weight whys did better because their primary mechanisms were often named. Weight-2 whys scored 0.0/20.0, showing that compact exception rationales vanished.
- **System-level vs feature-level:** system-level recovery (35.7%) beat feature-level recovery (15.6%). The plan preserved architecture-level mechanisms better than per-feature intent.
- **Multi-layer recovery:** primary layers survived most often; secondary calibration and downstream failure consequences were usually absent.
- **Subdomains:** accounts/sync and accessibility survived best; interaction nuance, social privacy, field notebook, return greeting, and privacy telemetry were mostly missing.
- **Evidence-bound effects:** many plausible v1-style credits were denied because PLAN/RECONSTRUCTION preserved only rules, especially F6, F14, F15, F23, F26, F27, F29, F31, F32, and F37.

The failure shape suggests a planner that compressed the product into an implementation skeleton. It captured enough nouns and architecture to build a generic aviary, but not enough rationale to protect why Pocket Aviary is different from adjacent products.

## 4. Recommendations for v2 hardening

- Keep the evidence-bound operator; this run would be over-credited by a scorer that treated rule mentions as why recovery.
- Add or retain targeted exception whys for label-only features. Starter birds, visit invitations, max-7, and performance targets were especially easy to name without rationale.
- Preserve multi-layer scoring for accessibility and sync; it exposed exactly which layers survived and which were flattened away.
- Add a diagnostic for label-only capture so benchmark reports can separate "feature name mentioned" from "builder could implement the right behavior."
- Keep the system cross-cutting bar, but ask scorers to state whether the cross-cutting evidence is a mechanism or a rationale.

## 5. Methodology caveats

- **Fresh-context fidelity:** same-context safeguard held for this scorer; I used the assigned phase_two files, plan, metadata, TIMING entry for run 001, and frozen reconstruction only.
- **Single-run limitation:** this is one run for one candidate/effort setting; no variance claim is made.
- **Borderline capture calls:** I leaned inclusive on product non-goals, LWW-by-server-source, reduced-motion charm, and performance observability. Those calls affect planning quality more than fidelity.
- **System cross-cutting:** S1, S6, S7, and S9 required judgment about whether repeated mechanisms expressed a principle. I awarded partial when only primary/mechanism layers survived.
- **Confabulation:** no meaningful ungrounded reconstruction claims were found. The reconstruction mostly stayed plan-derived and often marked items not recoverable.
- **Rule-without-why:** the largest caveat is the volume of rule-only captures. They count for planning where captured, but not as why recovery.
