## 3. Diagnostic patterns

- **Affective vs functional.** Affective whys recovered better (84/98, 85.7%) than functional whys (42/54, 77.8%). The plan translated affective goals into enforceable mechanisms, so B could recover many from lints, closed enums, UI refusals, and designed accessibility surfaces.
- **Weight-3 vs weight-2.** Weight-2 whys recovered at 90.9%; weight-3 whys at 79.6%. The high-weight rows were more discriminating because they required secondary contributors and downstream consequences, not just the core rule.
- **System-level vs feature-level.** System-level fidelity was high (92.9%), but S3 and S4 were compressed into consequences rather than named as principles. Feature-level fidelity was lower (80.6%) because partial multi-layer misses accumulated.
- **Multi-layer recovery patterns.** Primary causes survived most often. Secondary contributors and downstream failure modes leaked: examples include F2's Tamagotchi/screensaver endpoints, F4's stacked-loop phase artifact, F16's impossible-retrofit warning, and F20's private-relationship-to-data-product rationale.
- **Subdomain patterns.** Sync/server-canonicality and accessibility were especially strong. Privacy plumbing survived, but the deeper relationship rationale was thinner. Starter/adoption identity headroom rows revealed the most compression: F29 none, F30 partial, F31 partial.
- **Evidence-bound effects.** The stricter v06 gate mattered. Several rows would likely look strong under rule-only scoring, but were partial or none because the reconstruction carried the mechanism without every gold layer. No ungrounded reconstruction cases were found.

The failure shape suggests a very strong executable plan whose reconstruction preserved architecture and rules better than some of the product-intent explanations behind those rules.

## 4. Recommendations for v2 hardening

- Keep F29-F40-style targeted headroom. This run captured all features, yet F29, F30, F31, and F35 still separated mechanism from deeper why.
- Clarify how to score system principles that B reconstructs outside the System-level intent list. S6 was fully recoverable from the artifact but not cleanly named as a top-level principle.
- Consider splitting privacy whys into technical-boundary and relationship-rationale rows. F20 recovered the telemetry pipeline boundary but compressed the private-relationship-as-data-product layer.
- Retain multi-layer scoring for weight-3 rows. Most of the meaningful signal came from partials, not from missed feature capture.
- Keep the cross-cutting system bar, but require scorers to list inheritance evidence as this report does; it makes S3/S4-style compression visible.

## 5. Methodology caveats

- **Fresh-context fidelity.** Same-context safeguard appears to hold from this scoring context. The frozen reconstruction was treated as immutable, and this scorer did not modify it.
- **Single-run-at-temperature limitation.** This is one plan/reconstruction/scoring run; no variance signal is available here.
- **Borderline capture calls.** Only feature #7 was borderline: the plan lacks a literal glossary, but domain terms are defined operationally throughout. Counting it captured changes planning by less than one percentage point and does not affect fidelity denominator.
- **System-level cross-cutting.** The strict three-feature inheritance bar was easy for this plan because the plan is dense and heavily cross-referenced. The subjective call was whether B named S3/S4 as principles; I scored them partial.
- **Confabulation cases.** None found. Some reconstructed rationales are compressed, but I did not find rationales asserted without PLAN support.
- **Evidence-bound denials.** Partial rows mostly reflect lost layers where PLAN carried the rationale and B did not: F1, F2, F4, F12, F13, F16, F20, F24, F30, F31, and F35.
- **Rule-without-why cases.** F29 is the clean case: starter birds are reconstructed, but the arrived-not-catalog/avatar-selection rationale is not.
- **Operational compromise.** TIMING.json had phase 1 and phase 2A timing for run 001, but no phase 2B timing inside this scorer context, so phase 2B timing was omitted rather than fabricated.
