## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered 50.0/54.0 weighted points and affective whys recovered 90.0/98.0. The gap is small; the visible losses are not a broad inability to carry affect, but specific compressed exceptions such as S2/F10/F14 and F33.
- **Weight-3 vs weight-2.** Weight-3 whys recovered 98.0/108.0, lower than weight-2 whys at 42.0/44.0. The primary rule almost always survived; secondary or downstream rationale layers were the common loss.
- **System-level vs feature-level.** System fidelity was 26.0/28.0 and feature fidelity was 114.0/124.0. The planner preserved both philosophy and detailed mechanics; the main leak was rationale depth under otherwise correct implementation instructions.
- **Multi-layer recovery patterns.** Lost layers were mostly L2/L3: processed-vs-seen for S2/F10, intention-rotation for F14, retrofit consequence for F16, and deletion privacy rationale for F35.
- **Subdomain patterns.** Audio, accessibility, simulation, visit isolation, and telemetry were strong. Account lifecycle and quiet engagement-exception whys were more compressed.
- **Evidence-bound effects.** F33 was the clearest denial: the read-only notebook rule survived, but the observer-record versus user-journal why did not. No ungrounded reconstruction claims were found.
- **Borderlines.** Feature 7 and feature 87 were captured inclusively; even if both were marked missed, planning quality would remain 98.3%, so the headline would not materially change.

The failure shape suggests a very strong plan whose reconstruction preserves most causal structure, but tends to shorten subtle affective rationales into broader labels like quietness, privacy, or continuity.

## 4. Recommendations for v2 hardening

- Add more probes that separate a mechanism from its affective reason. F33 shows that read-only can survive without observer-record/journal intent; F14 shows no-streak can survive without the user-intention-rotation rationale.
- Add a per-layer loss cause field: absent from PLAN, absent from RECONSTRUCTION, or present but ungrounded. That would make partial multi-layer calls easier to audit across scorers.
- Keep weight-3 whys demanding. They provided most discrimination in a near-saturated plan, especially on S2, F10, F14, F16, and F35.
- Consider making account lifecycle whys more explicit in future gold sets. Export/deletion/privacy areas are fertile places where correct implementation can mask missing product intent.
- Preserve the validity audit. This reconstruction did not mirror gold IDs, but the audit usefully distinguished plan-structure mirroring from gold-list mirroring.

## 5. Methodology caveats

- **Fresh-context fidelity.** The user prompt asserted fresh context and prohibited subagents. This pass used only the allowlisted phase-two files and assigned run 001 files; no context-bleed signs were found in the reconstruction.
- **Single-run-at-temperature limitation.** This is one run, so it provides no variance estimate.
- **Borderline capture calls.** Feature 7 was counted because domain terms are operationally defined without a formal glossary. Feature 87 was counted because settings/privacy copy is present without a literal privacy-policy-link phrase.
- **System-level cross-cutting.** The strict three-feature inheritance bar was satisfied for every system why; S2 is partial because a rationale layer was compressed, not because the PLAN lacked cross-cutting inheritance.
- **Confabulation cases.** None detected. Partial rows reflect compression or missing rationale, not unsupported invention.
- **Evidence-bound denials.** F33 was denied as mechanism-only. F10, F14, F16, and F35 received partial layer credit rather than full credit under v06 evidence rules.
- **Operational compromise.** TIMING.json exposed phase 1 and phase 2A timings for run 001 only; no phase 2B timing was available at write time, so phase 2B timing fields were omitted.
