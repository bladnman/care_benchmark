## 3. Diagnostic patterns

The candidate plan captured **117/120** features. The three misses were all non-gold-why feature anchors: the nightjar-like active bird in the night state, an explicit privacy-policy link in account settings, and a concrete browser support matrix.

Functional rationale survived better than affective rationale. Functional whys scored **48.0/54.0**, with especially strong recovery around presence precision, server-side simulation, no last-write-wins, deletion, and telemetry boundaries. Affective whys scored **72.0/98.0**; the losses clustered around social/notebook/exception whys where the plan named the rule but not the deeper relationship-shaping reason.

Weight-3 whys recovered **92.0/108.0**, better than weight-2 whys at **28.0/44.0**. The plan's load-bearing invariants helped high-weight items survive, but B often dropped downstream consequences: F2 lost the Tamagotchi-vs-screensaver band, F16 lost the retrofit consequence, F30 lost the unlock-economy consequence, F31 lost the retroactive-relationship consequence, and F40 lost the visual-rhythm rationale.

System-level fidelity was high because B recognized the plan's organizing principles. Feature-level fidelity was lower because several feature-specific whys collapsed into generic rules: F19 became simply matter-of-fact voice, F23 simply no leaderboards, F33 simply read-only notebook, F37 simply per-invite sharing, and F39 simply actual host snapshot.

Evidence-bound scoring changed the outcome meaningfully. Seven included whys were marked `rule_without_why`; these rows counted for planning capture but not for rationale recovery.

## 4. Recommendations for v2 hardening

For v2, keep the evidence-bound operator: it cleanly separated a high-quality implementation plan from missing rationale recovery.

- Add more targeted exception whys like F29-F40. They discriminated well because strong plans often build the rule while losing the reason.
- Preserve multi-layer judging, but consider adding a required downstream-failure note to phase 2A prompts. The common leak was not the mechanism; it was why the wrong version becomes a different product.
- Keep the cross-cutting system bar, but ask scorers to flag when B identifies a principle only outside the system section. S3 and S4 were preserved in the plan but not cleanly reconstructed as system intent.
- For social and notebook features, add even more rationale anchors. This run showed that social-scope refusals can collapse into generic 'no social network' language.

## 5. Methodology caveats

- Fresh-context fidelity: scoring used only the allowed phase-two files, assigned plan/metadata/timing slot, and frozen reconstruction. The reconstruction was not modified.
- Single-run-at-temperature limitation: this is one sample only; no variance signal is available from this run alone.
- Borderline capture calls: features 7, 43, 44, 52, 55, and 57 were captured inclusively; none affected feature-level why reachability except F11, where the captured anchor still scored no recovery.
- System-level cross-cutting: S3 and S4 were the main subjective calls. The plan preserved each across at least three decisions, but B did not identify them cleanly in system-level intent.
- Confabulation cases: none were scored as recovered without plan grounding. No ungrounded reconstruction count was recorded.
- Evidence-bound denials: F11, F19, F23, F29, F33, F37, and F39 preserved mechanisms without the gold rationale.
