# Pocket Aviary — v1 implementation plan

## 1. Product contract and scope

Ship a browser-only, single-screen aviary with two starter birds and a hard maximum of seven. A signed-in person has one canonical aviary, may name or rename birds, and may accept age-paced arrivals from a roughly six-species pool. The two starter species are assigned by the system; naming is the only initial choice. The scene fits any supported viewport without panning, zooming, or cropping a bird. The first usable frame shows the ongoing aviary, not an entrance sequence. A returning host is noticed by one bird within one to two seconds, with behavior conditioned on elapsed absence, boldness, and mood. There is no textual return greeting.

V1 includes watchful presence, listen-in, seed/song-fragment/still-pool offers, settle with five-second undo, a sparse read-only field notebook, local-time lighting and rare ambient weather, magic-link accounts, multiple signed-in devices, account export and deletion, accessibility settings, and named read-only visit invitations. The product voice is lowercase, specific naturalist observation; auth, account, error, and accessibility settings use direct matter-of-fact copy.

Explicitly exclude scores, streaks, visit-frequency displays, achievements, levels, leaderboards, care meters, hunger, distress or death, direct perch placement, public profiles or discovery, comments, co-presence, shared aviaries, multiple aviaries, native clients, payments, push engagement, and recorded call loops. No host interaction signal is sourced from a visitor. Bird trait numbers have no in-product UI. The required account JSON export contains the user's raw vectors as data portability, behind account settings; it is not rendered as a stats surface.

## 2. Delivery shape and ownership

Build a small web client, an authenticated API, a durable simulation worker, and a transactional store. Keep the simulation logic in a versioned, deterministic engine package used by the worker and by test fixtures. Use a relational database for accounts, aviaries, birds, event log, invitations, visits, notebook, and tick checkpoints; use an object store only for short-lived account-export artifacts. The server is the sole writer of bird personality, mood, perch/behavior schedule, weather, notebook, and age-based adoption availability. Clients submit bounded intentions and attention evidence, then read versioned projections. The browser alone renders continuous frames and synthesizes calls. An edge-served HTML shell may carry a small, signed, fresh snapshot for a returning session so the first bird need not await the full JS bundle; validate freshness and immediately reconcile with the canonical API. Never put a private snapshot in a shared public cache.

Separate three kinds of state:

1. **Canonical simulation state:** persisted and versioned by server ticks, continuing with no client connected.
2. **Ephemeral session state:** local focused bird, audio permission, top-bar opacity, open panels, and a five-second settle undo window. Server records settle as a session gesture; it does not alter bird identity or permanent traits.
3. **Render ornaments:** leaf/feather drift and subsecond pose interpolation generated locally from a stable snapshot seed. These never enter the event log or cause drift.

Use schema versions for snapshots and engine rules. Migrations preserve bird IDs and vectors; reject any migration that silently regenerates a bird or resets a vector. Encrypt email only on the account record. All internal joins, service messages, logs, and operational metric dimensions use a synthetic account UUID, with no email-derived key. Restrict database access so analytics jobs have no access to bird, event, notebook, or per-account state tables.

## 3. Persistent data model

| Record | Essential fields and constraints |
| --- | --- |
| Account | synthetic UUID, encrypted verified email, email verification state, IANA timezone, settings (caption preference, reduced motion override, visit notification opt-in), creation time, deletion requested/effective times; one aviary FK; per-device revocable sessions stored as token hashes. |
| Aviary | UUID, account UUID unique, creation time, monotone state version, last successful tick, deterministic engine seed, lighting/weather state, next age-based adoption availability, scene layout version. |
| Bird | stable UUID, aviary UUID, species ID, user name, adopted time, five bounded scalar personality traits (boldness, social warmth, vocal frequency, plumage saturation, curiosity), mood enum and mood-transition time, perch zone/slot, behavior phase and phase origin, call-signature seed, last offer-accept timestamps. Constrain 2–7 active birds and never replace an existing ID on rename or rule migration. |
| Interaction event | account UUID, aviary UUID, event UUID/idempotency key, per-account sequence, server receipt time, validated client event time, session/device ID, type, bird ID or offer type where applicable, bounded duration and payload, processing tick/version. Append-only; retention bounded to what simulation and privacy duties require. |
| Presence interval | session/device ID, server time bounds, qualified evidence timestamps, settled/closed/expired reason; stored as event-derived intervals. Merge overlapping host intervals across devices before drift. No visitor presence rows. |
| Field notebook entry | stable UUID, aviary UUID, occurrence time, template/grammar version and rendered naturalist text, referenced bird IDs, observation category. Append-only, paginated oldest-to-newest access without archival cutoff. No entry reports user attendance. |
| Invitation and visit | invitation UUID, host account UUID, encrypted invitee email on restricted invite record, hashed one-time redemption secret, issued/expires/revoked/redeemed time, bound visitor identity or scoped session, active authorization expiry; visit UUID, started/ended times and approximate duration. Host-facing log joins invitation data; general telemetry never does. |

Keep a private audit of vector deltas and engine versions alongside canonical records for correctness and recovery, isolated from analytics. Snapshot projections include species, name, mood-derived behavior cues, perch, scheduled calls, weather, scene time, state version, and server time; they omit raw vectors and internal presence details. Bird identity is always stable across projection, export, rename, and visit views. Account export explicitly includes vectors, moods, birds, notebook, and settings; transmit only through a short-lived download link emailed to the verified address. Deletion marks the account immediately, suspends sessions and invitations, offers recovery for 30 days, then hard-deletes dependent records and artifacts, including account-linked telemetry where any exists.

## 4. API and authorization contract

All mutating routes require authenticated host sessions, CSRF protection for cookie auth, rate limits, payload validation, and an idempotency key. A visitor token only grants the narrow snapshot route. Define explicit schema versions and error codes; errors use matter-of-fact copy in the UI.

| Route | Behavior |
| --- | --- |
| `POST /auth/magic-links` and `POST /auth/consume` | Issue 15-minute, single-use link with per-email/IP abuse limits; atomically consume and issue a revocable per-device session. Do not log secrets. |
| `GET /aviary/snapshot?sinceVersion=` | Return current canonical projection, server time, next recommended pull, and ETag/version. `304` when unchanged; never let a cache serve stale authorization. Include a small current timeline so the client can enter mid-action. |
| `POST /aviary/events` | Accept batches of presence evidence and start/end events for listen-in, offer, settle/undo. Return accepted IDs, rejected reasons, server receipt time, and state version. Duplicate IDs return prior result. Do not accept vector, mood, or perch writes. |
| `GET /notebook?cursor=` | Stable cursor pagination, read-only entries. |
| `PATCH /birds/{id}` | Rename only, with ownership check, length/safety rules; does not touch identity or engine state. |
| `POST /aviary/adoptions` | Accept only a server-offered age-eligible bird, transactionally enforce cap and no duplicate acceptance; server assigns species/seed and persists identity before response. |
| `GET/PATCH /account/settings`, session revocation, email-change start/confirm, export request, deletion/recovery | Account actions with fresh-auth checks where appropriate. Email change commits only after new address verification. Export link short-lived and single-account scoped. |
| `POST /visits/invitations`, `GET /visits/invitations`, `DELETE /visits/invitations/{id}`, `GET /visits/log` | Explicit host invitation and revocation, current outstanding invites, host-only log. |
| `POST /visits/redeem` and `GET /visits/{id}/snapshot` | Redeem a one-time email link, bind a narrow viewer session, then serve the same scene projection as host snapshot. Every pull checks expiry and revocation. No event route accepts a visitor session. |

Interpret “one-time visit link” as one-time redemption into a scoped visitor session, not a single snapshot. Unredeemed invites expire after 30 days; revocation invalidates both outstanding links and active viewer sessions, with the next pull returning a plain “visit no longer available” surface. Use short visible-page pull intervals (target 15–30 seconds) so this takes effect promptly, and recheck on visibility resume. The host sees visit email, date, approximate duration, and outstanding invitations only on demand in settings; no badge or default notification. Support the explicitly opt-in visit notification setting only after deliberate enablement, with no onboarding prompt.

## 5. Presence, event processing, and simulation

### Honest presence

The client qualifies a presence interval only while **all three** hold: `visibilityState === visible`, window focus, and pointer movement or keypress within a calibrated few-minute window. Start with a three-minute activity window and measure it in qualitative testing against people who sit quietly; do not tighten it to a few seconds. On any condition failure, settle, navigation, or page hide, end the interval immediately. Send short heartbeats (for example every 20 seconds) only while qualified; server caps each credited segment to the heartbeat lease plus small network grace and expires abandoned sessions. A fresh pointer or key event alone cannot retroactively credit unobserved time. Pointer movement is throttled locally and does not emit raw coordinates or keystrokes. On mobile, a touch may count as pointer activity, but mere visible tab time does not. Visitors never run this collector.

Use server receipt time as the authority, clamp delayed client times, deduplicate retries, and union simultaneous host-device intervals to prevent double drift. Track listen-in duration from validated start/end pairs with timeout caps; a new focused bird closes the previous interval. Settle terminates credited presence at once. A click in the scene within five seconds reverses the client lighting transition and submits an undo/re-engage event; any later re-engagement starts a normal new presence interval. Tab-close and settle yield the same absence treatment. No engine penalty exists for either.

### Tick and drift

Run an approximately one-minute durable tick for every aviary, including inactive ones. Partition work by synthetic aviary UUID; lease each partition and serialize each aviary's tick in a database transaction. Read event sequence after the checkpoint, compute at a fixed effective tick time, append server-authored deltas, update mood/behavior/call schedule and notebook decisions, increment state version, and advance the checkpoint atomically. Retry idempotently after crashes. If a worker is down, deterministically catch up elapsed ticks from the last checkpoint in bounded batches without creating presence or forcing sudden client-visible jumps; alarm on lag. Never use client last-write-wins for personality.

Use normalized traits in `[0,1]` with species-specific initial distributions and soft caps. For each trait, calculate a nonnegative incremental target from capped, recency-filtered signals: qualified presence dominates; listen-in adds warmth/vocal frequency for the focused bird; offers add small curiosity for accepted offers and boldness for a bird approached, subject to per-bird cooldown (start at five minutes). Apply a slow first-order low-pass step, `delta = max(0, rate * (target - current))`, then cap to the trait ceiling. Keep the filter's decaying input accumulator separate from persisted trait values: after absence the signal fades, but the trait never declines. Do not let repeated offers or two devices accelerate drift past daily caps. Plumage saturation likewise never drops. Use engine fixtures modeling a regular 5–10-minute daily observer: instrumentation should detect change around week one; blinded visual/audio comparisons should become noticeable around week three; no individual session should produce a visible vector jump. Test two-week absence to ensure birds remain healthy and familiar, with less immediate greeting from a faded recent-attention signal rather than reversed personality.

Mood is a persisted enum (start with wary, content, curious, drowsy, alert) plus timers. At each tick, compute a transition probability from prior mood, local time, recent offers, weather, other birds' calls, and trait biases. Use hysteresis and minimum dwell times to prevent jitter. “Daily-ish reset” means a gradual time-of-day pull toward a baseline over hours, never setting all birds to neutral at midnight or page open. Sample rare short rain and soft wind from seeded, persisted weather schedules a few times a week; rain briefly quiets calls, wind modestly changes alert/wary probabilities. Store the account's IANA timezone and evaluate local time with DST-aware conversion; a timezone change affects future lighting/ticks, not bird identity or history. Night settles most birds but leaves the nightjar-like species eligible for occasional late calls.

The tick selects perch zones from mood and boldness, with spacing constraints and stable bird IDs; it schedules phase origins, transitions, call events, and occasional bird-to-bird responses. Calls from one bird can nudge nearby moods and produce organic chorus windows, but never a synchronized return cue. For return greeting, calculate absence since last qualified host presence, rank one eligible bird by boldness, warmth, and mood with seeded variation, and schedule a gesture within two seconds of visibility. A quick return favors a glance; days away favor a slightly longer orientation. Stagger any secondary response. Suppress visitor greetings. Keep each greeting seed/event different without cycling a tiny fixed list.

Notebook generation runs from salient canonical observations, not every session or raw event. Apply a rarity budget around one entry every few days for regularly visited aviaries, with a distinctiveness threshold and dedupe window; notable moments may earn an extra entry. Render bird-specific, present-tense naturalist prose from vetted grammar templates plus state context and store the rendered result so later rule changes do not rewrite history. Never mention visit frequency, vector values, or a behavioral score.

Age-based adoption offers derive only from aviary creation time, never session count or interaction volume. Define initial pacing in configuration (first additional bird after a few months, later intervals widening toward at most five or six in a year); tune editorially without promising more birds as a reward. Transactional cap stays seven under concurrent devices.

## 6. Scene and audio pipelines

### Visual

Use one normalized scene coordinate system with front, middle, and back perch zones. Layout solves bird bounds and perch spacing for viewport changes; on a narrow phone, compress spacing and scale uniformly enough to retain all silhouettes and accessible hit areas. A wide viewport adds air between perches. Render small SVG/vector silhouettes or compact raster details over a calm sky/foliage scene, with restrained foreground depth. The top bar alone contains account, accessibility, notebook, and offer controls; its opacity falls after a few seconds of pointer stillness and returns immediately on pointer or keyboard activity. No buttons, labels, tooltips, or counters sit inside the scene.

Initialize each bird pose from snapshot behavior phase plus `(serverNow - phaseOrigin)`, so the first frame is mid-preen, scan, tilt, shuffle, or call. A small server-provided timeline bridges current and next snapshot; the client interpolates perches and mood-shaped poses, corrects small clock error gradually, and snaps only on an explicit large-gap resync behind a soft pose transition. Locally generate sparse leaf/feather motion and subtle parallax; pause rendering and ornament generation when hidden, then fetch fresh canonical state on visibility return, browser resume, or long frame gap. A cold uncached snapshot may show a quiet field with faint ambient cues; never show a spinner or fade into a supposedly new aviary. Only the real post-adoption empty state permits a soft first-bird fly-in. Settle fades lighting over seconds and lowers calls; normal local day/night lighting continues independently of whether the tab is open.

Reduced motion is a designed second renderer chosen by `prefers-reduced-motion` or an override. Keep the same canonical state and actions; replace pose micro-motion with slow still-pose cross-fades, flight paths with perch-to-perch cross-fades, and remove drifting leaves/feathers. Slow ambient color changes remain. Honor setting changes live. Avoid layout flashes while switching renderers.

### Calls and listen-in

Define a versioned call grammar per species: motif families, interval contours, note envelopes, rhythm distributions, and a stable per-bird signature seed. At playback, vary microtiming, pitch, timbre, and gaps within signature bounds using the tick's scheduled call event seed and current mood. Keep Pip recognizable across moods and drift; vocal-frequency trait changes call probability and chorus participation, not the identity motif. The browser uses WebAudio oscillators/noise/filter/envelope nodes or an AudioWorklet with pooled voice objects and bounded polyphony. Schedule ahead against the audio clock; mix species/bird channels into a restrained ambient bus, with limiter and volume control. A chorus is overlapping independent generated calls, never layered recordings.

Listen-in ramps the focused bird up and other birds to a quiet **nonzero** ambient level over a few seconds; disengagement ramps back symmetrically. Clicking the same bird, another bird, empty space, or moving keyboard focus away follows the specified transitions. The song-fragment offer uses a small motif library rendered through the same synthesis path; its call response is server-decided by mood and personality. Captions are generated from the actual grammar event parameters, including bird/location and audible contour, so a caption describes the call that would play.

Modern browsers may block autoplay until a user gesture. Render the first scene without waiting for audio permission; if audio cannot start, keep it quiet and expose captions automatically until a user enables sound. On unsupported or failed WebAudio, use silence with captions on by default, never recorded fallback. Do not display an intrusive audio prompt over the greeting. Respect mute; record only the permitted, coarse interaction signal needed by the engine, with no audio recording.

## 7. Accessibility, interaction, and copy

Make the scene a meaningful focus region with individual bird controls represented in the accessibility tree while keeping chrome visually outside it. Tab traverses top-bar controls then the first bird; arrows move between birds; Enter starts listen-in; Escape exits; focus departure disengages. The offer menu, notebook, settle, settings, and dialogs are keyboard-complete with visible focus against both day and night backgrounds. Use touch targets that survive phone compression. Screen-reader narration is composed from the same snapshot and grammar events as rendering: slow naturalist prose every 30–60 seconds during idle, with promptly queued user-initiated greeting, offer response, and settle observations. Coalesce stale updates and avoid flooding the live-region queue. Do not narrate raw status codes, perch numbers, or trait values.

Call captions are optional in normal operation and enabled by default when WebAudio is unavailable. Position them near the calling bird while ensuring they remain readable and do not cover another bird; allow a text alternative in the accessibility tree. Test WCAG AA text contrast for all top-bar, caption, notebook, and settings copy across daylight, dusk, rain, and settled lighting. Produce authored naturalist copy for product surfaces and direct system copy for sign-in, errors, revocation, and settings. Test the experience with screen-reader, keyboard-only, captions, muted audio, reduced motion, and combinations of these, not only individual toggles.

## 8. Performance, privacy, and operations

Hard budgets: initial JS under 2 MB gzip, first bird visible within 500 ms on a mid-tier mobile device over 4G, 60 fps idle on a five-year-old mid-range laptop during a 30-minute session, and no sustained client memory growth over that session. Set CI bundle budgets and a mid-tier mobile cold-load lab profile. Put first-scene code and tiny assets in the critical path; lazy-load notebook, account, invitation, and settings views. Bound ornament objects, voice pool, AudioContexts, timers, and notebook virtualization. Maintain scene work below a 16.7 ms frame budget, with headroom for browser work. Treat 500 ms as a performance gate, not a best-effort aspiration; if authentication/network architecture makes it unattainable, surface that as a launch blocker and optimize edge snapshot delivery rather than weakening the requirement.

Collect aggregate-only operational metrics: request counts/latencies/errors, first-bird timing, frame-time histograms, memory trend in synthetic runs, audio-context errors, snapshot freshness, event acceptance/retry counts, tick latency and lag, auth/invite error counts. Synthetic browsers run from common geographies on a schedule. Alarm if simulation tick p99 exceeds five seconds. Logs may carry opaque request and synthetic account IDs for support but must never contain emails, invitation secrets, per-bird state, presence histories, or notebook prose. Do not build a population drift dashboard or copy event tables into an analytics warehouse. Calibration of drift uses deterministic synthetic fixtures and consented qualitative user research, not aggregation of private interaction histories. Keep a per-account operational path for diagnosing corruption under strict access control without exporting it to telemetry.

Target last two major Chrome, Safari, Firefox, and Edge versions. Unsupported browsers receive a direct explanatory surface. Handle network outages by retaining the last visually coherent snapshot as a read-only local view with an unobtrusive, matter-of-fact system status outside the scene; queue bounded, idempotent interaction events only for a short authenticated interruption, and do not credit unverified offline presence. On reconnect, fetch canonical state before playback of queued outcomes. An expired session asks for sign-in rather than inventing local drift.

## 9. Execution sequence and acceptance gates

1. **Foundation:** schema, synthetic IDs, encrypted email, magic-link consumption, per-device sessions, deletion/export scaffolding, privacy access boundaries, API contracts. Gate with single-use 15-minute links, revocation, email change verification, and data-deletion tests.
2. **Canonical engine:** deterministic tick, checkpoints, event idempotency, presence interval union, trait drift, mood/weather, perch/call schedule, age-based adoption. Gate with concurrent-device replay, tick crash/retry, two-week absence, DST transition, monotonic trait invariants, and stable bird-ID migration tests.
3. **First scene:** snapshot delivery, responsive one-screen composition, mid-action first frame, return-greeting, continuous idle/mood behavior, hidden-tab resume. Gate at cold-load first-bird <500 ms and no spinner/entry sequence on target browsers.
4. **Interactions and voice:** listen-in, all offers with per-bird cooldown, settle/undo, notebook generation and pagination, copy review. Gate with reaction coverage by mood, no repeated canned greetings, sparse notebook output, and no user-attendance prose.
5. **Audio and accessible renderers:** procedural grammar, mixing/captions, reduced-motion pose renderer, narration, keyboard and contrast. Gate with call recognizability listening tests at two through seven birds; screen-reader and reduced-motion qualitative tests; autoplay/WebAudio failure tests; 30-minute frame and memory runs.
6. **Visits and release:** invite redemption/revocation/log and read-only projection, account settings, threat/privacy review, synthetic monitoring. Gate with revocation on next pull, visitor event rejection at API and database boundaries, no visitor drift, no default notification, and no hidden social discovery.

Roll out behind server flags: internal aviaries with two birds, a small opt-in cohort, then broader availability after drift and accessibility reviews. Increase the *supported count in active aviaries* from two toward seven only after chorus recognizability and scene-density tests at each count; keep the seven cap enforced from day one. Monitor technical health and opt-in qualitative reports, not engagement leaderboards or population interaction patterns. Launch gates require the budgets and privacy boundary, not just a pleasant demo.

## 10. Key risks and explicit decisions

| Risk | Mitigation and decision |
| --- | --- |
| Drift too fast, too slow, or falsely credited | Strict three-signal presence with heartbeat lease and cross-device interval union; deterministic week-one/week-three fixtures; per-day signal caps; qualitative longitudinal review. Never reduce traits on neglect. |
| Lost vectors or divergent devices | Server-only additive deltas in serialized ticks, atomic checkpoints, immutable bird IDs, backup/restore drills, schema migration invariants; no client personality writes or last-write-wins. |
| Tick backlog after outage | Durable partition leases, idempotent catch-up, lag alarms, bounded replay and controlled client reconciliation. Keep inactive aviaries ticking without manufacturing attendance. |
| Calls sound canned or chorus blurs | Per-bird stable grammar signatures with bounded variation, pooled synthesis, seven-bird listening tests, gradual nonzero listen-in mixing; no recorded loops. |
| Autoplay prevents audible first call | Draw instantly; start WebAudio on permitted gesture; captions and silence maintain access until sound is available. Do not promise audible autoplay on platforms that prohibit it. |
| Accessibility becomes a state dump | Author narration/caption grammars from shared events, slow live-region pacing, designed reduced-motion poses, human testing across combined modes. |
| Privacy leaks through logging or exports | Schema-level separation, synthetic IDs, secret redaction, restricted export jobs and short-lived links, no analytics access to interaction store, hard-deletion verification. |
| Browser/device variance breaks first frame | Edge snapshot, compact critical bundle, asset fallback silhouettes, lab runs on target browsers/devices, no spinner. |

Resolve remaining tunables through implementation experiments: exact presence activity window, tick cadence near one minute, trait rates, offer cooldown, greeting timing distribution, weather frequency, and adoption age thresholds. Keep them versioned server configuration with invariant tests so calibration can change without resetting a bird or altering old notebook entries.
