# Pocket Aviary — v1 implementation plan

## 1. Product contract and decisions

Build one private, browser-only aviary per email magic-link account. Each starts with two stable, named birds from a coherent pool of roughly six species; the maximum is seven. The host can watch, listen in on one bird, offer a seed/song fragment/still pool, settle the session, read an automatically written field notebook, and invite a named visitor to a read-only view. Birds continue changing on a server tick with no browser open. Every client renders the same canonical bird identities, moods, and accumulated personality drift.

Keep the aviary a single responsive horizontal scene with front/middle/back perches and no pan, scroll, zoom, bird placement, or UI overlays. The only scene-adjacent chrome is a thin top bar. Product prose is lowercase, specific, present-tense naturalist observation. Identity, settings, errors, and accessibility-setting prose is plain and direct. Never present a welcome banner, streak, score, trait stat, distress, hunger, death, public discovery, comparison, or notification by default. Do not build native apps, payments, shared aviaries, comments, feeds, profiles, or recorded-call fallback.

Resolve three specification edges before implementation by adopting these rules:

1. `accounts_sync.md` explicitly requires raw personality vectors in an account JSON export while `bird_engine.md` bars numerical traits in product UI. Treat the on-demand portability export as the sole raw-data exception. Do not send vectors in scene snapshots, telemetry, notebook prose, settings, or a debug panel. Label the export as account data, not bird stats.
2. Settle is reached through an item in the account icon's top-bar menu. This preserves the four-icon top bar specified by `aviary_layout.md` while satisfying the top-bar access requirement in `interactions.md`. Its item and immediate aviary response use product voice; account administration in the same menu uses system voice. Verify the discoverability of this placement in usability review.
3. Visit notifications are an explicit opt-in exception to the general no-notifications rule. Keep them off for every new account, absent from onboarding, and without icon badges. If enabled, send one restrained email per visit; no push channel or engagement reminders.

## 2. Delivery shape and ownership boundaries

Use a small web client, an authenticated HTTP API, a relational transactional store, an email worker, and a continuously running simulation scheduler/worker pool. The API owns authentication, event validation, reads, invitations, exports, and deletion. The simulation service is the **only** writer of bird personality, mood, perch/behavior timeline, weather, call schedule, and notebook observations. The browser owns interpolation, ambient ornament, audio synthesis, presentation, and ephemeral UI state; it never advances canonical simulation time. A separate operational metrics path receives only schema-allowlisted aggregate health data and has no read access to the simulation database.

Deploy the HTML shell and critical SVG/CSS close to users. Fetch a private, authenticated, compact initial snapshot at the edge and embed it in the first HTML response; mark personalized responses `private, no-store` so a CDN cannot mix accounts. Server-render the first bird pose/perch in that response, then hydrate motion without replacing the DOM. Noncritical account, invite, and notebook code loads on demand. The first visible scene is already at a sampled point in its timeline, never an entry animation. If the authenticated snapshot is delayed, paint a quiet field with subtle non-bird motion, without a spinner or status toast. The only empty aviary is the interval after the first adoption; those first birds then arrive with a soft fly-in.

Use versioned data contracts and feature flags for simulation coefficients, species assets, call grammar, and eligibility. A grammar or visual release changes future expression without regenerating bird IDs, resetting persisted vectors, or rewriting old notebook entries. Roll migrations forward with compatibility readers before switching writers; practice recovery from backups before launch.

## 3. Persistent model

| Record | Required fields and invariants |
| --- | --- |
| Account | Random UUID primary key; encrypted verified email stored on this record; pending new email until verified; IANA timezone; accessibility/audio preferences; visit-notification opt-in default false; creation and optional soft-delete deadline. Email is never an ID, partition key, telemetry field, or log field. |
| Device session | Opaque token digest, account UUID, device label, issue/expiry/revocation times. Device tokens are individually revocable. |
| Aviary | Account UUID, creation time, deterministic random seed, monotonically increasing snapshot version, last completed tick index/time, last consumed event sequence, current weather and day-cycle state. Exactly one per account. |
| Bird | Stable UUID, aviary UUID, species, mutable name, adoption time, individual call-signature seed, five normalized persisted traits (boldness, social warmth, vocal frequency, plumage saturation, curiosity), mood and mood-since, perch/behavior state and transition timeline. Never replace ID on rename, migration, or asset update. |
| Interaction event | Server-assigned sequence and receipt time, account/session UUID, optional bird UUID, type, validated bounded payload, idempotency key, and consumed tick. Append-only until short recovery retention expires. Clients submit observations/actions, never absolute trait values. |
| Presence lease | Session UUID, server-bounded eligible interval, last qualifying ping, stop reason. Merge intervals across the host's tabs/devices before drift credit; a visitor cannot create one. Retain raw intervals only as long as required for tick recovery. |
| Notebook entry | UUID, aviary UUID, observed time, immutable lower-case prose, observation-kind and dedupe key. Cursor pagination has no archive cutoff. |
| Invitation / visit | Host UUID, invitation UUID, encrypted invitee email (stored once in the invitation record), digest of one-time token, expiry, redeemed/revoked state, scoped visit-session digest, last observed visit time, and visit-log interval. Logs reference invitation IDs rather than duplicating emails. |

Store only the account email on the account record; invitation email is separate necessary contact data, encrypted and never used as an internal identifier. Keep link tokens hashed at rest, with no tokens or emails in URLs recorded by access logs. Encrypt sensitive fields and backups, restrict service credentials by table/function, and audit access to exports and deletion jobs. Use per-account encryption material so hard deletion can make any backup remnants unreadable while backup rotation removes them.

Capture the account's IANA timezone at first setup and let the host change it in settings. The canonical day/night cycle follows that setting, including daylight-saving changes. Do not let two devices in different timezones silently fight over it. Render clients from the timezone and server time in each snapshot. Settle's lighting override is local to the initiating host session; its small mood-quieting event is canonical. This keeps another device on the same bird state without unexpectedly imposing that device's goodbye gesture.

## 4. API and security contracts

Version the API under `/v1`; require TLS and CSRF protection for browser mutations. Use same-site secure cookies for host/visit sessions. Every write accepts a UUID idempotency key; the server returns the prior result on retry. Return matter-of-fact errors with stable machine codes and a recovery action, never naturalist prose.

| Endpoint family | Contract |
| --- | --- |
| `POST /auth/link`, `POST /auth/consume` | Request an email magic link; token expires after 15 minutes and is consumed atomically once. Consumption uses an explicit POST after landing so mail scanners cannot spend it. Rate-limit requests per email within the isolated auth boundary without emitting email as a log or telemetry key. Issue a revocable device session. |
| `/account`, `/account/sessions`, `/account/email-change` | Read settings; list/revoke sessions; verify a new email before switching while the old address continues to work. Account and accessibility settings are lazy loaded. |
| `GET /aviary/snapshot` | Return version, server time/timezone, bird IDs/names/species, mood and perch/pose/timeline directives, weather/light, current and near-future call events, and active transitions. No raw personality vectors or per-bird event history. Support conditional version requests, but refresh time-dependent directives even when state version is unchanged. |
| `POST /aviary/events` | Accept bounded `listen_start`, `listen_end`, `offer`, `settle`, `return` and rename/adoption commands as appropriate, with session, target, and idempotency key. Validate ownership, cooldown, bird count, eligibility, and server receipt order. Append an event; do not update traits inline. Return accepted sequence and any immediate presentation cue. |
| `POST /aviary/presence` | Receive periodic qualifying host lease pings and explicit stop events. A ping reports the three browser conditions and last pointermove/keypress age; server clamps intervals and rejects stale/malformed reports. This endpoint is unavailable to visit sessions. |
| `GET /notebook?cursor=` | Immutable newest-first entries with stable cursor, page size, and no age cutoff. |
| `/invites`, `/visit/redeem`, `/visit/snapshot`, `/visits/log` | Host creates/revokes/lists invitations and reads the on-demand visit log. Visitor redeems a one-time link into a scoped, revocable, read-only session, then pulls only visit snapshots. Visitor endpoints reject every host mutation and never expose host account settings, raw vectors, or private event log. |
| `/account/export`, `/account/delete`, `/account/recover` | Generate the requested JSON export on demand and email a short-lived, one-time download link to the verified address. Start 30-day soft deletion immediately, allow explicit recovery during that window, and then hard-delete all account-tied data. |

Define schemas for each event and snapshot with size ceilings and contract tests. The host snapshot and visitor snapshot use the same visual/audio scene directives, but visitor capabilities are absent at the authorization layer, not merely disabled buttons. A visitor receives no greeting cue, presence lease, offer, listen-in, settle, or notebook mutation. For privacy, v1 visitor chrome exposes only a way to leave; the field notebook remains host-only. The host's on-demand visit log shows invitee email, visit date, approximate duration, and outstanding invitations, with no badge or default notification.

An invitation is sent only by explicit host action, expires after 30 days if unredeemed, and is never automatically renewed. Store a token digest; exchange the one-time bearer link for a visit cookie on deliberate redemption. Cap a visit session's lifetime and require another invite after expiry. Revocation invalidates outstanding tokens and active sessions immediately in storage; the next snapshot pull returns `visit_no_longer_available` in system voice. Keep visible visitor polling at a bounded interval (target 15 seconds) so revocation reaches an open view promptly. No host presence or drift credit is produced by visit traffic.

## 5. Server tick, presence, drift, and mood

Schedule each live aviary at an approximately 60-second canonical tick whether a client is connected or not. Partition jobs by aviary UUID; workers claim due jobs with leases. In one database transaction, lock one aviary, load events after its consumed sequence through the tick cutoff, process them in server sequence order, advance state and call/weather timeline, append any notebook entries, update the consumed sequence and tick index, and commit. Retrying the same tick must return the committed result rather than apply deltas twice. After an outage, process missed tick indices deterministically in bounded batches; do not freeze state until the next visit or fabricate catch-up on the client. Alarm on backlog and p99 tick latency over 5 seconds.

Presence eligibility is exactly `document.visibilityState === "visible"` AND `document.hasFocus()` AND a pointermove or keypress within a provisional four-minute activity window. Do not count a page simply because it is open, audio is playing, a pointer is down, or the browser reports focus without visibility. The four-minute value is a build-time calibration parameter: test stationary watching and mobile-browser behavior, then freeze it before drift calibration. The host sends a qualifying ping about every 15 seconds, immediately stops on hidden/blur/settle, and cannot backfill an interval after a missed ping or suspension. The server credits only the bounded time between consecutive qualifying pings, closes a lease after a short missed-ping timeout, and unions overlapping host-device intervals. Mobile touch behavior must be tested against the literal pointermove/keypress rule; if touch-only watching cannot produce the signal, resolve that product/spec gap explicitly before launch rather than silently count taps as presence.

Treat presence as the dominant slow input for every resident bird; listen-in adds a bird-specific signal; an accepted offer adds a small curiosity signal and proximity to an offer adds a small boldness signal. Rate-limit effective offer influence with a per-bird cooldown of a few minutes and a daily cap. A settle event ends presence and only nudges short mood toward quiet. Normalize signal per elapsed time, cap daily influence, and avoid a multi-tab or rapid-click multiplier. Use a nonnegative low-pass state per bird/trait, for example `h[t] = decay*h[t-1] + (1-decay)*bounded_signal[t]`; apply `delta = rate*max(0,h[t])*dt*(1-trait)^gamma`, then clamp to `[0,1]`. Persist the new vector as an additive, server-authored delta. Zero input decays the filter, never reduces the vector. Any lingering positive filtered signal can continue a little after departure; no invented presence is added. Plumage saturation also never declines. Quietness after long absence is a temporary expression/mood effect, never a reversal of earned personality.

Calibrate using synthetic accounts and scripted presence/interaction histories, not analysis of real per-bird histories. A proposed acceptance envelope is: regular 10–20 minute visits on most days yield instrument-detectable trait change after roughly a week, and a blind visual/audio comparison becomes noticeable around three weeks; one session and two weeks of absence must not produce a visible personality jump or distress. Tune coefficients and rendering thresholds together, because a numerically correct delta that is visible too soon is still a failure. Test saturation, cooldowns, 7-bird load, simultaneous devices, daylight-saving days, and outage replay.

Mood is a persisted five-state model (`wary`, `content`, `curious`, `drowsy`, `alert`), not reset on tab open. Use a seeded semi-Markov transition with minimum dwell times and a gentle daily pull toward time-of-day baselines. Inputs are recent interaction events, the account-local circadian phase, rare ambient weather, bird-to-bird responses, and personality biases. High boldness lowers wary probability; curiosity alters offer investigation; warmth changes greeting and response likelihood. Morning favors alert, dusk favors drowsy, and night is mostly settled while the nightjar-like species can remain active. A few short rain events per week lower calls temporarily; soft wind changes scanning/wariness. Persist mood and transition time each tick so the next session begins from the actual intervening trajectory, without a snap to neutral.

The server also chooses each bird's perch zone and behavior intent from personality/mood, with dwell times that avoid jitter. A wary bird tends toward the back, a bold bird toward the front; content preens, curious tilts toward sound, drowsy sits low. Model cross-bird calls and mood influence with bounded response probability and staggered timing so seven birds remain a small social system rather than a row of independent loops. Per-leaf and feather motion stays client-only ornament; it is never persisted as a simulation event.

## 6. Call grammar and greeting runtime

Give each of the roughly six species a compact motif grammar: note contour, syllable envelopes, rhythmic intervals, timbre, and allowed variation ranges. At adoption assign a stable bird-level signature seed and small immutable motif preferences. A scheduled call event carries bird ID, event ID, absolute server start time, grammar version, motif choice, pitch/timing/dynamic parameters, and response/chorus relationship. The browser synthesizes those parameters with WebAudio oscillators/filters/envelopes (an AudioWorklet only if profiling requires it), using bounded voice pooling and reusable nodes/buffers. Do not download recorded calls or concatenate audio loops. Preserve the recognizable motif contour and timbre across mood and trait changes; mood changes amplitude/tempo/spacing within tight bounds, while vocal-frequency trait chiefly changes call probability and chorus joining. Cap simultaneous voices and preserve a quiet ambient floor so the mix never becomes shrill.

On a host navigation or return from a hidden/blurred state, derive absence length from the last host presence/session time without exposing it as text. The server chooses one primary greeter weighted by boldness, warmth, current mood, and absence length. A short absence can produce a glance or short call; a long one can yield a step nearer or longer phrase. Seed genuine motif/pose variation per return event so greetings are never a three-clip rotation. Render the primary cue within one to two seconds; if another bird responds, stagger it with a small randomized delay, never a synchronized arrival chorus. The greeting is a bird action, with no toast, banner, absence count, or entry animation. A visitor never triggers it.

Client audio scheduling maps server time to `AudioContext.currentTime` from a snapshot clock sample and resynchronizes softly after long gaps. Listen-in ramps the focused bird up and the others down over a short, perceptible interval; the others remain audible. Disengage on a second click, another bird, empty-space click, or keyboard focus leaving; ramp back to ambient. Offers synthesize their song fragment from a small motif library and schedule a mood/personality-shaped bird response. A still pool and seed alter the scene/reaction without becoming hunger mechanics. Settling ramps the call mix down with the lighting shift; a click within five seconds cancels the local settle transition and restores presence, otherwise the settle event commits. Re-engaging later clears the local settled presentation.

Browser autoplay policy may block sound before a trusted gesture. Attempt to start when permitted, keep call captions on by default while blocked, and expose a plain audio-enable control within accessibility settings; resume on the first valid gesture. Do not add a fifth top-bar icon or recorded fallback. If WebAudio fails or is unavailable, run in graceful silence with captions enabled by default. Measure audio-context failures without recording bird or call content.

## 7. Scene and interaction client

Use compact SVG bird/perch assets and DOM/CSS compositor transforms for the seven-bird scene; keep a semantic DOM control for each bird. Render background sky/foliage, middle-plane perches and birds, then occasional foreground branches/leaves. Use normalized scene coordinates and responsive perch spacing so every bird stays visible on narrow phone and wide desktop viewports; never crop, pan, zoom, or require horizontal scroll. The day/night palette interpolates continuously in account-local time. A nightjar-like bird remains active at night. Weather is soft and rare, with no dramatic storm mode.

Snapshots provide an action's start/end time, position endpoints, pose phase, and easing. The client samples at the current server time on its first frame and interpolates subsequent snapshots without teleporting. If a tab hides, pause rendering and audio for battery; the server keeps ticking. On visibility return, a long animation-frame gap, or a low-frequency visible keepalive, request a new snapshot and blend to it only when the timeline allows. If a network error delays a refresh, retain the last scene quietly for a bounded period, then show a matter-of-fact recoverable error rather than pretending stale state is current indefinitely. Ambient leaves/feathers use seeded, slow client-side intervals and pooled DOM nodes; they never alter canonical state.

The top bar contains account/settings, accessibility settings, notebook, and offer icons; the account menu also houses Settle. Fade the bar nearly transparent after a few seconds of pointer stillness, restore it on pointer movement or keyboard activity, and keep it visible while any control has focus or a menu is open. Icons remain keyboard reachable and retain touch targets. There are no bird labels, tooltips, badges, or inline controls in the scene; enabled call captions are the intentional accessibility exception. The offer sheet is opened from the top bar and contains seed, song fragment, and still pool. Show a short functional cooldown state without suggesting a reward or penalty. Reactions are conditional and sometimes quiet or absent; do not guarantee a positive animation.

Two starter species are assigned by the service, then the host names them (with renameable suggestions). Do not present a species catalog. Later bird eligibility depends only on aviary age: provisional schedule at 90, 180, 270, 365, and 540 days for birds three through seven. Eligibility is never earned from visit count, offers, or payment. Present an available newcomer quietly in the account menu after the return greeting has had room to occur; allow `later` without a countdown, badge, or loss of eligibility. On adoption, allocate a new stable UUID/vector/signature, enforce the cap transactionally, and animate only that new bird's arrival. Review the precise adoption copy and placement with design before release.

## 8. Notebook and accessible expression

Generate notebook entries in the simulation transaction from noteworthy **aviary** observations: unusual greeting order, a long quiet interval, a perch change, weather passing, a characteristic call exchange. Use editorially reviewed grammar/templates with species, bird names, time of day, and local context; dedupe similar observations and target roughly one entry every few days for a regularly visited aviary, with a strict cap to keep even active aviaries sparse. Persist the finished prose so later renames do not rewrite history. Never turn it into an event feed, trait readout, visit-frequency report, or user-behavior judgment. The notebook is read-only, can be paged backward indefinitely, and is not shared into public discovery.

Build narration from the same scene/call timeline as visual rendering, using naturalist prose composed from current birds, perches, light, and noteworthy motion. Send a slow `aria-live="polite"` update approximately every 30–60 seconds at idle, suppress near-duplicates, and prioritize concise user-initiated observations (return greeting, offer reaction, settle) without flooding the screen reader queue. Keep controls and narration separate so keyboard focus is not stolen. Do not emit raw state labels or numerical personality values as narration. Test with actual screen readers for pace and coherence, not only ARIA snapshots.

Provide a designed reduced-motion path from `prefers-reduced-motion` or a saved accessibility setting: slow cross-fades among meaningful still poses, cross-fades rather than flight paths between perches, no leaf drift, and slower continuous color changes. The bird mood, calls, notebook, and progression remain the same. Caption each procedural call from the **actual scheduled grammar event**—for example, a soft three-note rise—near its bird, with timing tied to the sound and accessible text in the same naturalist voice. Captions can stay on with audio off and default on when WebAudio fails. Avoid captions that cover another bird or fall off a narrow viewport.

Tab order enters the four top-bar controls before the aviary; Tab into the scene focuses the first bird, arrows move among bird IDs in stable spatial order, Enter engages listen-in, Escape leaves it, and focus moving away disengages it. All offer and account dialogs are fully keyboard operable and restore focus on close. Provide high-contrast, visible focus across day/night palettes and WCAG AA contrast for all copy, controls, captions, settings, and errors. The visual designer supplies exact palette/focus tokens and the team tests them over every lighting state. Accessibility ships in the same release gate as the visual/audio path.

## 9. Sync, failure handling, and privacy

The simulation database is the single source of truth. Snapshot versioning and server time let multiple host devices render the same state; clients do not send absolute mood or personality values. Sequence events at receipt, apply each once in the next tick, and commit event cursor plus state atomically. If two devices listen or offer concurrently, both valid events are processed in sequence; offer cooldown is checked under the same aviary lock and a rejected duplicate gets a clear functional result. Presence intervals union across devices to avoid doubled credit. Rename/adoption/settings mutations use optimistic version checks or transactions and return the current record on conflict. Never use last-write-wins for vectors. Replay idempotency keys after network retries and make tick recovery tests prove no lost or doubled drift.

Magic-link replay returns an expired/used-link error. Expired device sessions stop new writes and show a direct sign-in path. During a read outage, keep a previously rendered view briefly and present a matter-of-fact retry surface if freshness cannot be restored; do not run a local substitute simulation. During an event-write outage, do not claim an offer was accepted; show a clear retry affordance. Queued client events have bounded lifetime and idempotency keys, and are never reinterpreted from stale absolute state. A revoked visit is rejected on the next visitor snapshot, even if the client has old art assets cached.

Per-bird interactions and presence are stored only for that aviary's simulation, with bounded recovery retention and deletion thereafter. Do not join this store to a warehouse or use it for training, recommendation, cross-account behavioral analysis, or population drift dashboards. Operational telemetry has an allowlist of request counts, latency histograms, anonymized session-duration histograms, first-bird and frame timings, audio-context errors, tick latency/backlog, and export/deletion job failures; labels exclude account UUID, email, bird ID, species, mood, interaction type, and prose. Add automated telemetry-schema checks and production sampling audits for PII/cardinality leakage. The settings privacy link plainly states the allowed categories and per-bird exclusions.

Exports are generated only at host request, include birds/names/raw vectors/current moods/notebook/settings as specified, are encrypted at rest while queued, and use a one-time short-lived emailed download link. Initiating deletion marks the account unavailable immediately while allowing sign-in and explicit recovery for 30 days. At deadline, revoke sessions and invites, delete birds, vectors, events, notebook, visit records, exported files, and account/contact data; destroy account encryption material and ensure backup retention eventually removes ciphertext. Do not retain an account-identifiable deletion tombstone or per-account telemetry. Test recovery just before the deadline and irreversible purge just after it.

## 10. Performance, verification, and rollout

Set CI budgets: initial JavaScript **under 2 MB gzipped** (aim substantially lower on the first route); first bird visible **under 500 ms** on a defined mid-tier phone and 4G profile; sustained **60 fps idle** on a five-year-old mid-range laptop through a 30-minute session; no positive client heap trend over that session. Keep SVGs compact, render the first bird before loading account/notebook code or initializing audio, reuse pooled nodes/audio resources, and stop hidden-tab render work. Run scheduled synthetic browsers across supported geographies and the last two major versions of Chrome, Safari, Firefox, and Edge. Older browsers get a direct unsupported-browser surface. Gate on first-bird, frame-time, heap-slope, and accessibility checks across normal and reduced-motion modes. Alert when simulation tick p99 exceeds 5 seconds, and monitor tick lag/replay backlog separately.

Verification matrix before launch:

- Deterministic simulation fixtures: one week/three weeks/absence calibration; vector monotonicity and upper bound; mood continuity through close/reopen and DST; rain/wind/night behavior; bird-to-bird responses; seven-bird chorus and call-signature recognition with blind listening tests.
- Presence fixtures: all eight combinations of visible/focused/recent-activity flags; inactivity threshold; blur/hide/settle and tab close; suspended laptop; multiple tabs/devices and overlapping intervals; mobile browser pointer behavior. Confirm a background tab overnight contributes zero.
- Sync/security fixtures: concurrent offers, listen-in, rename and adoption; tick crash at every transaction boundary; replay/idempotency; two-device snapshot convergence; magic-link expiry/replay; per-device revocation; invite redemption/expiry/revocation during an active visit; visitor mutation attempts; export scope and hard deletion.
- Experience fixtures: first frame sampled mid-action, greeting timing and variation by absence/mood, no welcome text; responsive all-birds-visible views; stable 30-minute render/memory; WebAudio blocked/unavailable captions; screen-reader narration quality/cadence, keyboard routes, WCAG AA at every lighting state, and reduced-motion cross-fades.
- Privacy fixtures: static and runtime assertions that raw vectors never enter normal API responses or telemetry, account emails stay out of identifiers/logs, and metric schemas cannot add per-bird/per-account dimensions. Use synthetic accounts for coefficient tuning rather than real interaction aggregation.

Ship in dependency order: (1) data/auth/tick skeleton plus synthetic simulation harness and deletion model; (2) two-bird scene, snapshot/event/presence path, first-frame performance; (3) call grammar, mood, greetings, interactions and sparse notebook; (4) complete accessibility and browser fallback paths; (5) visits, export, recovery/deletion, operational hardening. Run a closed alpha at two birds, then a limited beta with synthetic aged aviaries at three/five/seven to tune recognizability and load. Release production with two starter birds and age-based later additions; keep the seven-bird capacity built and tested from day one. Flags may pause new adoption offers or a faulty grammar version without deleting an existing bird or rolling back a vector. Ramp traffic by cohort only after performance, privacy, accessibility, and sync gates pass. Instrument aggregate health from day one, never per-bird engagement.

## 11. Risk register and response

| Risk | Detection and mitigation |
| --- | --- |
| Drift too fast, too slow, or inflated by background tabs | Synthetic regular/absent histories, exact three-signal presence tests, daily influence caps, monotonic assertions, coefficient/version rollout. Do not tune on real-user bird histories. |
| Lost or doubled personality across devices/outage | Single server writer, transactionally coupled event cursor/state, idempotent tick index and event keys, unioned presence, replay and concurrency fault tests, backup restore drills. |
| Calls sound canned, uncanny, or indistinguishable at seven birds | Stable per-bird grammar signatures with bounded variation, pooled procedural synthesis, chorus voice cap, blind recognition and long-listen tests; revisit motif design before raising bird count. |
| Browser audio permission undermines audible first impression | Captions on while blocked, resume on trusted gesture, accessible settings control, no recorded substitution; measure only aggregate audio failures. |
| Accessibility becomes a static afterthought | Narration/caption/reduced-motion contracts developed with visual/audio work, screen-reader and vestibular reviews in each milestone, release-blocking quality checks. |
| Edge snapshot or render path misses first-bird budget | Private edge-delivered first snapshot, server-rendered first pose, tiny critical path, per-device synthetic RUM gates, staged rollout and rollback flag. |
| PII or relationship data leaks into telemetry | Synthetic UUIDs, encryption, strict service credentials, metric-label allowlist, automated leakage tests, no warehouse path from simulation records. |
| Invitation link misuse or stale access after revocation | One-time token exchange, scoped visit cookie, server authorization on every pull, short polling interval, expiry and revocation tests. |
