# Pocket Aviary — v1 implementation plan

## 1. Product boundary and decisions

Ship a browser-only, single-screen aviary for one signed-in owner and one canonical aviary. Start each account with two system-selected birds from a coherent pool of about six species; support age-based invitations to adopt additional birds up to a hard limit of seven. Owners name and rename birds. Include return-greetings, ambient watching, listen-in, seed/song-fragment/still-pool offers, settle, a sparse read-only field notebook, magic-link accounts, cross-device state, optional read-only visits, account export/deletion, naturalist narration, call captions, and a deliberately designed reduced-motion scene.

The aviary has three depth zones and remains fully visible on phone and desktop without pan, zoom, or scrolling. Birds choose perches. The scene contains no controls or labels; a thin top bar holds account/settings, accessibility, notebook, offer, and the required settle action. The settle control should be a quiet icon in that bar, resolved with visual design because the layout's enumerated icons omit it while the interaction specification explicitly requires top-bar access. No welcome toast, entry sequence, visit badge, or numeric personality display. Product prose is lowercase, present-tense naturalist observation; identity, error, sync, and accessibility-settings copy is direct and matter-of-fact.

Exclude native clients, payments, scene customization, multiple or shared aviaries, profiles, chat, comments, public discovery, feeds, rankings, achievements, scores, levels, streaks, visit-frequency surfaces, hunger, harm/death, and push re-engagement. A visit-notification setting exists off by default as specified; if enabled it applies only to visits and is never an onboarding prompt. There is no generic notification service for aviary activity. Offers are gestures, not feeding.

Interpretation decisions to validate during build: use a four-minute recent-activity window for presence initially; use a one-minute server tick; reserve age-based adoption eligibility at about months 3, 5, 8, 10, and 12, independent of attention. These are versioned configuration, not promises shown as progress. Bird adoption can be declined or deferred without pressure. Use the account's IANA timezone for the day/night cycle, with an explicit settings override and a device-timezone suggestion; a visitor sees the host's time cycle. Use the same host state for visits with a distinct authorization and presentation boundary.

## 2. System shape and ownership

Use a small web client, an authenticated API, a transactional primary database, a one-minute simulation scheduler/worker, an email delivery adapter, and a separate aggregate-only operations telemetry path. The API serves a private, compact canonical snapshot and accepts intent events. The worker is the only writer of personality, mood, perch decisions, weather, and notebook observations. API transactions may write account settings, bird names, invitations, sessions, and append-only intent events, but never client-submitted personality or mood. Schema and simulation rules are versioned so migrations do not regenerate birds.

Concrete v1 stack: a TypeScript web application with a server-rendered HTML/SVG first scene and hydrated HTML controls; a TypeScript API and simulation worker sharing typed contracts; PostgreSQL for the canonical rows, ordered event log, and transactional worker cursor; and a durable scheduled-job queue backed by the same transactional store. Do not add a streaming broker or client-state database for v1. SVG gives seven birds individually focusable semantic elements and compact vector silhouettes; use transform/opacity updates on a bounded animation loop, with DOM panels kept outside the scene. If profiling shows SVG paint costs above the frame budget, optimize assets and invalidation before changing the accessible scene architecture. Load the WebAudio worklet after first paint. The API and worker may deploy separately but share versioned simulation code and migrations.

Store one aviary row per account with a monotonically increasing `state_version`, `last_tick_at`, deterministic random seed/counter, local timezone, weather/settle state, and timestamps. Partition scheduled ticks by aviary UUID. One worker at a time acquires an aviary lock; within one database transaction it consumes ordered unprocessed events, advances minute steps, writes the new state and notebook entries, advances the event cursor, and increments the version. Retry the same tick safely after failure. Keep the scheduler active for unvisited accounts; catch up missed minutes in bounded batches using recorded timestamps and deterministic seeds, with alerts on backlog. This preserves continuous canonical evolution without inventing presence during downtime.

The browser owns only ephemeral rendering state: interpolated positions, pose phase, local ornaments, AudioContext state, focus, open panels, and an outbox of not-yet-acknowledged intent events. It never ticks mood or personality. Snapshot projections omit raw vector values and private interaction history from ordinary client responses; they contain the behavior/render parameters and semantic events needed to present the bird. The owner's export is an explicit exception: raw current vectors are available in the authenticated export artifact, not in a stats UI. A visitor receives a narrower projection with neither controls nor notebook/account data.

For signed-in navigation, return HTML with a compact private initial snapshot and enough inline/critical scene code to paint a bird immediately; hydrate without replacing that first frame. Keep personalized responses private (`no-store` or an equivalent authenticated edge response), never a shared CDN cache entry. Serve immutable code and artwork from CDN. If a snapshot is delayed, show the quiet sky field with subtle cues, no spinner; reserve a first-bird fly-in only for the one-time post-adoption empty state. Subsequent loads seek a mid-pose, already-running first frame. Record snapshot age and refresh after hydration. Browser autoplay policy may block audible calls before a user gesture: attempt playback when permitted, preserve the active call score and show matching captions otherwise, and resume audio on the first ordinary interaction without a modal.

## 3. Persistent model and privacy boundaries

| Record | Required fields and invariants |
| --- | --- |
| `Account` | Synthetic UUID primary key, encrypted verified email, email-verification state, IANA timezone, settings (audio/captions/reduced-motion/visit notifications), created/deletion dates. Email never appears in account IDs, partition keys, general logs, or telemetry. A narrowly scoped identity lookup supports magic links and named invitees. |
| `Aviary` | Unique owner UUID, state version, simulation seed/counter, last tick/cursor, weather state, scene time anchors, settle flag/expiry. Exactly one per owner. |
| `Bird` | Stable UUID and aviary UUID; species ID and immutable motif/silhouette seed; user name; adoption time; five persisted normalized `[0,1]` traits: boldness, social warmth, vocal frequency, plumage saturation, curiosity; mood enum plus entered/expiry times; perch zone/transition; transient recent-attention/quietness state; call scheduling state. Bird ID survives renames, rule changes, and migrations. |
| `InteractionEvent` | Server sequence, event UUID/idempotency key, owner/session UUID, server receipt time, bounded client interval/time, event kind, optional bird UUID and validated payload, consumed tick. Append only. Retain only as needed for simulation, support, export/deletion policy; do not feed analytics. |
| `PresenceInterval` | A normalized event derived from host client samples: start/end, visibility/focus/activity assertions, device/session, accepted duration. The server unions overlapping intervals across host devices before drift, so simultaneous tabs cannot double count. |
| `NotebookEntry` | UUID, aviary UUID, observed time, template/version and rendered naturalist prose, referenced bird UUIDs. Read-only, paginated indefinitely; preserve rendered text across template changes. |
| `Session/MagicLink` | Per-device revocable session UUID and secure token hash; one-use, 15-minute magic-link hash with expiry and consumed time. Tokens are never logged. |
| `Invitation/Visit` | Invite UUID, host UUID, recipient identity UUID, hashed one-use redemption token, 30-day unused expiry, revoked/redeemed timestamps, scoped visitor session UUID, visit intervals. Recipient email is resolved from an encrypted identity/account record for email delivery and the host log; no email in generic event keys. |

Encrypt email and token-bearing records at rest; restrict service access by purpose. The invitation service is the only place where a recipient email is resolved for delivery or shown to the host in account settings. Avoid creating a second clear-text invitation email field. Separate simulation storage from the aggregate operations warehouse by credentials and network permissions. Neither per-bird states nor per-account interaction histories, invitation recipients, names, or email enter RUM, tracing attributes, training, recommendations, or population dashboards. Operational metrics use fixed names and coarse buckets, not account/bird labels. The privacy policy lists allowed aggregate categories and the excluded relationship data.

Account export is an authenticated, on-demand JSON snapshot of birds, names, current vectors/moods, notebook, and settings, generated at a consistent state version and delivered by a short-lived download link to the verified email. Revoke links after use/expiry. Deletion immediately disables normal use, allows explicit restoration within 30 days, and after the window removes birds, vectors, notebook, events, invites/visits, sessions, export artifacts, and any account-linked support/operational records. Use a deletion manifest and audit of purged stores; aggregate telemetry has no account key to recover. Do not hard-delete a bird or reset a vector during ordinary upgrades.

## 4. API contract and event ingestion

Version JSON contracts (`/v1`) and define explicit schema validation, authorization, `state_version`, server time, and simulation-rule version. Mutations require CSRF protection or same-site session safeguards, bounded body sizes, rate limits, and an idempotency key. A stale client may submit an intent, never a replacement snapshot.

| Endpoint | Behavior |
| --- | --- |
| `POST /v1/auth/links` and `POST /v1/auth/consume` | Request rate-limited email magic link; atomically consume its 15-minute one-use token and issue a revocable, secure per-device session. Uniform request response prevents email enumeration. |
| `GET /v1/aviary/snapshot` | Owner-only compact projection: `state_version`, `server_time`, `next_poll_after`, scene/daylight/weather, birds with IDs/names/species, mood-derived poses/perches and transition anchors, scheduled/active call descriptors, pending greeting/reaction cues, caption material or grammar seed, notebook unread state only if needed for UI. Never raw vectors. Private cache semantics. |
| `POST /v1/aviary/events` | Append a bounded batch of `presence_interval`, `listen_start/end`, `offer`, or `settle` intents. Validate host ownership, bird IDs, allowed offer/motif, cooldown, time bounds, and deduplicate idempotency keys. Return accepted event IDs, any rejected reasons, and latest state version. The server stamps order; effects appear on the next tick or a server-authored immediate cue, then reconcile with the canonical snapshot. |
| `GET /v1/notebook?cursor=...` | Owner-only, newest-first keyset pagination, stable historical entries, no write API. |
| `PATCH /v1/birds/{id}` and `POST /v1/adoptions` | Owner-only rename; age-gated adoption with transactional seven-bird cap and idempotency. Adopted bird receives an immutable ID and seed. |
| `GET/PATCH /v1/settings`, `GET/DELETE /v1/sessions/{id}` | Settings, timezone, accessibility choices, visit notification preference, and device revocation. |
| `POST /v1/invitations`, `GET /v1/invitations`, `DELETE /v1/invitations/{id}` | Host explicitly creates a named invite, lists outstanding/active invites with visit log, and revokes. No discoverability endpoint. |
| `POST /v1/visits/redeem`, `GET /v1/visits/snapshot` | One-use email link exchanges for a short-lived read-only visitor session; subsequent polls check revocation before returning the host's current ambient projection. Expired, replayed, or revoked links use the same matter-of-fact unavailable surface. No visitor event endpoint or host notebook access. |
| `POST /v1/export`, `POST /v1/account/deletion`, `POST /v1/account/restore` | Consistent export, 30-day soft-delete, explicit restoration. Confirm sensitive actions within a fresh authenticated session. |

The client sends presence intervals at most every 30 seconds while all three conditions are true: document visible, window focused, and pointermove or keypress seen within the previous four minutes. It closes an interval immediately on blur, hide, inactivity expiry, settle, or page departure, and never manufactures time for a sleeping device. Server accepts only plausible intervals inside the authenticated session's lifetime, caps each report at its wall-clock span and a short maximum, deduplicates retries, and unions overlap across devices. Clock skew and lost final beacons cannot yield unlimited credit. The activity window must be tested with quiet watching, not tuned for click volume. Visitor pages never initialize the presence reporter.

Snapshot polling occurs on initial load, visibility return, long frame/suspend gap, and a low-frequency visible keepalive (initially 30–60 seconds with jitter). Version comparison discards out-of-order responses; interpolation starts from the last displayed pose to new server anchors, with a bounded correction for long gaps. Revocation is checked on every visitor pull; additionally shorten visitor poll cadence enough to make revocation perceptibly immediate (target under 15 seconds while visible), and invalidate server-side visitor credentials at once. An offline owner may keep viewing the last state with a small matter-of-fact connectivity status, but no local simulation advancement or speculative durable vector writes; pending intents are retried with the same idempotency keys and accepted only inside bounded time windows. Authentication errors and sync failures use direct system copy.

## 5. Simulation, drift, mood, and calls

### Tick sequence

At each minute boundary: (1) acquire aviary lock and load state and unconsumed ordered events; (2) validate/dedupe accepted presence and interaction intervals; (3) advance local-time daylight and scheduled weather; (4) update a decaying attention trace and monotonic personality deltas; (5) transition moods and perch/pose goals; (6) schedule semantic call events and any bird-to-bird responses; (7) select rare notebook-worthy observations; (8) commit state, cursor, and version together. Use a seeded deterministic PRNG keyed by aviary/bird and tick index; replay fixtures must reproduce state exactly. Never infer presence from tab-open duration or from a visitor.

### Personality

Seed distinct species-consistent but per-bird vectors within `[0,1]`; keep numbers internal. Use a low-pass attention trace (initial proposal: seven-day exponential decay) over daily capped host presence and smaller per-bird listen/offer signals. For each trait, compute `new = min(1, old + nonnegative_delta)`, with server-authored additive deltas applied in event order. Presence is the dominant common contribution; listen-in biases the focused bird's warmth and vocal frequency; offers modestly bias curiosity (accepted) and boldness (offered nearby). Per-bird offer cooldown begins at acceptance (initial proposal: three minutes), and per-day signal caps prevent a burst of clicks from moving a trait visibly. Settle only quiets transient mood and ends presence; it has no drift term. No absence or neglect term subtracts from any trait, including plumage saturation.

Calibrate coefficient tables offline with scripted histories before release. The starting target is a few hundredths of normalized movement measurable after seven days of regular 15–30 minute visits, and a perceptible change in behavior/plumage after about 21 days, with no single-session visible jump. Run zero-presence/two-week-absence cases: persisted vectors never decrease, the attention trace decays, greeting probability becomes more ambient, and baseline calls remain. This reconciles quieter returns with non-punitive monotonic personality. Keep a versioned rule ID on each tick and migration tests to avoid apparent resets when tuning coefficients.

### Mood and place

Use five moods (`wary`, `content`, `curious`, `drowsy`, `alert`) with a daily-ish relaxation toward a local-time baseline, not a session-open reset. Transition probabilities depend on persisted mood, mood age, local dawn/dusk/night, weather, recent owner gestures, personality, and other birds' calls. Add dwell-time floors and hysteresis to prevent flicker. Night is mostly drowsy/settled, with the nightjar-like species retaining occasional calls. Weather is sparse (short rain a few times a week, occasional wind), seeded and persisted; it adjusts mood/call rates briefly, with no catastrophic events. Perch selection is bird-authored from boldness and mood across front/middle/back zones and preserves collision-safe composition for seven birds. A settled tab has a local evening overlay and quieter mix until re-engagement; if represented server-side for continuity, keep it scoped to the owner session so another device does not mistake a goodbye for permanent night. Settle and tab-close both end presence, and an aviary click within five seconds undoes the local settle transition.

### Return-greeting and call grammar

On owner session entry or genuine focus return, compute absence since last accepted presence and pick one eligible greeter weighted by boldness, warmth, mood, and recent greeting history. Short absence favors glance/head tilt; long absence permits approach or a longer call. Seed variation in pose, onset, motif, and timing so consecutive greetings are not identical. A second bird may answer after a small randomized delay, never a synchronized all-bird greeting. No textual return message. Avoid treating a rapid visibility flurry as repeated arrivals.

Define a small motif library per species and a stable bird-specific signature (pitch contour/rhythm/timbre seed). A call descriptor carries bird ID, motif, start time, duration, variation seed, mood envelope, and gain intent; the client compiles it into oscillator/noise/envelope instructions. Variation changes phrasing without erasing the recognizable signature. Vocal-frequency trait shapes call rate and chorus joining; mood/time/weather shape articulation and density. Bird-to-bird responses use a bounded probability and refractory period to prevent runaway choruses. The tick schedules enough near-future semantic calls for the client to render between pulls; client time synchronization and deterministic seeds yield the same underlying events on two devices. Never layer looped recordings or download call files.

Notebook generation consumes meaningful state transitions and contrasts over time (which bird greeted first, unusual quiet, first rain after a stretch, a perch preference shift), with per-aviary rate limits and a target near one entry every few days under regular use. Deterministic, reviewed templates bind concrete bird/time/scene facts; suppress duplicate phrasing and avoid visit counts, trait values, generic event-log language, and behavior judgments about the user. Store the rendered prose so old entries do not rewrite after rule updates. Do not manufacture a noteworthy entry on every visit.

## 6. Client scene and interaction rendering

Build one logical coordinate system with background sky/foliage, back/middle/front perches, birds, and occasional foreground leaves. Use compact SVG or procedural shapes for approximately six species; isolate pose drawing from state choice. Scale and redistribute perch spacing within viewport safe areas so all seven birds remain visible at narrow phone widths. Validate no clipping and no overlap that hides focused birds. The scene has no inline UI labels, hover tooltips, drag placement, or camera movement. Daylight palettes interpolate from host local time; wind/rain are restrained. Leaf and feather drift are client-only ornaments seeded independently of canonical bird state and never sent as interaction data.

Render from snapshot position/transition anchors using `requestAnimationFrame` only while visible. Start the first paint at the server-provided phase of a preen, scan, shuffle, or call rather than at pose zero. Blend to subsequent anchors and mood-shaped micro-motion; do not let a tick hard-snap a bird. Pause frame work in hidden tabs, then fetch before animating again. In reduced-motion mode, swap pose animation for slow still-pose cross-fades, replace flights with perch-to-perch fades, remove drifting ornaments, and slow ambient color change. The same moods, calls, offers, notebook, and continuity remain present.

Listen-in starts via pointer/tap or keyboard Enter on a focused bird; tap again, tap empty aviary, focus another bird, keyboard focus leaving scene, or Escape disengages it. Keep the focused call prominent via gradual gain ramps while every other bird remains audible at ambient level. Record bounded listen start/end intervals for the host; visual focus and event ingestion are separate, so a failed network write does not hard-cut the mix. Offers open from the bar, expose three choices plus song-fragment library, and show reaction poses from a server-accepted event. A cooldown disables repeated offers with restrained, matter-of-fact affordance text only in the control surface. Settle shifts light and mix over seconds, has a five-second click-to-undo, and ends presence regardless of whether the tab later closes. An ordinary tab close requires no gesture.

## 7. Audio and captions

Create one bounded WebAudio graph: per-bird synthesis voice(s) into per-bird gain, ambient/foreground bus, limiter, and master gain. Reuse oscillators/worklet resources or short buffers; cap simultaneous voices and avoid creating unbounded nodes per call. Apply envelopes, small pitch/timing deviations, filtering, and restrained spatial cues from the call descriptor. Crossfade chorus layers and cap summed energy to avoid clipping. Listen-in ramps over roughly 0.5–1.5 seconds, with nonfocused birds above a quiet floor; settle uses a longer quieting ramp. Time and mood affect rates, not a global playback loop.

Generate each caption from the exact compiled motif and variation parameters used for that call, including note count, rise/fall, trill, pause, softness/sharpness, and source perch. Associate a caption with bird ID and call interval; position it near the bird without covering birds or controls and provide an accessible text equivalent. Captions can be enabled by choice, and are on by default when WebAudio is unavailable, denied, or effectively silent. Browser autoplay restrictions also trigger a silent/captioned initial experience until the browser permits playback. No recorded-audio fallback. Audio-off remains a complete aviary through captions and narration.

## 8. Accessibility as a release path

Use semantic top-bar buttons and accessible dialogs; Tab reaches controls and then the scene, first bird receives focus, Left/Right arrows move bird focus, Enter starts listen-in, Escape exits. Restore focus when panels close. Offer and settle are keyboard reachable. Give the focused bird a visible high-contrast outline that works in day, dusk, night, rain, and all species colors. Do not expose hidden trait numbers or raw mood state as an ARIA status feed.

Generate naturalist narration from the same snapshot and call/gesture facts used by the visual scene. Compose specific lowercase present-tense prose with names, relative perch, weather, and call character. Idle live-region updates occur every 30–60 seconds and only when meaningful; coalesce changes so the screen-reader queue does not grow. Return-greetings, accepted offers, and settle get prompt but noninterruptive priority. Keep controls' functional labels direct while scene prose stays observational. Captions appear near birds and can be accessed as text without flooding the live region. Respect `prefers-reduced-motion` initially and allow an explicit setting; test switching live without resetting the scene. Specify color tokens and verify WCAG AA text contrast on every palette, including top-bar fade and captions; when keyboard focus enters the bar it returns to full opacity and remains readable.

Test with keyboard only, screen readers across supported engines, zoom and narrow viewports, reduced motion, audio blocked/off, simultaneous captions and narration, and a 30-minute session. Include qualitative review with users of these modes: the release condition is that the birds still feel like a continuing place, not merely that controls can be reached.

## 9. Performance and observability gates

Gate the initial gzipped JS at **<2 MB** in CI, with the actual target comfortably lower to preserve room for critical CSS and scene assets. Split account/settings, notebook, invite flow, and noncritical species detail. Keep the first private snapshot in kilobytes and do not wait for audio or lazy panels before paint. Measure **first bird visible <500 ms** on a defined mid-tier 4G phone profile for signed-in navigation, from navigation start to the first actual bird pixel, not to a placeholder. Use a warm and cold run distribution and report regressions; auth/onboarding is a separate path. Maintain **60 fps idle** on a five-year-old midrange laptop for 30 minutes, with frame-time distributions and long-task checks. CI memory endurance compares warmed baselines over 30 minutes and rejects sustained heap/AudioNode growth; allow bounded GC sawtooth, not a monotonically rising retained heap. Bound notebook DOM via virtualization and release scrolled-out references.

Run synthetic browsers on a schedule from common geographies for first-bird timing, scene continuity, keyboard/reduced-motion/captions, snapshot failures, and revocation. Aggregate RUM records page timing, first-bird timing, frame-time histograms, audio-context failures, request errors, and coarse anonymized session-duration histograms. Server metrics include tick queue lag, tick duration, catch-up steps, failed/retried ticks, event ingest rejection categories, and snapshot latency; alarm when tick latency p99 exceeds **5 seconds**. Dashboards have no bird, account, email, event payload, or invitation dimensions. Use sampling that cannot be turned into per-account interaction analytics. Test the telemetry schema with an allowlist and secret/PII scans in CI.

Support the last two major versions of Chrome, Safari, Firefox, and Edge. Feature-detect WebAudio and reduced-motion support; show a direct unsupported-browser surface outside the supported matrix. Avoid compatibility bundles that threaten the first paint.

## 10. Build sequence, verification, and rollout

1. **Contracts and design baseline.** Freeze the state/event schemas, ownership matrix, naturalist/system copy rules, scene composition grid, motif identity rules, and accessibility acceptance examples. Create deterministic simulation fixtures and privacy field allowlists before building UI. Review the settle/top-bar discrepancy and timezone setting with design. Define device/network profiles for performance gates.
2. **Persistence/auth/tick spine.** Implement UUID account identity, encrypted email, one-use magic links, revocable device sessions, unique aviary, birds/vectors, append-only events, transactional ordered tick, deterministic catch-up, and consistent snapshots. Prove no client path writes vectors. Test concurrent devices, retries, worker crashes, timezone/DST transitions, and long absence with invariant checks (`new_trait >= old_trait`, stable bird IDs, one writer, no fabricated presence).
3. **First living scene.** Ship two species initially behind internal flags, first-frame snapshot rendering, all three perches, idle pose scheduler, greeting, day/night and weather, responsive composition, basic call synthesis, and captions. Compare actual on-screen/audio behavior against recorded design references; detect repeated greetings/calls with sequence tests and human listening. Expand to approximately six species only after signatures remain recognizable.
4. **Interactions and notebook.** Add exact presence gating, listen-in gain ramps, offers/cooldowns/reactions, settle/undo, age-based adoption and renaming, sparse notebook. Use scripted 1-, 7-, 21-, and 60-day histories to calibrate drift and mood; run absence and high-click adversarial cases. Blind listening tests should identify each bird by call across mood and a seven-bird chorus at an agreed threshold, then tune mix/cap if needed before ramp.
5. **Full access and account lifecycle.** Ship narration, reduced-motion composition, keyboard/focus, contrast, settings, export, deletion/restore. Run accessibility and endurance gates as part of the same release train, not after launch. Verify export includes current vectors while ordinary UI and API projection never expose them numerically.
6. **Quiet visits.** Add per-invite email flow, read-only projection, visit log, opt-in notification setting, expiry and revocation. Penetration/authorization tests prove visitors cannot call owner interaction APIs, inspect notebook/vectors, or contribute presence. Test revocation during an active visit and link replay/expiration.
7. **Controlled release.** Internal accounts first, then a small opt-in cohort, then broader web availability. Start with two birds and keep later age gates behind configuration; exercise three-to-seven-bird synthetic scenes and gradually enable each age cohort only after call recognition, layout, CPU, and accessibility remain acceptable. Do not use user engagement/streak metrics as rollout success criteria. Monitor first-bird timing, tick p99/backlog, sync divergence, frame time, audio errors, memory, and accessibility regressions. Roll back rules by version without replacing bird IDs or lowering vectors; stop ramp on canonical-state mismatch, persistent audio failure, or accessibility gate failure.

Acceptance tests are behavioral, not just endpoint tests: opening a long-unvisited account displays a mid-action bird and a varied single-bird greeting; background/blurred/idle tabs add zero presence; two active host devices cannot double-credit time or overwrite a vector; 21 days of regular watching changes expression without a numeric UI; two weeks away never harms a bird; every call caption matches generated sound; a visitor cannot change host state; revoked visitors lose access on their next pull; keyboard/screen-reader/reduced-motion users can complete the same quiet session. All tests use synthetic private fixtures, not production interaction histories.

## 11. Main risks and responses

| Risk | Detection and response |
| --- | --- |
| Drift is too fast, too slow, or accidentally negative | Versioned simulation fixtures at one/seven/21 days, rate caps, monotonic assertions, cohort review using synthetic histories, rollback of coefficient version. Never recompute stored vectors from history. |
| Presence is inflated by inactive or duplicate tabs | Three-signal client state machine, immediate interval close, bounded server acceptance, cross-device union, blur/sleep tests. Calibrate activity timeout with quiet watching rather than engagement counts. |
| Multi-device or tick retry loses identity/drift | Single transactional writer and event cursor, idempotency, row lock, stable UUIDs, concurrency/chaos tests, state-version alarms. No last-write-wins client merge. |
| Calls sound canned, chorus clips, or autoplay blocks sound | Stable signature plus seeded motif variation, human listening/recognition tests, bounded voice graph/limiter, honest caption-first autoplay behavior and silent WebAudio fallback. |
| First paint or long session feels like an app loading or leaking | Inline private snapshot, critical scene path, no spinner/fade, performance CI under defined devices, 30-minute memory/frame endurance, code-split noncritical surfaces. |
| Accessibility surface becomes a static or noisy translation | Shared semantic state, authored narration templates and cadence, designed reduced-motion pose system, caption/audio equivalence, screen-reader and vestibular user review as launch gates. |
| Visits leak access or change the host's birds | Scoped read-only visitor sessions, owner/visitor API separation, revocation check on every pull, no visitor presence reporter, authorization tests, token replay/expiry tests. |
| Relationship data leaks to telemetry | Synthetic UUIDs, encrypted email, schema allowlist and separate credentials, payload scans, no simulation DB-to-warehouse connection, deletion audit. |

The implementation is complete when these release gates pass together. A visually polished scene with missing sync, captions, narration, privacy isolation, or long-session performance is not v1.
