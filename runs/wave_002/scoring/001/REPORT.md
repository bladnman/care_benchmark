## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered 11.0 / 34.0 (32.4%), while affective whys recovered 14.0 / 54.0 (25.9%). The plan kept technical skeletons like server-side canonical sync better than poetic relationship rationales.
- **Weight-3 vs weight-2.** High-weight whys did only slightly better (29.4%) than weight-2 whys (25.0%). Multi-layer rationales usually retained the first operational layer and lost the downstream consequence.
- **System-level vs feature-level.** System-level fidelity (39.3%) beat feature-level fidelity (23.3%). The planner preserved labels such as "feels alive," "notice never announce," and "first-class accessibility," but feature exceptions like F16, F27, F31, and F36 mostly became rules without reasons.
- **Subdomain patterns.** Accounts/sync and accessibility had the strongest feature capture rates; aviary layout, interactions, social, and bird-specific relationship details were heavily compressed. Social was mostly reduced to "read-only visitor" and public-feed exclusions.
- **Evidence-bound effects.** Several apparent v1-style recoveries were denied because the reconstruction had only the rule: F4 procedural audio, F14 no streaks, F16 synthetic UUID, F27 no gamification, F31 stable identity, and F36 aggregate telemetry. The evidence-bound operator made the loss of rationale visible instead of allowing rule names to stand in for intent.

The failure shape suggests a planner that can produce a plausible implementation spine from the PRD, but compresses away most of the product's non-obvious design pressure. The reconstruction honestly reflected that compression rather than inventing missing whys.

## 4. Recommendations for v2 hardening

- Keep the evidence-bound operator. This run shows why: the plan often named the correct rule while omitting the rationale that protects it from later erosion.
- Add a separate diagnostic for "label-only system preservation." S1-S4 were present as philosophy words, but only weakly connected to implementation decisions; that pattern is different from total absence.
- Preserve targeted headroom additions like F29-F40. They caught real blind spots: stable identity, mood persistence, export/deletion, visit log, and narration cadence were easy for the planner to omit.
- Consider making planning-quality capture stricter for principle-derived exclusions. Borderline captures such as #37 and #50 came from broad principles rather than explicit feature rows; scorer variance may appear there.
- Keep multi-layer whys for high-impact rules, but report layer-level loss prominently. This run mostly recovered operational first layers and lost secondary/downstream protection.

## 5. Methodology caveats

- **Fresh-context fidelity.** This scoring pass treated phase 2A as frozen and did not modify `RECONSTRUCTION.md`. The reconstruction itself shows no significant contamination signs; see `VALIDITY_AUDIT.md`.
- **Single-run limitation.** This is one candidate run at one sampled configuration. It gives no within-model variance signal.
- **Borderline capture calls.** Inclusive capture affected these notable features: #17 Procedural call grammar (motifs combined at runtime); #28 Personality vector persistence (server-side, never resets); #29 Mood persistence across sessions; #31 Bird identity stability (stable internal id); #37 No "Welcome back!" toast or banner; #50 No streak counter, no "days visited" display; #71 Email + magic-link sign-in (no passwords); #76 Client pulls state snapshot on visibility; #79 Last-write-wins is forbidden for personality state; #85 No telemetry on per-bird interactions for ML model training; #91 Visit is read-only ambient view (no interaction by visitor); #92 Visitor cannot trigger greetings, listen-in, or offers; #99 Screen-reader narration of aviary state (running prose); #103 Reduced-motion mode preserves charm (not a stripped fallback); #104 Captioning toggle for procedural calls (text describes mood); #110 60fps idle motion target on 5-year-old laptop; #111 No memory growth over 30-minute session; #114 Performance observability (synthetic + RUM, aggregate-only); #119 Out of scope: Tamagotchi-style mechanics (death, hunger, distress). These calls raised planning quality but did not inflate recovery unless the reconstruction and plan carried rationale evidence.
- **System-level cross-cutting.** The three-feature bar was hardest for S2-S4 and S8. I counted broad exclusions as inheritance for S2, but not label-only specificity/restraint as full preservation.
- **Confabulation cases.** I did not count clear ungrounded reconstruction content; most reconstruction claims were plan-derived and compressed. Some phrase-level rationales were generic, but not enough to mark contamination.
- **Evidence-bound denials.** F4, F14, F16, F21, F23, F26, F27, F31, F32, and F36 were included but scored none because rule evidence existed without gold-why recovery.
- **Operational compromise.** Timing was available for phase 1 and phase 2A only in `runs/wave_002/TIMING.json`; phase 2B timing was not fabricated.
