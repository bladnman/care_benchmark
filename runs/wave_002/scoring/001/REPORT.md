## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys scored 38.0/54.0 (70.4%); affective whys scored 68.0/98.0 (69.4%). The difference is small. Explicit architecture/privacy whys were strong, while relationship-specific affective exceptions such as F29, F34, and F39 leaked.
- **Weight-3 vs weight-2.** Weight-3 whys scored 76.0/108.0 (70.4%), slightly above weight-2 whys at 30.0/44.0 (68.2%). High-weight rows often preserved primary mechanics but dropped downstream consequences.
- **System-level vs feature-level.** System-level fidelity (78.6%) exceeded feature-level fidelity (67.7%). The planner encoded the philosophy, but feature-level exception rationales were more fragile.
- **Multi-layer recovery.** Primary layers usually survived; secondary calibration details and downstream product-collapse consequences were the common losses, especially F1/F2/F13/F16/F27/F40.
- **Subdomain patterns.** Accounts/sync/privacy and server simulation were strongest (F17/F18/F20/F36). Social/relationship refinements were weaker where the plan had the rule but not the why (F23, F37-F39 mixed). Accessibility was mixed: reduced motion was strong, screen-reader cadence/narration lost some rationale.
- **Evidence-bound effects.** F11, F23, F26, F29, F34, and F39 were denied because they carried only operational rules or were marked not recoverable, not because their features were missed.

What this suggests: the candidate is an excellent implementation planner, but not every downstream builder would receive the product-theory reasons behind the rules. CARE v06 is correctly separating feature capture from rationale carry-through.

## 4. Recommendations for v2 hardening

- Keep the evidence-bound operator. This run demonstrates why PLAN evidence alone cannot establish recovery; otherwise rule-only rows would be over-credited.
- Keep targeted exception whys like F29, F34, and F39. They reveal when a plan implements a rule while losing the relationship reason behind it.
- Preserve multi-layer whys for calibration-heavy features. F1/F2/F13/F40 exposed common loss of silent-failure and downstream-consequence layers.
- Add a structured diagnostic for partial multi-layer rows caused by downstream-layer loss. The current report has notes, but a cross-run field would make patterns easier to compare.
- Keep the system-level cross-cutting bar at three or more inherited decisions; it distinguished philosophy preservation from isolated slogans without becoming too brittle in this run.

## 5. Methodology caveats

- **Fresh-context fidelity.** I treated the frozen reconstruction as immutable and did not modify it. No subagents or background agents were used.
- **Single-run limitation.** This is one scorer pass for one candidate run; no variance conclusion should be drawn from it alone.
- **Borderline capture calls.** The only missed planning features were the glossary/domain-term surface and empty-aviary transitional state. I marked no-avatars-during-visits and no-show-off visitor rendering as captured but borderline because they are inferred from nearby social/profile and read-only snapshot rules.
- **System-level cross-cutting.** S1-S4 are the most subjective calls; the plan preserves them across many decisions, but the reconstruction compresses some downstream consequences, so I scored them partial.
- **Confabulation cases.** I did not identify clear ungrounded reconstruction assertions; denied rows were mostly rule-only or non-recoverable, not fabricated.
- **Evidence-bound denials.** The main denials were F11, F23, F26, F29, F34, and F39. These were captured as features but lacked recoverable rationale evidence in the frozen reconstruction and PLAN grounding.
- **Operational timing.** The timing ledger included phase 1 and phase 2A only for run 001; score JSON omits unavailable phase 2B/run-complete durations.
