## 3. Diagnostic Patterns

- **Affective vs functional.** Functional whys recovered 40.0/54.0 weighted points (74.1%), while affective whys recovered 82.0/94.0 (87.2%). Functional misses were mostly calibration or data-boundary middle layers, not architectural absence.
- **Weight-3 vs weight-2.** Weight-3 whys recovered 84.0/104.0 (80.8%); weight-2 whys recovered 38.0/44.0 (86.4%). High-weight rows were stricter because multi-layer evidence exposed omitted consequences.
- **System-level vs feature-level.** System fidelity was 24.0/28.0 (85.7%), above feature fidelity at 98.0/120.0 (81.7%). Philosophy largely survived, but targeted feature whys exposed rule-only capture.
- **Multi-layer recovery patterns.** Dropped layers were usually secondary calibration or downstream consequence: population drift corruption in F1/F13, Tamagotchi-vs-screensaver in F2, and the data-product relationship layer in F20.
- **Subdomain patterns.** Core server simulation, sync, audio grammar, accessibility, and rendering performed strongly. Social and lifecycle headroom rows had the clearest rule-without-why behavior, especially F29 and F39.
- **Evidence-bound effects.** V06 denied full credit where the reconstruction had a correct implementation mechanism but lacked the gold rationale: F5, F16, F20, F27, F35, and F39 are the most visible cases.

The failure shape suggests a very capable planner whose compressed plan carried implementation invariants better than some relational and exception rationales.

## 4. Recommendations for v2 hardening

- Add more feature-level exceptions around tempting-but-wrong social/account surfaces. This run implemented boundaries but sometimes dropped why the alternative would change the product.

- Continue treating named exclusions as specific capture requirements. The missing welcome-back-toast feature is a useful example: adjacent anti-engagement language did not guarantee that exact exclusion.
