## 3. Diagnostic Patterns

- **Affective vs functional.** Affective whys recovered slightly better by weight (80/98, 81.6%) than functional whys (40/54, 74.1%). The functional drop was concentrated in deeper calibration/privacy architecture layers such as F1, F2, F16, F20, and F35.
- **Weight-3 vs weight-2.** Weight-3 whys recovered 84/108 (77.8%), below weight-2 at 36/44 (81.8%). The high-weight rows exposed layer compression: primary rules were usually present, while secondary warnings and downstream failure modes often disappeared.
- **System-level vs feature-level.** The plan encoded philosophy very well: system fidelity was 26/28. Feature fidelity fell to 94/124 because rule-level implementation survived more often than the feature-specific why.
- **Multi-layer recovery.** Missing layers were most often Layer 2 or Layer 3: S2 lost the processed-vs-seen rationale; F2 lost the one-week/three-week and Tamagotchi/screensaver calibration; F20 lost the private-relationship-as-data-product layer.
- **Subdomain patterns.** Accessibility, procedural audio, server authority, identity, and visit isolation were strong. The weakest pockets were relationship-copy/anti-curation/anti-comparison rationales: F8, F23, F33, and F34.
- **Evidence-bound effects.** The evidence gate mattered. F8, F23, F33, and F34 all had rules in both PLAN and RECONSTRUCTION but no recoverable gold rationale, so they did not receive semantic-credit shortcuts.

What this suggests: the candidate produced an excellent implementation plan, but even a strong plan can compress away reasons that feel obvious to the planner. The benchmark's useful signal is not whether the product would mostly be built, but whether future builders inherit the reasons not to turn it into a neighboring product.

## 4. Recommendations For V2 Hardening

- Keep the v06 evidence-bound report shape. It clearly separated perfect feature capture from lower why fidelity.
- Add or preserve more headroom for rules that look operationally simple but carry relationship-defining rationales: hidden vectors (F8), no leaderboards (F23), read-only notebook (F33), and export as quiet relationship copy (F34).
- Consider making some current weight-2 affective whys multi-layer. Several none calls were mechanism-plus-some-reason but could not receive partial credit under single-layer scoring.
- Keep the system-level cross-cutting bar, but require scorer notes like the appendix above. System whys are easy to over-credit when a plan is broadly aligned.
- In a future instance, add more exact anti-pattern rationales to test whether candidates preserve not just a prohibition but the product-adjacent failure it prevents.

## 5. Methodology Caveats

- **Fresh-context fidelity.** The same-context safeguard held by instruction: phase 2A was frozen before scoring, and this scorer did not modify it. The validity audit verdict is PASS.
- **Single-run-at-temperature limitation.** This is one run only. There is no within-model variance signal here.
- **Borderline capture calls.** Feature 7 (glossary) was counted as captured through distributed operational definitions rather than a standalone glossary. Because all other features were clearly addressed, this single inclusive call did not materially change the reading.
- **System-level cross-cutting.** The S2 score is the main subjective system call: the no-announcement rule was cross-cutting, but the reconstruction did not preserve the processed-vs-seen layer.
- **Confabulation cases.** No ungrounded reconstruction cases were scored. The reconstruction read as plan-derived.
- **Evidence-bound denials.** F8, F23, F33, and F34 were denied why credit because the rationale evidence was absent even though the mechanism survived.
- **Rule-without-why cases.** Four included whys were mechanism-only: hidden numeric vectors, no public ranking/discovery, read-only notebook, and account export.
- **Operational compromise.** The wave timing ledger supplied phase 1 and phase 2A timing only; phase 2B timing was not fabricated. The run label was left blank because wave metadata was outside the supplied read allowlist.
