## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys survived better: **12.0/30.0** weighted recovery versus affective **9.0/46.0**. The server-side simulation spine (S7, F17, F18, F7) was the clearest carry-through; affective principles such as S2, S3, S4, F14, F23, F27, and F28 mostly collapsed into rule names without rationale.
- **Weight-3 vs weight-2.** High-weight multi-layer whys did better (**20.0/56.0**) than weight-2 whys (**1.0/20.0**) because the compressed PLAN still had architecture layers. The lone weight-2 credit was S5 partial for naturalist voice, while many single-layer feature whys were exact examples of `rule_without_why`.
- **System-level vs feature-level.** System fidelity (**32.1%**) exceeded feature fidelity (**25.0%**) because the reconstruction could infer broad architecture and accessibility posture. Feature-level affective reasons were usually missing once the PLAN omitted concrete product surfaces.
- **Multi-layer recovery.** Primary mechanism layers survived most often; secondary failure-mode and downstream consequence layers were usually absent. F17 is the exception: server tick, sync coherence, and no-LWW consequence were all present.
- **Subdomain patterns.** Accounts/sync and performance/accessibility had the most captured features. Aviary layout, interactions, and bird-engine affective details were mostly absent, especially return greeting, field notebook, scene loading, bird counts, and offer/listen-in specifics.
- **Evidence-bound effects.** The stricter operator denied many plausible v1-style recoveries: F26 had the 500ms metric but no felt-aliveness rationale; F20/F36 had aggregate telemetry rules but not the privacy/back-door rationale; F14/F27 had no-streak/no-gamification rules but not the relationship-protection reason.

The failure shape suggests a planner that produced a plausible technical skeleton but compressed away the product's delicate emotional contract.

## 5. Methodology caveats

- **Fresh-context fidelity.** The scoring prompt states this is fresh context and the reconstruction was frozen. I did not modify `RECONSTRUCTION.md` and treated its `NOT RECOVERABLE FROM PLAN` entries as none recovery.
- **Single-run-at-temperature limitation.** This is one candidate run; no variance signal should be inferred from this slot alone.
- **Borderline capture calls.** I leaned inclusive on several compressed implementation mentions: procedural calls (#17), mood persistence (#29), snapshot-on-visibility (#76), no per-bird ML telemetry (#85), read-only visit mechanics (#91/#92), reduced-motion charm (#103), call captions (#104), observability (#114), and Tamagotchi exclusions (#119). These inclusions help planning quality; excluding all borderline calls would lower it further.
- **System-level cross-cutting.** The 3-feature bar was decisive. S7 and S9 met it; S1, S5, and S8 had related mechanisms but not enough explicit inheritance for full credit.
- **Confabulation cases.** I did not credit unsupported extrapolations. The reconstruction's strongest inferences were plan-derived; none were counted as ungrounded reconstruction.
- **Evidence-bound denials.** Twelve included rows were marked `rule_without_why`, mostly because the PLAN named a rule or metric but did not carry the gold rationale into the reconstruction.
- **Operational issue.** `TIMING.json` contained phase1 and phase2a timings for run 001, but no phase2b timing. The score JSON includes only the bounded available timing fields and does not fabricate phase2b duration.
