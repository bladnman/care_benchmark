## 3. Diagnostic patterns

- **Affective vs functional.** The split was close: affective whys recovered 75.5% and functional whys recovered 74.1%. The strongest functional survivals were S7/F17 server-side simulation, S8/F20/F36 telemetry privacy, and F2 drift calibration. Affective losses clustered where the plan kept the rule but compressed the relationship rationale, especially F11, F33, F34, and F39.
- **Weight-3 vs weight-2.** High-weight whys recovered better (75.9%) than weight-2 whys (72.7%). This is the expected shape: load-bearing mechanisms like drift, calls, server tick, reduced motion, and narration were repeated often enough to survive reconstruction.
- **System-level vs feature-level.** The plan preserved the system philosophy more strongly (85.7%) than the feature-level why ledger (72.6%). S3 and S4 are instructive: the plan clearly implemented specificity and restraint, but the reconstruction did not name them as system-level principles.
- **Multi-layer recovery patterns.** Layer 1 survived most often. Layer 2 was usually retained for technical mechanisms (presence, drift, sync) and less often for affective temptation/adjacent-product arguments. Layer 3 was the most fragile when it described downstream product drift rather than an implementation failure.
- **Subdomain patterns.** Accounts/sync, privacy, accessibility, and performance were very strong. Social and notebook features were more brittle: read-only visits and no notifications survived, but the visitor-as-witness and notebook-as-observer-record rationales were compressed away.
- **Evidence-bound effects.** Five included feature whys were denied outright because only the rule survived: F11, F19, F33, F34, and F39. Additional partial rule-without-why pressure appears in F10, F14, and F27. S2/S3/S4 show the same pressure at the system level, though they retained partial credit through cross-cutting plan evidence.

The failure shape suggests a very strong implementation planner whose compression strategy favors architecture and acceptance criteria over small affective exception rationales.

## 4. Recommendations for v2 hardening

- Add more single-layer affective exceptions like F11, F33, F34, and F39. They are useful headroom because strong plans often build the right mechanism while dropping the reason.
- Keep multi-layer scoring for high-weight whys. It distinguished strong partial recovery from perfect recovery without over-penalizing otherwise faithful plans.
- Consider requiring system-level reconstructions to name S-like principles separately from feature clusters. This run preserved S3/S4 in the plan but B did not identify them as system-level intent.
- Add a small validator for score JSON and report data. The schema is strict and easy to satisfy, but mechanical validation would prevent accidental qualitative leakage into loose JSON.
- Preserve the evidence-bound operator. It correctly denied plausible v1-style credit where the frozen reconstruction only had the rule, not the why.

## 5. Methodology caveats

- **Fresh-context fidelity.** The prompt asserted fresh context for the reconstructor and scorer. I did not read PRD files, peer slots, other waves, memory, or harness-specific agent folders.
- **Single-run-at-temperature limitation.** This is one run, so it has no variance signal by itself.
- **Borderline capture calls.** Feature 7 was counted as captured because the plan operationalized domain terms rather than writing a glossary. Feature 87 was counted as captured because privacy-policy acknowledgement appeared in account settings, though the link itself was implicit. Features 68 and 116 were not captured.
- **System-level cross-cutting.** The strict three-feature bar was met for every S1-S9 in the plan. The subjective part was whether the reconstruction identified S3/S4 system intent; I marked those partial rather than full.
- **Confabulation cases.** I found no credited ungrounded reconstruction. Some reconstruction wording was polished, but it traced back to plan phrasing.
- **Evidence-bound denials.** F11, F19, F33, F34, and F39 were mechanism-only survivals and therefore scored none.
- **Operational compromise.** TIMING.json contained phase 1 and phase 2A timings only; the score JSON includes only those bounded timing fields and does not fabricate phase 2B duration.
