# Pocket Aviary — v1 implementation plan

## 1. Product contract and decisions

Build one browser aviary per email magic-link account. Two system-chosen birds appear at adoption; the account may grow to seven at age-based intervals. The one-screen horizontal scene has front, middle, and back perch zones, local-time light, rare mild weather, procedural calls, mood-shaped motion, listen-in, seed/song-fragment/still-pool offers, optional settle, and a sparse read-only field notebook. Ship the quiet, opt-in, read-only invitation flow, device sessions, JSON export, deletion and recovery, narration, captions, and a designed reduced-motion rendering at v1 launch.

Keep user-visible personality numerical values, progress counters, streaks, achievements, care meters, distress/death, onboarding sharing prompts, public discovery, comments, feeds, co-presence, scene customization, multiple aviaries, payments, notifications about the aviary, recorded call loops, and native clients out of scope. An optional *visit* email notification exists only after an explicit settings opt-in; default is silence. Product prose is lowercase, present-tense naturalist observation. Identity, settings, access, and failure surfaces use direct matter-of-fact language. No arrival toast or banner.

Decisions to settle PRD degrees of freedom during implementation: normalized traits are internal values in `[0,1]`; presence uses a 4-minute recent-activity window initially; one canonical tick is scheduled per aviary per minute; offers have a 3-minute per-bird cooldown; live snapshot polling is every 20 seconds while visible (also on visibility return and long frame gap); invitation tokens expire after 30 days if unused. These are versioned configuration values, not product promises. Calibrate the 4-minute presence window, drift coefficients, and age-based bird schedule before broad rollout. Keep the seven-bird ceiling and absence of negative drift invariant.

### Acceptance gates

* The first visible bird renders within 500 ms on the target mid-tier mobile/4G test profile; first frame depicts an already-running aviary for returning accounts. A never-adopted account alone may show the quiet empty field and a soft first-bird fly-in.
* A returning host receives one procedurally varied bird greeting within 1–2 seconds. Bird selection and form use current mood, boldness, and absence length; any additional greeting is staggered. No text welcome.
* A week of regular, valid presence produces instrument-detectable trait movement; three weeks produces a perceptible behavioral difference in blinded review. One session cannot visibly move a trait. Two weeks away never decreases stored personality, resets birds, or generates distress.
* Two concurrent signed-in devices converge on one server snapshot and never overwrite each other's drift. Visitor activity produces zero host interaction events and zero drift input.
* All supported sensory paths retain the aviary experience: naturalist narration, call-matched captions, and slow pose cross-fades. Keyboard-only and screen-reader flows cover every host interaction and settings surface.

## 2. Architecture and ownership

Use a small web client with an edge-delivered document and compact bootstrap snapshot, an authenticated application API, a transactional relational store, a simulation worker, a mail sender, and a separate aggregate-only operations pipeline. The database is authoritative for account, bird, invitation, notebook, and simulation state. A per-aviary append-only input log captures host interactions. The worker alone advances personality, mood, weather and behavior timelines and writes canonical snapshots. The API validates and appends actions; it never accepts client-authored trait, mood, or position values. The client renders snapshots and makes only local, ephemeral interpolation and audio decisions. Asset/code caches may use a CDN, but private snapshots must be scoped to the authenticated user/invite and never stored in a shared public cache.

Define a shared, versioned snapshot schema and deterministic seed protocol between worker and client. A snapshot contains scene time, canonical revision, next due tick, locale/time-zone context, ambient weather/light descriptors, and each bird's public render state: stable ID, name, species, perch/pose/motion phase, mood-derived presentation cues, call grammar/motif ID plus seeded near-term call schedule, and active transition times. It does **not** carry raw personality-vector numbers to a client, visitor, UI component, accessibility label, or telemetry event. The worker maps traits into bounded render parameters (e.g. approach tendency, call cadence and palette token); those are presentation instructions, never displayed as statistics. Keep per-bird identity and grammar signature stable across schema migrations.

At login/return, serve a small authenticated bootstrap snapshot with the HTML response where feasible, so painting the first bird does not wait for a second round trip. If a valid snapshot is unavailable, paint a quiet sky field with subtle non-spinner motion and fetch; never show a cached bird state as canonical if authorization fails. Code-split notebook, account/accessibility settings, invitations, and export. Render scene and chrome separately: scene contains only birds/place, while the thin top bar contains account/settings, accessibility, notebook, and offer. Settle is reachable through the account/settings top-bar control or a directly accessible top-bar action without placing chrome in the scene; design review should choose the smallest discoverable treatment consistent with the sparse bar requirement.

## 3. Persistent data and migrations

Relational tables, keyed internally by synthetic UUIDs:

* `accounts(id, encrypted_email, verified_at, timezone, created_at, deletion_requested_at, deletion_due_at, settings_version, visit_notifications_enabled)`. Keep email only on this encrypted record; invitee email requires a separately encrypted access-control field, never an identifier or telemetry dimension. Store normalized email in a keyed, nonreversible lookup index for uniqueness/rate limiting, not in logs. Account ID is used in all foreign keys, messages, and sharding.
* `sessions(id, account_id, token_hash, device_label, created_at, last_seen_at, expires_at, revoked_at)` and `magic_links(id, account_id_or_signup_nonce, token_hash, expires_at, consumed_at)`. Email change has a pending encrypted address and new-address verification token; old address remains valid until transactionally replaced.
* `aviaries(id, account_id UNIQUE, created_at, current_revision, last_tick_at, next_tick_at, last_host_presence_at, last_host_arrival_at, settle_until_or_state, weather_seed, world_seed)`. `birds(id, aviary_id, species_id, name, adopted_at, personality_vector, mood, mood_since, perch_zone, motion_state, motion_phase_seed, call_signature_seed, call_grammar_version, row_version)` has a stable immutable ID; never regenerate it during rename or migration. Store each of five scalar traits separately or in a schema-validated structured value, with a version and strict bounds.
* `interaction_events(id, aviary_id, host_account_id, type, bird_id?, payload, occurred_at_server, idempotency_key, client_session_id, sequence, consumed_revision)` is append-only. Store only necessary bounded durations and enum offers. Validate event types and bird ownership at ingress. Partition or purge raw inputs after their needed simulation/audit retention period, while retaining the canonical vector and notebook; document retention in privacy settings. `presence_segments` records validated time intervals rather than unbounded ping rows.
* `aviary_snapshots(aviary_id, revision, produced_at, schema_version, public_render_json)` retains the current snapshot plus a bounded recent window for debugging/recovery. `notebook_entries(id, aviary_id, occurred_at, prose, source_kind, source_event_ids, generator_version)` is append-only to users, chronologically queryable indefinitely, and cannot be edited/deleted individually.
* `invitations(id, host_account_id, encrypted_invitee_email, token_hash, created_at, expires_at, redeemed_at, revoked_at, grant_id)` and `visit_grants(id, invitation_id, visitor_session_hash, active_until, revoked_at)`. `visit_sessions(id, grant_id, started_at, last_seen_at, ended_at)` supplies the host-only visit log with approximate duration. Visitor identity is disclosed to the host through the invited email only. No visitor state enters the host simulation input log.
* `export_jobs` and `deletion_jobs` carry only IDs, status, expiry and audit timestamps. Export object storage uses short-lived encrypted links; deletion removes objects and all related rows after 30 days, including account-linked operational records where any exist.

Enforce database constraints: one aviary/account, 2–7 birds after adoption, unique event idempotency keys per account/device, monotonic snapshot revision, and single-consumer tick lease. Migrations preserve bird IDs, vectors, mood history and call signature seeds. Back up encrypted canonical state and test restore at account granularity; alert on missing/invalid vectors and halt mutation for that aviary rather than silently reseeding.

## 4. API contract

All mutation endpoints require a signed-in host session, CSRF protection where cookies are used, strict ownership checks, request-size limits, and an idempotency key. Use a typed error envelope with machine code and plain system copy. Version APIs and snapshot schema. API timestamps are server UTC; the account time zone determines visual day/night and daily mood boundaries.

| Surface | Contract | Important behavior |
|---|---|---|
| `POST /v1/auth/magic-links` | Email request | Generic response to avoid account enumeration; per-email/IP rate limits; link expires in 15 minutes. |
| `POST /v1/auth/magic-links/consume` | One-time token | Atomic consume, then per-device session issue; replay fails clearly. |
| `GET /v1/aviary/snapshot` | ETag/revision support | Current canonical render state, server time and revision; small kilobyte response; no raw vector. `304` allowed only while access remains valid. |
| `POST /v1/aviary/events` | Batched host events | Accept listen-in start/end, offer, settle/undo, greeting observation and bounded presence segments; validate cooldown and order, return accepted event IDs plus latest revision, never speculative personality. |
| `GET /v1/notebook?cursor=` | Paginated, immutable entries | Read-only; cursor by time+ID; old entries remain available. |
| `PATCH /v1/birds/{id}` | Rename only | Validate length/content, keep ID/vector/mood; return updated revision. |
| `POST /v1/birds/adoptions` | Accept age-eligible offer/name | Server checks schedule, current count and idempotency; never based on visits or score. |
| `GET/PATCH /v1/account/settings` | Time zone, accessibility, visit-notification preference | Version check for ordinary settings conflicts; expose session list/revoke and verified email-change workflow. |
| `POST /v1/account/export`, `POST /v1/account/deletion`, `POST /v1/account/recover` | Account lifecycle | Export JSON by expiring mail link to verified address; immediate soft-delete state, 30-day recovery, scheduled hard deletion. |
| `POST /v1/invitations`, `GET /v1/invitations`, `DELETE /v1/invitations/{id}` | Issue/list/revoke | One-time emailed token, 30-day unused expiry, explicit host action, revocation updates grant immediately. |
| `POST /v1/visits/redeem`, `GET /v1/visits/snapshot`, `POST /v1/visits/end` | Read-only visit | Redeem only once, give limited visit session, return exact same render snapshot at host's world time, recheck grant on every pull; no event-write route. |
| `GET /v1/visits/log` | Host-only log | Invited email, date, approximate duration and outstanding invites; no badge or push. |

For all write APIs, transactional idempotency turns retries into the original result. Reject impossible timestamps and excessive durations; server receipt time bounds client claims. A visitor token is scoped only to visit snapshot/end, cannot use host action, notebook, settings, or account endpoints, and is invalidated on revocation. If a host has opted into visit notifications, a separate mail job sends only that notification; no default notifications or onboarding prompt.

## 5. Canonical tick, presence, mood and drift

The scheduler partitions aviaries by UUID and durably schedules their next minute tick even when no browser is connected. A worker acquires a per-aviary lease or row lock, loads the last revision and unconsumed events in stable server order, advances from `last_tick_at` to the scheduled time, commits vector/mood/world/snapshot/event offset atomically, and moves `next_tick_at`. Retried jobs are idempotent by `(aviary_id, tick_boundary)`; stale workers cannot write an older revision. On delay or outage, replay missed boundaries in bounded batches with deterministic seeds and publish only the newest state; do not invent presence. Alarm when tick latency p99 exceeds 5 seconds. Load test the number of idle accounts implied by always-on ticking and size the partitioned workers accordingly.

The client establishes presence **only** while `document.visibilityState === visible`, `document.hasFocus()`, and a pointermove or keypress occurred within the rolling activity window. Sample/aggregate contiguous qualifying time into short segments, ending immediately on hidden/blur/settle and after activity expiry. Use monotonic client elapsed time but cap each submitted segment by server receipt gaps and reject overlapping segments per session. Reconcile duplicate devices by unioning overlapping intervals for the *same host* so two open screens cannot double-count attention. Do not count pointer/keyboard activity when the tab is hidden. Closing without settle and settling both end the presence interval with no penalty; `pagehide` sendBeacon is best effort and expiry closes a missing end. Presence pings are input evidence, not an engagement metric.

Maintain five traits in `[0,1]`, versioned baseline seeds per species, and slow filtered exposure per bird. Each tick computes validated presence minutes and capped interaction impulses since prior tick; apply a saturating low-pass update, e.g. `e_i(t+1)=e_i(t)*exp(-dt/tau)+weighted_inputs_i` and `trait_i(t+1)=min(1,trait_i(t)+k_i*max(0,e_i)*dt)`. Calibrate `tau`, `k_i` and caps with replayed synthetic timelines so one intensive session stays visually invisible, normal weekly use is measurable, and ~three weeks is perceptible. Presence is the dominant shared positive input. Listen-in duration modestly raises the focused bird's social warmth and vocal frequency. An accepted offer modestly raises curiosity; an offer near a bird modestly raises boldness. Plumage saturation rises only with sustained valid presence. Settle changes current quietness, not personality. Cooldowns and daily input caps make repeated offers ineffective as a drift accelerator. Trait deltas are server-authored and nonnegative; no neglect subtraction. Persist applied deltas in the canonical transaction for audit and recovery, without analytics export.

Separate *expressiveness at the moment* from stored personality: a short-lived recency/absence factor may reduce greeting likelihood and calls on return after a long absence, then recover through ordinary mood transitions. It may never make a bird visibly distressed, imply punishment, or lower stored traits or plumage. Mood is a persisted enum (`wary`, `content`, `curious`, `drowsy`, `alert`) with bounded dwell times and transition probabilities conditioned on current mood, trait-derived tendencies, local time, recent accepted actions, mild weather, and other birds' calls. Daily-ish relaxation is applied by the tick, not at tab open; no snap to neutral. Persist the resulting mood and behavior phase across sessions. Weather is a sparse, deterministic per-aviary schedule: light rain a few times weekly and occasional wind, with brief, gentle effects; no dramatic storms.

At a host arrival or visible return, the server-derived absence interval and current bird state seed a greeting choice. Select one likely greeter weighted by boldness, warmth, mood, and recent greeting history. Short absences usually yield a glance; longer absences can prompt a step/call. Vary timing, motif and pose with deterministic per-event entropy; stagger any secondary response. Arrival does not reset the world. The renderer can play this prompt layer over the canonical ongoing motion, recording the host arrival once to avoid cross-device duplicate greetings.

Generate notebook candidate observations from noteworthy *aviary* events (unusual greeting order, weather plus behavior, quiet preen, long-term changed perch tendency). Apply rarity gates, per-aviary spacing and editorial templates with bird names, time/weather and specific detail. Target roughly one entry every few days for regular visits, with extra entries only for genuinely notable moments. Never log session starts, visit streaks, trait deltas, or generic action receipts as prose. Use deterministic selection and duplicate suppression; review a corpus for repetition, grammar and voice. User cannot edit entries; pagination works indefinitely.

## 6. Bird behavior and audio

Define a coherent pool of about six species, each with a distinct silhouette, muted palette and compact motif grammar. At adoption, choose two system-selected species with contrasting signatures, then let the user name them. Later adoption is offered by aviary age (provisional schedule: third after several months, subsequent spaced farther apart), never usage; a migration-safe schedule table controls eligibility and caps at seven. Renaming affects copy only. A nightjar-like signature remains possibly active at night.

The simulation produces high-level call intentions and near-term seeded schedules; the client synthesizes waveforms locally using WebAudio oscillators/noise envelopes, frequency contours, articulation, harmonic shaping and subtle variation. A grammar combines motif tokens with per-bird immutable signature constraints so calls vary but Pip remains recognizable across mood and trait drift. Use seeded event IDs so two devices rendering the same snapshot get coherent timing without distributing audio files. Bound simultaneous voices and avoid clipping with per-bird gain, headroom and a soft limiter. Chorus eligibility responds to neighboring calls and vocal tendency; schedule responses with jitter, never synchronized on arrival. Test by ear for recognizable birds and repetition over long sessions, including seven-bird mixes.

Listen-in changes per-bird bus gains by smooth envelope (provisionally 1–2 seconds) while other birds remain audible at an ambient floor; disengagement ramps back. Click/tap or Enter on a bird begins listen-in; second activation, another bird, empty-space click, focus leaving, or Escape ends it. Offer song fragments are short procedural motifs from a small library and route through the same mixer. Settling gradually quiets calls without replacing the scene's canonical time of day. Reuse audio nodes/buffers and suspend AudioContext while hidden. WebAudio must unlock on an allowed user gesture in browsers that block autoplay; until then show the same live visual scene with captions available, and quietly enable audio at the first gesture. Do not claim audible calls on a browser that forbids autoplay. If WebAudio is missing/denied, remain silent and enable captions by default; never ship recorded-loop fallback.

Every synthesized call emits a structured description derived from the actual motif sequence, contour, timbre and source location. Caption grammar turns that into short naturalist prose near the calling bird, fading with the call; captions remain meaningful when muted or fallback-silent. Keep a transcript accessible to screen readers without flooding live regions. Limit concurrent visible captions at seven birds by priority and spatial placement, while preserving each audible call in an on-demand accessible transcript if needed.

## 7. Frontend scene and accessibility

Use a responsive scene coordinate system normalized to the full visible viewport, with front/middle/back depths. Compute safe perch positions for two through seven birds so every silhouette stays visible on narrow phones and wide screens, without scroll/pan/zoom. Render a quiet background, subtle parallax and bird/perch plane; leaves/feathers are local, seeded ambient ornaments, not server state. A small scene graph (Canvas/WebGL or optimized SVG/DOM chosen by measured mobile performance) draws from immutable snapshot render descriptors. Interpolate canonical positions and motion phases by server time, with bounded correction on new snapshots; never teleport unless the behavior is itself a cut. The server stays canonical; the client may stop frames when hidden and immediately fetch/rephase on return or long frame gap. Never animate an entry for returning accounts. Time-of-day palette follows the host account's local timezone, including for visitors, with gradual sunrise, dusk and active night.

Normal idle loops are not fixed loops: use phase-offset pose blends and stochastic preen, scan, shuffle and sound-directed tilt keyed by mood. Low boldness/wary favors back perches and scanning; content preens; curious investigates; drowsy settles low. Settling animates warm evening light over several seconds, quiets calls, and persists until close or re-engagement. Any scene click within five seconds reverses settle; provide keyboard equivalent through the focused scene. Do not count settle itself as a drift reward.

Reduced-motion uses the same snapshot and behavior events but slow cross-fades among still poses; perch changes cross-fade rather than fly; no leaf drift; palette changes slow further. Initialize from `prefers-reduced-motion` and allow an explicit account override. Test vestibular comfort with real users. Screen-reader narration is composed from scene state into specific lowercase present-tense prose every 30–60 seconds when idle, faster only for user-initiated offer/settle or return greeting. Maintain a small priority queue: drop stale ambient observations, keep immediate user response, avoid repeated announcements. Use a polite live region for observations and explicit controls/labels for operations; never expose numerical traits or raw state lists as the primary experience. Offer an on-demand current-scene description so a user can inspect the aviary without waiting for cadence.

Keyboard order: top-bar icons, then scene birds; arrow keys move between birds, Enter starts listen-in, Escape exits; offer menu and settle are fully operable and focus returns predictably. Clicking empty space should not create inaccessible behavior. Focus outline must remain visible across bright/dim scene states and fade rules; top bar reappears on keyboard activity and stays present while focused. Meet WCAG AA for all copy in top bar, captions, settings, errors and displayed narration. Provide semantic names and status without turning the aviary into a noisy ARIA event stream. Test screen readers on supported browser/OS pairs.

## 8. Sync, failure behavior, security and privacy

Snapshot revision is monotonic. Clients pull on start, every ~20 seconds visible, when visibility returns, after long frame gaps and after accepted actions. They reconcile by revision, discard older responses and interpolate from current displayed state. An event submission may succeed while its snapshot lags one tick; show the immediate *reaction* as a reversible client prediction, then reconcile to canonical state. No last-write-wins path exists for personality. Two devices' events are ordered by server sequence and processed once. Ordinary settings and name conflicts use row-version checks with a clear system message/refetch, not silent overwrite. Offline interactions are not used to grow drift: if temporarily disconnected, the scene can render last known state with a quiet connection status, but queue only bounded, idempotent actions and presence evidence; reconnect validates time limits. Never pretend the simulation advanced locally as canonical.

Use short-lived, single-use, hashed magic/invitation tokens, TLS, encrypted email fields, secure session cookies, token rotation/revocation, per-device session list, and separate authorization scopes. Recheck invitation grant on *every* snapshot request, including conditional requests; revocation returns a matter-of-fact unavailable state at next poll. Outstanding unused invitations expire after 30 days and cannot be revived. The host can inspect the visit log on demand; there is no badge. Email-change verification and deletion/recovery are atomic, with a hard-delete worker and completion audit. Threat-model account enumeration, token replay, invite forwarding, CSRF, snapshot cache leakage, and visitor endpoint privilege escalation.

Operational telemetry is isolated by design from simulation data. Emit only aggregate counts, request/tick latencies, error rates, anonymous session-duration histograms, first-bird timing, frame timing and audio-context errors. No account UUID, email, bird ID, trait, offer/listen-in history, or per-bird state in analytics, RUM payloads, logs, traces, warehouse exports, or model-training pipelines. Where incident logs need a correlation token, use an ephemeral request ID with restricted short retention and no join to bird history. The simulation store has no read path into the analytics warehouse. Privacy settings describe these categories plainly. An account export intentionally includes current numerical vectors in the private downloadable JSON because the PRD requires them; this is a user-initiated data copy, never a product UI stat view. Protect its emailed link with short expiry and one-time access.

## 9. Performance, tests and observability

Set CI budgets: first-load JS under 2 MB gzipped; first bird visible under 500 ms on the defined mid-tier phone/4G synthetic profile; 60 fps idle on a five-year-old mid-range laptop over 30 minutes; no positive retained-memory slope over 30 minutes. The 500 ms gate must measure navigation to first painted bird for a warm signed-in account, with separate cold-auth and adoption measurements so failures are not hidden. Inline only critical scene code and compact silhouettes; lazy-load notebook/settings/visit UI and noncritical species assets. Keep snapshot payload in kilobytes. Reuse audio nodes, object pools and frame arrays; virtualize notebook history and release scrolled-out entries. Profile 2-bird and 7-bird cases, normal and reduced-motion modes, captions and narration. Synthetic browsers run from common geographies; aggregate RUM records timing/error distributions only. Alert tick p99 >5 s and watch queue age, snapshot freshness, failed token consumption, revoked-grant leakage, audio errors and first-bird percentile, without per-account bird analytics.

Build a deterministic engine test harness with fixed seeds and simulated weeks. Property tests assert nonnegative bounded drift, no decay on neglect, vector identity persistence, mood continuity, idempotent tick replay, and no visitor drift. Concurrency tests submit two devices' events during a delayed tick and prove all deltas apply exactly once. Presence tests cover hidden/focused, visible/blurred, visible/focused/idle, activity-window expiry, settle/close, duplicate devices, suspended tab and clock skew. Contract tests verify visitors cannot write, cannot read notebook/account data and lose access at the next pull after revocation. Visual/audio review should judge greeting variety, seven-bird call recognizability, notebook specificity, and absence of canned loops over long sessions; use blinded human review where the target is felt aliveness. Accessibility tests cover keyboard, screen-reader queue pacing, caption-to-sound matching, contrast across day/night, and reduced-motion transitions. No launch waiver for accessibility.

## 10. Delivery sequence and rollout

1. Establish domain schemas, account UUID/encrypted email handling, auth/session lifecycle, transactional event ingestion, canonical tick and snapshot revision. Build migrations, backups, restore drills and idempotency/concurrency tests before client behavior depends on them.
2. Build two-bird scene, first-frame bootstrap, local-time world, mood motion, call grammar/synthesis, presence accounting and greeting. Integrate offer/listen-in/settle with the server event contract. Tune audio by listening, not solely waveform tests.
3. Add notebook candidate/editorial system, age-based adoption schedule, account settings/export/deletion, and quiet invitations with revocation and visit log. Keep visitor scopes separate from host routes.
4. Complete narration, captions, reduced-motion design, full keyboard coverage, contrast and supported-browser fallback. Run the full 30-minute performance suite and fix regressions before external exposure.
5. Internal dogfood with two birds, then a small opt-in cohort. Ramp eligible bird count through three, five, then seven only after seven-voice chorus, responsive layout, accessibility and perf gates pass. The age schedule means individual users still gain birds slowly. A staged flag may cap newly offered birds during rollout but must never remove an already adopted bird. Expand cohort only on stable tick freshness, first-bird timing, sync correctness, and qualitative aliveness review. Roll back client or worker by versioned snapshot/grammar protocols without rewinding vectors or bird IDs.

Instrument operational metrics from day one. Calibration uses synthetic trajectories and consensual qualitative research, not population-level analysis of private per-bird interactions. Track performance and failures in aggregate. Review account deletion completion and privacy-pipeline isolation as release gates.

## 11. Main risks and mitigations

* **Drift too fast, slow, or gameable:** bounded input, offer cooldown, low-pass filter, week/three-week calibration suite and blinded longitudinal review. Keep coefficients versioned; migrate them without resetting vectors.
* **Lost or divergent canonical state:** single writer, ordered event offset, transactional tick, monotonic revisions, idempotent retries, backup/restore drills and vector validation. Halt an aviary on corruption rather than reseeding a bird.
* **Canned or uncanny audio:** grammar-level variability under stable signatures, jittered chorus, gain/headroom controls, long-session listening review and seven-bird recognition tests. Browser autoplay restrictions yield captions and quiet unlock on gesture.
* **First-frame delay or load-state leak:** edge bootstrap snapshot, compact critical path, small assets and an unobtrusive quiet field only when data is unavailable. Measure actual first bird on target hardware/network.
* **Accessibility as a stripped fallback:** build prose narration, call-derived captions and reduced-motion pose system alongside the core renderer; gate release on user testing and automated regression checks.
* **Privacy leaks through convenience logging:** synthetic IDs everywhere, encrypted email storage, separate simulation and telemetry permissions, schema allowlists on every metric, and tests that reject per-bird/account fields in observability payloads.
* **Always-on tick cost and outages:** partitioned worker capacity/load test, durable next-due scheduling and deterministic bounded catch-up. Alert on p99 latency and freshness, without moving simulation to clients.
* **Invitation leakage or stale access:** hashed one-time tokens, least-privilege visit grants, short snapshot polling, authorization checks on conditional responses and immediate server-side revoke state.
