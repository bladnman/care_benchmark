# Pocket Aviary — v1 implementation plan

## 1. Delivery contract

Build one browser aviary per email magic-link account. A new aviary starts with two system-chosen birds, each with a stable ID and a user-chosen name; age-based invitations to adopt more birds can take it to seven. The main experience is a single, unscrolling scene with return greetings, idle presence, listen-in, seed/song-fragment/still-pool offers, settle, and a sparse read-only field notebook. Ship multi-device continuity, account export/deletion, revocable read-only visit invitations, screen-reader narration, reduced motion, and procedural-call captions in v1.

The product has no score, visit streak, level, distress, feeding need, public discovery, co-presence, or user-editable scene. No toast, banner, push prompt, or badge announces a return or a visit. Product copy is lowercase, present-tense naturalist observation; identity, errors, sync, and settings use direct matter-of-fact language. A missing settle gesture and a long absence have no penalty. The implementation review checklist must reject UI or telemetry that turns attention into a counter.

Decisions needed to make the PRD executable:

* Normalize hidden personality traits to `[0,1]`, with trait mappings and seed distributions versioned in the simulation service. No personality value or trait name appears in the aviary UI or normal snapshot API. The explicitly required on-demand account JSON export includes the raw vectors as user-owned data, outside the aviary experience.
* Start with a three-minute activity window for presence, a 30-second qualified heartbeat, a five-minute per-bird offer cooldown, and a 60-second tick. These are versioned calibration parameters; changing them requires replay and perceptual gates below.
* Use an account-level IANA timezone for the canonical day/night cycle. Seed it from the host browser at adoption. A foreground host device may update it when the device's timezone changes; the server grants a short lease to the latest active host device so two devices cannot oscillate it. Visitor devices never set it. All clients render the same host-time scene.
* Make additional adoption available at aviary ages 90, 180, 270, 365, and 540 days (birds three through seven). The account/bird settings panel quietly exposes the available adoption action; there is no alert, badge, score, rarity catalog, or visit-based acceleration. The server enforces age and the seven-bird cap.

## 2. System boundaries and deployment shape

Use a web client with a small edge-served HTML/JS shell, an authenticated API, a transactional primary database, a server simulation worker, a due-tick scheduler, an email worker, and private short-lived export storage. Start as one deployable API/worker codebase with separate process roles; keep the simulation module pure and versioned. Use a relational database with row locking/transactions (for example PostgreSQL) rather than cross-device client state merging. A durable append-only `interaction_event` table is the input journal; the current bird and aviary rows are authoritative, not event-log reconstructions. Retain consumed events for a bounded 30-day operational replay window, then purge them; preserve only the current state, notebook, and minimal derived facts needed for future observations.

The only path for a personality write is the tick worker. API commands append validated events; the worker applies additive deltas to persisted vectors inside a transaction. The client owns presentation state only: frame interpolation, local ambient leaf/feather ornaments, WebAudio voices, focus, and open panels. It never advances mood, drift, weather, adoption eligibility, or offer cooldowns. The server resolves commands that need an immediate visible response into a persisted short-lived presentation cue, then the next tick incorporates their mood/drift effects. All connected host devices can see the same cue in snapshots; the initiating client can render the command response immediately.

The initial authenticated HTML response should include a compact private scene projection and a server timestamp so the first bird can render without an extra API round trip. Serve it from an edge-adjacent authenticated snapshot read with `Cache-Control: private, no-store`, never from a shared cache. Keep critical scene renderer and two starter silhouettes on the initial path; lazy-load notebook, settings, invitations, export UI, and later-species assets. If the snapshot is unavailable, paint a quiet sky field immediately, fetch the snapshot, and show a matter-of-fact retry/error surface only if recovery fails. No spinner, canned entry, or fade from a static bird. After adoption, and only for that one first appearance, birds may softly fly into the empty field; all subsequent navigation begins at the current motion phase.

Server and client share a versioned presentation schema. Each snapshot has `aviary_id`, monotonically increasing `revision`, `tick_at`, `server_now`, `scene_seed`, `timezone`, `day_phase`, active weather window, settled presentation window, bird presentation records, scheduled calls, active cues, and an `expires_at`. A bird presentation record has stable ID/name/species, perch zone and normalized position, pose/motion phase, mood enum, appearance and motion parameters derived on the server, and a stable call-signature identifier. It does **not** contain the five raw personality values. The renderer combines this projection with elapsed server time; it may interpolate between server positions, but never infer a new canonical perch or mood. Version mismatches trigger a fresh snapshot and safe quiet-field recovery, not a client reset of bird identity.

## 3. Persistent data and invariants

Email is never a partition key, telemetry dimension, or log identifier. One account owns one aviary. |

| `bird` | Stable UUID, aviary UUID, species and call-signature seed, name, adoption time, five numeric personality values, current mood and transition time, perch/pose state, last offer time, short-lived expression state, UTC-day evidence counters | IDs survive rename, migrations, and species-library revisions. | `notebook_entry` and `observation_fact` | Entry UUID, aviary UUID, event/evidence references, prose/template version, creation time; minimal rolling facts for truthful comparisons | Append-only to the user, ordered by time, never user-editable; entries survive until account deletion. | `invitation`, `visit_session`, `visit_log` | Invite UUID, host UUID, encrypted recipient address plus lookup HMAC, token hash, 30-day unused expiry, revocation/redemption time; scoped token; visit start/end and approximate duration | No global sharing switch. Use transactions and schema constraints for one aviary per account, maximum seven birds, unique event keys, and valid state transitions. Encrypt email and private export/visit data using per-account envelope keys. Account email exists only on the account row as an identity field; invitation recipient addresses are encrypted invitation data, not account identifiers. Restrict the simulation database from the analytics pipeline at the network and credential layers. Operational metrics are emitted from request and worker boundaries only, with no account ID, bird ID, event payload, vector, invitee email, or per-account interaction history.

### Lifecycle and deletion

Magic-link request responses are identical for existing and new addresses, with per-email and per-IP rate limits; link redemption creates or resumes the single-user account. Use secure HTTP-only same-site cookies, CSRF protection on mutations, session rotation on sign-in, and a visible per-device revoke list in account settings. An on-demand export contains birds, stable IDs, names, current personality vectors, moods, notebook entries, and account settings as JSON; email a short-lived one-use download link to the verified address. The account settings link to a plain-language privacy policy naming the permitted aggregate operational metrics and excluding per-bird interaction data. Deletion immediately disables invites/export jobs and marks the account recoverable for 30 days. A signed-in recovery action restores it. At the deadline, a deletion worker removes birds/vectors, events, notebook, invites, visit logs, sessions, jobs, and any account-correlated operational/security records, then destroys the per-account encryption key. Backups must be encrypted so key destruction makes residual copies unreadable; backup retention and deletion audits must meet the same hard-deletion deadline. Aggregate telemetry has no account linkage to erase. A deletion test enumerates every owned table and object-store prefix.

## 4. API contracts and command handling

Expose versioned JSON over HTTPS. Host endpoints require the account session; visitor endpoints use a separate read-only scoped visit session. Use server-derived identity from the credential, never an account ID submitted as authority. Return a structured error code and matter-of-fact copy for expired auth, unavailable visit, version mismatch, and temporary sync failure.

| Endpoint | Behavior |
| --- | --- |
| `POST /v1/auth/links`, `POST /v1/auth/redeem`, `POST /v1/auth/logout` | Request and atomically consume 15-minute magic links; create/revoke a device session. Rate limit without revealing account existence. |
| `GET /v1/aviary/snapshot?since_revision=` | Return current private presentation projection, clock anchor, and revision. A same-revision response is small; never expose vectors. Host reads are available on first load, visibility return, long frame gap, and low-frequency visible keepalive. |
| `POST /v1/aviary/arrival` | On a host's foreground return, derive absence from server-recorded last foreground interval, select a greeting bird using boldness, warmth, mood, and absence, and return a unique timed cue. Debounce brief focus flaps; any secondary response is staggered, never synchronized. Visitor sessions cannot call it. |
| `POST /v1/events` | Batch qualified presence starts/heartbeats/ends, listen-in start/end, offers, settle, and settle undo. Validate event schema, session sequence, target ownership, idempotency, rate limits, and server-time bounds. Return accepted sequence/revision and any immediate offer or settle cue. |
| `GET /v1/notebook?cursor=` | Stable reverse-chronological keyset pagination; immutable entries; no edit/delete endpoint. |
| `PATCH /v1/birds/{id}/name`, `POST /v1/birds/adopt` | Host-only rename; server checks age availability and seven-bird cap atomically, picks a species from the coherent pool, creates a new stable ID/vector/grammar seed. Never replace an existing bird. |
| `GET/PATCH /v1/account/settings`, `GET /v1/account/sessions`, `DELETE /v1/account/sessions/{id}`, `POST /v1/account/email-change`, `POST /v1/account/export`, `POST /v1/account/delete`, `POST /v1/account/recover` | Matter-of-fact account and accessibility controls; verify new email before switching; send one-use export download link to verified address; enforce deletion window. |
| `POST /v1/invitations`, `GET /v1/invitations`, `DELETE /v1/invitations/{id}`, `GET /v1/visits` | Host creates a named email invite, sees outstanding grants and a quiet visit log, and revokes any grant. Notification setting is off by default. |
| `POST /v1/visits/redeem`, `GET /v1/visits/snapshot` | Atomically redeem a one-use, 30-day invitation link into a scoped read-only session; recheck grant/revocation on every snapshot; log approximate session duration without sending presence events. No host write endpoints accept visitor credentials. |

The visitor link is a bearer capability delivered to the named email, so redemption proves possession of that link rather than a separate identity claim. Keep token hashes only, redact links from referrers/logs, use `Referrer-Policy: no-referrer`, and warn only in the invitation settings that forwarded links can be used by their holder. A redeemed link cannot create a second visit session. A revoked or expired invite and a revoked active visit both reach the same clear “visit no longer available” surface. Because revocation is checked at every pull, cap visible visitor snapshot intervals at 15 seconds; the state revocation latency target is at most one pull interval plus request latency. Visitor projection uses the host's canonical timezone, mood, calls, weather, and appearance, without host notebook, settings, export, or interaction controls. A visitor hears and sees the actual aviary, without a prettified state or greeting. The host's visit log is on demand and has no new-visit badge. If the host explicitly opts into visit notifications, send a restrained visit email with rate limiting; never enable browser push or onboarding prompts.

## 5. Presence, concurrency, and synchronization

The client qualifies presence only while **all** three signals hold: `document.visibilityState === 'visible'`, `document.hasFocus()`, and a pointermove or keypress within the previous three minutes. Record activity timestamps from trusted user events, not synthetic timer callbacks. A tab can remain visibly idle for nearly three minutes after the last activity so quiet watching counts; an unfocused or hidden tab stops immediately. Send a start when qualification becomes true, a heartbeat every 30 seconds while true, and an end on loss, settle, or unload when possible. The server derives bounded intervals from received consecutive pings and never counts beyond the last qualified heartbeat plus a small network grace. It clips each interval by server time and session order, ignores late/duplicate pings, and refuses gaps larger than the heartbeat cap. `sendBeacon` is a best-effort close path; missing close is bounded by heartbeat expiry. Offline time is not retroactively claimed as presence. An active listen-in event does not substitute for the three-condition presence test.

Multiple host devices may be open simultaneously. Each produces an independent qualified interval; the worker unions the intervals in UTC per aviary so one minute of overlapping attention counts once. Commands from both devices enter one ordered per-aviary stream. Accept an offer only after an atomic per-bird cooldown check; store a deterministic reaction cue with an idempotency key. The server applies each accepted event once in increasing sequence. A tick locks the aviary row, reads events after the committed offset, applies state changes, increments revision, persists the new offset and projection, then commits as one unit. A worker crash before commit replays the same uncommitted batch; a crash after commit cannot reapply it. There is no last-write-wins update to personality under any API path.

Schedule a due tick for every active account every roughly 60 seconds, whether any browser is connected or not. Shard due work by aviary UUID; use leases plus transactional row locks to prevent double ticking. The worker advances elapsed server time, including time while absent, in bounded deterministic steps. If workers fall behind, catch up server-side from the last committed tick and alert on lag; clients never perform the catch-up. Snapshots carry `revision` and `server_now`; clients estimate clock skew, interpolate only within a bounded horizon, and request a fresh snapshot on visibility return, frame gap (including laptop wake), HTTP re-auth, or visible keepalive. On a revision jump, blend presentation state over a short bounded interval while preserving the actual server mood and perch destination. If a mutation's response is lost, retry with the same idempotency key. Show a matter-of-fact recovery surface only when state cannot be fetched; never let a stale device upload absolute state.

Settle ends the initiating device's presence interval and starts a server-timed evening presentation cue in the canonical scene, so another host device and an active visitor see the same quieted aviary at their next snapshot. A click anywhere in the host scene within five seconds submits an idempotent undo, reverses the lighting ramp, and can start a new presence interval if the three conditions hold. After five seconds, ordinary host re-engagement clears the settled presentation state without treating the earlier settle as a failure. Closing the settling tab clears the cue via a best-effort end event or, if unload is missed, the bounded heartbeat lease; it is equivalent to ending presence for drift and creates no negative signal. The cue overlays, rather than replaces, the canonical local-time day/night cycle. Visitors cannot undo it or create their own settle state.

## 6. Simulation engine and content generation

Implement the tick as a deterministic pure reducer over `(prior state, elapsed time, ordered accepted events, engine version)`, with database I/O and scheduling outside it. Persist seeds, last tick, active weather, and engine version. Golden replay fixtures must yield identical state on restart or worker reassignment. Version migrations transform current vectors in place while preserving bird UUIDs and perceptual continuity; never regenerate a bird from an event log.

### Slow personality drift

For each bird and trait `j`, let `x_j` be the persisted value in `[0,1]`. Sum **newly covered**, overlap-deduplicated qualified presence minutes in a UTC day; UTC keeps travel/timezone changes from resetting a daily cap. Start with `P = min(presence_minutes/10, 1)`, `L = min(that_bird_listen_minutes/5, 1)`, `A = min(accepted_offers_to_bird, 1)`, and `N = min(offers_near_bird, 1)`. Set initial evidence weights: boldness `0.85P + 0.15N`; warmth and vocal frequency each `0.70P + 0.30L`; plumage saturation `P`; curiosity `0.80P + 0.20A`. Presence remains the dominant component of every trait. Start `k_j` at boldness `0.005`, warmth `0.006`, vocal frequency `0.006`, plumage `0.004`, and curiosity `0.005`, with a hard `0.006` per-trait daily delta cap. On each tick, apply only the increase in the day's capped evidence since the last committed tick: `x'_j = min(1, x_j + (1 - x_j) * k_j * max(0, E_new - E_applied))`, then persist `E_applied` with the vector and event offset in the same transaction. Reset evidence counters at the next UTC day; do not reset the vector. These are versioned starting calibration values, to be tuned with synthetic replay and user studies. A single session must remain below a perceptible change. Five regular 10-minute visits/week should yield instrument-detectable positive deltas after seven days and observable changes in paired bird behavior/appearance after roughly 21 days. Add tests that all traits are nondecreasing for any event trace, neglect leaves vectors unchanged, replay/duplicate events do not add drift, and one very long session or offer spam cannot saturate a trait.

Keep a separate bounded recent-expression signal for greetings and ambient call density. It can relax toward a quiet baseline after long absence without lowering any personality vector, making a two-week return calmer but never distressed, mistrustful, or desaturated. Do not turn absence into an event or hidden debt. Settle changes short-term mood/volume only.

### Fast mood, perch, weather, and relationships

Persist a small mood enum (`wary`, `content`, `curious`, `drowsy`, `alert`) and last transition. At each tick, compute a seeded transition distribution from time of day in the host timezone, recent accepted events, active weather, neighboring bird calls/moods, and the bird's personality. Hysteresis and minimum dwell times prevent one-minute flicker. Daily-ish relaxation is gradual; opening a tab never resets mood. Map mood plus boldness into a perch-zone preference and bounded transitions among front/middle/back. Wary tends back and scans; content preens; curious investigates and tilts; drowsy sits low; alert responds to other birds. No state implies hunger, illness, death, or neglect distress. Use deterministic, rare weather windows (a few short rains per week, occasional wind); weather briefly alters mood/call likelihood. Night quiets most birds but leaves the nightjar-like species potentially active. Bird-to-bird replies and chorus arise from overlapping probabilistic call windows, with timing offsets so they do not perform in lockstep.

### Greeting and offer resolution

On host return, the server uses the elapsed absence from prior qualified presence and current bird state to choose one primary greeter. Short absences favor a glance or head movement; longer absences may produce a step closer or longer call. Boldness/warmth affect which bird volunteers; mood shapes its gesture. Draw a fresh seed/event ID so variants are not cycled in a fixed order. If another bird responds, delay it by a small randomized offset; never fire all birds together. Do not wait for the cue before rendering the first aviary frame, and never accompany it with return text.

An offer is selected from the top bar, then placed toward a bird/area without clicking a bird as the entry point. The server atomically enforces the per-bird cooldown, evaluates reaction using mood, curiosity, boldness, and offer type, and returns a timed cue: approach/hesitate/ignore seed, join/quiet/call-against a library motif, or drink/bathe/watch the still pool. Ignoring is a valid bird reaction, not an error or punishment. The cue plays immediately; the next tick applies any mood and small drift effects. Rejected cooldown requests remain quiet with a naturalist affordance state, never a score or admonishment. Song fragments are a small bundled symbolic motif library synthesized through the same audio engine as calls, not audio files.

### Call grammar, notebook, and narration facts

Give each of roughly six species a compact motif grammar (phrase contour, intervals, timbre envelope, rhythm) and each bird a stable signature seed. A scheduled call event contains bird ID, motif/phrase grammar tokens, variation seed, onset/duration, envelope, and a call ID. The server schedules symbolic calls based on mood, local time, weather, vocal-frequency-derived behavior, and other birds; the browser synthesizes sound from those symbols. Constrain variation so repeated calls are never identical while species and individual signatures remain recognizable after drift. Avoid same-phase overlapping oscillators and hard simultaneous choruses. The same instantiated call event generates a matching caption; captions never come from a static species string. Perceptual tests must confirm users can distinguish individual birds at two through seven birds, across moods and listen-in, and flag uncanny/repetitive calls before rollout.

Generate notebook entries from persisted observation facts, not arbitrary session logs or raw vectors. Candidate facts include an actual first greeting ordering, an unusual perch choice, a quiet rain, or a bird-to-bird reply; comparative claims such as “first time this week” require a stored seven-day fact window. Render with reviewed naturalist templates and grammatical variants, named birds, present tense, lowercase. A sparse rate gate targets about one entry every few days for a regularly visited aviary, with a higher-priority truly noteworthy event allowed through but no entry-per-session behavior. Never mention user attendance, streaks, trait numbers, or fabricated facts. Store final immutable prose plus evidence/template version for audit. The same fact/prose layer feeds screen-reader narration at a different cadence, with current-state descriptions rather than notebook spam.

## 7. Browser scene, audio, and accessibility

### Rendering and interaction

Use a retained scene graph over Canvas 2D for sky, three perch planes, birds, and restrained foreground detail, with a small DOM layer for actual controls, captions, accessible narration, and visible focus. Keep content coordinates normalized; a responsive layout solver adjusts spacing, bird scale, and front/middle/back offsets so all two to seven birds and their focus targets remain visible on narrow phones and wide desktops. No panning, zoom, scrolling, direct perch placement, inline bird labels, or tooltip chrome. Separate bird hit regions from artwork so touch and keyboard targets remain usable even when silhouettes are small. Species assets are compact SVG/shape definitions. The first frame samples each bird's persisted motion phase at `server_now`; ongoing preen, scan, head tilt, shuffle, and perch transitions blend from there, never start at frame zero. Client-only leaves and feathers use bounded seeded randomness and do not enter canonical state. The top bar has only account, accessibility, notebook, and offer controls; fade it toward transparency after a few seconds of pointer stillness and restore full contrast on pointer or keyboard activity. Keep keyboard focus indicators visible even while the bar is faded.

Pause draw loops when hidden, dispose of obsolete visual resources, and fetch fresh state on return. The server continues ticking. Blend local day/night color with host-time sun phase and canonical weather; a host session's settle cue ramps to evening over several seconds and can reverse during the five-second undo window. When `prefers-reduced-motion` or the explicit setting is active, replace micro-motion with slowly cross-faded still poses, replace flights with perch-to-perch cross-fades, remove drifting leaves/feathers and parallax, and slow color changes. Never present a frozen or empty substitute. Both modes use the same bird/mood/drift state and notebook.

### Audio graph

Use one bounded WebAudio context per visible host or visitor tab, one reusable voice pool with per-bird gain/pan/filter and a master limiter. Synthesize calls from the symbolic motif grammar via oscillators/noise/envelopes (or an AudioWorklet where supported); schedule ahead against the server clock, with jitter correction on new snapshots. Reuse buffers and node pools, disconnect completed voices, and cap polyphony without erasing a bird's characteristic call. The ambient chorus is the mix of independent procedural voices, not stacked loops. On listen-in, ramp the focused bird's gain up and all other bird gains down to a nonzero ambient floor over a gentle interval; disengagement ramps back at the same pace. Clicking the same bird, switching bird, clicking empty scene space, moving keyboard focus away, or Escape ends listen-in. Persist accepted listen-in start/end events for drift, but an audio-disabled user still gets the interaction and captions.

Modern browsers may block autoplay despite the desired audible first frame. Attempt to resume an already-permitted context; if gesture permission is required, render the aviary in motion immediately, enable captions while silent, and unlock procedural audio on the first explicit user gesture. Do not add a recorded fallback, fake playback, or a blocking audio modal. On WebAudio unavailability/denial/hardware error, stay in graceful silence with captions on by default and show a matter-of-fact audio control only in accessibility settings. A mute setting never stops mood or call scheduling.

### Equivalent accessible experiences

Create a real navigable DOM structure: top bar controls in tab order; entering the scene focuses the first bird; arrows move among birds; Enter activates listen-in; Escape exits; offer menu and notebook are keyboard navigable and restore focus on close. Use a visible AA-contrast focus treatment on both bright and dim palettes. All user-copy text, including captions and overlays, meets WCAG AA in every day/night/weather state; define tokens and automated contrast fixtures for each surface. Account/accessibility/error copy uses the system voice.

The screen-reader scene has a slowly refreshed naturalist paragraph describing birds, place, and calls from the same current projection. An idle `aria-live="polite"` update occurs roughly every 30–60 seconds, coalescing stale observations so it never floods the queue. A return greeting, offer reaction, or settle may interrupt at a higher priority but is phrased as an observation, not a raw state change. Include on-demand review of the current description without exposing mood codes or numeric vectors. Call captions are placed near the actual calling bird, use the instantiated grammar's audible contour and timing, and fade with the call. When sound is unavailable, turn captions on automatically; users may also opt in while audio works. Test with screen readers, keyboard only, high contrast, reduced motion, no audio, and combinations of these settings from the first milestone.

## 8. Budgets, instrumentation, and gates

Set hard build/runtime gates: initial gzipped JS below 2 MB, with a much smaller critical scene target; first bird visible within 500 ms on the agreed mid-tier 4G mobile profile for returning authenticated users; sustained 60 fps idle on a five-year-old mid-range laptop over 30 minutes; no upward retained-heap trend over a 30-minute session after warmup. Reserve roughly 6 ms of a 16.7 ms frame for scene draw/updates and target p95 frames at or below 16.7 ms on the laptop profile; investigate p99 long frames. Keep snapshots in kilobytes, cap active audio voices/nodes, release notebook rows after virtualized scroll-out, and stop hidden render loops. Run cold/warm, two-bird and seven-bird, day/night, rain, notebook open/closed, audio on/off, and reduced-motion profiles in CI. A realistic cold authenticated browser/network test must measure navigation-to-first-painted-bird, not only API time. If the 500 ms gate misses, profile edge state delivery, critical JS, and first draw before adding a loading flourish.

Operational observability is intentionally aggregate-only: request volumes/statuses/latencies, first-bird render timing, frame timing histograms, WebAudio startup/error counts, tick duration/lag and backlog, invitation redemption/revocation errors, and anonymized session-duration histograms. Emit no per-bird state, per-account interaction counts, drift measurements, email, or account dimensions into metrics/RUM. Separate request-trace IDs from user identity; sanitize URLs and event bodies before logs. Synthetic browser probes from common geographies and deterministic simulation fixtures provide performance and engine calibration without reading production relationships. Alert if tick p99 latency exceeds five seconds, if due-tick lag grows, if snapshot error rate rises, or if first-bird/performance budgets regress. Product success is judged through consented qualitative research and synthetic traces, never a visit-frequency leaderboard or account behavior warehouse.

Acceptance suites:

1. **Engine:** property tests for nonnegative bounded drift, order/idempotency, presence dominance, no neglect decay, mood persistence, stable identity, weather rarity, offer cooldown, and no seventh-to-eighth adoption. Replay deterministic weeks of synthetic presence and absence through worker restarts and version migrations.
2. **Sync/security:** two simultaneous host devices and a visitor; overlapping presence counts once; command retries apply once; stale device cannot overwrite vectors; visitor commands return forbidden; revocation blocks next snapshot; magic-link replay fails; email changes require verification; deletion removes every owned record and key.
3. **Experience:** varied return greetings honor absence, bird boldness, and mood without text announcements; first frame is mid-motion; calls remain distinguishable at seven; listen-in ramps and leaves other birds audible; notebook entries are sparse, true, and naturalist. Evaluate with blinded paired clips/screens after simulated one versus three weeks, including people using captions/narration.
4. **Access/performance:** automated contrast and keyboard paths plus manual assistive-technology review; reduced-motion pose cross-fades; WebAudio-denied captions; 30-minute frame/heap soak; 4G first-bird and bundle checks in release CI.

## 9. Build sequence and rollout

1. **Foundation:** schema, per-account encryption, magic-link/session flows, static shell, private snapshot contract, two stable starter birds, and a first-bird performance fixture. Exit only when a return visit paints the existing birds within budget without an entry animation or spinner.
2. **Canonical engine:** append-only command path, strict presence qualification, due-tick worker, deterministic reducer, mood/perch/weather, drift, and two-device synchronization. Gate on replay/idempotency tests and a multi-week synthetic trace whose vectors never fall on absence.
3. **Expressive surface:** species silhouettes and grammar, procedural chorus and listen-in, offer and settle cues, return greeting, naturalist notebook generation, and day/night scene. Run repeated-call listening studies and drift-calibration studies on synthetic aged accounts; retune versioned parameters before production accounts accumulate long histories.
4. **Equal access and account controls:** narration, call captions, reduced-motion scene, keyboard/focus/contrast work, export, deletion, device revocation, and the invitation/visit path. These are launch requirements, not a later patch. Review copy in both voice registers and test the WebAudio-blocked path.
5. **Private beta to general availability:** begin with two birds per production aviary. Use synthetic aged accounts to exercise three through seven. Roll out age-gated adoption capacity in stages (third, then five, then seven) only after distinct-call recognition, layout, audio CPU, and accessibility checks pass at each count; real eligibility remains based solely on aviary age. Ramp server traffic gradually and watch aggregate operational budgets, tick lag, crash rates, and support feedback. Have rollback switches for new audio grammars, presentation versions, and adoption capacity; do not roll back persisted bird IDs or vectors. Migrate vectors with explicit, tested transforms if a calibration change is necessary.

## 10. Risk register and decisions to revisit with evidence

| Risk | Mitigation and release signal |
| --- | --- |
| Drift too fast, too slow, or quietly punishing absence | Versioned coefficients, daily caps, long synthetic traces, monotonic property tests, blinded one/three-week comparisons. Tune before broad rollout; never use production per-bird histories for population calibration. |
| Presence inflation from background tabs or concurrent devices | Enforce all three browser signals, bounded 30-second heartbeat intervals, server clipping and UTC union across devices; test hidden/unfocused/suspended/offline cases. |
| Personality loss through races, retry, or migration | Server-only writes, ordered per-aviary event offsets and atomic tick commits, stable UUIDs, restore drills, migration checksums and reversible deploys. Any vector reset is a stop-ship incident. |
| Calls sound canned or indistinct by bird seven | Stable per-bird signature with bounded procedural variation, motif collision analysis, controlled listening tests, chorus/polyphony tuning, no recorded fallback. Hold bird-count ramp if recognition fails. |
| First frame feels like software starting | Inline private projection, tiny critical render path, phase-anchored motion, quiet-field recovery, synthetic first-bird gate; no welcome or load animation. |
| Browser audio permission contradicts immediate sound | Unlock on permitted context/first gesture, captions while blocked, visible-but-unobtrusive settings; test Safari/Chrome/Firefox/Edge policies. |
| Accessible mode loses the aviary's character | Design narration/captions/reduced-motion alongside the base renderer, test assistive tech and combined preferences, require parity in user studies before launch. |
| Invitations leak access or influence host state | Hashed one-use tokens, encrypted recipient data, read-only scoped credentials, per-pull revocation check, no visitor event ingestion, silent visit log and explicit-only notification toggle. |
| Privacy boundary erodes via analytics | Separate credentials/network paths, allowlisted aggregate metrics schema, CI checks for account/bird fields in event payloads, deletion inventory and security review. |

The v1 release is complete only when a returning user on two devices sees the same continuing birds, a visitor sees only that canonical scene, absence causes no harm, and every supported sensory path offers a living aviary within the stated budgets.
