# Pocket Aviary v1 implementation plan

## 1. Product scope and invariants

Ship a browser-only, single-user aviary with two system-selected starter birds, room to grow to seven, email magic-link accounts, one canonical aviary per account, multi-device snapshots, the field notebook, presence-based personality drift, optional read-only visits, procedural calls, screen-reader narration, captions, and reduced-motion rendering. Build the quiet everyday session first: the aviary is already moving on first paint; one bird notices the returning user; the user can watch, listen in, offer a gesture, settle, or open the notebook.

Preserve these invariants in code and schema: the server alone owns persistent mood and personality; each bird has a stable immutable ID; clients submit events, never state; drift is additive and monotonic toward expressive and neglect never subtracts traits; a visitor never contributes host presence or events; private interaction history never enters analytics; numbers for personality are never exposed in product UI. Avoid game framing, counters, streaks, distress, care schedules, public discovery, shared aviaries, native clients, payments, customizable scenes, multiple aviaries per account, and notification-driven return loops. Visit notifications may be enabled by the host in settings but default off. Do not add a welcome banner, visit badge, or visit-frequency notebook entry.

V1 also includes account export and deletion, device-session revocation, per-bird rename, age-paced additions, visit log and invitation revocation/expiry, and matter-of-fact account/accessibility/error surfaces. Account settings, accessibility settings, and visit flows are supporting surfaces and should be lazy-loaded.

## 2. Architecture and ownership

Use a web client and a small set of server-side logical services, deployable together initially and separable by load/ownership later:

- **Web app / renderer:** downloads an HTML shell and small initial scene payload, paints from the latest canonical snapshot, interpolates between snapshots, handles input and local procedural audio. It may maintain transient animation and audio state but has no authority over canonical state.
- **Identity and account API:** magic-link issue/consume, session lifecycle, email verification/change, export and deletion. Use a synthetic UUID as the account key everywhere except the encrypted email field and outbound email delivery.
- **Aviary API:** authenticated snapshot reads, append-only interaction/event writes, bird naming, notebook reads, settings, and visit token operations. Authorize every operation against account ID and resource ownership.
- **Simulation worker:** processes due aviaries at roughly one-minute cadence, consumes ordered events, and commits mood, personality deltas, world state and notebook candidates transactionally. Idempotent tick processing is required so retries cannot double-apply drift.
- **Invitation/mail boundary:** sends sign-in and invitation links; stores only token digests and invite metadata. A visit-scoped capability grants read-only access to a single aviary until revoked/expired.
- **Operational telemetry:** isolated from simulation storage. Publish only aggregate request/latency/error/frame/audio metrics with no account dimension and no bird fields.

Persist records in a transactional relational store. Keep interaction events append-only for deterministic tick consumption and operational debugging within retention/deletion policy. Keep canonical current state separately for fast snapshots. Add an outbox or equivalent transactional publication mechanism for email, notebook generation and tick scheduling so a committed domain change cannot be lost between the database and a queue. Do not place email in IDs, logs, trace attributes, shard keys or event payloads except where strictly needed for invitation display/delivery.

## 3. Data model

Suggested core records (timestamps UTC; derive local day-cycle and mood inputs using the user's saved IANA timezone):

- `Account(id UUID, encrypted_email, verified_at, timezone, accessibility/audio preferences, visit_notifications_enabled, created_at, deletion_requested_at, deleted_at)`.
- `DeviceSession(id, account_id, token_hash, created_at, last_seen_at, revoked_at)`; tokens are device-specific and revocable.
- `Aviary(id, account_id UNIQUE, created_at, updated_at, canonical_revision, simulation_cursor, settled_until_or_state)`. The revision increases on every canonical mutation and is useful for clients to reject stale snapshots.
- `Bird(id UUID, aviary_id, species_id, display_name, adopted_at, personality[boldness,social_warmth,vocal_frequency,plumage_saturation,curiosity], mood, mood_updated_at, perch_zone, animation/call seed state, last_tick_at)`. Trait values are server-only normalized scalars with bounds. Never reuse an ID when renaming, migrating, or changing species catalog data.
- `InteractionEvent(id, aviary_id, bird_id nullable, device_session_id nullable, kind, occurred_at_client, received_at_server, idempotency_key, payload, sequence)`. Event kinds include presence interval/ping, listen-in begin/end, offer, settle/undo, and host return. Validate allowed payload by kind, cap sizes, and use server receipt time for ordering and rate limits.
- `PresenceInterval` or compact presence-event segments keyed by account/session, start/end, and qualifying signal summary. Only accrue time when visible AND focused AND recent pointermove or keypress falls within a calibrated few-minute activity window. Do not store raw pointer/key streams. Deduplicate overlapping devices conservatively: one account should not accumulate parallel presence-time for two devices; count the union of qualifying intervals.
- `NotebookEntry(id, aviary_id, created_at, observation_type, prose, source_revision)`, generated sparsely (typically every few days; noteworthy moments can qualify sooner), immutable/read-only, with no visit-frequency observations.
- `VisitInvite(id, aviary_id, host_account_id, visitor_email_encrypted, token_digest, created_at, expires_at, revoked_at, first_used_at)` plus a minimal visit record with visitor email and approximate duration for the host's transparency log. Invitation expires after 30 days unused; use/revocation is scoped to that invite.
- `BirdOfferEligibility` can be derived from aviary age and adoption history; if materialized, it must not depend on visit count, interaction score, or payment.

Choose stable enumerations for moods (wary, content, curious, drowsy, alert), offer types (seed, song_fragment, still_pool), and species/motif IDs. Trait ranges, starter seeds, cooldown duration and exact presence activity window are calibration parameters in versioned server configuration; document a chosen initial value and change it only through a reviewed calibration release.

## 4. API and event contracts

Use versioned JSON endpoints (or equivalent typed RPC) with authenticated session credentials, request IDs, idempotency keys for writes, and a consistent matter-of-fact error envelope. No client endpoint accepts personality or mood values.

- `POST /auth/magic-links` accepts email and sends a 15-minute one-use link with per-email rate limiting. `POST /auth/magic-links/consume` invalidates atomically and issues a per-device session. Email change verifies the new address before changing the encrypted canonical email.
- `GET /aviary/snapshot` returns current canonical revision, server time, local-time inputs, scene/day phase, weather, birds' IDs/species/names/perch/mood/pose and next transition/call timing, plus active settle state. Omit raw personality values; the rendering contract can include derived presentation cues needed to reproduce the same state. Include a compact boot snapshot with the HTML/CDN path when available. Pull again on visibility return, long frame gap, and low-frequency visible-tab keepalive.
- `POST /aviary/events` accepts one or a bounded batch of typed events with idempotency key and client timestamp. Server authenticates and validates ownership, clamps unreasonable durations, sequences events, records receipt time, and returns accepted IDs/cursor. Presence signals are accepted only from an authenticated host session and are checked against server-observed visibility/focus heartbeat semantics as far as browsers permit. Client signals are evidence, not direct trait updates.
- `GET /aviary/notebook?cursor=...` returns immutable entries in reverse chronological pages. `PATCH /birds/{id}` permits display-name change only. An age-derived `GET /aviary/available-bird` and `POST /aviary/adoptions` expose a new bird when the aviary's age schedule permits and below the seven-bird cap; present it as an offer, never a reward counter.
- Account endpoints cover preferences, device sessions/revocation, on-demand JSON export delivered through a verified-email download link, deletion request/recovery in the 30-day soft-delete period, and privacy policy access. At hard deletion, purge account-linked simulation, notebook, invite, session, event and telemetry linkage per retention requirements.
- Host invitation endpoints create/send an invite for a specifically entered email, list outstanding invites and visit log, and revoke an invite. Store token digests, use unguessable single-invite capabilities, rate-limit sends, and avoid enumerable public IDs. Visitor snapshot endpoint validates capability and returns the exact live host scene in read-only form; all mutating routes reject visitor credentials. Check revocation on every snapshot pull; return the same unavailable response for revoked/expired links. Record approximate visit duration without treating it as presence. Default visit notifications off; if enabled, use only the stated setting and do not create push infrastructure in v1.

Use optimistic revision checks for ordinary account/settings edits where needed, but never resolve simulation writes by client last-write-wins. Concurrent client events are both appended and serialized by server sequence; the worker applies them once in order. A snapshot is an observation of canonical state and can safely be refreshed after a conflict.

## 5. Simulation and content engine

The scheduler finds aviaries with due ticks and locks each aviary or uses compare-and-swap on its canonical revision. For each tick, in a single transaction: consume events after the saved cursor in server sequence; close/accrue only qualified host presence intervals; compute normalized input summaries over a bounded recent window; apply small trait deltas to existing values with upper bounds and no negative movement; transition mood from current state, local time, recent interactions, ambient events and personality; advance weather/day-night timers and bird-to-bird effects; generate any eligible observation candidate; persist state, cursor, revision, and outbox work. A retry with the same cursor and tick ID must not apply twice. Alert if tick p99 exceeds five seconds.

Calibrate drift with synthetic controlled schedules: measurable in instrumentation after about one week of regular presence, but no visibly attributable session-sized jump; a user can feel the accumulated change after about three weeks. Presence dominates; listen-in weights the focused bird's social warmth and vocal frequency; accepted offers slightly affect curiosity and offering near a bird slightly affects boldness; settle ends presence and quiets mood without trait direction. No negative drift on absence. Mood is persisted across sessions and evolves while clients are disconnected. Mood may use time-of-day and rare weather without creating distress or a care obligation.

Represent calls with a compact grammar/motif library and deterministic per-bird seed plus fresh event variation. Preserve recognizable signature across mood and drift; personality and mood influence timing, pitch and motif selection, not identity. Generate a call event/timing descriptor in the snapshot. The client synthesizes audio locally; it does not download or loop recordings. Generate caption prose from the same grammar decision that synthesizes the call, so the caption always describes the sound rendered. Generate notebook prose from typed observations using constrained templates and state facts; keep prose specific, lowercase, present tense, and sparse. Avoid claims unsupported by stored event history and exclude user attendance frequency.

Birds choose among the three perch zones from mood/personality and scene constraints. For a new aviary, server selects two species from a coherent pool of roughly six and seeds distinct but stable identities; user names them. New bird availability follows elapsed aviary age only, up to seven. Preserve identity and vector values through migrations and catalog changes.

## 6. Client rendering, session flow, and audio

Build the scene as a single responsive horizontal composition with foreground, bird/perch plane and soft foliage/sky background. Keep all birds visible at all viewport sizes; no pan, zoom, or scene scrolling. Keep interactive chrome only in the thin top bar. Render directly from a snapshot into already-progressing poses with a small deterministic phase offset—no entry animation or spinner. A genuinely cold/offline state uses a quiet sky field, then presents adoption's brief empty aviary and a soft initial arrival. On return, choose one greeter based on boldness, mood and absence length and procedurally vary the glance/call/approach; stagger any other greeting rather than trigger a chorus on cue. Never display textual welcome or absence-length message.

Drive scene transitions from canonical state and local interpolation. Client may interpolate positions and micro-motion, but not invent persistent outcomes. Idle motion remains active while visible and is mood-shaped: scanning and rear perch for wary, preening for content, head tilt for curious, low fluffed pose for drowsy. Use small bounded animation sets and reuse objects. Leaves/feathers and subtle parallax are client-only ornaments, not simulation entities. Day/night follows user's local timezone; ambient rain/wind is rare and affects mood/calls lightly. Settle triggers a slow evening/call quieting transition; any aviary click within five seconds reverses it. Closing the tab and settle both end presence. Hidden tabs stop rendering; server ticks continue.

Listen-in is a client mix state submitted as begin/end events. Ramp focused bird up and others down over a gentle interval; others remain audible. Disengage on second click, another focus, empty-scene click or keyboard focus departure. For offers, top-bar flow chooses seed/song fragment/still pool and a receiving bird; server enforces a few-minute per-bird cooldown and returns the reaction event/state. Reactions vary by mood/curiosity and preserve that the offer is a gesture, not nutrition.

The audio graph uses one bounded AudioContext, reusable oscillators/noise/envelopes, per-bird gain nodes and a master ambience bus. Synthesize each call from compact motif parameters with slight timing/pitch variation; smoothly ramp gains for listen-in and settle, duck ambient sounds gently, and avoid clipping as birds chorus. Reuse/stop nodes and buffers after each call; cap voices and workers. Respect browser audio activation/permission. If WebAudio is unavailable or denied, render in silence with captions enabled by default—never substitute recordings.

## 7. Accessibility and product voice

Ship accessibility surfaces with v1. Screen-reader users get one coherent live narration region generated from the same snapshot as the scene, in lowercase naturalist prose; idle cadence is 30–60 seconds, with user-initiated greeting, offer reaction and settle updates prioritized without flooding the queue. Do not expose trait values or announce raw state lists. Keep controls semantic and named, provide a useful scene summary, and ensure focus movement does not create duplicate speech.

Honor `prefers-reduced-motion` and an explicit setting. Replace frame motion with slow cross-fades among still poses, replace flights with perch cross-fades, remove drifting leaves, and slow ambient color changes. Continue mood, calls and notebook behavior. Captions are optional user preference and on by default when audio fallback is active; place short grammar-derived prose near the caller and ensure it remains legible. All copy, captions and visible narration meet WCAG AA contrast. Keyboard order: top bar, scene entry, arrow-key movement between birds, Enter listen-in, Escape disengage, keyboard-accessible offer flow and settle. Keep visible high-contrast focus. Product scene/notebook uses naturalist voice; sign-in, settings, accessibility settings, sync and error surfaces use direct matter-of-fact copy.

## 8. Security, privacy, sync, and lifecycle

Encrypt email fields at rest and restrict decryption to account/mail use. Use synthetic UUIDs in logs, telemetry and service boundaries. Hash magic-link/session/invite tokens at rest; make magic links one-use and 15-minute, session tokens revocable, invite tokens single-invite scoped and expiring after 30 unused days. Rate-limit authentication and invitation sends. Protect snapshots against cross-account IDOR and visitor token escalation. Visitor scope is read-only, checks revocation at next pull, never receives host controls/notebook unless explicitly required (default: scene only), and never generates host presence, drift or interaction events.

The server is canonical across devices. Each client reads the same revision; event writes are append-only and ordered server-side. If requests overlap or retry, idempotency keys prevent duplicate events; tick cursor and transactional updates prevent lost or repeated deltas. Avoid client absolute writes and last-write-wins for any personality/mood field. On reload after stale state, fetch snapshot and interpolate from current local frame without exposing a conflict dialogue unless the account/session truly cannot continue. Keep account-level errors clear and matter-of-fact.

Keep interaction event history in the simulation boundary only as long as needed for tick, notebook provenance and user's operation; establish a retention schedule as an implementation decision before launch. Operational analytics receives aggregate request counts, latency, anonymized duration histograms, frame timings and audio errors only; no per-account dimension, bird ID, mood, offer, presence interval, or personality field. Account deletion is soft for 30 days and recoverable; then hard-delete all account-linked records including events, notebook, vectors, exports, sessions, invitations, visit log and telemetry linkage. Export contains birds, names, vectors, moods, notebook and settings, generated on demand and delivered by verified-email download link.

## 9. Performance, observability, and release gates

Treat these as launch requirements: initial JavaScript below 2 MB gzipped; first bird visible under 500 ms on mid-tier mobile over 4G; 60 fps idle motion on a five-year-old mid-range laptop; no client memory growth over a 30-minute session. Keep first scene payload kilobytes, inline/edge-cache its minimum state, draw before noncritical assets, create compact SVG/procedural art and split settings/social code. Prewarm only bounded resources needed for immediate calls. Bound audio contexts, worker count, call voices, snapshot payloads and notebook DOM retention.

Run scheduled synthetic browsers from common geographies and aggregate-only RUM. Record page-load and first-bird times, frame timing percentiles, audio-context failures, API errors, snapshot/tick latency, and tick p99 alert at five seconds. No telemetry keyed by account and no state reconstruction. Track launch performance against device/browser matrix: last two major Chrome, Safari, Firefox, Edge. Unsupported older browsers receive a matter-of-fact explanation.

Before launch, make acceptance checks for canonical invariants (no trait decrease, no client trait writes, no visitor presence, idempotent tick replay), multi-device concurrent event processing, invite expiry/revocation, hard deletion, same call caption/audio grammar, keyboard operation, narration pacing, reduced motion, contrast, 30-minute memory, frame rate, bundle and first-bird budget. These are release gates rather than deferred polish.

## 10. Rollout and calibration

1. **Internal foundations:** establish schema/versioning, identity, immutable bird IDs, snapshot contract, event ingestion and server tick behind internal accounts. Populate a small two-bird aviary and verify continuity through sign-out/sign-in and two devices.
2. **Engine calibration cohort:** enable a limited internal/opt-in cohort with two birds. Review aggregate drift calibration and latency; use synthetic schedules for one-week measurable/three-week perceptible trajectories. Adjust versioned drift/mood parameters without exposing trait values or creating per-account analytics.
3. **Accessible beta:** ship narration, reduced motion, captions, keyboard paths and audio fallback together. Validate browser coverage and 30-minute performance before increasing traffic.
4. **Progressive public launch:** ramp account creation gradually while holding initial bird count at two. Enable age-based third-bird availability once stability and call recognizability are acceptable, then continue age pacing to a hard cap of seven. Availability depends only on aviary age. Social invites can launch opt-in after token scope, revocation, expiry and privacy checks are verified.
5. **Operational ownership:** define on-call for tick lag, snapshot errors and performance budgets; preserve aggregate-only telemetry. Review drift and audio quality through consented qualitative research or synthetic fixtures, not stored per-account relationship analytics. Roll back engine parameter versions or disable invitation creation if a release threatens canonical correctness or privacy.

## 11. Risks and mitigations

- **Drift is too fast or invisible:** monotonicity alone does not ensure the intended timescale. Version parameters; simulate week and three-week schedules; inspect only aggregate calibration outputs and user research. Keep per-session changes imperceptible and never surface numbers.
- **Presence is overcounted:** tab visibility/focus/activity semantics vary, and several devices can overlap. Require the three-signal conjunction, use short-lived server-validated pings without raw input capture, union qualifying intervals per account, and conservatively stop accrual on stale heartbeat/visibility loss. Calibrate the few-minute activity window without turning still watching into absence.
- **Lost or doubled drift during concurrent use:** retries, worker crashes, or two devices can reorder events. Enforce server sequence, idempotent event keys, transactional cursor/revision commits, and single-writer worker locking; never use client vector writes.
- **Mood or weather feels punitive:** avoid distress states and negative trait movement; cap weather frequency/intensity and ensure absence leads to quieter ambience only. Validate late return after two weeks as calm, not guilt-inducing.
- **Calls sound synthetic or lose identity:** procedural variety can become uncanny and signatures can blur as birds increase. Keep species motif families distinct, constrain pitch/timing drift, tune chorus headroom and limit to seven; ramp additional birds only after recognizability review. WebAudio failure remains graceful silence plus captions.
- **Accessibility narration overwhelms or flattens the scene:** use slow cadence, event prioritization and prose templates grounded in scene facts; review with screen-reader users. Reduced-motion is a designed pose/cross-fade system and must not degrade to a frozen scene.
- **Initial scene misses the first-bird budget:** keep state and code small, render from edge-delivered snapshot, defer noncritical UI, and monitor synthetic mobile runs; quiet sky field is a graceful slow-network state, never a spinner.
- **Privacy leaks through observability or visits:** enforce UUID-only identifiers and schema-level telemetry allowlists, isolate simulation store from analytics, audit visitor read-only scopes and revocation, and test deletion cascades including backups/exports according to retention policy.
- **Content becomes generic or gamified:** keep notebook sparse and observation-focused, reject engagement counters/notifications, and review copy against the two voice registers. Do not add public discovery or social comparison as a growth shortcut.
