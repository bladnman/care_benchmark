# Pocket Aviary — v1 implementation plan

## 1. Delivery contract and scope

Build a browser-based, single-account aviary that feels continuous across visits and devices. Launch with two server-selected starter birds, six coherent species, a single responsive horizontal scene, magic-link authentication, canonical server simulation, the three offers, listen-in, settle, a sparse permanent field notebook, optional private visits, account lifecycle controls, and all accessibility surfaces. Birds have permanent identities; personality changes slowly and only upward. No client can overwrite personality. Mood, timing, weather and perch state continue when no browser is connected.

The ceiling is seven birds, including starters. Additional adoption is optional and based exclusively on aviary age. Initial schedule: one opportunity at 90, 180, 270, 365 and 540 days. Opportunities remain available until accepted; do not send emails, add badges, count birds visibly, or display an unlock countdown. Show one quiet adoption option within account/bird settings, with a server-selected species and suggested name. Accepting it does not discard an existing bird. Rate and dates are versioned configuration; a later rollout cannot revoke an opportunity already earned by age. Six birds at one year and seven later is consistent with the brief's approximate pacing.

Explicit exclusions: payments, native clients, passwords, SSO, multi-aviary or shared accounts, customizable scenes, user-controlled placement, recorded calls, notifications about absence, hunger, distress, death, quests, points, scores, levels, streaks, visit-frequency surfaces, public discovery, follows, comments, rankings and co-presence. Do not build dormant metrics or schemas supporting rankings. No arbitrary regeneration or replacement of birds during releases.

Product text uses lowercase, present-tense, particular observations. Identity, errors, privacy, sync and accessibility settings use direct standard English. No welcome text, toast, congratulations, loading spinner or notification badge. Test copy and behavior as product requirements rather than leaving them to polishing.

### Decisions where requirements overlap

- **Export and hidden vectors:** `concepts.md` wins on vocabulary and explicitly forbids numerical trait exposure, while account export includes current vectors. Export bird names, mood, notebook and settings as ordinary JSON; include the exact current vector as a versioned opaque encrypted payload, not numeric JSON fields or a debug surface. Encrypt with an export-specific key wrapped by the service's export key, retain format documentation for internal preservation, and include a checksum. The user can keep the complete state artifact without a trait dashboard. This is a deliberate reconciliation, with the limitation that vectors are not human-readable or independently usable; revisit this conflict with product before changing the contract. No import UI in v1.
- **Visit notification exception:** implement the explicit social-settings opt-in, default off, as a quiet on-demand account-settings activity line for a newly recorded visit. No push, email or toast; the permanent visit log still exists independently. The toggle controls the extra activity line, without a badge. This fulfills an in-product notification narrowly while retaining the global no-ping posture; do not broaden it into an engagement loop.
- **Top bar:** retain exactly account/settings, accessibility, notebook and offer icons. The offer icon opens a small action panel with offers and a separated settle control, keeping settle reachable from the top bar without adding a fifth icon. Settings contain naming, additional adoption, sessions, invitations, export and deletion.
- **Captions and focus:** permitted accessibility text near calls and a keyboard focus outline are exceptions to the no-inline-chrome scene rule. Never add mood labels, hover tooltips or permanent bird name tags.
- **Timezone:** one persisted account IANA timezone drives canonical day/night and mood. Initialize from the first browser, editable in settings. A second device does not silently change it; visits use the host timezone. This avoids simultaneous clients requesting incompatible mornings.

## 2. System shape and ownership

Use a TypeScript web application and service, PostgreSQL for all durable canonical state, a durable job queue, a scheduler and transactional email delivery. Keep API and simulation code in one deployable service initially, with a separate worker process using the same versioned domain library. Avoid a stream platform or client-to-client synchronization. PostgreSQL transactions provide the main correctness boundary; queue delivery may repeat without repeating effects.

Serve the small scene shell, critical bird vectors and styles with the initial HTML. Use Canvas2D for scene composition and compact procedural/SVG-derived bird geometry; maintain a separate semantic DOM for focus, narration and controls. Offload pure geometry preparation if profiling requires it, not essential rendering. Lazy-load settings, notebook history and invitation management. Client packages cannot import simulation persistence code or receive hidden trait values. A versioned behavior projection turns traits into bounded pose/call parameters; it is descriptive rendering input, never a writable trait object.

The API handles authentication, snapshots and event acceptance. The simulation worker is the sole role authorized to update personality and canonical mood. Administrative migration tooling has narrowly audited migration rights, never a general reset endpoint. Account and naming handlers may update their own columns under the same aviary lock, but cannot mutate vector columns. A separate rendering planner publishes server-authored action descriptors following accepted gestures; fast reactions do not wait a full minute for the next tick. Such descriptors use the latest canonical mood/personality, affect visible response immediately, and become mood/drift inputs only at the next tick.

Render-only client work includes interpolation, procedural synthesis from supplied grammars, captions from actual call descriptors, slow pose motion, leaves/feathers and subtle parallax. These are not simulation ticks. The browser never chooses a mood, applies a trait delta or advances a durable event cursor. Ornamental randomness does not become canonical bird history.

### Deployment and initial state path

Deploy static assets at the edge; route authenticated HTML to a nearby service/edge handler that obtains a compact canonical snapshot. Embed that snapshot in an escaped JSON script in the private HTML response. Set `Cache-Control: private, no-store` on all authenticated HTML/state/export responses and prohibit shared CDN caching of private snapshots. Only immutable public assets are shared-cacheable. This uses the edge delivery path requested by the PRD without exposing one account's birds to another.

Maintain a small versioned render snapshot alongside canonical rows in the same transaction. Reads do not reconstruct personality from events. The initial render requires no settings code, audio permission, external font or bitmap download. If state is late, draw a quiet sky field with subtle cues; do not invent placeholder birds. Adoption alone permits the empty field followed by soft fly-in. Established accounts begin at a sampled in-progress action phase, without an entry animation.

Use UUID primary keys and UTC timestamps; use account UUIDs for references, jobs, logs and partition keys. Store email only as encrypted contact data, never a service identifier. No raw email in URL query strings, logs, traces or analytics.

Vectors are stored values in `[0,1]`, initialized in a species-specific middle range with seeded individuality. Persist them directly along with filter memory; events can be compacted without affecting identity. Keep event sequences per aviary, allocated under row lock; UUID idempotency is unique per account/session submission domain. Snapshot revision increases on each published canonical change and is independent from the event cursor.

Back up encrypted database state and test point-in-time restoration. Migrations must preserve bird IDs, traits, accumulators, notebook entries and call identity. Never fill missing vectors with seeds on read; quarantine corrupt state and alert through technical errors. Verify checksums and migration fixtures before deployment.

## 4. APIs and security contracts

All owner routes enforce a live device session, account ownership, deletion status and CSRF protection. Use HTTPS, Secure/HttpOnly/SameSite cookies, origin checks and CSP. Validate names as bounded Unicode text, escape all output, and prohibit user HTML. Requests receive opaque error codes plus direct user copy; redact bodies and credentials from tracing.

| Route | Contract |
| --- | --- |
| `POST /auth/magic-links` | Generic response regardless of address existence; send one-use 128-bit-or-better random link, valid 15 minutes. Per-address blind-index throttle (initial 5 per 15 minutes), plus bounded IP abuse limiting. Permit retries after the window. |
| `POST /auth/consume` | Atomically consume unused, unexpired challenge and issue browser session. Link landing page requires explicit consumption so email scanners cannot use GET to consume it. Replay fails cleanly. |
| `GET /api/aviary` | Snapshot with revision, server time, next pull hint, current bird identities/names/species, mood, perches, timed action/call descriptors, weather, lighting and render parameters. No trait values, attention totals or visitor identities. ETag support for repeat pulls. |
| `POST /api/interactions` | Bounded batch of `{event_id, session_sequence, type, bird_id?, client_time?, payload}`. Return per-event accepted/duplicate/rejected status, canonical revision, server acceptance times and response descriptors if applicable. Absolute personality or arbitrary mood payloads are rejected. |
| `GET /api/notebook?before=...` | Stable keyset pages of oldest-to-newest entries within a returned page; all history remains accessible. No mutation endpoint. |
| `POST /api/adoption/start` | Idempotently create the two stable starter birds, server-select species, accept names/defaults and publish the initial scene. Repeated navigation cannot duplicate birds. |
| `PATCH /api/birds/:id/name` | Version-checked rename, no identity or behavioral changes. |
| `POST /api/adoption/opportunities/:id/accept` | Lock aviary, verify age and cap, consume opportunity once; return the new bird's stable identity and entrance descriptor. |
| `GET/PATCH /api/settings` | Version-checked timezone, audio/accessibility and narrowly scoped visit-notification preferences. A stale patch returns 409 with current settings; no silent whole-record overwrite. |
| `GET /api/sessions`, `DELETE /api/sessions/:id` | Own session list and immediate revocation; revoke current session signs this browser out. |
| `POST /api/account/email-change`, `POST /auth/verify-email-change` | Verify new encrypted address via separate purpose-bound one-use challenge before atomic uniqueness-checked replacement; old address stays valid until then. |
| `POST /api/account/export` | Enqueue a transactionally consistent snapshot export and email a short-lived download link to verified contact. Explicit request permits this system email. |
| `POST /api/account/delete`, `POST /api/account/recover` | Soft-delete immediately for 30 days; recovery available on every signed-in deletion-state page. Suspend ordinary writes and simulation until recovered. |
| `POST /api/invitations` | Explicit named recipient creates a 30-day unused invite and sends the one-time link; no automatic invitations. |
| `GET /api/invitations`, `GET /api/visits` | Owner-only settings records, including outstanding invites and quiet log. |
| `DELETE /api/invitations/:id` | Revoke outstanding or active invitation atomically; no success toast. Stop its active sessions. |
| `POST /visit/consume` | Atomically exchange one-use invite secret for a separate read-only visit cookie; no account required. Expired/used/revoked link returns unavailable. |
| `GET /api/visit/aviary` | Check revocation every request; return same ambient scene projection and host time as owner, without notebook, settings, private attention/history, or interaction capabilities. |
| `POST /api/visit/keepalive`, `POST /api/visit/end` | Update approximate visit-log duration only; cannot submit simulation events or count presence. |

Initial device-session lifetime: 30 days absolute, adjustable after security review; list/revoke sessions in settings. Expired authentication stops event acceptance and shows sign-in guidance. Mutation routes never accept visit cookies even if the visitor knows a bird UUID. Enforce both routing and database ownership checks.

Active visits last at most 24 hours from link consumption, ending earlier on revocation or session close. An unused invitation expires after 30 days; consumed links cannot be reopened on another browser. An active visitor pulls at most every 10 seconds, so revocation is enforced at the next pull; discard the rendered host state when denied. Show the same unavailable surface for revoked/expired links. Maintain historical visit records, marking revoked access inactive rather than erasing transparency about past access; hide revoked outstanding access from the active list.

## 5. Simulation and calibration

### Tick transaction

Schedule every non-deleted aviary about once per minute, independent of connections. Partition due work by synthetic aviary UUID. For each job, lock the aviary, compare scheduled time with `last_tick_at`, and ignore duplicate work. Read accepted events after the committed cursor in server sequence order. Apply all due time boundaries and events to mood/filter state, add nonnegative trait deltas to the existing vector, advance weather/action plans, consider notebook observations, then atomically commit bird rows, cursor, revision, rendered snapshot and transactional outbox messages. Queue acknowledgment follows commit. Crash before commit changes nothing; crash after commit produces a harmless duplicate.

Do not let event producers take a separate lock ordering from tick workers. Limit transaction size through small event batches and authenticated rate limits. Reject spam before it enters the log. For outages, replay elapsed minute steps with original historical timestamps, not the returning browser's present time. Process bounded catch-up chunks with a stored cursor; no fabricated presence while offline and no skipped trait changes. A snapshot older than the freshness limit may still render as stale with a system error available, while the server prioritizes catch-up. The API must not masquerade stale state as freshly simulated. Mood/day changes since the last displayed frame cross-fade smoothly after recovery.

### Presence validation and multi-device union

Start with a five-minute activity window. Presence is true only while document visibility is `visible`, window focus is true, and a pointermove or keypress was seen within that window. Observe trusted events locally; accessibility keyboard activity counts. Throttle movement observation, not elapsed attention. A pointer-only session without focus fails. Initial navigation alone does not count as activity. Greeting is independent from earning presence time.

Emit eligible interval chunks every 15 seconds, flush immediately on blur, hide, settle and recent-input expiry, and send a best-effort terminal beacon on close. Each chunk covers only observed elapsed eligibility, never future time. The server bounds duration by arrival spacing and session lifetime, rejects overlaps/replayed sequence numbers and implausibly late evidence, and allows a limited 30-second transport delay. A missing terminal beacon does not grant an entire grace lease: count only accepted completed intervals. Activity expires even if a page remains foreground indefinitely. Offline presence is not backfilled after long disconnection; preserving honest drift outweighs crediting unverifiable time.

Take the union of owner intervals across devices per aviary, rather than summing concurrent laptop and phone attention. Union listen-in intervals per bird and cap their weight. Simultaneous listen-in to different birds splits the per-aviary attention budget rather than doubling it. Offers have canonical per-bird cooldowns across devices. Settle ends that device's presence; it cannot make another focused owner device absent. Visits have an entirely separate session/event boundary.

### Positive-only low-pass drift

Version and persist a daily presence accumulator and per-bird listen/offer accumulators. Define a daily normalized attention signal `p = min(unioned_presence_minutes / 15, 1)`. The reference calibration session is 15 minutes of eligible attention daily. Derive listen and accepted-offer signals with daily caps; ensure combined secondary weight remains at most 25% of total influence, with presence at least 75%. Offers without accepted presence never become a cheap trait farming path; weight secondary signals within the bounded owner-attention envelope.

For each trait, integrate a stored low-pass signal with a roughly three-day time constant: `filtered += (1 - exp(-dt/tau)) * (input - filtered)`. This accumulator may decline during absence; the personality never does. Compute `delta = rate_trait * max(filtered, 0) * dt_days * (1 - trait)`, then `trait_new = min(1, trait_old + delta)`. Use server-authored additive deltas and apply once under the tick cursor. Listen-in primarily adds social warmth/vocal influence; approaching offers add small boldness, accepted offers small curiosity; presence supports all five. Settle contributes zero trait delta.

Start rates around 0.004–0.008 per day per fully weighted input, subject to species calibration. With seed traits around 0.35–0.60, the reference scenario should produce instrument-resolvable changes around 0.01 after seven days and noticeable mapped behavior/appearance shifts around 0.03–0.06 after 21 days. These are experimental gates, not promises of an exposed number. Apply caps so a single session causes no visible threshold crossing. Calibrate rendering sensitivity separately from numeric rates so plumage is gradual, not a level-up.

After absence, a bounded recent-attention envelope decays toward neutral/ambient, reducing greeting probability relative to a recently attended aviary. It does not reduce stored vocal-frequency, warmth or saturation and does not cause distress, mistrust or punitive mood. Residual filter memory can continue positive drift after leaving, as the PRD requires. Absence does not invent new input. Wary mood arises only from ordinary ambient/context events, never missed visits.

### Mood, social behavior and weather

Use five states: wary, content, curious, drowsy and alert. Each has minimum dwell time and probabilistic transition hazards influenced by current traits, recent validated gestures, time, gentle weather and bounded bird-to-bird responses. Refresh toward a local-day baseline over approximately 24 hours; never reset to neutral on navigation. Night strongly favors drowsy; a nightjar-like species retains low-key late calls. Rain temporarily quiets calls without altering permanent vocal traits; wind mildly shifts alertness. Persist the weather schedule, sampled at two or three short rain intervals per week plus occasional wind, so every browser sees the same weather. Use IANA time conversion to handle DST without duplicate daily resets.

Server behavior planning produces perch targets and durations, preen/scan/tilt/body-shuffle actions and call/response windows. Mood and boldness influence front/middle/back perch weights; reserve distinct collision-free slots. Chorus is emergent from overlapping calls with bounded response probabilities. Prevent recursive alarm/chorus cascades through refractory windows and a maximum social-response depth. Weather and bird interactions remain modest; no jump-scare alarm bursts.

### Greeting and offers at interactive latency

On owner visibility return or fresh navigation, submit a greeting request as an accepted interaction context. Use absence length derived from previous owner observation, boldness, warmth and current mood to pick one primary bird and construct an unrepeatable seeded gesture from continuous timing/pitch/pose variation. First response is a glance/tilt/approach or call within 1–2 seconds; a subsequent bird may answer with a randomized stagger, never a synchronized arrival chorus. Debounce focus/visibility flapping and concurrent opens (initial 10-second aviary greeting window). Visitors never request greetings. Greeting selection and seed are server-authored; a gesture is not a prerecorded rotating variant.

Offer API atomically reserves eligible receiving birds with a three-minute per-bird cooldown. A single aviary-level seed, song fragment or pool offer chooses a nearby eligible recipient/limited response group based on published scene positions; it is never a direct click-on-bird offer. Return a server-authored response plan immediately. Mood/curiosity influence investigate, wait or ignore; ignoring is valid. Song fragments come from a small synthesized motif library. Pool drink/bathe/watch and seed approach have bounded scene lifetimes. Accepted reactions and merely offering near a bird generate different small tick inputs. Competing offers on two devices cannot bypass cooldown. Avoid visible timers or punitive alerts; show a calm naturalist observation when no bird is ready for another gesture.

## 6. Synchronization and continuity

Pull on visible navigation, return from hidden, a render gap over two seconds, and every 15 seconds while an owner page is visible. Use revision/ETag and monotonic server timestamps to avoid out-of-order responses replacing newer state. A small offset estimate aligns render time with server descriptors; never rewrite the device clock. Visible visits use the stricter 10-second revocation pull.

Interaction retries reuse the same event UUID. If the response is lost, retry returns the original acceptance and descriptor, not a second offer. Server order arbitrates incompatible gestures. A bounded in-memory retry queue survives short network disruptions; do not persist a long offline event backlog that could manufacture retroactive mood or presence. Non-presence gestures can retry within 30 seconds; beyond that present the failure inline in system voice rather than replaying an old gesture on reconnection. Server-issued cooldown/reservation timestamps remain authoritative.

A newly accepted gesture may be represented locally by its acknowledged action descriptor ahead of the next snapshot. It cannot mutate canonical mood or trait state. Replace it when a matching/newer revision arrives; reconcile softly rather than teleporting. Names/settings use revision checks and clear conflict handling, distinct from additive simulation events. No client absolute state saves, no last-write-wins vector path and no client merge algorithm.

Settled lighting/mix is local presentation state for the initiating session plus a small canonical quieting input. Other devices retain the same mood/canonical scene and their own viewing gesture state. Settle remains until close or deliberate re-engagement; motion/presence signals alone do not undo it. Any scene click within five seconds cancels via a linked undo event and reverses lighting/mix; server ignores the still-unconsumed quieting signal or applies its bounded cancellation. Thereafter explicit action re-engages. Ordinary tab close ends eligibility without any missing-goodbye penalty.

## 7. Rendering and interaction surface

Compose sky/light and weather background, back foliage/perches, depth-sorted birds, middle/front perches, optional pool, occasional foreground ornament. Use a normalized coordinate system with safe margins and species-specific collision radii. Responsive layout remaps perch slots across viewport width, preserving silhouettes and all seven birds; reduce decorative complexity on small screens rather than cropping. Reserve top-bar height and device safe areas. At extreme narrow/short sizes, shrink the contained scene and provide usable semantic controls; the scene itself never pans, scrolls or zooms. Settings and notebook panels may scroll.

At first paint sample each server action at `server_now - action_start`; a bird begins halfway through preening if appropriate. Continuous low-frequency pose noise gives breathing and weight shifts without regular identical loops. Interpolate position transitions using bounded easing along paths that stay inside safe margins. Avoid animation bursts on catch-up. Ornaments are bounded pools sampled with a random initial age so the scene does not wait for its first leaf. Feather detail and saturation reflect gradual traits through published render parameters. Do not show numerical personality in text, accessibility metadata or developer controls shipped to users.

Stop `requestAnimationFrame`, ornament timers and audible scheduling when hidden. On resume fetch and sample the new plan; do not play every missed call or fly through missed perches. While visible but unfocused, rendering continues and presence stops. Fade top-bar icons nearly transparent after four seconds of pointer stillness; never fade while keyboard focus is within it, a panel is open or assistive navigation is active. Movement/key activity restores it. Hit targets remain at least 44 CSS pixels with accessible names.

Click/tap a bird starts listen-in; another click on it, empty-space click, another bird or keyboard focus leaving ends it. Use one shared focus/listen state controller. Tab enters a roving-tabindex bird group; arrows move among stable bird IDs. Keyboard focus brings that bird into the listening mix per interaction spec; Enter toggles it, Escape clears it, and moving away releases it. On name or layout updates retain logical focus by ID. Offer panel has an explicit keyboard shortcut documented in its accessible help, fully operable choices, and focus restoration. Notebook/settings panels trap focus only when modal and return focus on close. Naturalist labels such as “listen in on pip” describe actions without displaying stats.

### Reduced-motion renderer

Default to OS preference unless an explicit accessibility choice overrides it; support live preference changes. Replace continuous skeletal micro-motion with slow cross-fades among carefully designed still poses (initial 4–8-second fades, pose dwell tens of seconds). Flights cross-fade between perches without traversing the scene; remove leaf drift and parallax. Day/evening shifts remain slower than standard mode. Greetings retain distinct quiet poses and calls. Keep focus, caption quality and timing unchanged. This is a separate art/QA deliverable with its own aliveness review, not a blanket animation-disable CSS switch.

## 8. Procedural audio and matching captions

Each species defines a small grammar of motif shapes, oscillator/noise timbres, envelopes, pitch contours, rests and bounded variation. Every bird adds a persistent signature seed giving recognizable interval/timbre tendencies. Grammar versions retain those signature anchors across updates. Personality affects call spacing, response probability and limited expressiveness; mood varies intensity and phrase shape inside a recognizable identity envelope. Avoid species-wide identical sound.

Server snapshots publish timed call windows, bounded grammar parameters and seeds. The browser materializes a call descriptor containing exact motifs, pitch contours, envelopes, source bird and caption facts. One descriptor drives synthesis, visual calling pose and caption text, so captions describe the actual procedural phrase. Schedule a short rolling horizon against `AudioContext.currentTime`; cancel/resample on large gaps. The server owns behavioral calling windows and social response plans; audio scheduling is a presentation layer.

Start with reusable WebAudio oscillator/filter/gain nodes or short-lived voices returned to a bounded pool; cap simultaneous voices and total gain for seven birds. Use gentle headroom, equal-power spatial balance, soft limiting and no repetitive recorded loop. Reuse generated noise/buffers and release completed graph connections. An AudioWorklet is optional only if profiling finds main-thread scheduling glitches; ship a bounded WebAudio node path first to minimize support risk.

Listen-in uses gain automation over roughly 1.5–2 seconds, with the focused bird modestly raised and others down to a nonzero ambient floor. Switching or ending cancels/reschedules ramps continuously from current gain, never hard cuts. Record listen start/end intervals even when audio is muted; they represent deliberate attention, not proof of hearing. Mute controls actual sound without negative drift. Settle softly quiets all calls over several seconds, without permanently silencing birds.

Browser autoplay rules can prevent calls on initial navigation. Render birds and call captions immediately, attempt audio only when permitted, and unlock/resume on a normal user gesture or accessible audio control in accessibility settings. No permission modal, audio nag or synthetic startup sound. If WebAudio is absent, denied or fails, continue in silence with captions enabled by default and a clear setting status. Never substitute recorded audio. A transient suspended context may retry on deliberate gesture; bound retries and avoid repeated errors. Audio errors do not prevent offering, notebook or mood rendering.

## 9. Narration, notebook and access quality

Build a shared curated observation library from semantic scene facts, not an LLM service. Templates support named birds, time/light, poses, perches, weather and call descriptors with grammar-safe variation. Voice review checks specificity, present tense, lowercase and no announcements or behavioral surveillance. No “mood: content,” “perch 2,” trait changes, visit streaks or generic “a bird greeted you.”

Narration uses the same rendered snapshot/acknowledged gesture facts as the scene. Maintain a polite atomic live region with roughly one prose update every 45 seconds at idle, within the 30–60-second target. Replace obsolete queued observations rather than accumulating them. A greeting, offer response or settle observation receives prompt priority but still calm prose and a bounded queue. Silence narration when hidden or visiting a separate panel; offer replay/current-scene narration through accessible settings. Do not populate hundreds of constantly changing ARIA labels. Birds have stable actionable labels by name/species, with naturalist scene prose providing changing context.

Captions are optional small prose near the calling bird, generated from descriptors even when synthesis is unavailable. Use an opaque enough quiet backing and tested contrasting text in every day/night/weather palette. Place within safe bounds without covering another bird, cap simultaneous visual captions and merge a chorus description when necessary. Cross-fade text gently; reduced motion avoids drifting labels. Captions need not independently flood a live region; narration integrates meaningful call observations. Keep call metadata available to narration even when audio is disabled.

Notebook generation occurs in the tick from sparse candidates such as changed greeter ordering, sustained unusual perch behavior, a notable pool reaction or quiet weather observation. Maintain within-aviary context for true claims like “first time this week,” referring to birds, not attendance. Baseline one entry per two to four days; noteworthy events may add an entry, with initial maximum one per day and a seven-day rolling cap of three. Store final specific prose and bird IDs, not just raw log events. No user-facing counts of entries or adoption milestones. Do not rewrite old observations after renames or template changes. Keyset pagination and a bounded rendered window allow indefinite history without retaining every DOM node.

Keyboard/screen-reader reviewers validate the complete adoption-to-offer-to-notebook-to-settings journey. Meet WCAG AA for all copy, errors, focus outlines and captions at brightest/dimmest lighting. Focus outlines remain visible independent of top-bar fading; icon labels are available to assistive technology. Modal headings and errors use system voice where appropriate. Use actual VoiceOver and NVDA testing in addition to automated audits. Reduced-motion users and audio-off users participate in quality review before launch.

## 10. Privacy, retention and account operations

Keep simulation rows and events in a service-owned database that operational analytics cannot query. Telemetry SDKs receive only an allowlisted metric schema; no bird IDs, names, vectors, grammar seeds, event payloads, offer/listen counts or per-account interaction series. Disable request body logging, query/credential capture, session replay and screenshot capture. Account UUID may identify narrowly scoped technical errors for support, with bounded retention, but never becomes an aggregate behavioral dimension. No telemetry warehouse or training system is granted simulation access.

Retain raw consumed interaction/presence events for 30 days for bounded correctness repair, then remove after verifying the committed cursor and persisted accumulators. Do not reconstruct vectors from history on normal reads or recovery. Retain notebook indefinitely while the account exists. Visit logs and encrypted contact data remain owner-visible until account deletion, with minimization of transient invite delivery data. Email provider delivery receives the contact and necessary transaction only; never bird state, notebook prose or offer events. No behavioral recommendation or model-training pipeline.

Export captures all specified data at one revision under a consistent database snapshot, including opaque vector preservation described above. Encrypt export objects at rest, deliver an authenticated/high-entropy one-use link expiring in 24 hours, and delete the object after expiry. No public object URLs or cacheable attachment endpoints. Account deletion cancels export jobs and invalidates links, device sessions and invitations immediately. Soft-deleted accounts can authenticate only into the recovery/deletion surface; recovery restores original IDs and vectors.

At 30 days a deletion worker transactionally removes account-owned birds, events, intervals, notebook, invitations/visits, sessions, exports and support telemetry records. Use foreign-key cascades with a tested inventory of non-database objects. Per-account envelope encryption allows destroyed keys to render retained backup ciphertext unreadable; store hard-delete tombstones outside restorable account data to reapply deletion after disaster restoration. Rotate backups within a bounded 30-day lifecycle. Aggregate irreversible operational histograms have no account dimension and cannot recover a relationship. Verify full purge in a staging account lifecycle test, including queued mail and object-store cleanup.

## 11. Performance budgets and observability

Treat the 500ms first-bird target as the end-to-end navigation metric, including state fetch and first paint, on an agreed mid-tier phone over a fixed 4G profile. Measure warm returning authenticated navigation and cold authenticated navigation separately; report both, never hide a cold failure behind a cache average. Sign-in and first adoption are distinct flows but must remain responsive. Initial engineering allocation: edge/private snapshot delivery about 150ms, critical asset delivery/parse about 150ms, first draw about 50ms, with remaining margin. Slow-network field is graceful handling, not permission to miss the budget.

Set a stricter working target of under 300KB gzipped critical JS, with a hard CI failure at the PRD's 2MB gzipped initial limit. Initial HTML/embedded state goal under 30KB compressed; snapshot target 5–20KB at seven birds. Inline compact initial geometry and reuse cached assets. Defer notebook/settings/adoption management, load no recorded audio and use system fonts. Track actual transfer size as well as JS cap.

On a five-year-old mid-range laptop, sustain 60fps for a 30-minute seven-bird session. Budget scene work below 8ms on p95 frames and avoid recurring frames over 16.7ms. Profile rain, chorus, caption, resizing and panel use. Bound all ornaments, pending actions, audio voices and queued narration. Visibility pause prevents battery waste; a visible slow device can lower decorative detail while retaining mood, bird identity, poses and calls.

Define “no memory growth” as a flat post-warmup baseline after GC rather than literally identical raw heap samples. In automated 30-minute scenarios, sample heap and audio-node counts after periodic GC; fail on a sustained positive retained-memory slope or over 5MB retained growth after warmup. Run a separate realistic non-forced-GC browser soak to catch pauses. Repeated notebook scrolling, listen switches, resize, hidden/resume and audio failures must not grow retained objects. Reuse pools and disconnect/release audio nodes, observers and workers at teardown.

Operational metrics: route request counts/latency/errors, tick compute latency and queue lag, oldest unpublished snapshot age without account dimensions, job retry/deadletter counts, first-bird timing histograms, frame timing, bounded memory checks, audio-context failure categories, anonymized session-duration histograms. Do not emit per-bird drift measurements from real accounts. Tick p99 over five seconds pages the operator; also alarm on missed due ticks/lag because a fast job can still sit in a slow queue. Target schedule freshness within 75 seconds normally and operational availability at least 99.9% initially.

Use scheduled synthetic browsers from common geographies and aggregate-only RUM with stripped identifiers/URLs. Privacy-check each metric schema and restrict dimensions to browser family/version, coarse device class, region and deployment version. Use generated synthetic aviaries to measure drift, mood and recognizability; do not aggregate real users' relationships for calibration. Support diagnostics require explicit narrowly scoped access, audit and no collection into product analytics.

## 12. Implementation sequence and acceptance gates

1. **Contracts and quality prototype.** Define snapshot/events/projection schemas, invariant tests, six species silhouettes/signatures, voice library and both motion styles. Build a disposable isolated rendering/audio prototype using synthetic state, not production product implementation here. Establish mid-tier phone/4G and laptop fixtures. Gate on two distinguishable calls, mid-action first frame, calm motion, and convincing reduced-motion/narrated equivalents. Finalize palette contrast tokens with the designer; none of the unavailable separate design-system documentation is presumed read.
2. **Durable canonical core.** Implement account/aviary/bird records, minute scheduler, transaction locking, event idempotency, persistent drift/filter and mood, backup/restore and migrations. Run simulated 7/21/90-day timelines, no-client days, DST transitions, crashes/retries and simultaneous devices. Gate on no negative traits, no resets, no duplicate delta, exact owner-presence union and no visitor simulation influence.
3. **Owner vertical slice.** Add magic links, two-bird adoption/naming, initial HTML snapshot, in-progress scene, greeting, client pull/reconcile and procedural audio. Test link replay/expiry, scanner landing, focus/visibility flapping, suspended laptops and stale snapshots. Gate on cold and returning first-bird performance and primary greeting latency under normal supported conditions.
4. **Complete quiet interactions and access.** Add offer reservation/reactions, mix ramps, settle/undo, notebook generation/history, semantic bird controls, captions and narration. Integrate reduced-motion mode from this milestone onward, not afterward. Gate on browser autoplay silence path, keyboard journey, actual screen-reader reviews and sparse specific notebook prose.
5. **Lifecycle and optional visits.** Add email change, session revocation, export, deletion/recovery/purge, age-based adoption, invitation consumption/revocation and visit logs. Attempt owner writes with visitor credentials and test immediate denial on next snapshot. Gate on privacy schema tests, full hard deletion and encrypted-backup restoration preserving deletions.
6. **Launch qualification.** Last two major Chrome/Safari/Firefox/Edge releases, representative phones/desktops, 30-minute memory/frame soak, seven-bird rain/chorus and assistive reviews. Unsupported browsers receive clear system guidance; WebAudio absence is supported through captions, not classified as unsupported. Conduct synthetic load with continuous ticks for disconnected accounts and injected queue/database failures.

Roll out to staff synthetic accounts, then a small consented real-user beta, then staged 5%, 25% and full signup availability once technical and qualitative gates pass. Every cohort gets two starters and every accessibility feature. Feature flags control admission and presentation assets, never erase identity or recalculate personality. Begin internal qualification at two birds, then four and seven through synthetic aged aviaries before public launch. Release age-based invitations at their specified dates; don't force users to adopt more birds and don't lower the seven cap to conceal a performance problem.

Use synthetic timeline acceleration to verify months/year adoption before those ages occur in real life. Calibration human studies use dedicated synthetic birds and explicit observations of call recognition and week-three change, not hidden real-account aggregate analysis. Freeze an engine version for the beta, tune only between reviewed versions, and preserve existing state on migration. If quality fails, stop new enrollment or disable an unstable cosmetic renderer; continue canonical ticks, retain bird identities and offer system error guidance. A database rollback must not roll back accepted event effects; use forward-compatible migrations and forward fixes for state.

### Test inventory tied to failure modes

- Property tests: all traits remain bounded/nondecreasing; vectors survive arbitrary client retry/interleaving; no write path outside tick changes vectors; event cursor/delta publication is atomic; long absence has no negative trait or guilt behavior.
- Deterministic temporal tests: ordinary daily attention reaches week-one instrument/week-three perceptual ranges; background, visible-unfocused and stale-input cases each earn zero; overlap earns union time; mute is not punished; tab close and settle terminate eligibility equivalently.
- Integration fault tests: duplicate queue delivery, lost offer acknowledgment, concurrent cooldown/adoption, stale settings patch, worker crash at commit boundaries, backlog catch-up and expired/revoked auth.
- Security/privacy tests: owner isolation, invite credential isolation, no visitor greeting/listen/presence route, secret redaction, private snapshot cache headers, encrypted contact lookup, export revocation and purge inventory.
- Visual/audio reviews: first-frame sampled action, no offscreen birds across viewport classes, natural call variation with stable signatures, staggered greeting, nonzero ambient during listen-in, captions matching descriptor and no repeated canned recording.
- Access/performance suites: actual keyboard and screen-reader journeys, all palette contrasts, live-region rate bounds, OS motion changes, denied AudioContext, seven-bird 30-minute memory/frame checks and synthetic initial load across regions.

## 13. Risks and operating responses

| Risk | Prevention and response |
| --- | --- |
| Drift too fast, too slow or visually discontinuous | Synthetic reference trajectories, daily secondary caps, persisted slow filter, gradual projection mappings and week-three human comparison. Ship calibrated rates with engine version; never fix by resetting birds. |
| Cross-device doubled attention or overwritten character | Union validated intervals, sole vector writer, row locks, ordered cursor and idempotency. Compare transaction outcomes under generated interleavings. |
| Scheduler scale/outage undermines continuity | Partition due work, observe compute and queue lag separately, historical bounded catch-up, transactional publication and deadletter recovery. Do not move simulation to the browser as a shortcut. |
| Audio uncanny or identities indistinguishable | Six curated grammar families, stable per-bird anchors, bounded variation, chorus response limits and human recognition at seven birds. Tune before adding age-based opportunities publicly. |
| Accessibility becomes a state-list fallback | Shared semantic facts/voice, designed still-pose art, queue cadence, matching captions and assistive reviewers as launch gates. Protect focus and controls from fading. |
| 500ms target conflicts with private state and slow links | Compact embedded snapshot, private edge path, small critical code and explicit cold benchmarks. Quiet field fallback, with missed target reported honestly. |
| Migration silently loses vector/identity | No reseeding reads, checked fixtures, versioned compatible projections, backup restoration and invariant audits against synthetic data. Quarantine damage; do not regenerate birds. |
| Privacy leaks through convenient instrumentation | Separate access roles, metric allowlist and telemetry schema tests; no session replay or simulation warehouse access. Inspect payloads in CI and restrict production support tooling. |
| Product gradually gains engagement mechanics | Review UI/copy against scope contract; tests reject welcome banners, counters, badges, absence notices and user-behavior notebook prose. No underlying ranking statistics. |
| Ambiguities in export/notification interpretation | Implement the narrow decisions documented above and retain their explicit limitations in release review; no numeric trait UI or outbound visit-notification channel added by default. |

V1 is ready only when the continuous two-bird encounter, week-scale persistence, seven-bird capacity, read-only privacy boundary and three equally designed access paths pass these gates together. Engineering completion does not substitute for the listening and observation reviews: aliveness is the central behavior being delivered.
