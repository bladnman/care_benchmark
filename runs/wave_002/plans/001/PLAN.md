# Pocket Aviary — v1 implementation plan

## 1. Product contract and decisions

Build one browser-based, private aviary per email magic-link account. Every account begins with two system-selected birds from a coherent pool of roughly six species. The owner names them and may rename them later. An aviary can grow to seven birds, with later adoption opportunities based only on its age. The main experience is a single responsive horizontal scene with three perch zones, procedural calls, mood-shaped motion, day/night light, rare weather, listen-in, three offers, settle, and a sparse read-only field notebook. Ship quiet, revocable, read-only visit invitations, account export/deletion, multi-device access, naturalist narration, reduced motion, and call captions in v1.

The product surface uses lowercase, present-tense, specific naturalist observations. Identity, errors, sync, and settings use plain system language. Bird greetings carry the welcome; no return toast, absence counter, status badge, metric panel, or visit prompt appears in the aviary. Never expose personality numbers in ordinary UI, including accessibility labels. Offers are gestures, not feeding; absence cannot harm or reset birds. No native client, second aviary, customizable scene, public discovery, shared simulation, chat, profiles, payments, ranks, achievements, streaks, scores, notifications about the aviary, or recorded-call fallback. The sole notification exception is an explicitly enabled email about visits, off by default.

The PRD leaves some operational choices open. Start with a four-minute pointer/key activity window, a 60-second tick, and a few-minute per-bird offer cooldown; tune them with synthetic and consented test accounts, not population analysis of private interaction histories. Use the owner's authoritative IANA time zone for the canonical day/night cycle. Initialize it from the browser at adoption and accept later changes from the most recently active owner device, with a 30-minute hysteresis to avoid devices in different zones oscillating; visitors never set it. Changes blend lighting gradually. Make settle reachable through a top-bar menu so the four-icon top bar remains sparse. A visit shows the same bird scene, mood, weather, and calls as the host, without the host's notebook or interaction controls.

## 2. System boundaries

Use a small authenticated web client, an HTTP/API application, a transactional database, a scheduled simulation worker, a transactional outbox/email worker, and a private object store for short-lived exports. Deploy the API and simulation close to the canonical database. An edge handler authenticates the owner session and serves a private HTML response containing a minimal, current scene projection and critical CSS/SVG. This is never a publicly cacheable account response. Lazy-load notebook, account, invitation, and settings code after the first scene. A tiny public asset CDN serves species silhouettes, compact decorative assets, and versioned client code only.

The database is the sole source of account, bird, and simulation truth. The simulation worker is the only writer of mood, position, call schedule, weather, notebook observations, and personality vectors. API handlers may append validated owner events, manage identity/invitations/settings, and read projections; they cannot set traits or mood. The client composes and interpolates the scene, synthesizes audio, and reports interaction/presence evidence; it never runs canonical ticks. Client-only leaves, feathers, subtle parallax, and focus/mix state have no persistent effect. Keep protocol types for canonical state, public scene projection, event payloads, and narration as separately versioned schemas; migrations preserve stable bird IDs and stored vectors.

Use a per-aviary monotonic `state_version` and immutable `tick_id`. The owner snapshot projection is small (target single-digit KB compressed); it includes bird ID/name/species, perch and pose/timing descriptors, current mood expression, call descriptors and seeds, ambient state, relevant transitions, server time, zone, and version. It omits numerical vectors, raw presence, private event history, and visitor addresses. A separate authenticated export endpoint is the only user-facing route that can disclose current numeric vectors, as required by account export; export does not add a stats UI. A visitor projection uses the same scene fields and excludes the host notebook and settings.

## 3. Persistent model and retention

| Record | Required fields and rules |
| --- | --- |
| `Account` | Synthetic UUID primary key; encrypted verified email in the identity vault; creation time, IANA zone, settings, deletion status/deadline. No email-derived keys, partitions, telemetry tags, or log identifiers. One-to-one aviary constraint. |
| `Session` | Opaque hashed token, account UUID, device label, issued/expiry/revoked times. Cookie is Secure, HttpOnly, SameSite; account settings can revoke a device. |
| `Aviary` | UUID/account UUID, creation time, canonical zone, tick clock/sequence, state version, weather/light descriptors, settle transition, current adoption opportunity, last owner presence end. |
| `Bird` | Immutable UUID and adoption time; species ID, editable name, initial trait seed and current persisted normalized vector (`boldness`, `social_warmth`, `vocal_frequency`, `plumage_saturation`, `curiosity`); mood and mood timer, perch/pose phase, stable motif identity/grammar version, call schedule seed, offer cooldown. Renames never replace ID or reset state. |
| `InteractionEvent` | UUID idempotency key, owner account/aviary UUID, server-assigned sequence and receive time, bounded client event time, owning session, type (`presence_start`, `presence_heartbeat`, `presence_end`, `listen_start/end`, `offer`, `settle`, `settle_undo`, `zone_change`), validated bird/offer data. Append only until processed and retained briefly for operational replay; never feed analytics. |
| `PresenceLease` | Per owner session, latest visibility/focus/activity evidence, lease expiry and qualified interval; tick computes the union of overlapping qualified intervals across owner devices. Visitor sessions have no such record. |
| `NotebookEntry` | Immutable UUID, aviary UUID, time, source state version, bounded naturalist prose, event category/deduplication key. Cursor pagination with no archive cutoff. |
| `Invitation` / `VisitSession` / `VisitLog` | Host UUID, opaque invite ID, encrypted recipient address in restricted PII storage, hashed one-use token, created/used/expiry/revoked times, revocable scoped visit grant, visit start/end and approximate duration. Logs surface recipient email only to the host. |
| `Outbox` | Transactional email jobs for magic links, invitations, optional visit emails, and export links. Redact tokens and addresses from general logs. |

Encrypt identity and invitation addresses at rest, limit PII-store access, and use UUIDs across the rest of the system. Invitation delivery necessarily holds a recipient address outside the account record; isolate it in the same restricted PII boundary rather than copying it into simulation/events/telemetry. Store hashed magic and invitation tokens, not reusable cleartext. Define event-log retention to cover retry/recovery (initially seven days after durable tick checkpoint); keep notebook and canonical state until account deletion. Export links expire and downloaded artifacts are automatically removed. At deletion request mark the account unavailable but recoverable for 30 days; after the deadline delete birds, vectors, events, notebook, sessions, invitations, visit records, exports, and account-linked operational records, including backups under a documented purge window. Restrict export and deletion to reauthenticated owners.

## 4. API and authorization

Use JSON over HTTPS, typed request/response schemas, CSRF protection for cookie-authenticated writes, rate limits, and owner/visit scopes checked on every request. Examples of routes (names may change together with the contract):

| Route | Contract |
| --- | --- |
| `POST /auth/magic-links`, `POST /auth/consume` | Request an email link; 15-minute expiry, atomic one-time consumption, per-email and IP limits, generic request response. Set a per-device session. Replay/expiry gets a direct system error. |
| `GET /v1/aviary` | Owner snapshot with `ETag=state_version`; `If-None-Match` may return 304. Include server time and interpolation anchors. Never return a trait number. |
| `POST /v1/events` | Accept a bounded batch of owner events with idempotency UUIDs. Validate ownership, bird ID, order, payload, cooldown and bounded timestamp skew; append with server sequence and return accepted sequence/individual rejection reasons. Retrying an ID returns its original result. No absolute personality/mood writes. |
| `GET /v1/notebook?cursor=...` | Stable newest-first pagination of immutable observations. |
| `GET/PATCH /v1/settings`, `GET/DELETE /v1/sessions/:id`, `POST /v1/email-change`, `POST /v1/export`, `POST /v1/deletion`, `POST /v1/recovery` | Account management. Mutations of settings/names use an expected revision and return a matter-of-fact 409 with current value on conflict; no client last-write-wins. Verify a new email before changing the account address. Export sends a short-lived link to the verified email. |
| `POST /v1/adoptions`, `PATCH /v1/birds/:id/name` | Claim a server-issued age opportunity transactionally, respecting seven-bird cap; rename by stable ID. No behavior changes on rename. |
| `POST /v1/invitations`, `GET /v1/invitations`, `DELETE /v1/invitations/:id`, `GET /v1/visits` | Host-only creation, listing, revocation, and quiet visit log. Unused invite expires after 30 days. |
| `POST /v1/visits/redeem`, `GET /v1/visits/aviary` | Atomically exchange one-use emailed token for a scoped visit session; subsequent pulls check grant status and return `410 visit no longer available` on revocation/expiry. Never expose owner event endpoints to visit credentials. |

The visitor's one-use link proves access to the addressed mailbox and creates a revocable, device-bound visit grant; the consumed URL cannot be redeemed again. An active grant remains usable until host revocation or its bounded session expiry; a new visit later needs a new invite. Pulls every ~15 seconds while visible bound revocation latency to the next pull. Visitor visit durations are approximate and logged silently. If the host enables visit email notifications in settings, send one email per completed visit from the outbox with rate limits; default is off, and there is never an in-aviary badge, push, or automatic invite. A revoked, expired, or consumed link gives the same matter-of-fact unavailable surface without leaking which case occurred.

## 5. Presence, event ordering, and simulation

The owner client has a single presence state machine. It qualifies only while `document.visibilityState === 'visible'`, `document.hasFocus()`, and a genuine `pointermove` or keyboard keypress occurred within the prior four minutes. Use Pointer Events and trusted keydown for modern browser keyboard events; ignore synthetic events. Recompute on visibility/focus/activity changes and a short timer; send start/heartbeat/end only on transitions plus a heartbeat about every 15 seconds. Settle immediately ends the current interval; undo within five seconds reverses the lighting and starts a new interval only if the three conditions qualify. Tab close and settle have identical drift accounting. An unavailable unload beacon is harmless because server leases expire. Never infer presence from an open tab, WebAudio playback, scroll position, visitor activity, or an offline client's later claim.

The server records bounded leases (initially 45 seconds) from live heartbeats, clamps times to receive time and permitted skew, and expires them if heartbeats stop. For simultaneous owner devices, merge interval unions before crediting presence, so one minute of overlapping laptop/phone attention is one minute. This is an honesty mechanism, not antifraud surveillance; store no pointer coordinates or keystrokes. A disconnected client may retry idempotent interaction events, but cannot backfill unverified hours of presence. Validate offer cooldown per bird on the server before event acceptance; UI also prevents repeated gestures for a few minutes without a punitive timer display.

A scheduler queues each aviary's due minute even with no connected clients. Partition due work by aviary UUID. A worker locks one aviary, loads its last checkpoint and next ordered event range, advances exactly one logical tick at a time, and atomically commits bird vectors/moods/world state, notebook entries, last processed sequence, tick ID, and version. Retries of a committed tick are no-ops. Process late or duplicated events by server sequence/idempotency, never by replacing a vector with a client snapshot. Catch-up after an outage uses bounded sequential ticks and deterministic seeds, preserving elapsed day/night and weather; alert on lag. Use row locking or compare-and-swap to prevent two workers from committing the same aviary tick. Every vector update is an additive server-authored nonnegative delta clamped to the normalized trait ceiling. Schema migrations preserve IDs/vectors, and backup/restore drills compare checksums so a reset cannot be hidden by a visually plausible bird.

Implement drift as a slow low-pass signal per aviary/bird, not a click counter. For each minute, calculate credited presence duration plus lower-weight bird-specific listen-in and accepted offer signals. An exponentially weighted signal with a multi-day time constant feeds capped deltas such as `delta_i = rate_i * filtered_signal_i * (1 - trait_i) * dt`, subject to a daily maximum and `delta_i >= 0`. Presence affects all five expressive traits; listen-in adds modest weight to the focused bird's warmth/vocal frequency; an accepted offer adds a small curiosity contribution and proximity adds a smaller boldness contribution. Settle adds no drift. A decaying filter may carry prior attention through absence, but it cannot produce negative drift, and its tail is bounded. Keep initial values and rates in versioned server config; run deterministic 1-, 7-, 21-, and 42-day scenarios to tune a measurable week-one numeric change and a perceptible roughly three-week visual/audio difference, with no single session visibly shifting a trait. Run these on synthetic/consented accounts only. Never calculate population drift dashboards from private production events.

Mood is a separate persisted finite state (`wary`, `content`, `curious`, `drowsy`, `alert`) with dwell times and stochastic transitions from local time, recent accepted interactions, weather, neighboring bird calls, and each bird's vector. Define probability tables and bounded hysteresis so mood does not flap every minute. A daily-ish pull toward a time-appropriate baseline occurs in ticks, not on page open; there is no session-start reset. Absence can produce a quieter greeting/ambient expression through recent-presence context and local time, without lowering traits or showing distress. A nocturnal species can remain active at night. Perch selection weights boldness and mood across front/middle/back, reserves non-overlapping responsive slots, and transitions through a tick-authored movement descriptor. Rain/wind use sparse deterministic schedules (a few mild events a week), with short-lived mood/call effects.

The server schedules calls as descriptors: bird ID, grammar version, motif ID, deterministic variation seed, start/end, pitch/rhythm envelope, mood and position. Species libraries supply distinct motif shapes; immutable per-bird signature parameters survive mood and trait drift. A call can trigger another bird's response after a varied delay, and overlapping calls can form a chorus. Bound repetition, call density, and simultaneous voices to preserve recognizability through seven birds. The server stores current/upcoming descriptors so two devices consume one world timeline; the client synthesizes each descriptor and renders matching captions. Never store or download recorded call loops. The song-fragment offer chooses a small coded melodic motif from the library and bird reaction at the next tick; seed and still-pool reactions similarly follow mood/personality and are represented as state transitions, not canned clips.

Greeting is a separate arrival response assembled from current canonical bird state plus owner absence duration, not an entry animation that wakes the aviary. Select one primary bird with boldness/mood-weighted odds; short absence favors a glance, long absence may yield a head turn, approach, or longer call. Use a per-arrival seed so the same bird is recognizable but the timing/pose/motif varies. If another bird responds, stagger by a small randomized delay. Only owners trigger greetings. A returning tab pulls fresh state before selecting the response; visitors never affect greeting or mood. Notebook generation uses state-level observations (e.g., relative greeting order, quiet rain, perch choice), a rarity threshold, deduplication, and a roughly multi-day cooldown, with rare noteworthy exceptions. The prose engine is a reviewed grammar/template system with bounded variation and a voice lint pass; it writes bird/place observations, never statements about the user's visit frequency or numerical traits. Entries remain immutable, sparse, and scrollable indefinitely.

Adoption opportunities are computed from aviary age alone: begin with an opportunity around month three, then at approximately months six, nine, twelve, and eighteen until the seven-bird cap. Show one available bird at a time without badges or urgency; declining leaves the opportunity available. Server enforcement uses account/aviary age and bird count, never session, visit, or offer totals. Species selection is server-seeded from the pool and not a catalog or rarity draw.

## 6. Sync and failure behavior

Owner devices pull the same versioned canonical projection on initial load, visibility return, a long frame/suspend gap, and about every 30 seconds while visible. Keep the last rendered frame during a transient fetch and smoothly reconcile positions/lighting over a bounded transition on new versions. Interpolation uses server timestamps and stable bird IDs; it never predicts trait or mood changes as canonical updates. A hidden tab stops rendering and audio work; simulation continues server-side. On resume, discard stale pending calls, fetch first, then restart visual/audio phases from the current descriptors. If events are pending during a network break, keep local affordance feedback restrained, retry by idempotency key when connected, and reconcile from the server result; do not claim an offer changed a bird until accepted. Failed auth/session writes show direct system copy and a sign-in path. A complete state outage shows the quiet field with a plain retry control outside the scene, never a bird reset. Settings/name conflicts present current server values and explicit retry; personality can have no UI conflict because clients cannot write it.

## 7. Client rendering and audio

Serve the initial authenticated snapshot embedded with the HTML and draw the first bird from minimal SVG/critical CSS before application hydration. Serialize each bird's pose phase and transition start time; start animation at its elapsed phase so the first frame looks ongoing, with no spinner, fade-from-static, or general entrance animation. If a cold authenticated snapshot genuinely lags, paint only a soft quiet field with faint ambient cues until state arrives. The unique post-adoption empty field may transition to the first birds with a soft fly-in; normal visits never show an empty aviary. Keep the scene within one viewport with no pan/zoom/scene scrolling. Use responsive normalized perch anchors, minimum separation, safe margins, and scale/spacing adjustments so two to seven birds remain visible on narrow phones and wide screens. Three depth planes and rare leaves/feathers provide gentle parallax; ambient ornaments are local rendering details, not tick records.

Build a scene graph with stable keyed bird nodes and a single `requestAnimationFrame` loop. Motion primitives (breathing, preen, scan, head tilt, shuffle, perch transitions) have species-specific silhouettes, seeded phase offsets, and mood-weighted schedules; never reuse one obvious global cycle. Interpolate tick positions using timestamps and easing, with no snap on snapshot replacement. Stop the loop when hidden and clean up timers/listeners when views unmount. Day/night palette follows canonical zone and blends continuously; settle overlays a slow evening lighting/call-quieting transition until reengagement/close, with a five-second any-scene-click undo. No control, hover label, status icon, or badge sits in the bird scene. The top bar has only account/settings, accessibility, notebook, and offer affordances; settle is an action in the top-bar menu. Fade the bar toward transparency after pointer stillness; immediately restore it on pointer or keyboard activity and keep it readable/focusable for keyboard users.

Reduced-motion is selected by `prefers-reduced-motion` or an explicit account accessibility setting (explicit setting wins). Use slow cross-fades among still bird poses, cross-fades between perches instead of flight paths, no drifting leaves/parallax, and slower color transitions. The same state, calls, notebook, moods, and drift remain. Audit transitions for vestibular triggers at each breakpoint. Focus treatment and call captions are deliberate exceptions to the otherwise chrome-free scene.

Use WebAudio with per-bird synth voices driven by call grammar descriptors: oscillator/noise components, pitch glides, harmonic envelopes, small deterministic jitter, reusable buffers/nodes, and one bounded master dynamics/limiter path. Preserve each bird's spectral/timing signature while mood changes pace and shape. Mix overlapping calls as a chorus with headroom and soft ducking, not synchronized loops. Listen-in ramps the focused bird up and others down over roughly 1–2 seconds; the others retain an audible ambient floor and the reverse ramp runs on disengage. Clicking/tapping a bird, Enter on the focused bird, or arrow navigation can engage; clicking it again, empty space, Escape, or moving keyboard focus away disengages. Keep local mix focus out of canonical state while reporting bounded listen-in intervals as owner events for later drift. Caption from the exact emitted grammar parameters, not from a fixed string per bird; position a small accessible caption near the caller and avoid overlapping captions by stacking.

Browser autoplay policy may prevent sound at navigation even when the visible scene is already mid-call. Construct the current call schedule immediately and start audible output as soon as an existing user activation permits; do not play a fake recorded loop or add an arrival modal. Until audio is available, caption calls by default and provide a quiet, keyboard-reachable audio control in accessibility settings. If WebAudio fails or permission is denied, continue in graceful silence with captions automatically on. Respect mute/audio preferences across devices; when audio unlocks, join the current timeline rather than replaying missed calls. Treat any unavoidable autoplay delay as a measured browser constraint and test the no-sound first visit as a complete product experience.

## 8. Accessibility and copy acceptance

Create a semantic scene region with a concise static orientation and a separate, throttled live narration queue. Narration consumes the same scene/call/interaction descriptors as the renderer and produces reviewed naturalist prose: a bird by name/species, perch/depth, call or weather, and a small temporal detail. Idle cadence is one update per 30–60 seconds, deduplicated; user-triggered greeting, offer reaction, and settle may preempt politely without dumping a list of state mutations into the screen reader. Pause/replace stale utterances when a newer high-priority event arrives. The notebook uses the same voice but is navigated as ordinary read-only content. Do not expose trait values, raw mood enums, or “perch 2” labels in the experience.

Tab order reaches the four top-bar controls and then the scene; arrow keys move among bird controls, Enter activates listen-in, Escape exits it. Offer menus, naming, settings, invitations, recovery, and notebook have complete keyboard paths and visible focus against daytime and nighttime backgrounds. In the scene, focus remains stable by bird ID across snapshot updates and perch movement. Call captions are optional for normal audio but enabled by default if audio is off/unavailable; a user may explicitly enable them at any time. Text in top bar, captions, settings, notebook, errors, and visible narration meets WCAG AA contrast in all light/weather states, with documented token ratios and automated checks plus human review. System errors and accessibility settings use plain direct language, never evasive bird prose. Test screen reader narration with actual assistive technology, reduced-motion with vestibular review, keyboard-only use, zoom/phone layouts, and audio-off captions before release.

## 9. Budgets, instrumentation, and rollout

Enforce initial JS <2 MB gzipped in CI; target well below the cap to leave network margin. Critical bird SVG/CSS and private snapshot must arrive without waiting for notebook/settings/audio worklets. On a defined mid-tier phone/4G profile, first bird is visible <500 ms from navigation; test both warm and cold authenticated paths. Target sustained 60 fps idle on a five-year-old mid-range laptop during a 30-minute session, with no upward retained-memory trend across repeated calls, notebook scrolling, visibility cycles, and seven-bird chorus. Pool audio buffers/nodes, cap simultaneous voices and ornaments, and virtualize old notebook entries. Last two major Chrome, Safari, Firefox, and Edge versions are supported; older browsers get a direct unsupported-browser page.

From day one collect only aggregate operational counters/histograms: request/error rates and latency, first-bird timing, bundle size, frame timing, audio-context failures, memory trend in synthetic runs, tick lag/duration, retry/dead-letter counts, invite delivery failures, and snapshot freshness. A p99 tick duration above five seconds alarms. Run synthetic browsers from common regions and privacy-preserving aggregate RUM with no account/bird/event dimensions or stable analytics user ID. Secure diagnostic logs may use synthetic account UUID when required to resolve an account error, with short retention and access controls; they do not flow into an analytics warehouse. The simulation database and private interaction events are inaccessible to aggregate telemetry/model-training pipelines. Do not instrument return frequency, average drift, popular offers, bird traits, friend graphs, or any per-account relationship data. Use synthetic scenarios, opt-in research sessions, and qualitative accessibility reviews for calibration instead.

Ship in gates. **Foundation:** identity, private snapshot, two-bird adoption, stable IDs, schema/migrations, deterministic tick and event ordering. **Core aviary:** motion/lighting/weather, calls, presence, listen-in/offers/settle, notebook, and multi-device reconciliation. **Full v1 surface:** export/deletion, invitations, narration/captions/reduced motion, account controls, and production observability. Gate each stage on invariants, not feature count. Start internal dogfood with two birds; run simulated weeks before showing drift to humans; then a small opt-in beta with all accessibility modes and multi-device usage; then ramp public accounts while allowing age-based additions to three through seven birds. Do not increase the seven cap. Each ramp requires audio signature recognition checks, sustained performance and memory, tick reliability, sync consistency, and accessibility sign-off. Keep a server flag to pause new adoptions or call-scheduling variants without altering existing identities/vectors; rollback code/config via versioned grammar and additive migrations, never regenerate birds.

## 10. Verification and risk controls

Build deterministic engine fixtures for years of ticks, time-zone/DST changes, weather, bird-to-bird calls, concurrent owner devices, outages, and seven-bird density. Property tests enforce vector bounds/monotonicity, no neglect penalty, exactly-once event application and tick replay, stable IDs across rename/migration, age-only adoption, visitor non-influence, and no personality data in snapshots/telemetry. Browser integration tests cover presence conjunction (visible + focused + recent move/key), hidden/open-tab exclusion, simultaneous-device interval union, settle/tab-close equivalence, resume-from-suspend, offer cooldown, invitation expiry/redeem/revocation, session revocation, and no auth leakage via edge caches. Audio golden checks compare per-bird recognizability across moods and weeks, caption-to-call agreement, clipping/phase artifacts, and no repeated exact loop feel. Copy reviews reject generic event-log entries, absence guilt, surprise notifications, and gamification vocabulary. Run 30-minute performance/memory tests and real assistive-technology sessions as release gates.

Main failure modes and responses:

- **Drift too fast, too slow, or corrupted by false presence:** gate on synthetic week/three-week trajectories, presence-state conformance, per-day caps, and shadow simulation before changing rates; version config and never rewrite existing vectors from history.
- **Lost or duplicated drift in multi-device/retry paths:** server sequence, idempotency IDs, one tick writer, transactionally stored checkpoints, overlap-union presence, backup restore drills, and end-to-end two-device fixtures.
- **Canned or uncanny audio:** grammar variation with stable signatures, bounded chorus density, listener studies, headroom/limiting, and a silence-plus-captions fallback rather than files. Browser autoplay remains a known launch constraint to measure.
- **A sterile first frame or frame/memory regression:** private edge snapshot with phase anchors, critical first-bird path, lazy secondary surfaces, visibility cleanup, and sustained-device benchmarks.
- **Accessibility delivered as a static fallback:** narration/caption/reduced-motion design reviews and release-blocking screen-reader, keyboard, contrast, and vestibular tests alongside the default view.
- **Privacy or visit scope leakage:** PII vault and encrypted invite addresses, strict owner/visitor projections, no interaction telemetry join, default-off visits/notifications, 30-day deletion execution and audit, and revocation checked on every visitor pull.

The final v1 acceptance demonstration is an owner returning after weeks on a second device: the first visible frame is the continuing aviary, one bird notices them without text, the birds retain their stable identities and accumulated vectors, mood reflects elapsed time, and the same scene remains meaningful with sound unavailable, screen reader active, or motion reduced. A read-only visitor can watch that scene without changing it.
