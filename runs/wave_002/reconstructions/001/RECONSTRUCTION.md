## System-level intent

1. Pocket Aviary v1 is meant to be a "browser-based virtual aviary focused on long-term relationships with procedural animated birds." This shows up in the opening description, the "Core Engine" scope, the "Drift Calibration" timing of "after 1 week" and "after 3 weeks," and the calibration warning that birds should feel neither like "Tamagotchis" nor "static wallpapers."

2. The product voice avoids gamification, custody, and distress. This shows up in "No Gamification," "No Custodial Mechanics," "No hunger, health, or death," and "Neglect results in ambient quiet, not distress." It also appears in the drift rule: "Drift is monotonic toward expressive; no negative drift on neglect."

3. Canonical bird state is server-owned, event-driven, and conflict-resistant. This shows up in "Server: Owns the 'Source of Truth,'" "Server is the only writer of personality vectors," clients submitting "Interaction Events, never absolute trait values," additive deltas processed "in event-log order," and the explicit prohibition on "Last-write-wins" for trait data.

4. The plan separates canonical simulation from local felt detail. This shows up in the rendering boundary: server-side "Simulation" computes positions, moods, and trait drift; client-side "Interpolation" avoids "teleporting"; client-side "Ornaments" preserve "felt-aliveness" without server overhead.

5. Privacy is a cross-cutting boundary, not just an account detail. This shows up in "AccountID" being "synthetic to protect PII," "Email" being encrypted and "stored once," one-time read-only visit invitations being "opt-in," "No Social Network," and telemetry that "never includes bird names, trait values, or interaction history."

6. Accessibility is part of the v1 surface. This shows up in the in-scope "Screen-reader narration, reduced-motion mode (cross-fade), call captions," plus the dedicated "Accessibility Surfaces" section with ARIA live narration, captions, reduced motion, logical tab order, and keyboard shortcuts.

7. The experience is designed around responsive performance and fast first visibility. This shows up in the CDN note to hit the "<500ms first-bird target," the "First-Bird-Visible" budget of "<500ms on 4G/mid-tier mobile," "Consistent 60fps" on older hardware, responsive rendering that "never crops birds," and "Zero growth over 30-minute sessions."

## Per-feature whys

### 1. Scope and v1 Boundaries

- Core Engine: Procedural bird behavior: The plan ties this to "long-term relationships with procedural animated birds." Personality drift, mood transitions, and idle motion are later calibrated so change is visible over weeks while avoiding both "Tamagotchis" and "static wallpapers."

- Audio: Client-side WebAudio procedural call synthesis and chorus mixing: The plan wants calls generated with species-specific motif grammars, random pitch/timing variations, and no loops, while chorus mixing supports listen-in focus without losing ambient sound.

- Interactions: Presence accounting: Presence-time and interaction signals are consumed by the slow tick. The risk section explains the need for "Visibility + Focus + Activity" to identify attention without false negatives for "still watching."

- Interactions: Listen-in: The audio pipeline gives listen-in a "slow gain ramp (3-5s)" to focus one bird while lowering others to ambient "(-12dB to -18dB)."

- Interactions: Offers (seed, song, pool): Offers are interaction events submitted to the server and consumed as recent interaction signals for drift and mood transitions.

- Interactions: settle gesture: NOT RECOVERABLE FROM PLAN

- Field notebook: The notebook is generated by "Auto-Notebook," which periodically evaluates state to create "naturalist prose entries."

- Starter species pool (6 species): NOT RECOVERABLE FROM PLAN

- Email magic-link auth: NOT RECOVERABLE FROM PLAN

- Server-side simulation tick: The tick lets the server own the "Source of Truth," consume interaction events, apply drift, update mood, generate notebook entries, and commit canonical state.

- Multi-device sync: The plan makes clients pull state snapshots while the server remains the only canonical writer, so multiple devices submit events rather than competing trait writes.

- One-time read-only visit invitations (opt-in): The plan allows a limited social feature while still making "No Social Network" a boundary: no profiles, discovery feeds, chat, or co-presence.

- Screen-reader narration: Narration provides accessibility through "Naturalist prose" delivered to ARIA live regions at a slow cadence.

- Reduced-motion mode: Reduced motion replaces "60fps animations" with slow "cross-fades between key poses" and removes ambient leaf/feather particles.

- Call captions: Captions provide procedurally generated call descriptions, such as "soft three-note rise," near birds.

- Responsive horizontal scene with parallax, day/night cycle, ambient weather: The plan ties this to a horizontal scene with 3 depth layers, smooth day/night transitions anchored to local time, and responsive rendering that preserves aspect ratio and "never crops birds."

### 2. Architecture

- React/TypeScript thick client: The client owns rendering and audio synthesis while staying stateless for canonical bird data by pulling state snapshots.

- Node.js/FastAPI server: The server owns the "Source of Truth" and runs the slow simulation tick.

- Relational database: It stores account and bird records.

- Append-only event log: It stores user interactions so the simulation can consume presence-time and interaction signals, and so sync can process additive server-authored deltas in event-log order.

- CDN edge caching: The plan uses edge caching for static assets and potentially initial state snapshots to hit the "<500ms first-bird target."

- Server-side simulation: Server simulation computes canonical positions, moods, and trait drift.

- Client-side interpolation: Interpolation smoothly animates between snapshots to avoid "teleporting."

- Client-side ornaments: Ornaments create non-canonical leaves, feathers, and micro-movements locally to preserve "felt-aliveness" without server overhead.

### 3. Data Model

- AccountID as synthetic UUID: The rationale is "to protect PII."

- Email encrypted and stored once: The rationale is privacy protection around email storage.

- AviaryID one per account: NOT RECOVERABLE FROM PLAN

- Settings for accessibility prefs and visit notifications: Settings preserve the v1 accessibility surface and opt-in visit notification behavior.

- BirdID as Stable UUID: NOT RECOVERABLE FROM PLAN

- SpeciesID reference to species pool: NOT RECOVERABLE FROM PLAN

- Name as user-assigned: NOT RECOVERABLE FROM PLAN

- Personality Vector: The vector is the trait surface that drifts over time; the server is the only writer, drift moves "toward expressive," and telemetry excludes trait values.

- Current State: Mood: Mood transitions are updated from local time, recent interactions, and ambient events.

- Current State: PerchPosition: Positions are part of the canonical state computed by simulation and returned in snapshots for rendering.

- Current State: LastInteractionTimestamp: Recent interactions feed mood transitions and event consumption.

- Interaction Log: The append-only log is used for presence events, offer events, listen-in events, ordered delta processing, and conflict prevention.

### 4. Simulation Engine Design

- The Slow Tick: Running every ~60 seconds supports server-side slow simulation rather than continuous client-owned canonical change.

- Fetch active aviaries or those with recent interaction logs: NOT RECOVERABLE FROM PLAN

- Consume event log for presence-time and interaction signals: The event log is the basis for turning presence and interactions into simulation input.

- Drift Function with low-pass filter: Drift is deliberately slow and "monotonic toward expressive," with "no negative drift on neglect."

- Mood Transitions: Moods respond to time of day, recent interactions, and ambient weather events.

- Auto-Notebook: The simulation evaluates state to generate naturalist prose entries.

- Commit new canonical state: The commit preserves the server as the source of truth.

- Drift Calibration: Calibration makes drift measurable after 1 week and visible after 3 weeks, while avoiding birds that feel too fast like "Tamagotchis" or too slow like "static wallpapers."

### 5. Sync and Multi-Device Model

- Canonical State: The server is the "only writer" of personality vectors so trait data has one source of truth.

- Clients submit Interaction Events, never absolute trait values: This prevents clients from overwriting canonical trait data and keeps client input additive.

- Additive server-authored deltas processed in event-log order: This is the conflict prevention model.

- "Last-write-wins" prohibited for trait data: The plan rejects last-write-wins to protect personality vectors from sync races.

### 6. API Surface

- POST /auth/request-link: NOT RECOVERABLE FROM PLAN

- GET /state: This lets the stateless client pull the current aviary snapshot from the canonical server.

- POST /events: This is how clients submit presence pings, offers, and listen-in events instead of trait values.

- POST /invite: This issues the one-time read-only visit invitation.

- Snapshot current server time: Server time is returned for cycle sync.

### 7. Frontend Rendering and Audio

- Horizontal scene with 3 depth layers: The plan uses this for parallax scene composition.

- Day/Night smooth CSS/SVG filter transitions: These are anchored to user local time to support day/night cycle sync.

- Responsive rendering: It preserves aspect ratio and never crops birds.

- Procedural Calls: Species-specific motif grammars and WebAudio generation support call synthesis without fixed audio loops.

- Chorus Mixing: Dynamic gain management lets listen-in focus one bird while lowering others to ambient.

- No Looped Audio: Random pitch and timing variations keep each call from repeating exactly.

### 8. Accessibility Surfaces

- Narration: Naturalist prose in lowercase, present tense is delivered through ARIA live regions at a slow cadence.

- Captions: Procedural descriptions of calls appear near birds.

- Reduced Motion: Cross-fades replace 60fps animation, and ambient particles are removed.

- Logical tab order: Navigation moves from Top Bar to Aviary bird focus to Field Notebook.

- Keyboard shortcuts for Listen-In and Offer: Keyboard commands make those interactions reachable without pointer-only input.

### 9. Performance and Observability

- JS Bundle budget under 2MB gzipped: NOT RECOVERABLE FROM PLAN

- First-Bird-Visible under 500ms: This supports the first-bird target on "4G/mid-tier mobile."

- Runtime 60fps idle micro-motion: The plan wants consistent idle motion on "5-year-old hardware."

- Memory zero growth over 30-minute sessions: Resource pooling for audio and sprites prevents memory growth.

- Synthetic heartbeat checks: Heartbeats monitor simulation-tick latency and alarm at "p99 > 5s."

- RUM anonymous timing: RUM measures page load and audio context initialization.

- Privacy Boundary for telemetry: Telemetry excludes bird names, trait values, and interaction history.

### 10. Rollout and Risk

- Drift "Vibe" Check: Testing simulated "weeks" of interaction is needed because too-fast drift feels like Tamagotchis and too-slow drift feels like static wallpapers.

- Audio Uncanniness: The plan uses soft noise-shaping and organic attack/decay curves so procedural calls avoid "beepy" synth qualities.

- Presence Honesty: The plan calls out Visibility + Focus + Activity so attention detection does not falsely exclude "still watching."

- Sync Race Conditions: Event log consumption must be atomic per account to avoid sync races.

- Beta with species 3-6 and visit invitation feature: NOT RECOVERABLE FROM PLAN

- v1 Launch with full accessibility suite and notebook generation: NOT RECOVERABLE FROM PLAN
