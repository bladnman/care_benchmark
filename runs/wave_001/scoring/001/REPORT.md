## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered better (16/42 = 38.1%) than affective whys (14/60 = 23.3%). Architecture-heavy rationales around S7, F17, and F18 survived because the plan used concrete sync language; relationship-shaping whys around S2, F14, F27, and F31 mostly did not.
- **Weight-3 vs weight-2.** Weight-3 whys recovered 26/80 (32.5%), better than weight-2 whys at 4/22 (18.2%), but usually only as partial layer recovery. The candidate kept primary mechanisms and dropped downstream consequences.
- **System-level vs feature-level.** System-level fidelity (42.9%) was meaningfully higher than reachable feature-level fidelity (24.3%). The plan preserved broad architecture/philosophy more often than feature-specific intent.
- **Multi-layer recovery patterns.** Layer 1 survived most often. Layers 2 and 3 - calibration gaps, failure modes, social/relationship consequences - were commonly absent.
- **Subdomain patterns.** Accounts/sync and simulation were strongest. Aviary layout, greeting/settle, privacy/telemetry, and social transparency were thin or absent.
- **Evidence-bound effects.** Many apparent recoveries became `rule_without_why`: procedural calls, mood-shaped motion, no streaks, no gamification, cap seven, synthetic UUID, TTFBird, and stable bird identity.

What the failure shape suggests: the candidate wrote a compact implementation spine, not an intent-preserving plan. It is buildable in several core areas, but a downstream team would recreate many features as generic mechanisms rather than the specific Pocket Aviary product.

---

## 4. Recommendations for v2 hardening

- Keep v06 evidence-bound scoring. It caught the main failure mode: rule preservation without why preservation.
- Add or retain targeted feature-level whys for social, privacy, greeting, settle, and accessibility surfaces; those areas expose whether the plan preserved relationship intent or only named features.
- Consider asking phase-1 planners for an explicit "why-critical rules" ledger. It would make intent compression observable without requiring PRD leakage in phase 2.
- Keep the >=3 cross-cutting bar, but ask scorers to record whether the inherited items preserve the rationale or only the rule. S4 and S5 were borderline because the rules existed but the rationale did not really travel.
- For compact plans, preserve the inclusive capture rule but report borderline calls prominently. It lets planning quality measure feature coverage while fidelity carries the real discrimination.

## 5. Methodology caveats

- **Fresh-context fidelity.** This phase-2B scoring used only the allowlisted phase_two files, the assigned PLAN, candidate metadata, run 001 timing entry, and frozen RECONSTRUCTION. The validity audit found no significant contamination signatures.
- **Single-run limitation.** This is one sample from one candidate run; no variance signal is available inside this report.
- **Borderline capture calls.** Inclusive calls included features 2, 12, 40, 45, 47, 76, 90, 92, 98, and 104. Tightening them would lower planning quality but would not rescue fidelity.
- **System-level cross-cutting.** The most subjective calls were S1, S4, S5, and S9. The appendix above lists the concrete plan inheritance used for each judgment.
- **Confabulation cases.** No strong ungrounded reconstruction cases were counted. The reconstruction mostly paraphrased PLAN content and often marked items NOT RECOVERABLE rather than inventing whys.
- **Evidence-bound denials.** Fifteen included whys were treated as rule-without-why cases. This was the dominant scoring effect.
- **Operational metadata.** TIMING.json contained phase1 and phase2a data for run 001 only; no phase2b timing was available at write time, so the score JSON includes only bounded available timing fields. Run label is blank because wave metadata was outside the read allowlist.
