## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered **44.0 / 50.0** weighted points (88.0%), while affective whys recovered **80.0 / 102.0** (78.4%). The biggest affective compression appears in S2, F10, F14, F27, F29, and F30: the plan protects the rule, but some relational rationale is absent.
- **Weight-3 vs weight-2.** Weight-2 whys were nearly saturated at **42.0 / 44.0**; weight-3 whys recovered **82.0 / 108.0**. The stricter multi-layer operator exposed missing downstream or secondary layers.
- **System-level vs feature-level.** System-level fidelity is high at **26.0 / 28.0**, because the plan repeatedly states the architectural philosophy. Feature-level fidelity drops to **98.0 / 124.0**, mostly from partial multi-layer whys.
- **Multi-layer pattern.** Primary mechanisms usually survived. The most commonly missing layers were downstream consequences: silent drift corruption, product becoming an economy, retrofit impossibility, or why a harmless-looking announcement changes the relationship.
- **Subdomain pattern.** Server simulation, sync, privacy, accessibility, and performance are strong. Affective onboarding/social/non-goal rationales are weaker, especially F29 and the announcement/gamification family.
- **Evidence-bound effects.** Only one included why is pure rule-without-why: F29. Several apparent wins remain partial because the reconstruction did not carry every required layer.

The failure shape suggests a very strong implementation plan whose philosophy is visible, but whose compressed rationale occasionally turns nuanced relationship design into enforceable product constraints.

---

## 4. Recommendations for v2 hardening

- Keep targeted headroom whys like F29-F40. They caught real compression: F29 was captured as a rule but explicitly not recoverable as a why.
- Add more single-layer affective exceptions where the mechanism is easy to specify but the rationale is non-obvious. This will reduce saturation among weight-2 rows.
- Preserve multi-layer scoring for high-weight whys, but require a short layer note in every scorer report; that will make partial calls easier to compare across scorers.
- Revisit S2-style system whys with a check that distinguishes rule refusal from affective rationale. This run shows no-toasts/no-streaks surviving more strongly than the processed-vs-seen reason.
- Keep the cross-cutting >=3 rule. It was workable here, but scorers should continue to list concrete inheritance sites to avoid preamble-only credit.

## 5. Methodology caveats

- **Fresh-context fidelity.** The audit found no gold-ID leakage, no rubric vocabulary, and headings that mirror the plan rather than the gold list. Fresh-context isolation appears intact from the artifact evidence.
- **Single-run limitation.** This is one run with no variance signal.
- **Borderline capture calls.** I leaned inclusive on feature 7 (domain terms), feature 57 (evening palette/call quieting), and feature 90 (visits default off). Those calls did not affect F1-F40 reachability.
- **System-level cross-cutting.** The main subjective call was S2: the rule is cross-cutting in PLAN, but one affective layer is missing in reconstruction, so it receives partial recovery.
- **Confabulation cases.** I counted no ungrounded reconstruction cases. The reconstruction stayed close to plan language and was honest on F29.
- **Evidence-bound denials.** F29 was denied despite the feature rule being captured because the reconstruction says `NOT RECOVERABLE FROM PLAN` and the plan did not ground the starter-birds-not-catalog why.
- **Rule-without-why cases.** One: F29. Partial multi-layer rows are not counted as pure rule-without-why because at least one rationale layer survived.
