## 3. Diagnostic patterns

- Functional whys survived somewhat better than affective whys: 46.0/54.0 weighted functional credit (85.2%) versus 78.0/98.0 affective credit (79.6%). The plan was excellent on architecture and privacy boundaries, especially S7, S8, F17, F18, F20, and F36.
- Weight-3 whys recovered at 90.0/108.0 (83.3%), above weight-2 whys at 34.0/44.0 (77.3%). The high-weight items were usually tied to repeated implementation rules, so the reconstructor could infer several layers from the plan.
- System-level fidelity was much stronger than feature-level fidelity: 92.9% versus 79.0%. The plan preserved the product philosophy cross-cuttingly, but some feature-specific affective rationales were flattened into rules.
- Multi-layer losses usually happened in layer 2 or layer 3. Examples: F16 preserved PII containment but not the impossible-to-retrofit consequence; F30 preserved age-based growth and anti-reward framing but not the economy/unlock downstream consequence; F31 preserved same-bird continuity but not the distinction between identity continuity and vector persistence.
- The most common leak was rule without why. F8, F23, F33, F34, and F39 all kept the operational rule but did not recover the relationship-level reason behind it.
- Subdomain pattern: sync/privacy/accessibility/audio were strong; social sharing and notebook/export rationale were weaker when the rationale depended on avoiding a future product-shape shift rather than enforcing a concrete mechanism.

What the failure shape suggests: the candidate planner is very strong at preserving buildable scope and implementation architecture. The remaining leakage is mostly rationale compression: rules like "do not expose numbers," "no leaderboard," or "read-only notebook" survive, while the exact relationship-protecting reason sometimes does not.

## 4. Recommendations for v2 hardening

- Keep v06 evidence-bound scoring. It usefully separated the near-perfect feature capture from the thinner rationale recovery in F8, F23, F33, F34, and F39.
- Add more targeted affective feature whys like F33/F39 in future instances. These exposed compression that broad system whys would otherwise hide.
- Preserve multi-layer whys for architecture and product-shape failures. Layer splits caught meaningful differences between "the rule is present" and "the downstream failure mode is understood."
- Consider a small explicit field for partial-layer diagnostics in machine-side aggregate reporting. The strict score JSON should stay qualitative-free, but aggregate counts by missed layer would help compare runs without leaking feature identities.
- The >=3 cross-cutting bar worked well here; it prevented isolated principle mentions from carrying system-level credit, while still recognizing a plan that repeatedly embedded the principle into decisions.

## 5. Methodology caveats

- Fresh-context fidelity: this scorer used only the allowed phase_two materials, the assigned plan, assigned metadata/timing, and the frozen assigned reconstruction. I did not read PRD files, peer slots, or other waves.
- Single-run limitation: this is one candidate run and one frozen reconstruction, so there is no temperature or prompt-variance signal inside this score.
- Borderline capture calls: #23 and #57 were counted as captured under the rubric's inclusive rule, despite missing exact numeric/detail targets. #58, #68, and #116 were scored missed.
- System-level cross-cutting is the main subjective judgment; the appendix in section 2.2 lists the concrete inherited plan sites used for each S why.
- Confabulation: I did not identify ungrounded reconstruction claims that should trigger a confabulation penalty. The reconstruction reads as plan-derived.
- Evidence-bound denials: five feature-level rows were denied recovery as rule-without-why cases even though the plan would let a builder implement the feature.
- Timing: TIMING.json had phase 1 and phase 2A data for run 001, but no phase 2B timing yet, so the score JSON includes only available timing fields.
