## 3. Diagnostic patterns

- **Affective vs functional.** Affective whys recovered at 93.9%, while functional whys recovered at 77.8%. The functional losses were mostly calibration and data-boundary details: F1/F13 presence corruption, F2 instruments-versus-user calibration, F16 retrofit consequence, and F35 deletion-regret layering.
- **Weight-3 vs weight-2.** Weight-2 whys recovered at 90.9%; weight-3 whys recovered at 87.0%. The higher-weight rows were more demanding because each downstream layer needed evidence.
- **System-level vs feature-level.** System-level fidelity was 92.9%; feature-level fidelity was 87.1%. The plan's philosophy traveled extremely well, but some feature-specific downstream consequences compressed away.
- **Multi-layer pattern.** Primary rules almost always survived. The most common missing layer was a secondary or downstream consequence: the population-wide silent failure in F1/F13, the one-week instruments/three-week user calibration in F2, the user-intention rotation in F14, and the retrofit/regret layers in F16/F35.
- **Subdomain pattern.** Audio, rendering, accessibility, and voice were especially faithful. Social/private-sharing had the clearest intent loss: F37 preserved per-invite mechanics without the private-relationship rationale.
- **Evidence-bound effects.** F11 and F37 are the cleanest rule-without-why cases. Several partials would have looked strong under a looser semantic read, but v06 denied full credit because only one or two layers had reconstruction evidence.

The failure shape suggests a highly capable planner/reconstructor pair that preserves mechanisms and headline philosophy, with residual leakage in rationale that lives behind compliance-like details or quiet social/privacy exceptions.

## 4. Recommendations for v2 hardening

- Keep the evidence-bound v06 operator. This run is a useful demonstration: a near-complete plan can still lose targeted why layers without looking superficially weak.
- Add more targeted social/privacy exception whys. F37 separated mechanics from rationale and reduced saturation; similar whys around quiet sharing, export, and visit affordances would be useful.
- Consider a bounded layer-count aggregate in the score schema. Partial multi-layer rows create layer-level plan-only losses, but the current JSON can only count row-level categories.
- Preserve the system-level cross-cutting bar. The >=3 inherited-decision requirement was usable and helped distinguish a strong but not fully elevated S6 from the other system principles.
- Keep capture permissive. The 119/120 planning score is appropriately high; discrimination came from fidelity rather than from punishing terminology differences.

## 5. Methodology caveats

- **Fresh-context fidelity.** I used only the phase-two package, PLAN, candidate metadata, TIMING for run 001, frozen RECONSTRUCTION, and the assigned scoring slot. I did not read prd/, peer slots, or other waves.
- **Single-run-at-temperature limitation.** This is one run and one frozen reconstruction; no variance signal is available here.
- **Borderline capture calls.** Feature 7 was a borderline-inclusive capture. It does not materially change the headline score: scoring it missed would move planning from 99.2% to 98.3%.
- **System-level cross-cutting.** S6 was the main subjective system call. I scored it partial because the reconstruction captured strict presence mechanics but did not carry the full settle/tab-close consequence as system-level intent.
- **Confabulation cases.** I found no scored ungrounded-reconstruction cases. The reconstruction reads as plan-derived.
- **Evidence-bound denials.** F11 and F37 were denied because rule mechanics survived without exact rationale evidence. The partial multi-layer rows were denied full credit for missing individual layers.
- **Operational compromise.** TIMING.json had phase 1 and phase 2A only; the score JSON includes those fields and omits phase 2B timing.
