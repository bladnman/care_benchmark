## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered much more cleanly: 50.0/54 weighted points (92.6%) versus 75.0/98 (76.5%) for affective whys. The plan is strongest where intent is embodied as architecture: presence accounting, server-side state, no last-write-wins, telemetry boundaries, and deletion/export mechanics.
- **Weight-3 vs weight-2.** High-tier whys did not dominate by much: score-weight-4 whys recovered 88.0/108 (81.5%) and score-weight-2 whys recovered 37.0/44 (84.1%). Multi-layer affective whys often lost a secondary or downstream layer even when the rule was excellent.
- **System-level vs feature-level.** System fidelity (89.3%) exceeded feature fidelity (80.6%). The planner carried product philosophy broadly, but the reconstruction compressed some targeted F29-F40 rationales back into mechanisms.
- **Multi-layer recovery patterns.** Primary layers usually survived. The most common dropped material was secondary affective explanation, such as S2's processed-versus-seen distinction, F10's well-meaning-toast temptation, F12's stock-event-log spell break, and F14's rotation into managing a number.
- **Subdomain patterns.** Sync, privacy, presence, and accessibility were strong. The weakest area was targeted social/onboarding headroom: F29, F33, and F39 retained rules but not the deeper relationship rationale.
- **Evidence-bound effects.** The stricter operator mattered most on F29, F33, and F39, where plan/reconstruction contained enough rule language to build plausible features but not enough gold-rationale evidence to award recovery.

What the failure shape suggests: this candidate is an excellent engineering plan with real architectural intent preservation, but it still compresses some delicate product-relationship whys into policy, scope, or implementation rules.

## 4. Recommendations for v2 hardening

- Keep the F29-F40 targeted headroom style. It exposed meaningful gaps even in a 120/120 capture plan, especially around onboarding, read-only notebook semantics, and visitor presentation.
- Add a few more single-layer affective exceptions where the rule is easy to state but the product relationship is easy to lose. This run shows strong planners can implement the rule while flattening the why.
- Preserve the evidence-bound operator. It prevented mechanism-only rows from receiving credit and produced a useful distinction between plan capture, reconstruction recovery, and rule_without_why.
- Consider making system-level S4-style restraint easier to audit by adding an explicit cross-cutting checklist. The plan preserved the principle, but B did not identify it as system-level intent because its evidence was distributed across cap, layout, chrome, palette, and audio.
- For future instances, keep functional whys multi-layered. This run handled functional architecture very well; more functional headroom may be needed to avoid saturation in server/sync/privacy areas.

## 5. Methodology caveats

- **Fresh-context fidelity.** The prompt states this scorer is fresh-context and the reconstruction is frozen. The validity audit found no gold ID leakage and no 1:1 gold-list mirroring.
- **Single-run-at-temperature limitation.** This is one run, so there is no variance signal. The high planning score should not be treated as distributional performance by itself.
- **Borderline capture calls.** Two inclusive calls were made: feature 7 (glossary captured through distributed domain definitions) and feature 68 (empty-aviary state named thinly through the signup/first-bird transition). These do not materially affect the fidelity reading because neither anchors a feature-level why.
- **System-level cross-cutting.** The strict three-feature bar was met for all system whys in the PLAN. S4 still scored partial because B did not identify restraint-over-richness in its system-level section.
- **Confabulation cases.** No ungrounded reconstruction was credited. Some rows were marked none or partial because a plausible why was not evidenced in both PLAN and RECONSTRUCTION.
- **Evidence-bound denials.** F29, F33, and F39 were the main denials: the operational rule survived, but the gold relationship rationale did not.
- **Rule-without-why cases.** There were 3 cases: F29 starter birds as arrivals, F33 read-only notebook as observer record, and F39 visitor sees actual aviary/no show-off mode.
- **Operational compromise.** TIMING.json had phase1 and phase2a data for run 001 but no phase2b timing yet, so the score JSON includes only available timing fields.
