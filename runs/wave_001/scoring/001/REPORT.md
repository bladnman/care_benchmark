## 3. Diagnostic patterns

- **Affective vs functional.** The split is nearly even: functional 36/54 (66.7%), affective 64/98 (65.3%). Functional architecture whys around server authority, additive drift, and telemetry boundaries survived well; affective whys failed when they depended on subtle relationship language, such as F8, F11, F23, and F39.
- **Weight-3 vs weight-2.** Higher-weight whys did slightly better (66.7% vs 63.6%). Multi-layer rows often preserved the primary rule and one downstream consequence while dropping the middle rationale layer, e.g. F4 chorus artifacts, F16 retrofit impossibility, and F30 economy erosion.
- **System-level vs feature-level.** The headline gap is system-level 85.7% vs feature-level 61.3%. The plan and reconstruction carried philosophy well, but feature-level exceptions often became implementation rules without the product reason.
- **Multi-layer recovery patterns.** Layer 1 survived most often. Layer 2 was the most common loss: the "why this specific precision matters" connective tissue was often compressed away.
- **Subdomain patterns.** Simulation/sync, accessibility, and performance were strongest. Social and relationship-protection details were weaker: leaderboards, actual visitor view, starter birds, and stable identity lost their deeper relationship rationale.
- **Evidence-bound effects.** Several apparent recoveries were denied because the reconstruction had only a rule: F5, F8, F11, F19, F23, F29, F31, F32, F35, and F39. Under a looser v1-style reading, some of these would likely have received credit from PLAN evidence alone.

The failure shape suggests a strong planner whose implementation plan is excellent, plus a reconstruction that preserved broad principles but often summarized feature whys into operational justifications.

---

## 4. Recommendations for v2 hardening

- Keep the evidence-bound operator. It was useful here: 100% planning quality would otherwise hide the fact that feature-level intent fell to 61.3%.
- Add more targeted feature-level exceptions in social/account identity areas. This run shows headroom in "actual aviary vs show-off mode," "private relationship vs data product," and "stable identity protects remembered relationship."
- Retain multi-layer whys for high-risk design decisions, but consider scoring per-layer evidence in the report UI more prominently. Layer-2 losses were the strongest diagnostic signal.
- Preserve the system-level cross-cutting bar, but ask scorers to list inherited features as done here; otherwise full system credit can be too easy when plans repeat philosophy without operational inheritance.
- Consider a separate "rule survived" diagnostic score. Many misses were not feature omissions; they were reason omissions.

---

## 5. Methodology caveats

- **Fresh-context fidelity.** This phase-2B scorer treated the reconstruction as frozen and did not modify it. The prompt stated fresh context and no prior-run memory; scoring used only phase-two package files and slot 001 inputs.
- **Single-run-at-temperature limitation.** This is one run with no variance signal. The result should be interpreted as a single sample for this candidate/evaluator pairing.
- **Borderline capture calls.** Feature 7 (glossary) and feature 44 (settle opt-in) were inclusive capture calls. Because planning was otherwise comprehensive, these did not materially change the headline.
- **System-level cross-cutting.** S2 and S6 were scored partial because the reconstruction carried the operational principles but missed one deeper layer each.
- **Confabulation cases.** No recovered rationale was judged confabulated or ungrounded in the plan.
- **Evidence-bound denials.** Ten feature whys were scored none because the reconstruction preserved only a rule/mechanism or explicitly said `NOT RECOVERABLE FROM PLAN`.
- **Rule-without-why cases.** The main examples are hidden trait numbers, settle optionality, matter-of-fact sync error tone, no leaderboards, starter birds, stable identity, mood persistence, deletion grace, and actual visitor view.
