## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered at 52.6%, while affective whys recovered at 34.2%. Server-owned state survived; relationship-shaping reasons around announcements, comparison, journals, and social exposure mostly did not.
- **Weight-3 vs weight-2.** Weight-3 whys recovered at 47.5%, better than weight-2 whys at 23.5%, but mainly because S7/F17/F18 are architectural.
- **System-level vs feature-level.** System-level fidelity (57.1%) is higher than feature-level fidelity (34.9%). The plan preserved broad categories better than feature-specific rationales.
- **Multi-layer recovery.** Downstream consequence layers were most often dropped: F2 lacks the Tamagotchi/screensaver band, F4 lacks audio-spine consequences, F12 lacks the stock-event-log spell-break, and F31 lacks relationship-continuity consequences.
- **Subdomain patterns.** Accounts/sync is strongest; social, aviary-layout, and affective onboarding are weakest. Accessibility is included in V1 and recovered at system level, but feature-level accessibility still compresses charm into mechanics.
- **Evidence-bound effects.** Mechanism-only rows such as F8, F14, F23, F26, F27, F31, F33, F37, F38, and F39 were denied recovery because they lacked rationale evidence.

What the failure shape suggests: this candidate is useful as an implementation scaffold, but it is not a high-fidelity intent carrier. It teaches a builder what to build more often than why the rule is load-bearing.

---

## 4. Recommendations for v2 hardening

- Preserve evidence-bound scoring. This run demonstrates why: a plan can name many exclusions and still lose the reasons that make those exclusions durable.
- Add more targeted affective feature whys in social and layout surfaces. Those areas are easy to implement superficially while missing the private-relationship/no-performance rationale.
- Keep multi-layer whys for high-risk exceptions. They separated compressed recovery (F2, F4, F12, F24, F25, F40) from true recovery (F17, F18).
- Require explicit layer notes for system-level whys. S1 and S9 show that cross-cutting mechanisms can otherwise make a principle look more recovered than it is.
- Consider sharpening privacy scoring. This run protected email PII but missed the per-bird relationship-data privacy boundary, which is a different kind of privacy.

## 5. Methodology caveats

- **Fresh-context fidelity.** The scoring context treated the reconstruction as frozen and did not edit it. The validity audit found no evidence that phase 2A had read gold IDs or rubric vocabulary.
- **Single-run limitation.** This is one candidate run and one reconstruction; no variance signal is available from this slot alone.
- **Borderline capture calls.** Starter birds, stable bird identity, and settle opt-in were counted inclusively. Each became reachable but recovered none of its feature-level why.
- **System-level cross-cutting.** The strict three-feature bar was most subjective for S1, S4, S5, and S9; the appendix above records the judgment trail.
- **Confabulation cases.** No clear contamination/confabulation was counted as recovered. Some reconstruction phrases are mild inferences, but each scored recovery only where the plan grounded them.
- **Evidence-bound denials.** The main denial mode was rule-without-why: 20 included whys had a surviving rule or mechanism without enough rationale evidence.
- **Operational issues.** Timing data existed for phase 1 and phase 2A only; phase 2B timing was not fabricated.
