## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered at 36/54 weighted points (66.7%), while affective whys recovered at 57/98 (58.2%). The model preserved technical reasons around server ownership, UUIDs, and telemetry better than relationship-shaping reasons such as F29, F33, F38, and F40.
- **Weight-3 vs weight-2.** Weight-3 whys were not dramatically safer: 66/108 (61.1%) versus 27/44 (61.4%) for weight-2. Multi-layer rows often kept the primary mechanism but dropped the temptation or downstream failure mode.
- **System-level vs feature-level.** System-level fidelity was strong at 23/28 (82.1%), while feature-level fidelity was 70/124 (56.5%). The plan encoded philosophy broadly, but the reconstruction compressed many feature whys into implementation rules.
- **Multi-layer recovery.** L1 mechanism layers were usually recoverable. L2/L3 losses show up in S2, S9, F1, F2, F3, F7, F10, F13, F16, F18, F25, F27, F30, and F31.
- **Subdomain patterns.** Accounts/sync and privacy were comparatively faithful. Quiet social surfaces and accessibility nuance were weaker: F22, F38, F39, and F40 all became rule-without-why or none.
- **Evidence-bound effects.** F5, F11, F14, F22, F26, F29, F33, F35, F38, F39, and F40 were denied recovery because the reconstruction carried a mechanism, a NOT RECOVERABLE marker, or no rationale evidence. S3 was plan-only: the plan preserved specificity, but the reconstruction did not identify it as a system principle.

The failure shape suggests this plan is a strong implementation carrier but a less complete rationale carrier for subtle affective exceptions.

## 4. Recommendations for v2 hardening

- Keep the v06 evidence-bound ledger. It clearly separated high feature capture from lower intent transfer.
- Add more targeted social and accessibility exception whys. This run's misses around visit notifications/logs/show-off mode and narration cadence exposed real headroom.
- Clarify whether system-level recovery can use rationale placed under per-feature reconstruction bullets. S6 was recoverable, but not in the ideal reconstruction section.
- Preserve multi-layer judging for weight-3 whys. It usefully distinguished primary-rule survival from deeper failure-mode survival.
- Consider an aggregate report field for plan-only-not-reconstructed and rule-without-why examples in HTML filtering, while keeping score JSON aggregate-only.

## 5. Methodology caveats

- **Fresh-context fidelity.** Scoring used only the allowed phase-two materials, the assigned plan, candidate metadata, run-001 timing, and the frozen reconstruction. No PRD, peer slots, other waves, subagents, or background agents were used.
- **Single-run-at-temperature limitation.** This is one candidate run at the recorded settings; there is no variance estimate.
- **Borderline capture calls.** I leaned inclusive on F11's anchor (#44), evening palette shift (#57), and visitor actual-aviary rendering (#97). These did not change reachable feature-why count because all 40 canonical feature anchors were captured.
- **System-level cross-cutting.** The cross-cutting bar was strict but subjective for S3 and S6; S3 became plan-only partial, while S6 counted because the reconstruction recovered the principle across per-feature evidence.
- **Confabulation cases.** No scored ungrounded reconstruction cases were found.
- **Evidence-bound denials.** Several plausible v1-style recoveries were denied because the reconstruction had rule evidence but no rationale evidence, especially F5, F14, F22, F26, F29, F33, F38, F39, and F40.
- **Rule-without-why cases.** 11 included whys were rule-without-why cases.
- **Timing.** TIMING.json contained phase 1 and phase 2A data for run 001 only; phase 2B timing was not present and was omitted.
