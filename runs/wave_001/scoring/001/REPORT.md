## 3. Diagnostic patterns

**Affective vs functional.** Functional recovery was stronger (74.1%) than affective recovery (71.4%). The plan and reconstruction preserved architecture-heavy whys such as S7, S8, F2, F7, F17, F35, and F36. Affective exceptions more often compressed into rules: F8, F11, F23, F29, and F37-F39.

**Weight-3 vs weight-2.** Weight-3 whys recovered at 81.5%, much higher than weight-2 at 50.0%. The plan made many load-bearing multi-layer mechanisms explicit, while several weight-2 affective rows were easy to implement as prohibitions without restating why.

**System-level vs feature-level.** System-level fidelity (85.7%) exceeded feature-level fidelity (69.4%). The reconstruction identified big themes like server-owned life, notice-never-announce, privacy architecture, and accessibility-first, but missed or undernamed charm-from-specificity, restraint-over-richness, and presence as a relationship model.

**Multi-layer recovery patterns.** The most common missing layer was downstream consequence: F1/F13 missed silent population drift failure, F16 missed retrofit risk, F18 missed invisible lost drift, F30 missed economy erosion, and F40 missed screen-reader queue overwhelm.

**Subdomain patterns.** Simulation/sync/audio/accessibility were strongest. Social and account-quality-of-life whys were weakest: the plan captured per-invite sharing, actual-aviary visits, visit logs, and export mechanics, but the reconstruction did not recover the relationship rationale behind them.

**Evidence-bound effects.** Ten included feature whys were marked `rule_without_why`. These rows counted for planning capture but received no fidelity credit because the frozen reconstruction did not contain the gold rationale. No ungrounded reconstruction was credited.

## 4. Recommendations for v2 hardening

- Keep the v06 evidence-bound operator. It separated a near-complete implementation plan from a lower, more informative intent-carrying score.
- Add or promote more social/share/export affective whys. Strong planners can easily implement these as privacy or API rules while dropping the relationship rationale.
- Consider splitting some single-layer affective exceptions into multi-layer rows. F8, F11, F23, F34, and F37-F39 have separable mechanism, relationship, and downstream-product layers.
- Add an explicit diagnostic for "unnamed but instantiated" system principles. S3/S4/S6 were present across plan details but not recovered as named system intent.
- Preserve the strict cross-cutting bar, but ask scorers to report whether failures were due to missing PLAN inheritance or missing reconstruction naming; this run had mostly the latter.

## 5. Methodology caveats

- **Fresh-context fidelity.** The same-context safeguard appears to hold. The frozen reconstruction contains no gold IDs, no rubric vocabulary, and headings that mirror the plan rather than the gold list.
- **Single-run-at-temperature limitation.** This is one candidate/reconstruction/scoring pass; there is no variance signal.
- **Borderline capture calls.** I leaned inclusive on the distributed glossary (#7), the top-bar account/settings merge (#64), and invite-only sharing as visits-default-off (#90). Only #87 was marked missed, so borderlines did not materially affect the planning score.
- **System-level cross-cutting.** The strict ≥3-feature inheritance bar was easy for this plan because the implementation was highly cross-linked. The subjective part was whether B named a principle as system-level intent.
- **Confabulation cases.** I found no scored ungrounded-reconstruction cases.
- **Evidence-bound denials.** Several plausible v1-style recoveries were denied because the reconstruction had only a rule or mechanism, not the why.
- **Operational timing.** `TIMING.json` exposed phase 1 and phase 2A for run 001; phase 2B timing was not present in the scorer context, so score JSON includes only available bounded timing fields.
