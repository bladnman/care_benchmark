## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered better: 48 / 54 weighted credit (88.9%) versus 74 / 98 for affective whys (75.5%). The strongest functional recoveries were S7, F13, F17, F20, F35 and F36. The main affective losses were rule-without-why cases such as F5, F8, F19, F22 and F29.
- **Weight-3 vs weight-2.** High-weight whys did slightly better, 88 / 108 (81.5%) versus 34 / 44 (77.3%). The multi-layer rows still exposed compression: F2, F4, F10, F14, F16, F18, F27 and F30 lost one or more secondary/downstream layers.
- **System-level vs feature-level.** The planner preserved philosophy very well at system level (26 / 28), especially server authority, privacy, access, and presence. Feature-level fidelity was lower (96 / 124) because several local exception rationales survived only as build rules.
- **Multi-layer recovery patterns.** Primary causes usually survived. Secondary temptation/shortcut layers and downstream product-collapse examples were the most likely to be compressed away.
- **Subdomain patterns.** Accounts/sync, privacy, server simulation, and accessibility were the most faithful. Audio and social recovered core rules but sometimes missed affective reasons. Bird-engine identity was strong; mood-readable motion and starter-bird onboarding lost rationale.
- **Evidence-bound effects.** v06 denied full credit where the frozen reconstruction named the mechanism but not the why: F5, F8, F19, F22, F29 and several partial multi-layer rows. There were no ungrounded reconstruction cases.

The failure shape suggests a very strong implementation planner whose plan carried almost the entire product surface, but whose compressed downstream reconstruction was better at architectural causality than delicate relationship-tone distinctions.

## 4. Recommendations for v2 hardening

- Keep targeted feature-level headroom. This run hit 100% capture, so F29-F40 style probes are needed to distinguish implementation completeness from intent recoverability.
- Add more affective exception rows where the rule is easy and the reason is fragile: hidden numbers, error tone, silent social events, starter identity, and mood-without-label presentation.
- For multi-layer whys, require a per-layer missing-type tag in the report data: primary mechanism, shortcut/temptation, or downstream product consequence. This would make partial patterns easier to compare across runs.
- Retain evidence-bound scoring. It prevented rule matches from becoming automatic why credit, which is exactly where this run's remaining gap lives.
- Consider keeping the system-level cross-cutting bar, but ask scorers to record whether the loss was in B's reconstruction or in PLAN inheritance. S2 here was cross-cutting in the PLAN but compressed by B.

## 5. Methodology caveats

- **Fresh-context fidelity.** I treated the reconstruction as frozen and plan-derived, did not edit it, and did not read `prd/`, peer slots, or other waves.
- **Single-run-at-temperature limitation.** This is one candidate/reconstruction pair; no variance signal is available from this artifact alone.
- **Borderline capture calls.** No borderline capture call affected planning quality. All 120 features had explicit PLAN coverage.
- **System-level cross-cutting.** The (b) judgments are the most subjective, but each S1-S9 had at least three PLAN inheritance points listed in section 2.2.
- **Confabulation cases.** I found no clear ungrounded rationale in the reconstruction and did not apply a confabulation penalty.
- **Evidence-bound denials.** Several plausible v1-style matches were denied or reduced because B preserved the operation but not all rationale layers.
- **Rule-without-why cases.** Thirteen included whys were marked rule-without-why, led by F5, F8, F10, F14, F16, F18, F19, F22, F27, F29, F30 and S2.
