## 3. Diagnostic patterns

- **Affective vs functional.** Affective recovery was slightly stronger (75 / 98 = 76.5%) than functional recovery (40 / 54 = 74.1%). The functional losses are concentrated in precision and architecture rationales: F1/F13 presence accounting, F16 synthetic ID, F20 telemetry boundary, and F35 deletion.
- **Weight-3 vs weight-2.** Weight-2 whys recovered better (37 / 44 = 84.1%) than weight-3 whys (78 / 108 = 72.2%). The model preserved headline rules, but often dropped secondary/downstream layers inside multi-layer whys.
- **System-level vs feature-level.** System-level fidelity (82.1%) exceeded feature-level fidelity (74.2%). The plan encoded product philosophy well enough for B to reconstruct continuity, server authority, privacy, and accessibility; feature-level exception rationales leaked first.
- **Multi-layer recovery patterns.** Primary-cause layers usually survived. Secondary contributor and downstream-consequence layers were more fragile, especially when the plan stated the implementation rule but not the PRD's affective consequence.
- **Subdomain patterns.** Accessibility, privacy boundaries, visitor sharing, server authority, identity continuity, and no-punishment drift were strong. Onboarding/reward-loop whys (F29, F30), affective performance (F26), and mood-as-unlabeled-communication (F5) were weak.
- **Evidence-bound effects.** Several v1-style apparent recoveries were denied or reduced because B had only rule text: F5, F26, F29, F30, and parts of F4/F35.

What the failure shape suggests: this plan is excellent at implementation coverage and high-level product philosophy, but it sometimes compresses the non-obvious emotional consequence of a rule into a terse operational constraint.

---

## 4. Recommendations for v2 hardening

- Keep the targeted headroom additions. F29 and F30 were captured as features but failed recovery, which is exactly the distinction v06 is trying to measure.
- Add more exception-style whys where the obvious implementation instinct is product-wrong: onboarding customization, reward timing, editable personal records, and performance thresholds all created useful signal here.
- Preserve the evidence-bound operator. Without it, F5/F26/F29/F30 would be easy to over-credit from PLAN feature capture alone.
- Consider separating rule, rationale, and downstream-consequence columns in future reconstruction prompts. Many partials recovered the rule and primary purpose while dropping the second-order failure mode.
- Keep the system cross-cutting bar, but call out cases like S4 where the plan preserved the principle across features while the reconstruction did not name it cleanly.

## 5. Methodology caveats

- **Fresh-context fidelity.** This scoring pass used only the allowed phase-two package, the assigned plan and metadata, the slot 001 timing slice, and the frozen reconstruction. The reconstruction was not modified.
- **Single-run-at-temperature limitation.** This is one run with no variance signal.
- **Borderline capture calls.** Capture was inclusive but not meaningfully borderline: all 120 features had explicit or semantically equivalent support in the plan.
- **System-level cross-cutting.** The most subjective call was S4: the plan clearly encoded restraint, but B reconstructed it as scattered feature rationales rather than one system-level philosophy.
- **Confabulation cases.** No ungrounded reconstruction cases were counted. The validity audit found no leakage or rubric vocabulary.
- **Evidence-bound denials.** F5, F26, F29, and F30 had reachable captured anchors but no recoverable frozen-reconstruction rationale.
- **Rule-without-why cases.** Six rows were marked rule-without-why, mostly where operational constraints survived without the deeper affective reason.
- **Timing.** TIMING.json contained phase1 and phase2a entries for run 001 but no phase2b timing when this scorer wrote the score file.
