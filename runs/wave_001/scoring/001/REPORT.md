## 3. Diagnostic patterns

- **Affective vs functional.** Functional whys recovered better: server authority, drift calibration, privacy boundaries, and performance targets carried through more reliably than relationship-shaping affective whys. The big affective losses were no-streak/no-gamification (F14/F27), starter birds as arrivals (F29), age-based birds as non-rewards (F30), read-only notebook as observer record (F33), and social visit surfaces (F38/F39).
- **Weight-3 vs weight-2.** Weight-3 rows did not uniformly survive better. They often recovered L1 mechanisms but lost L3 downstream consequences. S1, S6, S7, S9, F1, F3, F4, F7, F16, F17, F18, F20, F24, and F25 all show this partial-layer pattern.
- **System-level vs feature-level.** System-level fidelity (57.1%) exceeded feature-level fidelity (41.7%). The plan carried general architecture and philosophy better than feature-specific rationales.
- **Subdomain patterns.** Simulation, sync, privacy, and performance were strongest. Tone exceptions, social defaults, social transparency, top-bar behavior, and several bird-engine relationship whys were weakest.
- **Evidence-bound effects.** The stricter operator denied credit where the reconstruction repeated the operational rule but not the why. This was the dominant failure shape, counted in 19 `rule_without_why` rows.

What this suggests: the candidate can produce a broad engineering plan, but it compresses intent into mechanisms. A downstream builder would implement many features, yet would not reliably know why those features must resist plausible future changes.

---

## 4. Recommendations for v2 hardening

- Keep evidence-bound scoring. It cleanly separates implementation coverage from intent transfer.
- Add more feature-level exception whys around product relationship and social defaults. This run showed those can be implemented as rules while losing rationale.
- Preserve multi-layer rows and summarize layer loss explicitly; downstream consequence layers were the most fragile.
- Add or retain probes for tone exceptions, notification defaults, and hidden UI/social affordances because those were easy to drop from an otherwise comprehensive plan.
- Keep the cross-cutting system-level bar, but ask scorers to name the inherited PLAN surfaces as this report does; it reduces drift in system-level calls.

## 5. Methodology caveats

- **Fresh-context fidelity.** The frozen reconstruction appears plan-derived and passed the validity audit. I did not use prior memory or peer slots.
- **Single-run-at-temperature limitation.** This is one candidate plan and one reconstruction. No variance signal is available from this artifact alone.
- **Borderline capture calls.** I leaned inclusive on several rows: #15, #22, #24, #52, #69, #85, #92, #94, #97, #103, #104, and #110. These move planning quality slightly upward but do not alter the main fidelity diagnosis.
- **System-level cross-cutting.** The strict three-surface bar was easiest for S1, S6, S7, S8, and S9; S5 was weaker because the matter-of-fact system exception was largely absent.
- **Confabulation cases.** I found no included row that required an ungrounded-reconstruction penalty. Some reconstruction phrases synthesize plan material, but they remained grounded.
- **Evidence-bound denials.** F6, F8, F10, F14, F27, F29, F30, F33, F38, and F39 are representative mechanism-only denials.
- **Operational compromise.** `TIMING.json` had phase1 and phase2a only for run 001, so the score JSON includes those bounded fields and omits unavailable phase2b/run-completion timing.
