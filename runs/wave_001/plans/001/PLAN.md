# Pocket Aviary — v1 implementation plan

This plan is based only on `prd/1-START_HERE.md` and the nine PRDs it lists. It specifies a browser product and implementation work; it does not implement that product. Run: wave_001 / 001. Values marked as initial calibration choices are concrete starting settings, subject to the acceptance gates below rather than live-user behavioral analytics.

## 1. Product boundary and decisions

Ship one private aviary per single-user account, email magic-link authentication, two system-selected starter birds, and optional age-based adoption up to seven. Ship approximately six species with distinct silhouettes and procedural call signatures, persistent identity and personality, continuing server simulation, multi-device snapshots, return greetings, listen-in, three offers, settle, sparse read-only notebook, account controls, explicitly invited read-only visits, and all accessibility modes together.

The scene is a single responsive horizontal place with three perch depths. The viewer observes bird choices; there is no placement editor. No mood badges, numerical traits, user attendance history, or scene labels. The normal encounter starts already in motion, with one bird noticing the returning owner in one to two seconds. The only initial fly-in is after initial adoption, when the quiet field is genuinely empty.

Exclude native apps, payments, SSO, passwords, multiple aviaries, shared ownership, configurable scenery, catalogs/rarity, recorded calls, feeding schedules, hunger, death, distress from absence, streaks, scores, badges, milestones, achievements, leaderboards, public discovery, profiles, follows, chat, comments, co-presence, and all engagement notifications. Notebook observations concern birds, never the owner's attendance. Neither analytics nor hidden tables compute social rankings or attention scores for later display.

### Decisions where the PRDs need interpretation

| Issue | Implementation decision |
| --- | --- |
| One local day versus multiple devices in different timezones | Persist a single IANA `aviary_timezone`, initially the owner's detected zone; allow an explicit account-settings change. Every device and visitor uses it. Never switch it automatically on a snapshot request. This preserves canonical moods/light; traveling owners can deliberately update it. |
| Settle required in the top bar, while layout allows exactly four icons | Keep account, accessibility, notebook, and offer icons. The offer/action popover contains the three offers and a separate `settle` command. Both offer and settle are reachable from the top bar without a fifth icon. |
| No scene chrome versus call captions and focus outlines | Captions and keyboard focus are the explicit accessibility exceptions. No ordinary bird labels, tooltips, or inline controls. |
| Focus initiates listen-in; Enter also triggers listen-in | Moving keyboard focus onto a bird engages listen-in. Enter ensures it is engaged without toggling it off. Pointer/touch clicking the same engaged bird toggles it off. Escape disengages and returns focus to the scene container; subsequent Tab/arrow entry can engage again. |
| Export requests vectors, but concepts prohibit numerical exposure absolutely | Export includes current vector state as an opaque authenticated-encrypted personality payload, alongside readable names, moods, notebook, and settings. Do not deliver plaintext traits, a decoding key, numerical summaries, or a debug endpoint. This preserves a state copy but limits independent interpretation; the absolute concepts rule wins. Record this limitation in the system-voice export description. No restore/import feature is included in v1. |
| General no-notification rule versus explicit social notification toggle | Honor the specific social exception: an account-settings toggle, off by default, explicitly permits a visit email. Only hosts who turn it on receive one quiet message per visit session, coalesced to at most one per hour. No push, scene announcement, settings badge, onboarding prompt, or automatic opt-in. Auth, invitations, verification, and requested export emails are transactional. |
| One-minute tick versus immediate interactions | Accepted events return server-authored presentation receipts promptly. They do not mutate personality or replace canonical state. The next tick consumes their immutable outcomes and updates canonical mood/state. Clients render an acknowledged short-lived reaction overlay, then reconcile against snapshots. |
| Absence quietness versus monotonic vocal-frequency trait | Never decrease any persistent trait. Daily mood, time-of-day, and decaying recent-attention context moderate realized calls and greeting propensity. Long absence trends toward ordinary ambient behavior, never mistrust, loss of color, or distress. |

These choices are part of the implementation contract. Do not silently resolve the export tension by shipping raw vectors or the social tension by turning on notifications for everyone. The separate designer-owned design-system document was not provided; create palette, pose, and focus specifications as project deliverables within the budgets here, rather than assuming inaccessible assets exist.

## 2. Architecture and responsibility boundaries

Use a TypeScript modular monolith for HTTP/auth/domain services, a separately runnable simulation worker, and PostgreSQL as the transactional source of truth. Use a durable job queue for ticks, email, exports, and deletion; PostgreSQL-backed scheduling is sufficient initially. Serve static versioned assets through a CDN. Use a small server-rendered HTML shell with an inline initial scene snapshot and species SVG poses, plus a lightweight TypeScript scene renderer and separately loaded settings/notebook UI. Canvas 2D draws ongoing motion; DOM supplies semantics, focus targets, captions, and settings. Avoid requiring a large 3D engine or an AudioWorklet to draw the first bird.

Responsibilities:

- Identity module owns encrypted email, login challenges, device sessions, and email changes. All references and work items use synthetic UUIDs.
- Owner API validates commands, records append-only interaction events, reserves cooldowns, and returns receipts. It never updates personality columns.
- Simulation worker is the sole writer of stored personality, mood evolution, canonical perch/motion/call plans, weather, and observation facts. Creation/migration initialize or preserve state through restricted simulation-owned operations; they do not infer state from historical logs.
- Snapshot projector converts canonical internal state into display recipes. No trait vectors or named numerical trait fields leave this boundary. The numeric coordinates, colors, timing, and gain envelopes needed for rendering are not a trait dashboard.
- Visit API accepts a scoped visit session and exposes only the same scene projection the host sees. It cannot call owner commands and never creates drift input.
- Client evaluates supplied schedules and interpolation, synthesizes calls, collects precisely qualified owner-presence intervals, and renders accessibility prose. It never runs mood or drift simulation.
- Operational metrics exporter has no permission to query simulation/event tables. Only fixed operational counters and timings cross that boundary.

Flow: authenticated navigation -> private snapshot embedded in edge-delivered HTML -> immediate bird markup -> scene renderer hydration -> owner arrival confirmation and low-frequency pulls. Commands -> validated event/receipt transaction -> next minute tick -> versioned canonical state -> next pull. Tick scheduling continues when the account has no connected browser. No client-to-client sync, CRDT personality merge, client absolute-vector writes, or reconstruction from logs.

Deploy API near the primary database and use regional authenticated snapshot delivery. Static files may be publicly cached; personalized HTML and snapshots use `Cache-Control: private, no-store`. An internal encrypted projection cache may be keyed by aviary UUID/version and checked against account/session status; never expose cross-user CDN cache keys or leak a cached snapshot after authorization expires. Owner and visitor authorization is checked for every fresh pull before conditional 304 responses.

## 3. Persistent data model

All primary keys are random UUIDs except strictly internal ordered event sequence numbers. Store instants as UTC; compute local-day context from the persisted IANA zone. Use foreign keys and explicit account deletion ownership. Encrypt private payloads and names/notebook content at rest with per-account data keys; identity email encryption belongs to the identity module. Names are plain text after validation, never HTML; normalize Unicode, bound to 40 graphemes, and render using text nodes. Name changes preserve bird IDs, seeds, grammars, vectors, and notebook attribution.

Recipient emails for people without accounts live in an encrypted, restricted invitation-contact record: the social PRD requires sending and showing this address, but it is not an account identifier. If the recipient has an account, reference its account UUID and decrypt its single account email only in the authorized identity/contact service. Do not copy that email into visit logs. Purge contact data when no remaining invitation/log needs it, or on host deletion. Private visit logs may persist for the host's transparency; they are not exported to analytics.

Identity lookup uses the identity store's encrypted search capability; an email lookup value is never a cross-service identifier, partition key, telemetry dimension, or log field. Per-email rate limits are evaluated within this identity boundary and do not expose email or a reusable email-derived ID. Database partitioning, tick queues, snapshots, and private incident references all use UUIDs.

## 4. HTTP contracts and account flows

Version routes under `/api/v1`; use JSON, typed schemas, strict field allowlists, byte limits, no unknown payload fields, same-origin cookies (`Secure`, `HttpOnly`, `SameSite=Lax`), CSRF protection for mutations, and ownership/visit-scope authorization. Use HTTPS and a restrictive CSP. Redact token-bearing URLs, request bodies, bird names, notebook text, and emails from access/error logs. JSON failures have stable codes plus matter-of-fact copy; do not expose stack traces.

### Identity and lifecycle

| Method and route | Contract |
| --- | --- |
| `POST /auth/magic-links` | Email and purpose; identical generic response whether account exists. Initial per-email limit five requests per 15 minutes with separate IP abuse throttling; allow new requests within limits. Email a cryptographically random single-use link valid 15 minutes. |
| `POST /auth/magic-links/consume` | Exchange token atomically for owner device session; no login on prefetch GET. Landing page asks for explicit continuation so email link scanners cannot consume it. Concurrent consumption has one winner. |
| `GET /account/sessions`, `DELETE /account/sessions/{id}` | Owner's device list and revocation. Revocation invalidates next pull/command, closes presence leases, and removes private client state on response. |
| `PATCH /account/settings` | `If-Match` settings version; validated preferences/timezone/notification consent. Stale write gets 409 and current settings; no silent overwrite. |
| `POST /account/email-change`, `POST /account/email-change/verify` | Verify new address before atomic swap; old address remains active until verification. Enforce verified-address uniqueness within identity service. |
| `POST /account/exports` | Generate a transactionally consistent snapshot asynchronously; return status, no aviary toast. Email a private download link to verified address; link expires after 24 hours. Recheck account status at generation and download. |
| `POST /account/deletion`, `POST /account/recovery` | Mark deletion immediately, revoke visitors and stop ordinary owner operations/ticks. Recovery within 30 days restores stored state without resetting birds; accessible `I changed my mind` control on every signed-in deletion page. Recovery and hard-delete contend under one account lock. |

On first successful sign-in, atomically create account, aviary, two distinct starter species from the six-species pool, stable bird IDs, stored starting vectors, and suggested names. No species catalog. Keep `adoption_complete=false` until names are confirmed; retries cannot create another aviary or pair. During this initial naming flow the quiet empty field is permitted. Confirmation produces the sole initial soft fly-in, or pose cross-fades in reduced motion. Never repeat it on normal returns.

### Owner state and interaction API

`GET /aviary` returns a compact snapshot: schema/simulation version, state version, server_now/as_of/valid_until, timezone/day/light/weather, birds' IDs/names/species, semantic pose/perch/action timelines, call-plan seeds/recipes and stable signature references, and active settled context. Exclude vectors, event history, owner visit counts, other devices, and notebook contents. Target <12KB compressed for seven birds; separate notebook pagination. `ETag` is the state version; server time is still supplied for a 304. Only return a snapshot after authorization; cache misses show the quiet field, not fabricated/default birds.

`POST /aviary/arrivals` accepts a session arrival nonce and reason (`navigation/visible_return/resume`), appends one event, and returns an arrival recipe tied to the current canonical state. Bootstrap HTML may include a short-lived signed arrival proposal so the first greeting need not wait for a second round trip; confirmation registers its fact for the next tick. An unconfirmed proposal supplies no presence/drift. Arrival selection uses last owner attendance/absence length internally, boldness, warmth, and mood. Never display absence duration. Repeated requests with the same nonce cannot generate repeated greetings/notebook candidates.

`POST /aviary/events` accepts batches up to 32 events/16KB: `{idempotency_key, client_sequence, kind, bird_id?, interval?, payload}`. Session/device derives from auth, never payload. Kinds: presence interval/end, listen-in start/end, offer, settle, resume, audio preference change. The server assigns order and returns accepted/rejected IDs, server times, current version, and receipts. Listen-in durations are calculated from qualified leases, not trusted client totals. Presence batches normally ship every 15 seconds, and terminal events promptly on blur/hide/settle/pagehide. An optional same-origin beacon uses the same validation; loss of a terminal event is safe because leases expire.

Offer payloads permit `seed`, a validated `song_fragment_id` from a small library, or `still_pool`; no uploaded music. User offers to the aviary from the top bar; the server chooses the eligible recipient(s), guided by nearest/attentive bird and mood, not a user bird-placement command. Apply a three-minute per-bird cooldown across all offer types and devices. A scene-wide water pool can invite multiple birds, each with its own cooldown. If all eligible birds are cooling down, show a quiet explanation in the already-open offer panel, without countdown badges or punishment language. Reserve cooldowns and append reactions in the same transaction.

Settle receipts carry a five-second undo token. A scene click within five seconds sends undo before any listen-in/offer action. Later deliberate scene interaction sends resume; passive pointer motion alone does not reopen presence. Settle ends this owner's viewing-session presence and listen-in, persists the scene evening/quieting context for that session, and yields a small canonical mood-quieting stimulus. Other active owner devices do not lose their presence. Their birds receive any canonical mood update on the next pull. No trait reward for settle; tab close terminates presence equivalently without the ceremonial palette overlay.

`GET /notebook?before=cursor&limit=30` returns immutable oldest-accessible history, newest first on entry, stable cursor pagination, and no event-counter summary. `PATCH /birds/{id}/name` uses a bird metadata version; rename conflicts are explicit and never touch simulation state. `GET /adoptions/available`, `POST /adoptions/{id}/accept` expose only current age-based opportunities from account/bird settings. Initial thresholds: 90, 180, 270, 365, 540 elapsed days for birds three through seven. Accept one at a time, optionally defer indefinitely; no urgency, catalog, badges, countdown, or automatic adoption. Transactionally check capacity and opportunity uniqueness. Allocate distinct call-signature parameter sets even when species repeat.

### Invitation and visit flow

`POST /invitations` explicitly takes recipient email, issues a hashed 256-bit random one-time token with unused expiry 30 days, and queues that transactional email. Social starts unused/off; sending is the opt-in for that invitation. `GET /invitations` and `GET /visits` are private settings lists of outstanding invites, active visits, and historical visitor email/date/approximate duration, without icon badges. `DELETE /invitations/{id}` revokes unused or active access atomically and removes its active listing. Preserve historical visit facts as transparency rather than silently destroying history; no success toast.

A visitor link GET displays a minimal confirmation; `POST /visits/redeem` consumes it once and issues a separate visit-only cookie. Choose active-session lifetime 24 hours, bounded by revocation and explicit leave; the one-time link cannot start another session. Do not require the visitor to adopt birds or create an account. `GET /visit/aviary` returns the exact shared scene projection with host timezone, mood, weather, and audio plan, stripped of owner-only metadata and receipts. Pull every five seconds while visible and immediately on resume. Recheck invitation/session on every request and before 304: revoked, expired, or unavailable -> identical matter-of-fact unavailable page and clear rendered private state. This is the PRD's immediate-revocation contract at the next pull; worst visible-tab delay is five seconds plus network time. On loss of contact, blank the private scene after a ten-second authorization freshness lease; offline clients cannot retain an indefinitely watchable cached visit.

Visitors have no arrival/greeting event, presence reporting, listen-in, offers, settle, rename, or notebook interaction. Do not render owner bird controls; reject attempted owner API calls with 403 even if a visitor crafts requests. Local audio enable/mute, captions, narration, and reduced-motion controls remain available because they only affect that browser's presentation. Visit heartbeat records only approximate session duration in the private host visit log; it cannot enter the simulation event log. No cursors, host-online status, or co-presence channel. If the host opted into visit email, enqueue it once independently of simulation, never include bird behavior.

## 5. Presence and concurrency correctness

Use a five-minute recent-activity window initially. Eligible time is exactly the intersection of visible document, focused window, and pointermove OR keypress in that window, with session not settled. Do not substitute clicks, tab-open duration, audio playback, or visitor activity for the stipulated signals. Touch users qualify when supported input generates pointermove or keypress; provide ordinary keyboard-accessible interaction paths and test actual mobile pointer-event behavior rather than silently weakening the definition.

Maintain local monotonic timestamps for every qualification boundary and stop immediately on blur, hidden, five-minute expiry, settle, logout, or pagehide. Pointer/key handlers keep only the latest timestamp, never content or movement traces. A presence interval cannot start before the first qualifying pointermove/keypress. Ten minutes of perfectly still watching after one movement credits the first five, not all ten; calibration of the window can change within the stated few-minutes range without pretending continuous attention is measurable.

The server grants short receipt-based leases, clamps each heartbeat to at most 15 seconds of reported qualified time, and expires a missing heartbeat after 20 seconds. Require a live authenticated session, consecutive bounded intervals, and no client backdating beyond 30 seconds; clients cannot upload an offline hour. Local boundaries improve accuracy; the server bounds unprovable claims and never infers presence from a keepalive alone. Cross-device credit is a union of overlapping account intervals. Listen-in intervals similarly union by bird, limited to eligible owner-presence time; concentrating attention on multiple devices cannot multiply drift.

Idempotency is scoped to `(aviary, session, key)` and retained at least seven days; sequence/order is server-assigned. A retry returns the original outcome, without another offer, presence interval, or greeting. Late events are applied in receipt order for the next tick, not replayed into an old personality state. Invalid or expired receipts cannot create a lasting optimistic state. Offline clients render their bounded last-known scene with a quiet system connection message outside the scene; commands require acknowledgement and remain disabled until connection resumes. Do not persist a durable offline mutation queue; uncertain in-flight actions may retry their original key within 30 seconds, never as new commands.

Multi-device races in renames/settings use version checks; offers use locked reservations; ticks use the transaction/cursor discipline below. A client with a stale snapshot may send a gesture, but it cannot send a vector or dictate reaction acceptance. The server uses current state, returns current-version receipts, and the client blends to that result. Conflicts do not ask the user to choose between bird personalities because there is only one.

## 6. Server simulation engine

### Tick scheduling and transactional application

Use a 60-second initial cadence, staggered by a stable UUID-derived bucket so accounts do not all tick on the minute boundary. The scheduler scans indexed `next_tick_at` records and dispatches durable `(aviary_id, due_tick)` jobs regardless of connected clients. Shard worker assignments by UUID. Do not implement an inactive-account exemption: birds continue having mornings, weather, and moods while nobody watches. Deletion-pending accounts are the explicit lifecycle exception.

Each job:

1. Acquire the aviary row lock, check deletion status and due-time/idempotency, and load its stored vectors, filters, fast state, and cursor. Missing vector data is corruption: preserve the record, stop that aviary's tick, and restore from the durable stored-state backup. Never create default vectors or derive them from events.
2. Freeze the highest committed event sequence to consume in this tick. Read subsequent events through that bound in sequence order. Verify all targets belong to this aviary; derive interval unions/capped stimuli from validated events. Events committed later wait for the next tick.
3. Advance the filter, apply nonnegative additive trait deltas, advance daily mood context and weather timers, integrate accepted offer/settle/arrival facts, and run bounded bird-to-bird transitions. Use a stable seed per tick and engine version so retrying produces the same result.
4. Allocate perches/actions and procedural call timelines covering the current and next minute, with stable IDs for overlapping schedule windows. Preserve already-started accepted receipt actions; do not restart animations at snapshot boundaries. Extract candidate observation facts without writing routine session logs.
5. In one database transaction, write current vector plus additive delta, fast state, updated filters, notebook entries if selected, new snapshot version, event cursor, last/next tick timestamps, and a small internal processing receipt. Publish cache invalidation via a transactional outbox after commit.

Only the simulation DB role can update personality columns; API and analytics roles cannot. A crash before commit changes nothing; a crash after commit returns an already-applied tick. Cursor advancement and vector changes are inseparable. At-least-once delivery is acceptable because tick IDs and cursor bounds make application exactly once. Ordered events remain immutable; stored personality is the durable state, not a materialized projection that gets rebuilt on a replay.

On worker outages, reschedule overdue ticks independent of clients. Advance in chronological one-minute substeps using stored state, elapsed time, and historical timezone context; split large catch-up into bounded jobs and commit a progress watermark. Limit a transaction to 60 missed steps initially. Presence credit requires actual accepted historical intervals; absence generates none. Never multiply one last heartbeat by outage length. Render last stored snapshot quietly while recovering and surface a matter-of-fact connection/state-loading error if freshness exceeds the bounded schedule horizon. Tick freshness and queue backlog alarms must detect this before users do.

### Slow drift: explicit starting algorithm

Store traits as fixed-point values with sufficient fractional precision for minute increments; keep filter accumulators in double precision or deterministic fixed point, with rounding tests. Seed individual traits in approximately [0.20,0.55] with species-consistent variation, so individuals differ without starting at the ceiling. Never seed all birds identically.

For each trait `j`, calculate a nonnegative stimulus rate `r_j` from qualified presence plus bounded bird-specific attention. Reference calibration: ten minutes of qualified daily presence is one unit-day. For a minute with `q` qualified seconds, presence rate in unit-days/day is `144 * q / 60`. Cap qualified presence input to 20 minutes per rolling 24 hours, with smooth saturation near the cap, to keep longer sessions from accelerating growth arbitrarily. This is hidden engine calibration, not a displayed meter or a reason to end a session.

Presence is at least 80% of each trait's permitted stimulus. Listen-in supplies at most 15% additional input for the focused bird's warmth/vocal traits; accepted offers and nearby gestures together supply at most 5% for curiosity/boldness. Listen-in with no qualified presence supplies zero slow drift. Offers can produce their immediate reaction without presence but contribute only within the small offer budget; spam cannot dominate. No negative input, no settle coefficient, and no mute penalty. Muting is recorded only as the user's simulation context/preference, never a reason to reduce a trait or disadvantage hearing/audio-off users; the PRD does not prescribe an audio penalty.

For timestep `dt` in days, initially use filter time constant `tau=2 days`:

```
a = exp(-dt / tau)
z_next = a * z_old + (1 - a) * r
z_mean = r + (z_old - r) * (tau / dt) * (1 - a)
delta_j = max(0, k_j * z_mean * (1 - p_j) * dt)
p_next_j = min(1, p_j + delta_j)
```

The integrated `z_mean` prevents short attention bursts from becoming tick-size artifacts. Start `k_j` at 0.004 per reference day, with trait-specific adjustments within 25%. Cap realized per-trait delta at 0.004 per rolling 24 hours and preserve unapplied fractional precision. Bound all inputs and reject NaN/invalid ranges. The `(1-p)` factor approaches the ceiling gently; a cap is not an unlock or a level. Absent input decays the filter, so residual positive drift from earlier presence can continue briefly while the owner is away; traits never decrease and never reset.

These coefficients are an executable initial hypothesis, not a claim that the perception calibration is already solved. Before launch, synthetic ten-minute-daily fixtures starting around 0.35 should show an instrument-detectable delta of at least 0.005 in several presence-driven traits at day seven, roughly 0.025–0.06 by day 21, and no visually conspicuous single-session jump. Adjust coefficients/render mappings together until controlled perception review confirms approximately three-week visible change. Never calibrate by collecting average real-account drift or interaction histories. Compare stored vectors only for synthetic accounts and consented laboratory fixtures; live instrumentation carries no trait values.

Acceptance properties: every trait is monotonic; zero new input only drains the filter; one long absence cannot erase identity; two devices with identical overlapping presence produce the same delta as one; repeated events produce no extra delta; settle and ordinary close with the same intervals produce equal slow drift; rapid offers/listen toggles cannot outpace passive attention; changing a name changes no engine field.

### Mood, day cycle, and weather

Use `wary/content/curious/drowsy/alert` as the v1 mood enum. Model sleeping/eyes-closed as a drowsy pose, not a new numerical status surface. Evaluate a seeded transition table each tick, with personality-weighted probabilities and 5–20-minute dwell timers to prevent flicker. At each local dawn, blend away yesterday's transient interaction bias toward species/personality/day-context priors over 30–60 minutes; never reset to neutral on page open. Store transition timers and mood history summaries, not an open-time default.

Initial rules: seed acceptance favors content/curious; a curious bird investigates a pool, a wary bird delays, a drowsy bird may watch or ignore. Song fragments can elicit joining, pauses, or counter-calls from vocal propensity and mood. Early morning favors alert; dusk and night favor drowsy for most species. One nightjar-like species remains capable of late calls so night is alive. Ambient wind temporarily favors alert/wary for suitable individuals, rain suppresses realized call rate without decreasing vocal traits. No absence-to-wary rule or hunger/distress subsystem.

Generate quiet weather on the server from time/aviary seed: initially rain two or three times per local week, lasting roughly three to eight minutes, and occasional soft wind. No external weather/location API and no thunder/snow. Weather state is canonical, timers persist, and visual/audio intensity remains restrained. Continuous lighting is a server-supplied palette/time envelope evaluated in the host zone, not a device-local clock choice. DST changes use IANA transition rules; monotonic elapsed time governs durations. Explicit zone changes update day context gradually, without instant personality or mood resets.

Bird-to-bird behavior uses the previous committed states plus this tick's accepted stimuli, avoiding iteration-order cascades. A call may prompt one or two delayed replies; wary/alarm influence is weak and time-limited. Bound responses to one generation per call and impose refractory windows so seven birds cannot trigger an endless alarm loop. Chorus windows emerge from overlapping call probabilities, with staggered onsets, rather than a user-arrival fanfare. Greeter choice may favor bold/warm birds, but soft weighted randomness allows another bird to greet first occasionally. The primary bird notices at 0.8–1.8 seconds after scene readiness; any additional response is later and staggered.

### Motion and call planning boundary

Canonical action descriptors contain kind, source/target perch slot, start time, duration, procedural seed, and pose envelope. Mood influences rates of preening/scanning/head-tilting/body-shuffling and perch choice; boldness biases front positions, warmth biases proximity to other birds. Mood effects do not have labels on the scene. Perch capacity/spacing rules keep all seven distinct and visible. Position selection occurs server-side; responsive projection maps slots to viewport pixels client-side.

Stable bird signature consists of a species motif grammar plus a bird-specific base register, timbre, motif rhythm family, and immutable seed. Personality/mood vary motif probability, call timing, duration, dynamics, and pitch contour within bounded signature ranges. Drift must not make Pip sound like Wren. Initial six-species authoring includes several motifs each, distinctive silhouettes/palettes, and a night-active signature. Repeated species get sufficiently separated individual registers/rhythms, verified in seven-bird listening sessions.

The server compiles a small timed call schedule/grammar recipe using the canonical hidden state. The browser expands motifs into parameterized call events using recipe seeds: no mood transitions, personality updates, or independent call-response simulation. Motifs permit note/trill groups, rests, curved pitch contours, attack/decay envelopes, harmonic/noise mixtures, and bounded continuous variation. Exclude identical consecutive expanded calls within a bird's recent synthetic plan; preserve each signature. Schedule overlapping future windows by stable call IDs and retain a five-second near-term commitment horizon so a fresh snapshot cannot reschedule an imminent/playing call. Caption generation uses the final expanded descriptor, not a fixed species string.

### Notebook generation

Use deterministic, authored naturalist templates with varied phrase assemblies, grounded observation facts, and deduplication; no LLM or third-party text service receives a user's simulation history. Facts include changed greeting order, a sustained quiet preen, an unusual call exchange, a weather-shaped perch choice, or a bird approaching after earlier hesitation. Internal rolling fact memory can compare birds over a week; it must not emit owner attendance observations or numerical trait changes.

Start a sparsity target of one entry per two to four days for the synthetic regularly visited fixture. Score novelty relative to that aviary's recent observations, not population metrics. Use a normal 48-hour spacing window and allow at most one exceptional extra observation per day, with strong deduplication. Capture facts during absence as well; there is no guaranteed session-entry note. Rare observations can be deferred and superseded instead of generating a feed. Do not fabricate multi-minute behavior from a single instant. Every entry carries immutable name-at-observation, current tense/lowercase prose, and enough provenance for private correctness tests. Renaming does not rewrite the old observer's record.

## 7. Frontend rendering and session choreography

### First paint and continuity

Server-render minimal SVG birds at the exact snapshot action phase, inside the quiet field, before JavaScript runs. Their shape, perch, light, and pose are canonical, not generic placeholders. Inline the critical tiny pose assets and necessary CSS; do not wait for WebAudio, account panels, large art downloads, or font fetching. After hydration, swap the SVG presentation to Canvas only at a matching frame; retain equivalent DOM focus targets. Test this transition for no flash, duplicate bird, or pose restart. If Canvas is unavailable, the compact SVG pose renderer still supports the designed slow cross-fade surface.

Maintain estimated server clock offset from response time intervals and monotonic client time. Evaluate each action from its persisted start timestamp, so navigation starts mid-preen rather than at pose zero. Interpolate snapshot targets along supplied transitions; retarget gently only when a newer version changes the plan. Never interpolate trait vectors. Skip expired calls/animations when returning after suspend; do not play a catch-up queue. Pull immediately on visibility regain or a render gap greater than two seconds, then adopt the current timeline without a neutral mood reset.

While visible, pull owner state every 15 seconds with jitter; after acknowledged important commands, schedule another pull until their version is consumed. Idle ornaments are locally generated rendering-only leaves/feathers and subtle parallax; they create no server event. Seed a bounded number at nonzero phase so the first rendered frame can already contain motion. On hidden documents, stop RAF, ornament generation, snapshot polls, and audio scheduling; terminate presence immediately. On blur with document still visible, stop presence but continue visible motion. The server continues ticking in either case.

If a slow/cold snapshot is unavailable, show a quiet sky field with restrained faint ambient motion, no spinner or textual welcome. On a prolonged actual failure, provide an actionable matter-of-fact error in the system shell. Never recover by resetting birds. Initial adoption is the only genuine empty-to-fly-in sequence; ordinary returns always resume an already populated aviary.

### Composition and viewport

Use three logical depth bands, background sky/soft foliage, middle bird/perch plane, and occasional foreground ornaments. Layout slots are normalized semantic positions, not user-editable coordinates. At narrow widths, compress horizontal spacing and use slight vertical staggering within the three perch zones; at wide widths, spread them. Scale scene content uniformly within its container and adapt slot spacing, maintaining bird body proportions rather than stretching sprites. Safe bounds include each bird's pose/wing extent and caption anchor. No bird can leave the frame, be cropped by viewport changes, or be covered persistently by another bird.

Reference tests: 320px-wide portrait, typical 390px phone, tablet portrait/landscape, 1366px laptop, wide desktop, short landscape viewport, browser zoom to 200%, and text reflow to 400%. The scene remains a single fit-to-view region; settings/notebook can scroll in accessible panels. If the physical viewport is unusually small, reduce ornament density and use compact poses/spacing, not scene panning. Touch targets use at least 44px logical hit regions where feasible, disambiguated by nearest visible bird and stable keyboard order. Seven-bird narrow-view tests are a ship gate.

Top bar fades to nearly transparent after four seconds of inactivity. Any pointer movement, keyboard activity, touch on the reserved bar area, hover, focus within, or open panel restores opacity. Never fade a focused control or an open menu. Icon positions/hit areas remain stable; the scene does not shift as opacity changes. Focus outlines and captions do not inherit the fade. No textual greeting, counter, badge, or hover tooltip appears in the scene.

Listen-in locally ramps immediately after focus, with server event acknowledgement supplying slow-attention accounting; a network error rolls back uncertain state gently. Changing birds cross-ramps both gains. Clicking empty scene or moving focus away ends listen-in, as do Escape, settle, and hide. Settling shifts light over about four seconds and reduces calls, with a five-second scene-click undo. Do not automatically treat subsequent incidental movement as re-engagement. Close is always allowed without a ritual.

### Reduced motion

Apply OS preference before the first paint; load no default-motion flash first. Account override can select system/on/off. Replace preen/head/micro-motion with authored still poses cross-fading over roughly two to four seconds at 10–20-second intervals. Flights become perch-to-perch pose cross-fades, and initialization's fly-in becomes a fade. Remove leaf/feather drift, positional parallax, and fast ripples; keep weather through slow palette/texture changes. Day/settle lighting transitions take approximately eight seconds. The same mood/action facts, calls, captions, drift, notebook, and greetings remain. Avoid simultaneous moving layers or flashing opacity. Treat this renderer as a reviewed aesthetic, not `animation: none` on a paused frame.

## 8. Procedural audio and listen-in mix

Use one WebAudio context per active page, with shared wavetable/noise resources, per-bird synthesis voices -> per-bird gain/pan -> gentle bus compressor/limiter -> master gain. All resources are generated mathematically; no downloaded/recorded call files and no fallback audio loops. A small song-fragment library is note/contour data synthesized through the same graph, not uploaded recordings. The initial bird paint is independent of audio initialization.

Expand call descriptors deterministically, then synthesize pitch automation, timbre filtering, envelope, pauses, and trills with continuous bounded variations. Schedule against AudioContext time with a 100–200ms lookahead scheduler; map server-relative call times to context time. Late calls are skipped or resume only a valid remaining envelope, never piled up. Use a capped reusable voice pool initially 12 simultaneous voices for seven birds, stealing only low-amplitude tails with a ramp if necessary. Disconnect ended transient nodes, reuse generated buffers/periodic waves, and remove automation/listener references. No growing call history in memory; a bounded recent descriptor ring is sufficient.

Ambient chorus preserves individual signatures: stagger most onsets, limit synchronized peaks, use shallow spatial panning based on perch, and reserve headroom. Do not phase-align identical oscillators across birds. Start master peak target below -6dBFS and test limiter activity/listening comfort; normal operation should not continually squash the chorus. Enforce quiet nighttime/rain realization without changing persistent traits. Listen-in ramps over 1.5–2.5 seconds: focused gain increases modestly while other birds retain a nonzero ambient floor, initially approximately -12dB relative to ambient. Disengagement uses the same ramp; smooth every gain change, including interruption and rapid refocus. Master user mute alone silences all calls intentionally.

Browser autoplay restrictions mean audible calls cannot be guaranteed before a gesture. If a context can legally start, start at the current schedule phase. Otherwise render fully alive with captions temporarily on and expose a plain `Enable sound` control in the existing accessibility/audio surface; no modal, greeting banner, or canned substitution. The next eligible user gesture may resume the context. Distinguish user mute from failure: a muted user retains their selected caption preference, while unavailable/denied/interrupted WebAudio defaults captions on for that device. Audio availability never affects drift credit or the quality of motion/narration.

Handle context suspension, hardware interruption, and unsupported WebAudio by gracefully silencing, enabling captions, and emitting only aggregate error categories. Recreate a failed context at most once per explicit retry gesture; never create multiple contexts in an automatic loop. Hide/unload suspends/disposes scheduling, and returning starts at current time without old calls. Test Safari gesture handling and long interruption behavior in the supported-browser matrix.

## 9. Accessibility, language, and interaction semantics

Accessibility ships in the first usable vertical slice and in v1, including visits. Use the same projected semantic action/call data for narration, captions, visible poses, and notebook facts so they cannot tell contradictory stories.

- Narration: a concise running prose region with `aria-live=polite`, atomic updates, default idle cadence 45 seconds, adjustable within 30–60 seconds. Replace/coalesce stale queued idle prose instead of accumulating sentences. A confirmed greeting, offer reaction, or settle observation gets prompt priority without interruptive alert announcements. Omit hidden-tab updates. Deduplicate equivalent observations and suppress idle updates while the user is reading notebook/settings. Provide pause/resume and an on-demand current description. Never narrate numbered perches, raw mood labels, trait scores, or the user's absence/attendance.
- Call captions: derive phrase count, rise/fall, trill, pause, loudness, and perch description from each final procedural descriptor, so the prose matches the actual synthesized call. Place near bird in a contrast-backed caption layer with bounded overlap handling; for overlapping calls, shorten and stagger text without falsely claiming they are one call. Reflow within safe scene bounds. In reduced motion captions change gently without positional travel. Caption text is accessible as on-demand text, but not all calls are shoved into the live narration queue.
- Bird controls: retain a DOM semantic scene region with roving tabindex. Tab visits the four top-bar controls and then the first bird; arrows move through a stable bird order, Enter ensures listen-in, Escape exits. Pointer and keyboard focus share the same interaction state. Accessible bird names include the user's bird name and species, not internal numerical traits. Canvas itself does not contain duplicate interactive semantics. On visitor scenes, bird descriptions are noninteractive and no listen-in buttons exist.
- Panels: notebook/account/accessibility/action popovers have explicit headings, keyboard-reachable controls, predictable focus management, Escape close, and restoration to the invoking control. Notebook pagination uses accessible load-more behavior alongside virtualized visual rows so assistive technology can read history without losing focus. Adoption and email-change forms label fields and expose errors in matter-of-fact language.
- Shortcut: offer/action menu opens via a documented configurable `Alt+Shift+O`; it is optional and also reached through Tab. Avoid overriding bare character keys or browser commands. Settle is a labeled command in that menu. No mouse-only affordance.
- Contrast: normal text minimum 4.5:1; large text and focus/control boundaries minimum 3:1. Use subdued but compliant palettes and caption backplates across morning/night/rain states; test against actual composited backgrounds. The nearly faded top bar is idle decoration until interaction restores readable opacity. Never show focused or active copy below contrast thresholds.

Product copy is lowercase, present-tense, specific to bird/action: `pip tilts toward the still pool; wren keeps to the back rail.` System copy uses normal capitalization and direct action: `Your session timed out. Sign in again to keep watching.` Name input is escaped and text-only; do not impose lowercase on the stored user name, but templates may apply grammatical presentation consistently. Human review covers both voice libraries. No generic happiness messages, milestone prose, gamification terms, explanatory trait meters, or stock `Welcome back` strings.

Manual acceptance includes VoiceOver/Safari on desktop and phone, NVDA with a supported desktop browser, keyboard-only ownership/visit/account flows, audio-off/captions, reduced-motion-first-load, 200% zoom, and high contrast/forced-colors focus behavior. Review charm and pacing with screen-reader and reduced-motion participants, not just automated semantic checks. User research fixtures must be synthetic or explicitly consented, isolated, and never routed into population interaction analysis.

## 10. Performance budgets and operational observability

The PRD's initial-JS ceiling is not a target to fill. The first bird cannot depend on downloading two megabytes over 4G. Use a much smaller critical path and reserve the rest for lazy surfaces.

| Budget | Initial allocation / gate | Verification |
| --- | --- | --- |
| Initial JS at first paint | Strictly <2MB gzip; working target <=200KB including framework/runtime/renderer, with no UI-library/audio settings chunk blocking paint | Build manifest checks total initial/transitive chunks; inspect network waterfall |
| HTML, critical CSS, inline pose/snapshot | Aim <=35KB compressed total, snapshot <=12KB for seven birds | Seven-bird and first-account fixture size checks |
| Time to first visible bird | <500ms from navigation on defined mid-tier mobile/4G profile; target p95 <500ms in reference synthetic geography/device tests | Navigation-to-painted-canonical-bird mark, screenshot/paint evidence; not a loading silhouette or canvas created mark |
| First greeting | One bird visibly notices within one to two seconds after owner scene appears | Deterministic seeded return scenarios, narrative/audio-off variants |
| Reference first-paint path | Budget ~250ms navigation/edge response, ~100ms transfer, ~100ms parsing/layout/paint, <=50ms reserve | Warm and cold navigation, no service-worker cache assumption |
| Idle frame rate | Sustain 60fps over 30 minutes on a five-year-old mid-range laptop at seven birds | Frame interval distributions, long frames, CPU profile; target scene work <=8ms/frame, p95 frame interval near 16.7ms |

Fix the reference test profile in CI documentation: a named mid-tier mobile test device (or reproducible CPU throttle) with 4G shaping, approximately 4Mbps down/1Mbps up and 80ms network RTT, tested from several geographies. A 500ms navigation budget across an arbitrary slow connection is impossible; preserve the quiet-field behavior there, and report the reference profile honestly. Do not hide cold loads or slow regions from the benchmark. If the geography/TTFB budget fails, move snapshot delivery closer or reduce critical bytes; do not show a fabricated bird to mark the metric early.

Cap Canvas device pixel ratio at 2 initially; pre-render static foliage layers; reuse pose paths and scratch structures; update captions only at call boundaries; pool ornament objects. No per-frame component-tree reconciliation. Bound recent event/action arrays and notebook page retention. Prefer zero workers initially; if profiling requires a render/audio worker, enforce a single worker and account for its heap and transfer buffers. Heavy account, invitation, notebook, export, and accessibility-settings code loads on demand; basic keyboard semantics, OS motion detection, and captions are in the critical path.

For memory CI, warm up five minutes, then observe 30 minutes with calls, refocus, offer, resize, and notebook scrolling. Force collection in the test harness for retained-heap comparison, separately observe normal production collection. Require no monotonic retained-object increase, no accumulating audio nodes/listeners, and end retained heap within a measured noise allowance initially <=2MB above warm baseline. The allowance covers sampling noise, not a permissible leak slope. Fail linear growth even if below the allowance in one short run; rerun noisy failures with heap diffs. Test close/reopen cycles for bounded contexts and panels.

Instrument from day one: request counts/latency/error codes by route class, page/load/first-bird timings, coarse browser family/version, aggregate frame distributions, audio-context failure categories, queue wait/tick duration/freshness, cache delivery failures, email delivery success, deletion job completion, and export success. Optional anonymized session-duration histograms are bucketed locally/at ingress without account/device dimensions. Operational health can reference an account UUID privately to investigate a failed request, but no bird/interaction payload enters that incident log. In public metrics there are no UUID dimensions or joinable session IDs.

Do not measure retention funnels, streaks, offers-per-user, favorite birds, trait averages, response acceptance, mute-to-drift correlation, user interaction cadence, per-account scene state, visitor rankings, or population behavioral calibration. Metrics schemas accept only allowlisted operational fields; strip URLs/token queries, names, email, notebook, payloads, and arbitrary exception attachments. No session replay, screenshot collection from real aviaries, advertising SDK, behavior tracker, or analytics warehouse read access to the simulation store. Synthetic performance accounts are explicitly isolated so their state diagnostics cannot be confused with real-account telemetry. Alerting is for operators, never a bird-related user notification.

## 11. Privacy, durability, and security operations

Raw owner events exist only to drive that owner's simulation. Retain consumed events for seven days for idempotency/correctness recovery, then delete after confirming the cursor advanced; never purge unconsumed events. Keep long-term personality and compact per-aviary filter/observation summaries as current state, not reconstructed history. Receipts/reservations have bounded expiry; notebook remains browsable for the life of the account without archival hiding. Do not send simulation payloads to email providers, crash vendors, LLM providers, recommendation systems, or training pipelines. Mail delivery sees only the address and the requested transactional/explicitly-consented message; it does not see calls, offers, traits, or presence.

Persist current vectors transactionally with synchronous durable commit and replicated storage; require database backups and point-in-time recovery. Test restoration of stored vectors and stable bird IDs, rather than replaying events to invent them. Deployment/migration scripts cannot truncate personality or reseed established birds. Engine-version changes maintain compatible signature/pose data, and migrations assert every preexisting vector/id remains preserved or increases only by a documented simulation delta. Roll back code/config, never roll back an account's evolved personality to a stale frontend copy. Schema rollback uses forward-compatible expand/contract changes.

Deletion flow: mark pending immediately, revoke all visitor access, hide owner aviary behind recovery controls, pause simulation, and cancel outstanding exports/invites. During 30 days retain encrypted state; magic-link login can recover without recreating birds. A restored account resumes chronological ambient progression from stored state, with no invented presence or neglect penalty. At the due timestamp hard deletion locks against recovery, purges account, identity sessions/challenges, aviary/birds/vectors/filters, events/deduplication keys, notebook, invitations/contact references, visit records, export artifacts, queued jobs, caches, and UUID-associated private operational logs. Remove references to a deleted visitor account in other hosts' logs, using a neutral unavailable identity where a host's own historical visit fact remains. No address survives as a copied string.

Per-account keys are destroyed at hard deletion so encrypted database/backup payloads are unreadable; maintain a minimal non-PII deletion tombstone solely to prevent restoration resurrecting removed data, and expire it when all relevant backups age out. Backup retention initially 30 days; restore procedures apply tombstones before serving traffic. Existing irreversible aggregate histograms have no account linkage or per-account contribution records and cannot identify a deleted person; retain no attributed telemetry row under the guise of aggregation. Audit deletion through synthetic fixtures that search all stores, queues, artifacts, and restoration paths, without copying real PII into audit tools.

Export reads birds, names, moods, settings, and all notebook entries from a consistent database snapshot, paginating/streaming large history without unbounded memory. The vector section is the encrypted opaque current-state payload specified in the decisions table. Artifacts use random handles, account-specific encryption, private signed download authorization, and 24-hour deletion. Never mail an attachment containing traits or private state. Do not export owner presence histories or attendance logs as a disguised streak surface. Hosts' sharing transparency stays in private account visit settings.

Abuse controls cover token entropy, one-time redemption, replay, CSRF, cross-account object access, forged presence/durations, giant payloads, invalid names, invitation/email flooding, and unauthorized mutation using visitor cookies. Never log bearer tokens or email-link query strings; exchange tokens then remove them from history/referrer, serve `Referrer-Policy: no-referrer`, and keep third-party resources off redemption pages. Scoped cookies allow a browser to view a friend's visit without confusing it with its own owner session. Email scanners and browser prefetch must not consume links. Rate limiting is operational protection, not user interaction punishment.

## 12. Verification strategy and acceptance cases

Build tests around product invariants and failure cases rather than duplicating implementation internals. Use deterministic clocks/seeds and a test-only private fixture inspector that cannot be compiled or routed into production clients. No user-facing/debug trait display exists.

| Test group | Required cases and pass criteria |
| --- | --- |
| Vector integrity | IDs/seeds/vectors survive rename, sign-in, second device, deployment, engine migration, restart, backup restore. A missing vector fails closed; no default regeneration. |

| Presence truth table | Test all eight visible/focused/recent-activity combinations; only all true qualifies. Boundary at five-minute expiry; blur/hide/pagehide/settle; missed beacons; sleep/resume; mobile pointer/key behavior; two-device interval unions. |

| Sync | Laptop offer versus phone offer under cooldown, overlapping sessions, stale rename/settings conflict, network retry, expired session mid-write, missed snapshots/ETags, action receipt consumed on next tick. Same canonical state/version at equal server times. |

Use unit/property tests for filter monotonicity, interval union, grammar invariants, ordered consumption, and caption derivation; database integration tests for transactional races; browser end-to-end tests for visible scene/focus/network life cycles. Snapshot/image comparisons cover palette/pose/viewport/reference clocks without freezing procedural variation globally. Human listening and accessibility sessions are explicit launch gates for uncanniness, recognizable signatures, and felt aliveness. Automated pass alone cannot establish these.

For drift perception review, compare synthetic day 0/7/21 clips with naming/signature continuity and modest render changes; reviewers should not report an obvious jump after one session, should instrument a change at day seven, and should commonly perceive the day-21 difference. If the mapping needs adjustment, change initial calibration behind an engine version and rerun invariants; do not create live-account drift dashboards. Include quiet/absent aviaries in review to detect guilt/distress cues.

Load-test accounts that never connect as well as active owners and visitors. At capacity `N`, the tick system must handle approximately `N/60` jobs per second plus overhead, even with zero online accounts. Validate row-lock wait, snapshot delivery, event ordering, and backlog drain against that budget. Publish the supported scale based on measured results; never save capacity by freezing unattended aviaries. A queue outage recovery exercise and a hard-delete restoration drill are mandatory before external launch.

## 13. Delivery sequence, dependencies, and rollout

Organize delivery into small complete slices with testable exits. These are proposed execution stages, not benchmark phase-2 work.

1. **Foundations and specification assets.** Engineering/domain lead owns schemas, append-only event contract, UUID/privacy boundaries, engine seeds/versioning, and authorization roles. Visual/audio/accessibility designers define six species silhouettes/motif grammars, naturalist phrase libraries, palette/contrast/focus tokens, and both motion registers. Establish synthetic fixtures, supported-device/browser matrix, critical-path build gates, and metric allowlists. Exit: contracts reviewed, no unsupported design-system dependency, CI can render one moving and reduced-motion bird from a snapshot.
2. **Two-bird canonical vertical slice.** Implement durable stored vectors, minute tick independent of clients, mood/day cycle, private snapshot bootstrap, mid-action rendering, procedural calls/captions, greeting, presence truth table, keyboard targets, and paced narration. Exit: a two-bird aviary lives for 24 synthetic hours with no browser connected; two devices read identical canonical records; first-paint/audio-fallback/motion gates pass. Accessibility is present now, not reserved for the end.
3. **Owner interactions and observations.** Add listen-in ramps/leases, validated offer receipts/cooldowns, settle/undo/resume, rare notebook facts/prose/pagination, naming, and age-only adoption opportunities. Run week/three-week drift fixtures and human comparison review. Exit: spam cannot accelerate drift, no numbers/streak/counters in UI or payload, and all gesture paths work with keyboard and captions.
4. **Accounts and continuity operations.** Complete magic-link/session list/revocation, new-email verification, export, pending deletion/recovery/hard deletion, key management, backups, restore, idempotency, and outage recovery. Exit: lifecycle race tests and restoration/deletion drills pass; no reset on migration/restart.
5. **Read-only sharing.** Add explicit invitation email/one-time redemption, scoped visitor projection and authorization leases, private visit log/revoke, and the off-default consented notification exception. Exit: visitor actions are forbidden by service permissions, visitor attention has zero effect, host is never implicitly announced to, and revocation tests pass.
6. **Release qualification.** Complete six-species quality review, seven-bird narrow-view/chorus/load tests, supported-browser/accessibility manual checks, 30-minute runtime soak, synthetic geography checks, and privacy pipeline negative tests. Exit: all listed functional/performance/accessibility gates are met with a deploy/restore rollback exercise.

Ship an internal synthetic-only build first, then a consented closed pilot with real account privacy boundaries enforced, then staged public rollout at approximately 1%, 10%, 50%, and 100% of new registrations. Expansion gates depend on operational error/freshness/performance health and completed human quality review, never engagement/retention or population bird statistics. Observe each step through at least a full local day/night cycle across relevant zones; maintain three-week synthetic/closed-fixture evidence before broad release so slow drift is not judged from one afternoon.

Two birds is the public onboarding baseline throughout. Ramp engine support from two to four to seven in synthetic and pilot qualification; do not automatically add birds to public accounts for rollout testing. If additional-bird capability is temporarily limited, retain queued age eligibility and expose no misleading opportunity until that count is qualified. General v1 release supports all seven, with the stated age schedule, cap, and no gate based on visits/payment. Existing birds are never removed by a feature flag. Six-species assets/signatures and accessibility are v1 release requirements, not later polish.

Flags control projection/renderer versions, new-account rollout, adoption availability, and invitation availability, but cannot reset state or change ownership. Operational rollback can disable new invitations/adoptions, preserve existing records, or swap a compatible renderer; any already-authorized visitor remains subject to host revocation. Drift coefficient changes are versioned and apply prospectively with preserved vectors, never resimulation from event history. If simulation correctness is suspect, stop affected writes, preserve durable state/events, show a direct system failure surface, and repair/restore; do not pretend progress by reseeding birds.

Day-one operator runbooks cover tick p99 >5s/backlog, snapshot delivery failure, audio-context error spikes, magic-link delivery/replay, vector-integrity alarms, visit revocation, export failures, deletion overdue jobs, and restore. Record runbook diagnostics through UUID/error codes and operational timings only. No state dump into analytics/logging. Assign a release owner to sign off data continuity, an accessibility owner for the alternate surfaces, and audio/design owners for aliveness/recognizability.

## 14. Risks and mitigations

| Risk | What exposes it | Mitigation and release decision |
| --- | --- | --- |
| Drift too fast, too slow, or saturation after attention spikes | 7/21-day synthetic/perception fixtures; burst/absence tests | Integrating low-pass filter, strong presence weighting, caps, versioned coefficient/render calibration. Delay release if three-week perception is wrong; never use real-account trait aggregation. |
| Vector loss hidden by apparently functional UI | Backup/migration invariants, missing-record alarms | Single restricted writer, non-null records, atomic cursor commits, replicated durable state, tested restore. Missing data fails closed; no reconstruction/defaulting. |
| Multi-device double credit or cooldown races | Concurrent interval/offer fixtures and fault injection | Account interval union, idempotent event keys, row-locked reservations/ticks, versioned metadata updates. No personality last-write-wins path. |
| One-minute canonical latency makes offers feel unresponsive | E2E receipt-to-reaction tests, loss/retry scenarios | Server-authored accepted reaction receipts, immutable outcome, bounded overlay, next-tick reconciliation. Never let optimistic client state become a second simulation. |
| Procedural audio sounds robotic, harsh, or signatures blur | Human reviews across six species/seven birds/mood extremes | Distinct stable signatures, bounded contour variation, mix headroom, slow ramps, nonzero background, capped response chains. Re-author motifs before adding a seventh audible bird if necessary. |
| Autoplay restrictions break apparent aliveness | Real Safari/phone first navigation and denied-context tests | Fully active visual/narrated scene, captions on during unavailable audio, deliberate enable sound, no recorded fallback. Audio cannot block paint or penalize drift. |
| Presence overcounts open/away tabs or excludes still viewers | Full conjunction tests and five-minute boundary review | Exact signal intersection, bounded leases, union across devices, modest few-minute calibration. Do not infer attention from open sessions; acknowledge the observation limit. |
