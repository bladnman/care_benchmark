# Pocket Aviary — v1 implementation plan

## 1. Product boundary and decisions

Build one browser-based, single-screen aviary per email-authenticated account. Create two system-selected starter birds, let the user name and rename them, and let aviary age make additional adoptions available up to seven birds. The scene supports watching, listen-in, seed/song-fragment/still-pool offers, settle with five-second undo, a sparse read-only field notebook, and optional read-only invitations. Ship screen-reader narration, call captions, reduced motion, keyboard operation, account export/deletion, and device-session management in v1. Day/night, rare mild weather, bird-to-bird behavior, and procedural calls are part of the core experience, not later decoration.

Use the PRD vocabulary in code-facing product concepts and user copy: bird, call, presence, listen-in, offer, settle, notebook, visit. Product prose is lowercase, present-tense naturalist observation, specific to a bird and moment. Identity, sync, account, and accessibility-settings copy is direct and matter-of-fact. There is no textual return greeting. No scores, levels, streaks, visit-frequency surfaces, hunger, distress, deaths, notification loop, public discovery, profiles, comments, shared aviaries, native client, payment, or scene customization. The visit log is an account privacy surface; it is not a social feed. Visits remain off until a host sends an explicit invitation.

The following implementation choices resolve unspecified parameters and must be calibrated before general release: normalize hidden traits to [0,1]; use a four-minute activity window for presence; schedule a roughly 60-second server tick; start at two birds, offer age-gated additions at approximately 3, 6, 9, 12, and 18 months, with declined offers remaining available privately; begin with five moods (`wary`, `content`, `curious`, `drowsy`, `alert`). These are configuration constants, not user-visible progression. Change them through versioned simulation configuration after testing, never through client logic. A year-old aviary can thus have about five or six birds depending on accepted invitations to adopt. Do not show eligibility timers or bird-count progress.

## 2. System shape and ownership

Use a lightweight web client plus three server responsibilities behind one authenticated API: (1) account/auth/invitation service, (2) canonical aviary store and interaction ingestion, (3) partitioned simulation workers. A relational database provides transactions, uniqueness constraints, encrypted account email, canonical bird records, append-only interaction events, notebook entries, invitation state, and a tick cursor. A queue or partitioned scheduler dispatches account IDs to workers about once per minute; workers lock an aviary, read unconsumed events, compute a deterministic tick, and commit state, event cursor, notebook candidates, and monotonically increasing version together. The workers run for inactive accounts too. Shard by synthetic account UUID, not email. Scale the scheduler horizontally and make overdue ticks catch up in bounded chronological steps rather than skipping elapsed time or inventing presence.

Only the server writes canonical bird identity, hidden personality vector, mood, perch intent, current weather, and notebook records. A browser receives a compact *render projection* with current poses, timing seeds, perceptual parameters, and transition targets; it cannot submit absolute state or trait values. The browser owns interpolation, visual ornaments (leaves/feathers), sound synthesis, and local control state such as focused bird or temporary settled lighting. Render ornaments never become canonical events. A versioned projection contract separates internal simulation fields from scene fields; public/visitor responses omit vectors, event history, account settings, and notebook. Keep the visual and audio renderers driven by the same projection and simulation clock anchor so a visible call, caption, and synthesized call describe the same event.

Deliver the initial HTML, CSS, minimal shell, and a small signed state projection at the edge for an authenticated repeat visit where feasible; fall back to a fast snapshot request on cache miss. Per-account state is private: use short-lived, authenticated edge reads and `private, no-store` semantics rather than a public CDN cache. Render the first bird from the projection immediately, with its animation phase derived from server time and a stable action seed. Do not play an entry animation. A cold or delayed snapshot shows a quiet field, without spinner, then joins the current scene. The one allowed exception is the post-adoption empty field and first soft fly-in.

## 3. Data model and invariants

| Record | Required fields and rules |
| --- | --- |
| `Account` | Random UUID primary key; encrypted verified email held only here; timezone IANA ID; creation/deletion timestamps; settings (audio/captions/reduced motion/visit notification); one-to-one aviary. Email-change pending token is separate, verified before replacement. Do not use email in metrics, logs, queue keys, foreign keys, or tracing. |
| `DeviceSession` | Opaque token hash, account UUID, device label, issued/last-used/revoked timestamps. Revocation checked on every protected request. |
| `Aviary` | Stable UUID, account UUID unique, created timestamp, version, simulation time, last tick, event cursor, weather state/end, local-light parameters, age-gated adoption state, last host presence end, and notebook-generation cursor. One per account. |
| `Bird` | Stable UUID, aviary UUID, adoption time, species key, user name, immutable species/call-signature seed, baseline and current hidden five-component personality vector, mood and mood-since, perch zone/pose/target and transition anchor, last accepted offer time, call schedule seed. Renames and migrations preserve UUID/vector/history. Seven-bird cap checked transactionally. |
| `InteractionEvent` | Server ID, account/aviary UUID, device session ID, idempotency key, server receipt time, bounded client event time, kind, bird/offer reference as appropriate, normalized duration, accepted/rejected outcome, consumed tick cursor. Append-only; no direct trait update. |
| `PresenceLease` | Per host device/window lease with visibility, focus, recent pointer/key activity attestation, last heartbeat, valid-through time, server-clamped interval and union accounting cursor. Visitor sessions cannot obtain one. |
| `NotebookEntry` | Stable ID, aviary UUID, observed time, template/prose version, rendered naturalist text, source event IDs, uniqueness fingerprint. Immutable and ordered indefinitely; paginate oldest entries without archiving. |
| `Invitation` / `VisitSession` / `VisitLog` | Host account UUID, encrypted recipient email/reference, hashed single-use redemption token, issued/expiry/redeemed/revoked times; browser-bound read-only session hash and expiration; visit start/end and approximate duration. Never grant host write permissions through these credentials. |

Use schema migrations with compatibility windows and backup/restore drills that explicitly compare bird UUIDs and vectors before and after restoration. Guard vector writes in the database/service boundary so only the tick role can update them. Persist vector values directly; do not rebuild them from events at request time. Never place trait numbers in the ordinary scene or account UI. The PRD's on-demand JSON account export explicitly includes the current vectors; treat that file as private user data with a short-lived download link, and do not turn it into an in-product stats view.

## 4. API and event contracts

Use versioned HTTPS JSON endpoints with session cookies (`Secure`, `HttpOnly`, `SameSite=Lax`), CSRF protection for mutations, request size limits, and typed error bodies. The API may use equivalent route names, but preserve these contracts:

| Endpoint | Behavior |
| --- | --- |
| `POST /v1/auth/links`, `POST /v1/auth/consume` | Issue email magic link with neutral response and per-email/IP rate limits; 15-minute expiry, atomic one-use consumption; establish revocable per-device session. |
| `GET /v1/aviary/snapshot?afterVersion=…` | Return server time, version, projection schema, birds' render-facing identity/pose/mood/call schedules, weather, light/timezone, scene transition anchors, and next pull hint. On unchanged version, return lightweight response. The server may include greeting inputs for the host, not the visitor. |
| `POST /v1/aviary/events` | Accept bounded batch of `presence_lease`, `listen_in_start/end`, `offer`, `settle`, `settle_undo` with client-generated idempotency keys and bird IDs where relevant. Validate ownership, sequence, cooldown, and current session; acknowledge per event with canonical server time, accepted outcome, and for an offer a server-authored transient reaction envelope. Never accept trait or mood values. |
| `GET /v1/notebook?cursor=…` | Host-only reverse-chronological, stable cursor pagination. |
| `POST /v1/birds/{id}/name`, `POST /v1/adoptions` | Validate ownership and names; adopt only age-eligible, unclaimed offer, under seven birds, in a transaction. No species catalog or rarity selection. |
| `GET/PATCH /v1/account`, `GET/DELETE /v1/account/sessions/{id}` | Settings and device sessions; verify a new email before committing change. |
| `POST /v1/account/export`, `POST /v1/account/deletion`, `POST /v1/account/restore` | Send short-lived verified-email export link; soft delete immediately and allow explicit restore for 30 days; hard-delete account-linked data after deadline. |
| `POST /v1/invitations`, `GET /v1/invitations`, `DELETE /v1/invitations/{id}` | Explicit invite creation, host list, and revocation. Only operational invite email is sent; no automatic onboarding share prompt. |
| `POST /v1/visits/redeem`, `GET /v1/visits/snapshot` | Atomically exchange one-use email link for a scoped visitor session, then serve a sanitized read-only projection. Check revocation/expiration on every pull; log approximate visits silently. No mutation routes accept visitor credentials. |

Keep snapshot and event schemas versioned. Include an idempotency key unique per session/event for retry across network failures. On stale client version, accept valid additive events, return current version, and ask the client to refresh; no last-write-wins vector merge exists. Return direct, matter-of-fact session/availability/reload guidance for expired auth or unavailable visits. A client may queue a small bounded set of events during a short disconnect, but on reconnect the server rejects expired presence intervals and old offers; it does not replay hours of offline attention. A browser offline for long cannot simulate or author canonical history.

## 5. Simulation design

### Tick and deterministic inputs

Tick about once per minute in UTC, using the account's stored IANA timezone to derive local day phase (including DST). Under the aviary lock: advance through elapsed tick windows, consume each append-only event at most once in server order, expire leases and weather, compute input aggregates, update each bird's mood/perch/call intent and nonnegative personality delta, choose sparse notebook observations, persist all writes and the cursor atomically. Derive pseudorandom choices from `(aviary ID, bird ID, tick index, simulation config version)` so retry produces the same result. External email delivery is outside the transaction and uses an outbox. Backfill after worker outage through bounded windows; cap work per invocation, reschedule until caught up, and prioritize fresh snapshots only after canonical catch-up. Alert on lag.

### Presence and drift

The browser samples `document.visibilityState === 'visible'`, `document.hasFocus()`, and the timestamp of the last pointermove or keypress. All three must hold *at the same time* before it can request a presence lease. Pointer/key activity is a freshness signal, not click frequency; begin with four minutes so quiet watching counts. Send a heartbeat every roughly 15–30 seconds while eligible, plus prompt end on blur, hide, settle, or unload when possible. Server receipt time bounds each lease to a short maximum, expires missing heartbeats, and unions overlapping eligible intervals from multiple host devices so two tabs do not double-count. Browser claims are unverifiable, so cap durations/rates and use them only for this user's simulation; do not infer presence from open tab, audio playback, visits, or a stale heartbeat. Settling and ordinary tab close both end the lease, with no penalty. Presence ends at the earliest ineligible condition or lease expiry; a subsequent valid activity starts a new interval.

Maintain an exponentially smoothed, bounded presence signal over days, with per-day saturation and slowly decaying *input* when the user is absent. For each tick, calculate `delta_trait = max(0, rate_trait × filtered_presence × headroom × dt + accepted_event_bonus)`, clamp to [0,1], and commit as an additive server-authored delta. Presence dominates; listen-in modestly favors social warmth/vocal frequency for that bird; offers modestly favor curiosity/boldness for relevant birds. Settle affects only mood/presence ending. A bird without new attention gets zero trait delta; it never loses boldness, warmth, voice, or plumage. Apparent quietness after absence comes from a recency/mood expression factor, not negative personality drift. Cap event bonuses per bird/day and enforce the offer cooldown on the server (start with ~3 minutes) to prevent button-mashing from dominating. The exact rates are calibration data, not something users can optimize in a UI.

Build a deterministic time-compression harness with profiles for no visits, regular short visits, long quiet watch sessions, frequent offers, and overlapping devices. Acceptance targets: a week of typical visits yields measurable hidden deltas, a single session yields no perceptible change, and a side-by-side three-week comparison conveys change without numeric explanation. An untouched bird never regresses numerically or displays distress. Review the calibration with listening and visual panels because numeric thresholds alone cannot judge felt continuity. Store model/config version with each tick so changes can be audited without recomputing vectors.

### Mood, perches, weather, and greeting

Implement mood as a small state machine with per-bird transition weights from recent offers, interaction with other birds, personality, local day phase, and ambient weather. Daily-ish decay returns mood toward an appropriate local-time baseline while preserving continuity between sessions; opening a tab is never a reset. Wary favors back perch/scanning, content preening, curious head tilts/investigation, drowsy low/fluffed poses, alert scanning and responsive calls. Perch choices are bird-authored, with collision/spacing constraints and no user placement API. Rain is rare and short, suppresses call probability temporarily, and wind nudges alert/wary; weather has no task or warning surface. At night most birds quiet and settle, while the nightjar-like species may still call.

On host navigation or return to visible/focused state, derive an arrival cue from canonical mood, boldness, warmth, and server-recorded absence length, then use a fresh per-arrival seed for variation. Choose one likely greeter, usually the bolder/warmer bird, within 1–2 seconds; quick absences favor a glance, long absences can yield approach or longer call. If another bird answers, stagger it with a small seeded offset. The arrival cue is not a reset of canonical mood, not a synchronized chorus, and never paired with a welcome banner. Multiple devices seeing the same aviary may have different *local* arrival cues, but no device mutates canonical personality by arriving. Visitor snapshots omit greeting cues and visitor arrival does not trigger one.

### Calls and notebook

Give each species a compact motif grammar; give each bird an immutable signature seed that fixes contour, timbre family, and characteristic interval/rhythm. Mood and vector affect phrase density, timing, inflection, response probability, and dynamics within bounded ranges that preserve recognition. The tick schedules sparse call intents and bird-to-bird response/chorus opportunities using deterministic seeds; client synthesis introduces bounded timbral microvariation using the intent seed. Avoid two identical call events in a row and avoid exact periodic loops. At seven birds, apply chorus density control and priority to preserve individual signatures. User listening panels must identify familiar birds across moods and at different aviary sizes.

Generate notebook entries on the server from a small observation grammar and true state/event facts: first greeter relative to recent greeters, a quiet rain morning, a particular offer response, a bird using an unusual perch. Require source facts, deduplicate by semantic fingerprint, limit ordinary cadence to roughly one every few days, and allow rare noteworthy events through. No entry reports user attendance/streaks or raw trait deltas. Review templates for lowercase present-tense specificity and for avoiding false claims. Store the prose at creation so history stays stable when templates change. Notebook is read-only and indefinitely paginated.

## 6. Scene and interaction implementation

Render one responsive horizontal scene in a retained 2D scene graph (Canvas/WebGL or similarly efficient pipeline) with a DOM layer for the top bar, focus targets, captions, and assistive narration. Keep birds and all three perch zones in the viewport at phone and desktop widths; solve positions in normalized scene coordinates with minimum separation and no pan/zoom/crop. Layer calm sky/foliage, middle-plane perches and birds, occasional foreground leaf/feather; parallax is restrained. Bird silhouettes and compact vectors/atlases represent about six coherent species. Visual saturation reads the hidden trait through a bounded palette mapping; it never displays a number. Local light follows the account timezone and smoothly blends sunrise, day, warm evening, and dim night. Settling temporarily overrides local light to evening and lowers calls over seconds until re-engagement or close; any scene click in the first five seconds reverses it. A scene click used for undo must not accidentally make an offer or move a bird.

The initial projection includes pose and action start times, so the first frame samples a bird midway through preen/scan/call as appropriate. On new snapshots, interpolate positions and states from old to new anchored to server timestamps; detect long render gaps and fetch current state before resuming, rather than animating an hours-old path. On hide, stop requestAnimationFrame and audio scheduling, close presence, and keep the server tick running. On return, fetch then present current state. Ambient leaves/feathers are client-only, sampled sparingly; they do not determine mood or notebook facts. No controls, labels, badges, or tooltips inside the scene. The thin top bar contains only account/settings, accessibility settings, notebook, and a gestures control; it fades after stillness but reappears on pointer or keyboard activity and remains legible/focusable while used. The gestures control is the specified offer affordance and also exposes settle as a clearly separate action inside its menu. This reconciles the PRD's four-icon top-bar limit with its requirement that settle be initiated from the top bar.

Listen-in uses click/tap or focused-bird keyboard action. A focused bird's channel ramps upward while others ramp to a nonzero ambient floor; changing birds crossfades. Clicking the same bird, empty scene, or moving keyboard focus away disengages with a matching slow ramp. The top-bar gestures control opens a compact, keyboard-accessible menu with three offers and a separate settle action; the server's transient response envelope chooses an actual bird reaction to an offer from current mood/personality and cooldown. The client can display the accepted reaction immediately while the next tick commits any lasting mood/drift effects. A rejected or duplicate offer never produces a second reaction. Still pool and song fragment are brief scene/audio events, not resource meters.

## 7. Audio and captions

Compile motif grammars into a small synthesis library using WebAudio oscillators/noise/excitation, short envelopes, filters, and per-bird gain/pan nodes. Schedule with a look-ahead clock tied to server projection timestamps; bounded jitter prevents mechanical repetition while the bird signature remains stable. Route call intents through one event object consumed by (a) synthesizer, (b) beak/body cue, (c) caption generator. Caption prose is derived from the exact motif, contour, timing, and mood selected for the call: e.g., a soft three-note rise or a low trill with a pause. It is not a static species label. Chorus uses a shared limiter and density/ducking policy to protect headroom; never mute nonfocused birds under listen-in. Reuse node/buffer pools, limit polyphony, stop hidden-tab scheduling, and fade rather than cut gains on focus, settle, and visibility changes.

Browser autoplay rules may prevent immediate sound before a user gesture. Draw the moving aviary and captions without blocking first paint; resume the AudioContext on the first allowed interaction and keep the visual timing coherent. Do not add a disruptive autoplay modal. If WebAudio is unsupported or fails, remain silent and enable call captions by default, with a matter-of-fact audio setting/error surface when a user opens settings. Do not add recorded-call files as fallback. Test headphones and phone speakers for clipping, fatigue, phase artifacts, and seven-bird intelligibility, plus a 30-minute session for audio-node leaks.

## 8. Accessibility as a full scene

Build a semantic DOM representation alongside rendering: aviary region, named bird controls, current high-level observation, notebook dialog/list, and top-bar controls. Arrow keys move among bird focus targets after Tab enters the scene; Enter begins/ends listen-in; Escape exits; focus movement away ends the mix. Each control has a visible high-contrast focus treatment in morning and night palettes. The offer menu and settings have predictable tab order, focus trapping/restoration where appropriate, and touch targets sized for mobile. A visitor can focus/read bird descriptions but cannot invoke listen-in or any host action.

Generate naturalist narration from the same render projection and observed event facts, not raw ARIA state dumps. At idle, publish one coalesced prose update about every 30–60 seconds to a polite live region; prioritize user-initiated offer/settle and the return greeting without flooding the queue. Avoid narrating every pose change or mood enumeration. Provide a manual “describe the aviary” action for users who want the current prose without waiting. Use matter-of-fact wording only in settings/errors. Audit with actual screen readers for queue behavior, especially simultaneous captions and notebook navigation.

Reduced motion is a parallel renderer: slowly crossfade among still bird poses, crossfade perch changes rather than animate flight paths, remove leaf drift and parallax, and slow ambient color transitions. It preserves calls, captions, moods, drift, and notebook. Honor `prefers-reduced-motion` on first paint and allow an explicit override in accessibility settings. Captions appear near the calling bird but stay within viewport and pass WCAG AA contrast in every light/weather state. Test caption overlap at seven birds and offer a nonspatial caption list for narrow screens/screen readers if proximity cannot remain legible. All user copy, including top bar and system surfaces, meets WCAG AA contrast; automate color-pair checks from design tokens and visually inspect rendered composites.

## 9. Invitations, accounts, and privacy controls

Sign-up provisions the account UUID, aviary, and two stable starter birds transactionally. Show the system-selected species as arrivals, then collect names with suggestions; names can be changed later without altering bird identity. Magic links expire at 15 minutes and are single-use; neutral request responses avoid account enumeration. Device sessions are listed and individually revocable. Email change is pending until the new address verifies, with the old address valid until then. Export creates a point-in-time JSON snapshot including vectors and notebook/settings, encrypted at rest, emailed as a short-lived download link to the verified address. Do not include the email or export payload in logs. Soft deletion blocks ordinary use immediately, allows explicit recovery for 30 days, then a purge job deletes birds, vectors, events, notebook, invitations, visit logs, sessions, exports, and all account-linked operational records; prove purge completion with an auditable job status keyed by UUID. Anonymous aggregate counters have no account dimension.

An invite names one recipient email. Store only a hashed redemption token; unused tokens expire after 30 days. Redeeming atomically consumes the email link and creates a limited browser visit session scoped to that invitation. A redeemed invitation remains active until revoked; the visitor's browser session can renew while the invite remains valid, but cannot be transferred to other accounts or used to write. On revoke, the next snapshot pull returns an unavailable response and the client closes the view. Keep visible-tab visitor pulls frequent enough to make revocation prompt (target at most about one minute), and also check server-side authorization for every read. Visitors see the current host scene/audio/weather without prettifying it, and no notebook, controls, host-presence effects, greeting, co-presence marker, or interaction endpoint. Approximate visit duration is logged for the host settings page; there is no badge or default notification. The PRD allows a host opt-in visit notification toggle, off by default and absent from onboarding; if enabled, send only the notification the host requested, with no engagement cadence.

Make the simulation database unavailable to analytics jobs by credentials and network policy. Operational metrics are predeclared, aggregate-only counters/histograms with no account UUID, bird UUID, email, names, event payload, per-bird state, or per-account history. Keep request debugging in a separate short-retention security path with redaction and synthetic IDs only where necessary; do not build behavioral dashboards or population drift analytics. Privacy policy in account settings plainly states collected operational categories and the exclusion of per-bird interactions from aggregation/training/sharing.

## 10. Performance, observability, and quality gates

Initial gzipped JavaScript must stay below 2 MB; set a CI bundle-size gate and lazy-load notebook, account, accessibility, and invitation panels. Target first bird visible within 500 ms on a defined mid-tier mobile device/4G profile, measuring from navigation start to first rendered bird pixel (not merely shell paint). Use inline/edge-delivered compact projection when possible, small bird SVG/bitmap assets, critical CSS, and no audio or settings dependency on first draw. Target 60 fps idle on a five-year-old mid-range laptop throughout a 30-minute run, not just at load. Heap/audio-node counts must stabilize over 30 minutes with notebook scrolling and several listen-ins/offers; define a warmed-up plateau threshold in CI rather than masking a steady positive slope. Profile worst case seven birds plus captions/weather/reduced-motion.

Run synthetic browsers from common geographies against the supported last two major Chrome/Safari/Firefox/Edge versions. Collect aggregate page-load/first-bird histograms, frame-time histograms, audio-context error counts, request errors, tick duration and backlog, and snapshot size. Alarm if tick latency p99 exceeds five seconds, if backlog grows, or if first-bird/render budgets regress. Do not emit per-bird or per-account dimensions. Unsupported older browsers get a plain matter-of-fact explanation. A performance release gate includes first visit, returning visit, hidden/resume, slow network, and a seven-bird long session.

## 11. Delivery sequence and verification

1. **Contracts and foundations:** lock terminology, projection/event schemas, design tokens, accessibility semantics, timezone behavior, and privacy metric schema. Implement account UUID/auth/session primitives and persistence migrations. Prove magic-link one-use expiry, per-device revocation, account ownership, and absence of email in internal identifiers/logs.
2. **Canonical engine:** build scheduler, transactional tick/cursor, stable birds, mood/perch/weather/call-intent state, presence leases and interval union, monotonic drift, cooldowns, age-based adoption, and notebook fact pipeline. Run deterministic multiweek simulations and crash/retry/dual-device tests before adding visual polish. Assert only server tick writes vectors; assert no negative delta, no event double-consumption, and no client state merge.
3. **First complete aviary:** deliver first-frame projection, responsive one-screen scene, two starter species then full small pool, day/night and idle micro-motion, return greeting, listen-in, offers, settle/undo, notebook. Pair each visible behavior with a corresponding narration/caption/reduced-motion implementation. Validate naturalist copy against real generated observations.
4. **Audio and accessibility:** integrate motif synthesis, per-bird signatures, chorus control, WebAudio failure path, captions from played motifs, keyboard and focus flows, screen-reader narration, reduced-motion crossfades, and contrast checks. Listening studies test bird recognition at two and seven birds; accessibility sessions test whether the alternate surfaces feel like a continuing aviary rather than a status feed.
5. **Account completeness and visits:** export, deletion/recovery/purge, email change, visit invitations, read-only projection, revocation, silent log, and optional notification toggle. Pen-test token replay, cross-account access, visitor mutation, stale revoked sessions, and export-link leakage.
6. **Ramp:** internal dogfood with two birds, then small external cohort at two; enable third through seventh only when age eligibility naturally occurs for test accounts, using simulation fixtures for load and seven-bird audio tests. Gate each increase on recognition/listening, frame/audio memory, captions, and sync stability. Expand access gradually without engagement prompts. Maintain rollback flags for optional visits/new audio grammars while retaining canonical bird IDs/vectors; never reset a bird to roll back a renderer or model configuration.

Release acceptance scenarios include: laptop and phone concurrently offering/listening with retries; background tab overnight and foreground return; no input for four minutes then renewed activity; settle versus ordinary close yielding equal presence termination; worker outage and replay; DST/timezone change; rename and migration preserving identity/vector; revocation during an active visit; WebAudio denied; reduced motion from first paint; screen-reader narration during repeated calls; thirty-minute seven-bird run. Review both machine assertions and qualitative scene/audio samples. Shipping requires no known identity/vector loss, no drift from absence, no visitor influence on host state, and no missing accessibility mode.

## 12. Principal risks and responses

| Risk | Early signal and response |
| --- | --- |
| Drift feels too fast, too slow, or punitive | Time-compression simulations plus blinded three-week visual/audio comparisons. Tune only versioned rates and recency expression; never introduce negative vector drift or a user-facing meter. |
| Presence is inflated by idle/background or duplicate devices | Browser conjunction tests, server lease expiry and interval union, cap implausible durations, inspect *synthetic* scenario outputs rather than population interaction histories. |
| Concurrent ticks or retries lose/double-count drift | Aviary row lock/compare-and-swap version, atomic event cursor and state commit, idempotency keys, deterministic tick seeds, failure-injection tests and restore drill. |
| Calls sound canned, clip, or blur at seven birds | Motif grammar variation and stable signature constraints, headroom limiter/density control, repeat-pattern detector in test harness, human listening panels across devices. |
| Autoplay or WebAudio failure breaks first encounter | First-frame visual scene and captions independent of AudioContext; resume on allowed gesture; silent captioned fallback and aggregate error counts. |
| Accessible experience becomes a state dump or static image | Ship narration grammar and reduced-motion renderer with the normal renderer, test actual screen readers/vestibular settings in every milestone, hold release on regressions. |
| First-frame budget forces a spinner or stale bird | Edge private projection, tiny critical path, synthetic 4G gate, quiet-field delay handling, stale-snapshot refresh on resume. |
| Visitor access leaks private state or survives revocation | Separate visitor credentials/projection, endpoint authorization on every pull, no visitor write capability, short pull cadence, security tests. |
| Privacy boundary erodes via observability | Allowlisted aggregate metric schema and restricted analytics credentials, CI checks for forbidden dimensions/payloads, redacted logs, deletion audit. |

The governing acceptance criterion is continuity: the same named birds persist and continue evolving on the server, while every visual, auditory, narrated, and captioned surface reflects that one state without turning the relationship into a score or a notification loop.
