# Pocket Aviary v1 implementation plan

## 1. Product scope and invariants

Ship one browser-based aviary per single-user account, starting with two system-selected birds and supporting no more than seven. The v1 surface includes email magic-link auth, stable named birds, server-simulated moods and personality drift, the animated single-screen scene, procedural calls, listen-in, seed/song-fragment/still-pool offers, settle, a sparse read-only field notebook, presence accounting, account/accessibility settings, multi-device sync, export/deletion, and per-invite read-only visits. Both visual and audio accessibility paths ship at launch.

The product has no quests, scoring, streaks, visit-frequency display, distress or hunger state, bird death, shared aviary, public discovery, chat, comments, native client, payments, customizable scene, or multiple aviaries per account. Never expose personality numbers in user-facing UI or accessibility output. No textual welcome or return announcement. A visitor cannot affect the host simulation. Neglect never decreases personality traits; absence may leave birds ambient or quiet but never distressed. Account, error, sync, and accessibility-settings surfaces use matter-of-fact system copy; the aviary and notebook use specific lowercase naturalist prose.

Treat these as release invariants, not aspirational design notes: the server is the sole canonical state writer; client state is presentation/interpolation only; event history is not operational analytics; calls are generated procedurally; all seven-or-fewer birds remain in frame; reduced motion remains a designed aviary; and no user surface ranks or quantifies bird personality.

## 2. System shape and ownership

Use a web client, a state/simulation API, a relational persistence layer, a background tick worker, and narrowly separated auth/mail and operational telemetry components. Keep the first release as a modular service rather than prematurely splitting per-feature services. Modules should have explicit boundaries (identity, aviary state, simulation, notebook, invitations, export/deletion) so the state writer and privacy boundary remain auditable.

- **Browser client:** accessible shell and scene; fetches snapshots; interpolates visual poses; synthesizes calls; submits typed interaction/presence events. It does not calculate or persist canonical moods, personality, bird location, or drift.
- **API:** authenticates account sessions, authorizes account ownership, returns snapshots, validates and appends events, manages adoption/naming/settings/notebook/invites, and produces exports. It must not accept client-supplied personality values or event timestamps as authoritative.
- **Tick worker:** processes due aviaries approximately once a minute, whether or not a browser is connected. It is the only writer for canonical simulation outputs and processes each account's unconsumed events in order.
- **Database:** transactional source of truth for account, birds, canonical aviary state, interaction event log, notebook, and invitation/session records. Use account UUID for references and partitioning. Email exists encrypted on the account or invitation record only where required to send/authorize mail; it is not a key, log field, metric dimension, or inter-service identifier.
- **Mail/auth adapter:** sends one-time magic links, invite links, export links, and only explicitly enabled visit notices. Store token hashes, enforce expiry and single use, rate-limit requests per email, and avoid logging link contents.
- **Telemetry:** separate pipeline for aggregate request, latency, error, render, and audio health metrics. It cannot query or join the per-account simulation store; never emit email, account UUID, bird IDs, event payloads, personality, mood, or interaction histories to analytics.

The renderer consumes a compact snapshot contract shared by owned and visitor views. The owned route has authenticated write capabilities; the visit route is capability-limited and read-only. Serve HTML and the small bootstrap snapshot promptly, then let the client draw a quiet field until snapshot data is available. Do not show a spinner or a wake-up animation.

## 3. Persistent data and state boundaries

Use UUID primary keys and explicit schema versions for durable records. Suggested entities:

- **Account:** `account_id` (synthetic UUID), encrypted verified email, created/deletion timestamps, IANA timezone, accessibility preferences, optional visit-notice preference, and account lifecycle state. Timezone is captured/updated from the signed-in client because mood and day/night follow the user's local time; store it canonically so the worker and all devices agree.
- **DeviceSession:** session ID, account UUID, token hash, created/last-used/revoked timestamps, device label if safely collected. Revocation takes effect on subsequent requests.
- **Aviary:** account UUID unique (one per account), created timestamp/age, canonical scene state/version, last tick time, next bird-offer eligibility derived from aviary age, and settled/session presentation metadata only where needed. Do not model settle as required attendance.
- **Bird:** stable bird UUID, aviary/account UUID, species, user name, adoption timestamp, seed/version, normalized server-only personality vector (boldness, social warmth, vocal frequency, plumage saturation, curiosity), current mood enum, mood timing/last update, current perch/pose/transition, and stable call-grammar identity. Rename does not alter identity, vector, mood, or call identity. Keep trait ranges and starter seeds in versioned simulation configuration; clamp traits to configured bounds and never decrease them due to neglect.
- **InteractionEvent:** append-only event ID, account and aviary UUID, monotonic per-aviary sequence, bird ID when relevant, validated type/payload, server receive time, idempotency key, and processed tick/version. Types cover qualifying presence intervals/pings, listen-in start/end, offers, settle, and adoption/name actions as appropriate. Do not treat visitor activity as host events. Keep event retention/deletion aligned with account deletion and simulation requirements.
- **NotebookEntry:** immutable ID, aviary ID, created time, generated prose, and source-state references sufficient for audit/regeneration policy without exposing trait numbers. Entries are rare observations, approximately every few days for typical use, and may be generated for noteworthy bird moments. Generate only from that aviary's state; filter out user-visit frequency and private system measurements. User can read indefinitely but cannot edit/delete entries.
- **Invitation / VisitSession / VisitLog:** invite UUID, host account UUID, encrypted target email, one-time token hash, expiry (30 days unused), revocation/use timestamps, and active visit session token/expiry. Record visitor and approximate duration in the host's visit log for transparency. Invitation can be revoked at any time. Do not expose a visitor's presence to birds or the host's scene. Notice preference is off by default and only controls explicitly opted-in notices.
- **Export/deletion job:** job state and one-time download token metadata. Export contains the requested aviary snapshot (including vectors, moods, settings, notebook) and is emailed to the verified address. Soft deletion immediately blocks ordinary use, permits recovery during 30 days, then hard-deletes aviary, vectors, notebook, event records, sessions, invitations and tied telemetry/exports; deletion workers must cover backups/retention under a documented completion policy.

Canonical simulation writes should be committed atomically with the tick cursor and new snapshot version. Optimistic version checks or row locks serialize ticks per aviary. Use a unique event ID/idempotency key so retries cannot apply a drift signal twice.

## 4. HTTP/API contracts

Version the API and define typed request/response schemas. Authenticate owned routes with revocable per-device sessions; use short-lived, scoped visit capabilities for visitor routes.

- `POST /v1/auth/magic-links` accepts email, applies per-email rate limits, and sends a 15-minute link. `POST /v1/auth/consume` atomically consumes it once and issues a device session. Include matter-of-fact expired/used-link errors. Add endpoints for session listing/revocation and verified email change (new address works only after verification; old remains active until then).
- `GET /v1/aviary/snapshot` returns canonical version, server time, timezone/day-phase, current ambient weather, per-bird stable ID/name/species, presentation-safe mood/pose/perch, transition start/end, and deterministic call timing/grammar cues needed to render the current interval. Do not return personality vector fields. Snapshot payload should be kilobytes. Support `If-None-Match`/version cursors for unchanged state.
- `POST /v1/aviary/events` accepts an idempotency key and a narrow event union: offer type/target bird, listen-in start/end, settle, and presence heartbeat/interval. Server derives account, receipt time, duration caps, and authorization from the session. Validate bird belongs to aviary, offer cooldown (few minutes per bird), bounds on claimed intervals, and settle undo window (five seconds). Respond with accepted event sequence and cooldown/undo state, not a trait delta.
- `GET /v1/notebook?cursor=...` pages immutable entries newest-first; notebook copy is generated naturally and contains no streaks or visit-frequency observations.
- `POST /v1/aviary/adoption/names` completes initial naming for the two server-selected starter birds. Age eligibility endpoint reports whether an age-based bird offer is available, capped at seven. Acceptance creates a stable new bird from the species pool; do not tie eligibility to visits, click volume, or paid tier. Names can be changed through `PATCH /v1/birds/{id}/name`.
- `POST /v1/invitations` takes a visitor email, creates a one-time invite and emails a read-only link. `GET /v1/visits/{token}/snapshot` validates unexpired/unrevoked capability and returns the same state representation without write authority. A visitor's periodic snapshot pull enforces immediate-next-pull revocation. Add host-only list/revoke endpoints and visit log in account settings. Never provide interaction/event endpoints under visit authority. Log approximate duration without emitting visitor activity into drift.
- Account endpoints support settings/timezone, JSON export request/download, deletion request/recovery, accessibility preferences, and invitation notice preference. Use normal system language for these surfaces.

All event writes are idempotent and ordered per aviary. Return explicit conflict/auth/expired/revoked states. Avoid client conflict resolution: clients re-fetch canonical state after reconnect or version mismatch.

## 5. Simulation and behavior engine

Run a due-work scheduler with roughly one-minute cadence, with jitter to spread load. For each aviary, transactionally load its last canonical state, process new events by server sequence, compute elapsed time since the prior tick, apply time/ambient transitions, advance mood and timers, update bird-to-bird effects, append any sparse notebook observation, persist new state/version and event cursor, then commit. Catch-up over long offline periods must be bounded and deterministic: use elapsed-duration formulas or coarse elapsed buckets, never replay thousands of visual frames. Use idempotent tick IDs and retry safely.

Define a versioned deterministic simulation module with seeded pseudo-randomness derived from aviary/tick/bird IDs. It makes restart/retry behavior reproducible while preserving variety across events. Tune coefficients in offline simulation against the PRD targets: small measurable vector movement after about one week of regular presence and user-noticeable behavioral differences around three weeks, with no visibly moving trait in one session. Keep calibration configuration separate from API/client code and record its version in state.

The drift layer is a slow low-pass filter over validated signals: presence time dominates and applies expressive, nonnegative deltas to relevant traits; listen-in gives extra attention to the focused bird's social warmth/vocal frequency; an accepted offer nudges curiosity, and offering near a bird nudges boldness. Cooldowns prevent a single session from saturating curiosity. Settle quiets mood and terminates the presence window but adds no directional drift. Apply per-tick and lifetime bounds and monotonicity tests. Do not decay personality or infer negative signals from inactivity. Do not produce user-visible values.

Mood is a separate daily-ish fast state with enumerated wary/content/curious/drowsy/alert values (finalize and version enum at implementation). A transition function takes prior mood, recent event summary, local time phase, short-lived weather, bird-to-bird calls/alarm state, and that bird's personality. Mood persists across sessions; it never resets on open. Night generally settles birds while the designated nightjar-like species may remain active. Rain briefly dampens calling; wind affects alert/wariness. Ensure absence does not create distress. Birds choose perch/idle pose from mood and personality, with stochastic variation constrained by stable identity.

Calls use a per-species motif grammar and stable bird signature. The worker/snapshot supplies schedules and mood-dependent parameters; client synthesizes notes through WebAudio oscillators/noise/envelopes with bounded, reusable voices and small timing/pitch variation. Maintain recognizable signature across mood and drift. Bird-to-bird call response and chorus events are derived server-side or from the canonical event schedule so concurrent clients render the same aviary moments. Avoid downloadable or looped call assets.

## 6. Presence, sessions, and synchronization

The client tracks `visibilityState`, `document.hasFocus()`, and recent pointer/key activity. It reports presence only while all three hold. Activity should renew a short presence lease; the chosen activity window is a few minutes and should be calibrated toward the longer end so still watching remains valid. On loss of focus/visibility, settle, pagehide, or lease expiry, terminate the interval. Do not equate an open tab with presence. Validate and cap client-reported interval durations server-side to avoid clock tampering or background accumulation. Presence is the primary drift input, not click count.

While visible, clients pull snapshots on a low-frequency keepalive and push a qualifying presence lease/event. Pull immediately when visibility returns and after a long frame gap or device resume. Interpolate between canonical snapshots on the client, and fetch a fresh snapshot rather than simulating missed time after suspension. A local monotonic clock can animate between server timestamps, but all durable state remains server-owned. If two devices are open, both may present the same aviary; events are serialized on server receipt sequence. No last-write-wins for vectors: only the tick applies server-authored additive deltas to the existing canonical vector. Use database transaction/locking and event cursors to prevent lost updates and duplicate processing.

## 7. Frontend scene and interaction rendering

Build a responsive, single horizontal scene with front/middle/back perch zones, calm palette, subtle foreground/background depth, and all birds visible at the smallest supported viewport. No pan, zoom, scroll, drag-to-place, inline labels, badges, or bird overlays. Top bar contains account/settings, accessibility, notebook, and offer only. Fade the bar nearly transparent after cursor inactivity and restore on pointer or keyboard activity; preserve keyboard discoverability and focus visibility.

At first paint, show the quiet field or snapshot-backed scene directly, with motion already in progress. Bootstrap enough state with page delivery to meet first-bird-visible under 500ms on mid-tier mobile over 4G. Do not block first draw on notebook/settings, audio permission, or secondary assets. Birds run mood/personality-keyed idle motion (preen, scan, tilt, shuffle); leaves/feathers and subtle parallax are client-side ornaments, not persistent simulation entities. Day/night follows the account's IANA timezone. Weather and bird locations come from canonical snapshots.

Return greeting is selected from absence duration, boldness, mood, and deterministic procedural variation; only one bird notices first. Further birds, when appropriate, stagger by randomized offsets. No textual welcome or absence-duration UI. Listen-in engages by click/tap or keyboard focus, gradually raising the focused bird while others remain audible at ambient level; disengage on same bird, another bird, empty scene, or focus leaving, with gradual return. Offers open from top bar, select seed/song fragment/still pool and an eligible target, then render reactions from mood/curiosity/vocality without direct bird clicking. Settle fades light toward evening and quiets calls; any aviary click within five seconds undoes it. Tab close is equivalent at simulation level and never creates a recovery prompt.

Reduced motion replaces continuous movement with slowly cross-fading still poses, flight with perch-to-perch cross-fades, removes leaf drift, and slows ambient lighting change. Audio, mood, drift, and notebook behavior continue. Respect OS preference and explicit setting. Code-split account, accessibility, notebook, and invitation surfaces. Keep initial gzipped JavaScript below 2MB.

## 8. Audio, captions, and accessible interaction

Create a WebAudio engine with one bounded AudioContext, pooled/reused oscillators or worklet voices, per-bird motif grammar, envelopes, soft chorus mixing, and gradual listen-in gain automation. Handle autoplay restrictions by starting/resuming audio only after allowed user gesture; if unavailable or denied, render gracefully in silence and turn captions on by default. Do not ship recorded fallback audio. Define listen-in mix floors so other birds never become silent. Fade calls with settle and evening state.

Generate captions from the actual motif and performance parameters at call time (for example, “a soft three-note rise”), place them near the calling bird, and fade them with the call. Provide a user setting for captions. Ensure captions remain readable on all scene phases. Build a parallel prose narration surface from the same snapshot: naturalist lowercase present-tense observation, one update every 30–60 seconds at idle, prompt updates after user-initiated greeting/offer/settle, and no personality numbers or rapid state chatter. Use a polite live region with controlled queue/coalescing so users are not flooded.

All controls work by keyboard: top bar tab order; scene entry focuses first bird; arrow keys move bird focus; Enter begins listen-in; Escape exits; offers and settle are keyboard reachable. Provide visible soft high-contrast focus outlines against all scene palettes. Respect accessible names without exposing internal state. Meet WCAG AA for all copy including captions and visually displayed narration. Test screen-reader narration, keyboard-only flows, OS reduced motion, audio disabled/blocked, and narrow viewport as product acceptance work.

## 9. Notebook, account lifecycle, and visits

Notebook generation belongs to the simulation/domain layer, not a client event feed. Define noteworthy observation templates from state facts (who greeted first, posture/weather/call patterns) and a sparsity policy with per-aviary quiet periods. Use authored compositional prose with reviewed variants, not generic state labels or freeform text that might reveal sensitive attributes. No entry may count visits or say how often the user was present. Preserve entries in chronological history and paginate for long histories.

On account creation send a one-time link, create one aviary, choose two starter species server-side, and ask for names; first bird appearance follows the brief's quiet empty-state handling. Age-based bird offers become eligible over months (implementation config) and stop at seven, never based on engagement. Account deletion uses immediate soft deletion plus 30-day recovery, then a verifiable hard-delete job. Export is on demand, snapshot-based, includes sensitive vectors because the user owns their copy, and uses an expiring download URL delivered to verified email.

Visits default off in practice because no invitation exists until the host deliberately creates one. Validate target email and one-time invite link, expire unused links after 30 days, list current invitations and visit records in settings, and allow revocation. The snapshot endpoint rechecks revocation each pull. Visitor pages are ambient read-only, with no notebook browsing if it changes host state (ordinary read is harmless only if included in same view policy), no presence heartbeat, no offers/listen-in/settle, and no shared cursor. Log approximate visit duration solely for host transparency. Do not notify by default; honor the optional setting only if enabled. No social profile, feed, discovery, chat, comments, or show-off rendering.

## 10. Performance, observability, and release

Acceptance budgets: initial gzipped JS under 2MB; first bird visible under 500ms on mid-tier mobile/4G; idle motion at 60fps on a five-year-old mid-range laptop; no client memory growth over 30 minutes. Reuse audio buffers/voices, bound workers/contexts, release scrolled notebook references, pause rendering when hidden, and keep ornaments allocation-light. Support the latest two major versions of Chrome, Safari, Firefox, and Edge; older browsers get a clear matter-of-fact unsupported-browser page.

Collect aggregate-only synthetic browser checks by common geography and aggregate RUM for navigation, snapshot/first-bird timings, frame timing, audio-context errors, API/tick latency and error rates. Simulation tick p99 over five seconds pages/alarms. Do not collect bird ID, account dimension, state payload, interaction type history, or user email as telemetry. Operational logs use request correlation IDs that cannot be linked to an account UUID in the analytics warehouse. Keep telemetry schema review part of API review.

Roll out behind controlled server-side flags: internal deterministic fixtures; a small invited cohort with two birds; broaden account access after auth, sync, privacy, and accessibility acceptance; then ramp age-based adoption eligibility and load toward seven birds per aviary. Do not gate reduced-motion, captions, screen-reader narration, or keyboard support behind later rollout. Track operational and product-quality metrics only in aggregate: first-bird latency, tick p99, errors, frame budget, audio fallback incidence, and invite delivery/revocation correctness. Do not add engagement scoring or per-account usage dashboards. Calibrate drift and call mix with internal fixtures and consented qualitative review without retaining per-bird telemetry for population analysis.

Before launch, perform concurrency/retry verification for duplicate tick delivery, multi-device overlap, stale snapshots, event ordering and deletion races; browser/device performance profiling at two and seven birds; auth and invitation token/revocation checks; and accessibility audits across visual, keyboard, screen-reader, reduced-motion, captions, and contrast. These are launch gates for the stated product behaviors, not invitations to add engagement features.

## 11. Main risks and mitigations

- **Drift feels too fast, too slow, or rewards clicks:** calibrate low-pass coefficients against one-week instrument/three-week perceptual targets; make presence dominant, offers/listen-in secondary, bound contribution, and test multiweek simulated trajectories. Enforce monotonic nonnegative trait deltas and no absence penalty.
- **Presence is inflated or missed:** combine visible + focused + recent pointer/key activity, lease intervals, cap durations and terminate on hide/settle/expiry. Test idle watching and suspended/background tabs on all browsers.
- **Sync loses or duplicates personality history:** single server writer, ordered append-only events, idempotency, transactional tick cursor/state commit, lock/version per aviary, and recovery tests with simultaneous clients.
- **Mood jumps or scene feels newly started:** persist mood and absolute transition timing; account timezone drives scene phase; bootstrap a current snapshot; use deterministic bounded catch-up and avoid entry/loading animations.
- **Calls sound synthetic/uncanny or signatures blur:** prototype motifs early across six species and seven simultaneous birds, test recognizability across moods and drift, tune envelopes/timing and mix floors, retain graceful silence+captions as the only fallback.
- **Accessibility becomes a second-rate fallback:** design prose narration, reduced-motion poses, captions, focus and contrast in parallel with core renderer; include users of assistive technology in acceptance review.
- **Privacy leakage through logs, exports, invites, or analytics:** synthetic UUID everywhere except encrypted account email, isolated telemetry store, schema allowlists, token hashing, authorization tests, deletion propagation and audit of export contents.
- **Rare notebook output becomes repetitive or gamified:** template review, cadence limits and banned-category tests for user attendance, trait values, achievement language, and generic event-log phrasing.
- **Performance degrades at seven birds or long sessions:** profile max load and 30-minute sessions early; bound animation/audio resources and keep bootstrap payload small. Preserve a two-bird start and seven-bird cap if optimization is needed.
