# Pocket Aviary — v1 implementation plan

Phase-1 deliverable for wave_001, run 001. This document specifies implementation work; it does not implement the product or evaluate another plan. Its inputs are `prd/1-START_HERE.md` and all nine listed PRDs. The decisions below fill gaps in those PRDs without adding product scope. `concepts.md` governs terminology where descriptions differ.

## 1. Product contract and scope

Build a browser window onto one continuing aviary per signed-in account. The first ordinary frame contains recognizable birds already in motion. One bird notices an owner returning within one to two seconds. Attention changes personality across weeks, while mood and behavior vary within a day. Leaving causes no penalty. The product must work with a screen reader, reduced motion, silent audio, and keyboard input at launch.

V1 includes:

- Email magic-link accounts, device session management, verified email changes, settings, export, recoverable deletion, and one canonical aviary.
- Two server-selected starter birds from six species; editable names; additional age-based adoption invitations; an absolute maximum of seven birds.
- Persistent hidden personality, persistent mood, bird-to-bird behavior, procedural calls, front/middle/back perch choice, local-time lighting, rare weather, and continuous idle behavior.
- Precise owner presence accounting, listen-in, three offer kinds, settle with a five-second reversal, and a sparse, read-only field notebook with indefinite history.
- Explicit email invitations for read-only ambient visits, revocation, expiration, and an on-demand host visit log.
- Naturalist narration, runtime call captions, keyboard access, contrast, and a designed reduced-motion renderer.
- Operational telemetry restricted to performance, availability, and anonymous aggregate health.

Do not build native apps, passwords or SSO, payments, multiple or shared aviaries, scene customization, user-positioned birds, hunger or distress, dying birds, trait meters, gamification, visit streaks, adoption counters, public profiles/discovery, comments, chat, follows, ranks, badges, shared cursors, or engagement campaigns. No aviary push notifications, welcome banners, return toasts, absence-duration copy, or notebook observations about the user's attendance. No public or private population dashboards of personality or interaction behavior. Do not add a service worker installation flow or another app-like onboarding surface merely because the product is web-based.

Enter toggles the focused bird's listen-in, Escape ends it, and leaving bird focus ends it. | Account-local day versus traveling devices | Store one account-level IANA timezone, initially suggested from the first browser and confirmed in settings. Weather is synthetic, not fetched from a location service. |

| Mute is mentioned as relationship input without a defined drift direction | Audio preference changes are acknowledged by a quiet transient reaction at most. Never decrease traits, reward unmuting, or penalize hearing differences. Do not feed mute preference into personality drift in v1. |
| Minute tick versus prompt interaction response | Event ingestion returns an immutable, server-authored reaction plan immediately. Clients perform that presentation; the next simulation tick consumes the same plan and updates persistent state. There is no client-authored mood or personality write. Section 5 specifies how to avoid a second interpretation at tick time. |

## 2. Architecture and responsibilities

Use a TypeScript web application with a small server-rendered entry shell, a dedicated imperative SVG scene controller, Preact DOM panels, and shared versioned contract types. Use a Node.js HTTP service and a Vite asset build, keeping the critical scene independent of panel hydration. Use PostgreSQL for identity, canonical aviaries, ordered events, notebook, and visits. Run an API/web process and a horizontally scalable tick/job worker from the same codebase. Use an edge gateway for TLS, public immutable assets, and authenticated bootstrap forwarding. Use encrypted object storage for temporary exports and private backups, and a transactional email adapter. Avoid adding a distributed event bus, analytics warehouse, or client-side simulation framework to v1.

Suggested implementation boundaries, all to be created during engineering:

| Boundary | Owns | Must not own |
| --- | --- | --- |
| `domain/contracts` | Versioned API types, event kinds, render descriptors, export schema | Database credentials, private trait fields in public types |
| `domain/simulation` | Trait deltas, mood transition tables, action planning, call/behavior timelines, seeded randomness | Browser timers, audio nodes, telemetry transport |
| `server/identity` | Encrypted emails, tokens, device sessions, permissions, deletion | Bird behavior or analytics |
| `server/aviary` | Snapshot projection, command validation, ordered append, adoption/renaming | Direct personality mutations |
| `worker/tick` | Sole persistent personality/mood writer, timeline advancement, notebook selection | Marketing emails or interaction aggregation |
| `client/scene` | SVG composition, timestamp interpolation, responsive placement, reduced motion | Choosing moods, accepting offers, generating drift |
| `client/audio` | Synthesizing authorized call descriptors, gain ramps, fallback | Generating behavioral calls from a local personality model |
| `client/accessibility` | Semantic controls, prose narration, runtime captions, focus | Numeric personality exposure |
| `server/visits` | Named invite capabilities, read-only access, revocation, private visit log | Owner presence or shared interaction state |
| `operations` | Aggregate metrics, synthetic tests, release controls | Reads of interaction payloads or simulation values for analytics |

The canonical aviary has two related representations: durable materialized state last committed by a tick, and its bounded timeline of already accepted server-authored actions. A consistent snapshot folds accepted actions onto the materialized state for presentation. Both are on the server. Browsers receive a projection sufficient for rendering, not a copy of the personality model. Ingestion is allowed to append commands and their presentation plans; only the tick role can update persistent personality and mood fields.

A visible client pulls snapshots approximately every ten seconds, sooner after an owner action, visibility restoration, or a render gap over two seconds. This is deliberately polling rather than WebSocket co-presence. Conditional requests make unchanged polls inexpensive. Owner and visitor views use the same scene/call plan. Listen-in is a local mix preference; settling ends the initiating attention session and produces a server-authored shared temporary evening state. Hidden documents stop drawing, audio scheduling, and routine polls, while the server continues every minute.

### First navigation and the render boundary

1. The authenticated edge gateway forwards a request to the account's home region, obtains a transactionally consistent bootstrap snapshot, and embeds the small private snapshot plus first-frame SVG in the streamed HTML. Shared CDN caches store code, motifs, and species assets, never personalized HTML/snapshots. Private response caching cannot bypass authentication, deletion, or invite revocation.
2. The SVG depicts each bird at its current pose phase and perch, not a neutral loading pose. Critical inline scene code advances transforms from the supplied server-time epoch before noncritical component hydration finishes. Small species shapes and palette tokens needed for this frame are inline.
3. A visible owner sends an idempotent return command on document entry/restoration; the server selects the greeter and returns its procedural cue. Render it within one to two seconds of visibility. Prefetch response envelopes alongside the snapshot to minimize the round trip, but do not record presence simply because HTML was requested. A visitor never sends a return command.
4. Audio starts immediately if the browser already permits a running context. Otherwise the scene starts silently with captions available/defaulted on until the first explicit sound-enabling gesture; do not violate autoplay rules or introduce an audio welcome modal.
5. If bootstrap delivery misses the first-frame target, show the quiet sky/foliage field, possibly a faint ambient cue. No spinner, generic skeleton, progress text, or fade from a static bird scene. Treat this as a measured performance failure, not the normal experience.

The one-time post-adoption empty field and gentle first fly-in are the specified exception to ongoing-motion entry. Atomically record an initial-arrival plan during aviary creation; returning navigation later samples current behavior and never reruns it. Do not add fly-ins when signing into another device.

## 3. Data model and invariants

Use UUIDs for every stable identity and foreign key; use monotonic integers for ordering within an aviary. Store timestamps as UTC instants and timezone as an IANA identifier. All rows with account-owned data have an `account_id` or an explicitly traversable account foreign key for export/deletion. Use database row access policies plus service authorization checks. Separate database roles for API ingestion, simulation writes, auth email decryption, and operations.

| `Account` | UUID; encrypted verified email; keyed lookup digest; status `active/deletion_pending`; settings version; IANA timezone; created/deletion/recovery timestamps. Email plaintext is decrypted only for an authorized identity/mail operation. Never use email or its digest as an operational ID. |
| `MagicLink` | UUID, account UUID if existing, purpose, hash of random 256-bit bearer token, issued/expires/consumed times, safe redirect allowlist. New-account challenges temporarily hold encrypted destination until account creation; purge immediately afterward. |

| `Aviary` | UUID, unique account UUID, created time, lifecycle, simulation version, tick revision, event high-watermark, last logical tick instant, next due tick, private random seed, environmental state, settlement epoch, adoption eligibility state. Unique account constraint forbids a second aviary. |
| `Bird` | Stable UUID, aviary UUID, species/template version, original adoption time, user name, name version, private immutable identity seed/call signature, five persisted normalized trait values, nonnegative drift-filter memory, mood, mood-since/reset target, perch zone/slot, current action timeline, cooldown-until. Recipient emails do not belong in foreign keys or log payloads. Normalize named visitors through an encrypted identity-address store, referenced by UUID and purged with the last host-owned reference. If a recipient already has an account, use its verified account identity. For invite-only people the address record is the sole encrypted copy, analogous to the account record; this is the necessary narrow extension for named email invites, not permission to replicate plaintext. Host visit logs resolve the email only on authorized settings requests. The keyed lookup digest permits uniqueness/rate limiting without logging PII and is not an identifier outside identity storage.

Important constraints to enforce in the database and domain layer:

- Exactly two starter birds are committed with the new aviary; never create a persistent empty owner aviary. Adoption cannot exceed seven, including concurrent requests on different devices. No bird replacement/removal endpoint exists in v1.
- Trait columns lie in `[0,1]`. The tick applies nonnegative bounded additive deltas under a row lock; an update may not lower a prior value. Migration permissions are exceptional and audited privately. Clients/public contract types cannot specify these columns.
- IDs, adoption dates, stored vectors, call signatures, and accumulated filter state survive every rename and version migration. Never seed a new identity to repair a missing vector.
- Event sequence is assigned inside the aviary transaction, so committed append order equals simulation consumption order; sequence-allocation gaps and uncommitted events cannot be skipped by an advancing cursor.
- A materialized tick revision, consumed event cursor, trait update, mood update, notebook insertion, and plan revision commit atomically. Retry cannot apply drift twice.
- No raw interaction payload, notebook prose, bird identifier, trait value, email, or bearer token is exported to operational metrics/logs.

Name input allows Unicode, length 1–40 grapheme clusters, whitespace normalization, and no markup/control characters. Render as escaped text. Default name suggestions are editable, species selection is server-owned, and renaming is reachable from account → bird settings without an in-scene context menu.

## 4. API and authorization contracts

All endpoints are HTTPS, JSON except HTML and downloads, versioned under `/api/v1`. Owner mutations require a valid device cookie, same-origin/CSRF validation, and an idempotency key. Snapshot responses carry schema version, `server_now`, logical simulation time, revision token, and an ETag. Set `Cache-Control: private, no-store` on identity, private snapshots, visit capabilities, and exports; immutable public assets use content hashes. Errors use stable system codes plus matter-of-fact copy, not naturalist messages. Return no account enumeration details from email requests.

| Endpoint | Contract and behavior |
| --- | --- |
| `POST /auth/magic-links` | `{email, redirect_path}`; always 202. Issue a 15-minute single-use challenge and queue transactional mail. Start at five requests per address per hour with resend availability, plus bounded IP abuse limits; tune operationally without an onboarding quota UI. |
| `POST /auth/magic-links/consume` | Exchange token for a per-device cookie atomically. Concurrent replays have one winner. Email-scanner GET must never consume a link; landing page performs explicit browser confirmation/exchange. Invalid/expired/used links share clear replacement-link guidance. |
| `GET /account`, `PATCH /account/settings` | Return system settings and lifecycle only. Conditional `If-Match` settings version prevents overwriting a timezone or accessibility setting on another device. A conflict refetches with a matter-of-fact inline notice. No trait stats. |
| `GET /account/sessions`, `DELETE /account/sessions/{id}` | List/revoke the owner's device sessions. Revoking current session clears cookie. Subsequent interaction or snapshot request fails closed. |
| `POST /account/email-change`, `POST /account/email-change/verify` | Verify new destination before an atomic switch; old address remains authoritative until success. Invalidate outstanding old-address auth links on switch. |
| `POST /aviary/adoption` | Idempotently initialize the two preselected starter birds with proposed names, or accept one eligible additional server-selected bird. Availability token binds species/age and is rechecked in a locked transaction. Persist initial arrival cues only for creation/adoption. |
| `PATCH /aviary/birds/{id}/name` | Name and expected name version; 409 if stale, no effect on bird identity, behavior, vector, or call. No other bird patch fields accepted. |
| `GET /aviary/snapshot` | Canonical render projection, environment, active server cues, call horizon, natural-language facts, and action eligibility. No raw personality, filter state, prior owner presence totals, or device-attention history. Supports `If-None-Match`; server time can be supplied on 304. |
| `POST /aviary/events` | `{attention_session_id, client_seq, events:[...]}` bounded batch (at most 20). Each event has UUID idempotency key and approved kind. Returns per-event accepted/duplicate/rejected result, assigned order, effective time, immutable cue plan, and latest revision. Batch status is explicit; do not silently claim all were accepted. |
| `GET /aviary/notebook?before={opaque_cursor}&limit=30` | Read-only reverse chronological pages, stable UUID tie-breaker. No arbitrary offset scan; old entries remain queryable. No POST/PATCH/DELETE notebook endpoint. |
| `POST /account/exports`, `GET /account/exports/{id}` | 202 job request/status. Worker produces consistent JSON and mails verified owner a 24-hour one-use download link. The requested export is not a telemetry event with bird content. |
| `GET /exports/download/{token}` | Exchange capability after verification of validity; streamed encrypted-object download, no referrer leakage. Raw traits omitted according to section 1. |
| `POST /account/deletion`, `POST /account/recovery` | Mark immediate deletion-pending status with 30-day deadline; recovery is an explicit `I changed my mind` action after sign-in. These operations are idempotent and serialized with final purge. |
| `POST /visits/invitations` | Owner explicitly submits recipient email; 201 with invitation status, then one transactional invitation email. Never auto-invite contacts. |
| `GET /visits/invitations`, `GET /visits/log` | Owner settings only, paginated; decrypt named recipient address for this surface. No settings badge or unread count. |
| `DELETE /visits/invitations/{id}` | Atomically revoke invitation and active visit session(s); active/outstanding list changes inline. No success toast or host notification. |
| `POST /visits/redeem` | Consume unused invite token before 30-day expiry and issue a visit-only cookie. No owner account required. Same browser can resume this session; token itself cannot be redeemed a second time. |
| `GET /visits/snapshot` | Check capability and host lifecycle on every pull; return exactly the owner scene projection without owner settings/notebook/private fields. 410 for expired/revoked/host-unavailable capability with identical matter-of-fact unavailable surface. |
| `POST /visits/end` | Optional capability-only lifecycle close used to refine duration; cannot submit simulation events. Server timeout covers tab closure or dropped connection. |

Owner event kinds are `return`, `presence_interval`, `listen_start`, `listen_end`, `offer`, `settle`, `settle_undo`, and `attention_end`. A return opens/resumes an attention-session epoch but does not itself count qualified presence. Offer payload is one of `seed`, `fragment` with an allowlisted motif ID, or `pool`; the top-bar offer is to the aviary, and the server chooses eligible receivers. Listen-in payload names one existing owner bird. Settle/undo reference a settlement epoch; do not accept arbitrary state fields.

The snapshot includes bird IDs/names/species for semantics, perch zones/slots, posture expressions, motion phases and times, palette/feather presentation, stable motif family identifiers, and seeded call descriptors. These are rendering outputs; never name them `boldness`, `warmth`, or another numeric trait, publish sliders for them, or embed hidden vector data in HTML/ARIA/devtools helpers. A scene descriptor may necessarily contain pitch, color, and duration values; they are not personality statistics and cannot reconstruct exact stored vectors.

Capability separation is enforced at routing and database authorization, not merely by hiding buttons. A visit credential calling `/aviary/events`, rename, notebook, export, settings mutations, or adoption returns 403. A visitor choosing local sound/caption/reduced-motion preferences does not submit host events. Token redaction covers URLs, access logs, error reports, and referrers; bearer tokens are exchanged then removed from browser history.

## 5. Canonical simulation and immediate responses

### Tick scheduling and transaction

Schedule each account with a retained aviary once per 60 seconds, spreading accounts over that minute by a hash of the aviary UUID. Workers claim due rows in bounded batches using row locks with skip-locked behavior. Maintain one writer per aviary through a database transaction/advisory lock, not an in-memory lease alone. Closed tabs do not change scheduling. Deletion-pending accounts reject new interaction/adoption/visit work, while their birds continue the same absence-only tick until recovery or hard deletion. Recovery therefore preserves vectors and continuity without inventing presence or replaying a month on the browser.

For each logical minute:

1. Lock the aviary, check lifecycle and `last_tick_at`, and obtain the committed event high-watermark. Read ordered unconsumed events only through that watermark. Include prior filter state and bounded recent summaries; never rebuild personality from a historical log.
2. Advance the environment and behavior between event instants. Convert server-qualified presence/listen intervals to union durations, consume accepted offer outcomes, and apply settlement/re-engagement to the mood/presentation timeline. Use the stored reaction plans, not new random choices.
3. Integrate nonnegative trait deltas over actual elapsed UTC time. Advance mood timers and scheduled bird responses in chronological order. Extend bird action/call plans into the rolling horizon while preserving all previously published IDs and cues unless explicitly canceled by a later accepted action.
4. Select at most one notebook observation if sparsity/candidate rules permit. Write any entry with a unique private source key so retries cannot duplicate it.
5. Commit vectors, filter memories, mood, environmental state, cue horizon, consumed cursor, tick revision, and tick receipt in one transaction. Publish a cache invalidation only after commit through the transactional outbox. A rolled-back tick has no visible delta or advanced cursor.

Normal work is bounded by seven birds and a bounded number of accepted events. Rate-limit abusive high-frequency commands and coalesce presence intervals without losing their duration. Do not scan all account history each minute. Events accepted after the tick's high-watermark remain for the next minute. A worker retry finds either the old uncommitted state or a completed tick receipt; it never reapplies a trait delta.

If workers lag, replay missed logical minutes in bounded slices off the request path, preserving event order and actual UTC time. Fold stretches without events using the analytic filter and deterministic environment/mood schedule where equivalent, while processing significant weather/mood transitions in order. Never multiply a current presence value by the whole outage duration. Snapshots expose the last valid state with a matter-of-fact connectivity/loading explanation outside the scene when necessary; clients do not manufacture a replacement simulation. Tick latency and scheduling lateness are measured separately.

### Reaction plans: responsive without client state ownership

The command service takes the same aviary lock briefly, reads its materialized state plus bounded unconsumed authorized action plans, assigns the next sequence, and appends a validated event with an immutable cue plan. The plan contains bird targets, start/end times, random seed, pose/path/call instructions, intended transient mood effect, and cooldown reservation. No trait columns or persistent mood columns change in that transaction.

Both the command response and snapshots project this committed pending plan. The next tick materializes the same planned transition at its effective time and advances the event cursor. Thus an offer can receive a prompt reaction before the minute boundary, but the later snapshot does not replay the reaction or pick another bird. The logical revision is a tuple `(tick_revision, accepted_event_seq, scene_plan_revision)`; snapshots with that tuple describe one consistent server view. The API uses a transaction snapshot/row lock so it cannot combine birds from one revision with cues from another.

If a response is lost, resubmitting its idempotency key returns the original assigned sequence and plan. If a later action interrupts an earlier plan, append an explicit cancellation/transition plan; do not edit the old event. Persistent personality is affected only when the tick computes its additive delta. Immediate animations are authoritative server instructions, not optimistic local personality changes. Local listen-in gain and rapid settle reversal can start provisionally for responsiveness, but never count as accepted drift inputs without a server receipt.

### Personality initialization and drift

Initialize each of the five traits within approximately 0.20–0.45, using bounded species differences and per-bird seeded variation. Avoid uniformly identical starters and avoid initialization close to saturation. Store the vector once. Initialize the call signature separately so increasing vocal frequency cannot replace the recognizable motif. Seed sources come from server cryptographic randomness, with deterministic pseudorandom streams separated by behavior, weather, calls, and observations.

Maintain private rolling 24-hour qualified durations and capped interaction summaries through consumed events. They are engine state, not user counters. Use these initial calibration values:

- `P = 1 - exp(-qualified_owner_seconds_24h / 900)`, with the duration input capped at 1,800 seconds. Qualified presence is unioned across devices.
- For bird `b`, `L_b = 1 - exp(-qualified_listen_seconds_24h(b) / 600)`. Listen time is also unioned across devices for the same bird and must overlap qualified owner presence.
- `O_near_b` and `O_accept_b` are bounded `[0,1]` signals from accepted eligible offers, capped at three useful offers per bird per day; ignored offers can contribute proximity but not acceptance. Cooldowns and caps make clicking unable to accelerate drift arbitrarily.
- Drive signals: boldness `u=.95P+.05O_near`; social warmth and vocal frequency `u=.85P+.15L`; curiosity `u=.90P+.10O_accept`; plumage `u=P`. Interaction-only drive cannot dominate regular presence. Interaction contributions require a qualifying owner attention session; a visitor never contributes.

For each trait `j`, keep nonnegative low-pass memory `z_j` with a three-day time constant. For a segment of duration `dt` days with constant drive `u_j`:

`z_next = u_j + (z_prev - u_j) * exp(-dt / 3)`

`integrated_drive = u_j * dt + (z_prev - u_j) * 3 * (1 - exp(-dt / 3))`

Compute an additive nonnegative delta:

`delta_j = (1 - v_j) * (1 - exp(-k_j * max(0, integrated_drive)))`

`v_next_j = min(1, v_j + delta_j)`

Start `k_j`, per day, at boldness 0.018, social warmth 0.014, vocal frequency 0.010, plumage 0.008, curiosity 0.014. These are tuning seeds rather than claims of validated perceptual thresholds. Persist both `v_next` and `z_next`; use float64 calculations and avoid rounding away minute deltas. Segment integration when rolling inputs or events change; do not apply the final drive value retroactively to a whole minute containing a transition.

With a synthetic ten-minute daily presence routine, these seeds should produce instrument-visible week-one changes and modest multiweek changes. The first calibration task measures actual outputs: require positive changes comfortably above numerical tolerance by day seven and no perceptible single-session jump, then tune presentation sensitivity and coefficients so blinded design sessions distinguish a three-week bird from its starting behavior. Do not certify the calibration using the formula alone. Include one-minute, ten-minute, thirty-minute, highly active, and irregular routines, all generated synthetically, plus controlled consented evaluation without recording real interaction histories into analytics.

When presence disappears, rolling inputs expire and `z` decays; residual positive drift from previous attention is allowed and finite. Vectors never decrease. Absence quietness is handled through neutral recent-attention expression and natural mood/time-of-day, not a decreased vocal trait, dulled feathers, learned distrust, or a distress state. The unobserved ambient call process has a nonzero species baseline outside its natural sleep periods. Long absence never replaces a bird or triggers a guilt observation.

Do not use a trait value directly as a public meter. Map it through species-specific behavior curves: boldness affects front-perch choice/approach distance; warmth affects response/greeting weights; vocal frequency affects call hazard/chorus participation; plumage modifies a modest bounded color/detail range; curiosity affects investigation probability. Each curve must remain consistent in identity while showing a subtle perceptual change across weeks.

### Mood and environmental state

Use the five states `wary`, `content`, `curious`, `drowsy`, and `alert`. Sleeping and settled are posture/environment expressions, not harmful need states. Each species has a small transition matrix conditioned on account-local solar-like time phase, recent accepted interactions, short weather effects, neighboring calls, and persisted traits.

Choose time-of-day curves by account clock rather than location coordinates: warm morning around 06:00–09:00, bright midday, gradual evening around 17:00–21:00, dim night. Store UTC transition instants derived from the IANA timezone so DST changes do not create negative durations, duplicate drift, or divergent devices. A timezone settings change smoothly retimes the scene over approximately a minute and changes subsequent mood schedules; it does not reset birds.

Each bird has a randomized daily relaxation window of roughly 18–30 hours. At that timer, relax toward an appropriate time-of-day prior using an ordinary low-amplitude transition rather than resetting the entire scene to neutral. Keep mood on reopen; a client arrival is not a reset event. Minimum dwell times around two to five minutes and limited transition magnitude prevent noisy state flipping. An accepted seed may nudge content; a novel fragment may prompt curious/alert; wary birds pause and approach slowly; a drowsy bird can ignore an offer without negative consequences.

Generate a small rain approximately two to four times per synthetic week, each five to twelve minutes, and occasional soft wind. Schedule each event server-side with deterministic seeds, including while no one is connected. Rain temporarily lowers call hazard, never the stored vocal-frequency trait. Wind's mild alert/wary influence depends on the bird. No thunder, severe weather, snow, alert banner, local weather API, or user-driven weather selector.

Bird-to-bird influence is bounded: a call can schedule a response after a small natural delay; a wary call may briefly raise nearby vigilance; overlapping compatible calls can form a chorus. Use at most one response-generation hop and a refractory window to prevent an alarm/chorus feedback cascade. Neighbor effects adjust transition probabilities rather than forcing every bird into the same state. Keep a quiet baseline floor and species differentiation.

### Behavior and call planning

The server creates timestamped action spans: preen, scan, weight-shuffle, head-tilt, hop, short flight, rest, and contextual reactions. Selection depends on mood/traits, but the browser sees only the chosen spans and rendering parameters. Serialize phase origins so a joining client samples a span mid-action. Each span includes its from/to perch slot, pose parameters, deterministic variation seed, and transition duration. Do not synchronize all idle movements to the minute boundary.

Keep a 120-second rolling call/behavior horizon, extending it every tick and preserving published cue IDs. A server interaction may cancel future cues and inject a response; pulls distribute explicit cancellations. Already sounding calls taper smoothly rather than disappear. Pending action planning is bounded and does not regenerate the same horizon on each GET. Past call IDs are not played on resume.

Each species grammar defines a small motif family: note count ranges, rise/fall contours, pauses, trills, envelope types, and response-compatible transitions. Bird identity fixes a narrow timbre/pitch/motif preference within that family. Mood and expressive drift alter timing, intensity, and bounded variation but cannot change the identity's recognizable anchor. A call descriptor contains a call UUID, bird UUID, server start time, motif/seed, actual note/envelope/contour parameters, duration, amplitude, position, and semantic shape. Clients synthesize it deterministically; they do not roll a new call or locally choose chorus participants.

Resolve per-call variation with seeded continuous values and valid motif combinations, not a rotating list of recorded variants. Ensure adjacent returns/calls do not use identical resolved descriptors. The engine's audibility schedule is the same for owner and visitor; listen-in only rebalances gain on the particular client. Limit simultaneous sounding calls through natural scheduling to four ordinary voices while allowing seven signatures over time; occasional chorus can include more if the measured mix remains clear.

## 6. Presence, session behavior, and interactions

### Qualifying attention precisely

Implement one owner-only presence controller outside the render loop. At any instant, presence qualifies only when all three are true: `document.visibilityState === 'visible'`, `document.hasFocus() === true`, and a trusted pointermove or keypress/key-down equivalent has occurred within the past five minutes. Use the platform's trusted keyboard event equivalent without double-counting keypress and keydown. Pointerdown/touch alone is not an additional substitute signal; touch pointer movement qualifies normally. Navigation, audio playback, focus, a timer, and an open tab alone never seed recent activity.

Track the activity timestamp with a monotonic clock; record state-change boundaries on visibility/focus/activity-window expiry. While all conditions hold, form short intervals and send them every 15 seconds. Stop the interval immediately on blur, hidden, expiry, settle, or unload/pagehide. A final beacon is best effort, not necessary for correctness. Use server-clock synchronization from snapshots to bound intervals, and accept at most the last 30 seconds of an active authenticated stream; never award an hour from one delayed ping. A client cannot write a trusted presence total or vector.

On receipt, validate sequence, session epoch, interval ordering, receipt-time bounds, and a maximum duration. Union overlapping intervals by account before drift, rather than adding durations from two visible devices. Preserve the recent interval-union summary across tick boundaries so two streams delivered on opposite sides of a tick cannot earn the same second twice. Slightly late but valid intervals enter the next tick's rolling drive; never rewrite an already committed vector to backdate them. Listen-in durations are intersected with qualified presence and unioned per bird. The server trusts the browser's signal report only within these bounded intervals; detecting forged attention perfectly is outside a calm browser product's scope, while basic replay/inflation remains preventable. No pointer coordinates, key contents, keystroke logging, or raw activity stream leave the browser.

Use a single owner attention leader per tab group where possible through a lightweight tab lock/BroadcastChannel, but retain server interval union as the correctness mechanism across browsers/devices and after leadership loss. Ping silence expires server-side attention intervals promptly; no ongoing duration is awarded after the final validated interval. A tab held open with a once-active mouse for eight hours earns at most the five-minute window, not eight hours. Keyboard interaction participates equally; missing pointer movement cannot exclude a keyboard user.

The product's specified presence conjunction may undercount stationary touch or assistive-technology use without the listed activity signals. Do not silently change the definition. Test actual mobile and screen-reader behavior, document the limitation in engineering acceptance, and choose accessible keyboard controls so real activity can qualify without requiring repetitive movement. Nothing in the UI asks a user to move a pointer to retain attention credit.

### Return-greeting

On fresh visible owner navigation, tab restoration, or wake from suspend, send one return command for that visibility epoch, deduplicated on retries. Pass no client-estimated personality; the server knows the last owner-return/session time and current projected mood. Use a smoothly bounded function of absence length to select glance versus reorientation, and weighted bird selection favoring warmth/boldness while respecting wary/drowsy states. Always choose one initial noticing bird within one to two seconds; it can notice through a small glance rather than a call. Additional responses are eligible at randomized offsets, never an all-bird arrival chorus.

Procedurally resolve the head tilt, glance timing, approach distance, and optional call within identity bounds. This is distinct from an entry animation: the first ongoing motion is already present, and the greeting occurs within it. A long absence can yield a quieter notice, not a distrust/neglect punishment. An internal absence interval is never rendered as text, a streak, a date counter, or a tooltip. Screen-reader narration describes the bird's action promptly in naturalist prose; that accessibility observation is the greeting, not a separate welcome announcement.

### Listen-in

Click/tap or bird focus engages one local bird mix; changing bird transfers attention with a slow ramp. Clicking the active bird, blank aviary space, moving keyboard focus away, Enter toggle-off, or Escape ends it. A local gain ramp starts on input without waiting for network; idempotent start/end events record the qualifying attention intervals for the selected bird. The server closes stale listen intervals on presence/session expiry so a parked selection does not accumulate forever. Losing sound does not disable the visual/semantic attention gesture or count it as negative input.

### Offers

Offer controls live in the top-bar panel. A seed appears on the foreground perch area, a fragment is a soft procedurally synthesized library motif, and a pool adds a temporary reflective surface. The user does not drag a gift onto a bird or select a target bird through an in-scene control. The server selects one primary eligible receiving bird and optional non-rewarding observer reactions.

Reserve a 180-second per-bird cooldown when accepting the command, including pending unconsumed plans. Concurrent phone/laptop offers cannot bypass it. If all birds are cooling down, the panel quietly explains availability in naturalist phrasing, without countdown, progress bar, punishment, or failure toast. A drowsy/wary receiver can ignore or delay the gesture; the cooldown still bounds input, and only actual accepted investigation contributes its small drift term. Bound the object's scene lifetime, remove it smoothly, and dispose all rendering/audio references. Fragments cannot be user-uploaded audio or arbitrary text-to-audio input.

### Settle and leaving

Settle appends an epoch-specific server plan, ends the initiating attention/listen session at its effective timestamp, slowly warms/dims lighting over about four seconds, and gently quiets calls. It creates a small drowsy/content mood influence with zero directional personality input. A plain close ends that session's qualified presence identically, without a settlement mood gesture or guilt message. Presence on another genuinely active owner device remains unioned normally; neither ending one tab nor settling can erase another tab's already accepted attention.

Any click/tap in the scene captured within five seconds issues `settle_undo` and locally begins reversing the visual transition. The server validates the same epoch and a monotonic elapsed-time witness, with a bounded network transit allowance up to three seconds; it does not reopen unrelated older settlements. Keyboard Enter/Escape provides an equivalent accessible reversal. Undo starts a fresh attention epoch and never invents presence for the closed gap. Suppress other scene actions on that reversal click so it cannot simultaneously offer or start an unintended listen-in.

After the reversal window, deliberate re-engagement (scene input, listen-in, offer, or a new owner return) clears the shared evening override with a gentle transition and opens a new attention session. Passive pings do not reopen a settled session. The settled tab remains settled until close or re-engagement; closing releases that tab's settlement override, and the next session follows the account-local time. Shared state changes use settlement IDs, so delayed acknowledgments from one device cannot resurrect a cleared override.

Refresh a settlement presentation lease through the initiating visible view's ordinary snapshot pulls, independently of presence. A close callback releases it best effort; absent that callback, expire it after 45 seconds without a pull. This detects a closed/suspended tab without counting a settled tab as attention. A settled tab left visibly open continues its evening scene; a returning owner explicitly re-engages before clearing an old override. Local cached offline lighting is presentation only and cannot retain a server lease indefinitely.

## 7. Snapshot synchronization and failure handling

Every owner device reads one server record plus its committed plans. No device sends an absolute vector, locally ticks a mood model, merges bird histories, or selects a winning personality state. All drift is additive and server-authored. Client queues hold commands awaiting acknowledgment, never a vector delta. A late device has no state it is permitted to overwrite.

On each pull:

1. Validate schema compatibility and canonical revision. Ignore a response older than the most recently applied revision, even if its HTTP request finished later. Match action/call IDs to prevent repeats.
2. Estimate server/client time offset from request send, response receipt, and `server_now`; keep a smoothed estimate and prefer low-round-trip samples. Do not use client wall time to determine absence or drift. Snap large timing errors through a short pose/cue reconciliation rather than replaying all skipped actions.
3. Apply the latest server plan and sample it at corrected current time. Interpolate a perch transition along its supplied path/duration. If the entire transition occurred while hidden, join its resulting pose; do not fly a bird around to reenact missed history.
4. Cancel obsolete future call/pose IDs, retain already-live audio tails with a short taper, and extend the lookahead horizon. Keep bounded recently-played ID sets (for example, five minutes) rather than one growing set for the entire session.

Pull triggers are visible entry/restoration, ten-second visible keepalive, accepted interactions, and a render-frame gap over two seconds. Blur stops presence immediately but leaves the visible scene running; hidden stops rendering/audio and normal pulls. Wake from suspend first revalidates auth and state, then resumes at current phase. Owner actions on one device become visible on another within the next pull, generally ten seconds; persistent vectors reflect the next minute tick. There is no claim of subsecond cross-device shared presence.

Per-device command sequences must be monotonically increasing. A missing earlier command returns `missing_sequence` and the next expected sequence; the sender resends its bounded queue in order. Duplicate idempotency keys return their original outcome. Device-local order plus server commit order defines the global event stream; an untrusted old timestamp cannot reorder the stream. For transport retries within 30 seconds, preserve the same key/sequence. After longer offline gaps, expire unaccepted presence/listen duration and transient offers instead of replaying gestures into a different mood. A user may explicitly try an offer again; this creates a new command with a new outcome.

Keep the pending queue in memory, limited by count and age, and clear it on sign-out/account change. If a transient retryable failure occurs, use jittered exponential backoff. Respect 429 `Retry-After`. Auth failures stop writes and offer sign-in in an inline matter-of-fact system surface. A 409 on a name/settings update shows the latest saved value and asks for a new edit; do not silently last-write-wins the fields. A trait conflict UI is unnecessary because the API never accepts trait writes.

When offline, continue sampling only the published horizon and local decorative motion. After the horizon expires, use gentle stationary breathing/pose cross-fades from the last authorized posture; do not generate new behavioral calls, moods, weather, or drift. Show a small matter-of-fact connectivity explanation in the system chrome, with no celebration when connection returns. No offline interaction history export, pending-count badge, or estimated attention meter. On reconnection pull fresh state before accepting new commands.

Snapshot caches, if added after measurement, are revision-keyed private caches. Authentication/lifecycle authorization happens before every serving path; invite revocation cannot be bypassed by a cached snapshot or 304. A command invalidates its aviary's projection cache. Strong reads and tick transactions use the account's home-region primary rather than an unbounded-lag replica. Scale by UUID partitioning only when measured load justifies it; one aviary must retain one transactional writer domain.

## 8. Frontend scene and rendering pipeline

### Composition and layout

Use a single SVG scene with a normalized horizontal coordinate system, compact procedural/SVG bird shapes, and DOM overlays only for semantics, focus, and optional captions. Six species get distinct silhouettes, wing/head features, muted palettes, posture sets, and stable per-bird appearance details. Do not substitute a generic bird shape differentiated only by color. Mood expressions are posture/pose choices, not labels or status icons.

Layer order is sky/day palette, background foliage, back perch/birds, middle perch/birds, front perch/birds and offered objects, then restrained foreground ornaments. The server chooses logical zones/slots. The client maps them to pixel-safe responsive locations; resizing does not change a bird's underlying chosen proximity. Include safe boundaries for full silhouettes, wings during flight, focus outlines, and captions.

Use a height budget based on the available dynamic viewport below the thin top bar. At narrow phone widths, compress lateral spacing and distribute slots across the three depth rows; retain the horizontal scene rather than creating vertical browsing. Preserve bird body proportions, adjusting environment spacing and scale within a legibility floor. Use `preserveAspectRatio`/fit transforms with letterboxed soft sky where necessary, never cover/crop transforms. All seven birds remain visible at the smallest supported reasonable viewport (start acceptance at 320×568 CSS pixels) and landscape phones. There is no scene scrollbar, camera pan, zoom, drag-to-place, or offscreen wandering. Notebook and settings panels may scroll independently.

The first-frame SVG is server-rendered from the same snapshot used by the controller. Inline critical code starts from the supplied phase and epoch, so hydration does not reset poses. Assets below the critical path cannot delay showing a bird. Later updates modify bounded transforms, colors, and shape parameters without remounting the whole scene. Separate frame-rate scene work from DOM panel component rendering.

### Motion, time, and lifecycle

Use one `requestAnimationFrame` loop. It samples approved behavior spans and adds small mood-shaped micro-motion within those spans: weight shifts, preening articulation, scanning/head tilt, and breathing. Use continuous seeded noise/splines rather than repeating a fixed animation cycle. Clamp amplitudes, avoid high-frequency shaking/strobing, and vary phase per bird. Full motion perch changes are short supplied paths with eased landing, not teleportation. Corrections from a newer snapshot transition from the current sampled pose without discontinuous jumps where safe.

Leaves and feathers are client-only decorative objects, as the PRD permits. Maintain a fixed-size pool with a maximum around eight ornaments, long irregular spawn intervals, bounded lifetimes, and no references after removal. Initialize occasional ornaments partway along a path for the first frame. Subtle parallax is a low-amplitude autonomous scene offset, not a cursor-tracking spectacle; disable it in reduced motion. Ambient weather timing comes from the server; individual rain strokes may be renderer ornaments.

On hidden, cancel frame callbacks, stop ornament scheduling, dispose expired cues, suspend audio scheduling, and flush final qualified presence if feasible. On visible blur, keep rendering while presence ends. On reveal, pull state before restarting stale action scheduling and jump to current phases. Use one set of visibility/focus/resize listeners per view, with explicit disposal on route changes. Route teardown aborts requests, clears timers and DOM refs, disconnects observers, and stops audio nodes.

### Reduced motion is a rendering mode

Respect system `prefers-reduced-motion` before the first bird frame; an account setting can force it on but cannot silently force off a system safety preference. In this mode, sample a small authored set of still poses and cross-fade over approximately three to six seconds. Perch transitions cross-fade between the source and destination; no flight path, head oscillation, falling feather, leaf drift, moving rain stroke, or parallax. Day/night and settle color transitions remain slower, approximately six to ten seconds. Keep scene state, bird identity, mood, calls, captions, and notebook identical to full motion.

Changing preference mid-session preserves the current pose and switches gently; it does not replay arrival or reset mood. Screen-reader/keyboard narration receives the same observations because it consumes the canonical projection, not animation callbacks. Design and review cross-fade pose sets independently rather than treating disabled animation as completion.

### Chrome and panels

The four top-bar icons have accessible names, adequate hit areas, calm high-contrast focus treatment, and no badge counts. After four seconds of pointer stillness fade the bar nearly transparent only when it has no focus, open panel, hover, or error requiring action. Restore it before handling pointer movement/keyboard activity. Never make a focused control faint or inaccessible. On coarse-pointer devices keep a usable persistent low-chrome treatment until a deliberate idle period and make the first touch reveal safely; do not consume a touch that was targeting a visible control.

Account, accessibility, notebook, and offer panels are lazy-loaded. Use focus-managed dialogs/panels, return focus to the triggering icon on close, provide Escape dismissal, and avoid blocking the continuing scene unnecessarily. Notebook scrolling cannot alter presence semantics except for real trusted keyboard/pointer activity. Adopt/rename/invite actions are on-demand system/account surfaces rather than new persistent scene icons.

## 9. Audio pipeline and call captions

Build one WebAudio graph per aviary view: per-bird voice bus → per-bird gain → gentle spatialization if supported → master headroom/limiter → output. Use one AudioContext and, where supported, one AudioWorklet for allocation-bounded synthesis. Native oscillators, filters, gain envelopes, and reusable procedurally created noise/wavetable data are the fallback if a worklet cannot initialize; this remains procedural audio. There are no downloaded bird recordings or recorded-loop fallback assets.

Resolve authorized descriptors to note events with continuous pitch contours, controlled harmonic/noise mixtures, small identity-bounded variation, short attacks, and natural tails. Reusable waveform tables are synthesis primitives, not prerecorded calls. Schedule against AudioContext time using the smoothed server offset, with a short approximately 100–200ms scheduling lookahead. The server's two-minute horizon supplies future descriptors; a light scheduler starts only upcoming nodes. Never create all nodes for the full horizon or schedule from frame callbacks alone.

Call identity stays anchored through motif family, pitch band, timbre ratio, and signature pauses. Mood changes contour/intensity within those anchors; drift changes call frequency and subtle expression. A chorus is multiple live generated voices with independent phase/variation and headroom, not a pre-rendered chorus clip. Rate-limit rapid responses in the server grammar, cap node/voice counts, and duck the soft offered fragment enough for bird responses to remain identifiable. Test the nightjar-like signature at night without filling the scene with constant sound.

Start calibration with ambient gain 0.55 per bird, focused bird 0.80, other birds 0.25, and a 1.5-second smooth ramp into/out of listen-in. Final gains depend on synthesis loudness tests, but the nonfocused floor is always greater than zero. Rapid switching retargets a continuous envelope from the current level; canceling a ramp must not step the gain. A settle uses a several-second downward ramp rather than a mute. Master mute is an explicit audio preference and suppresses sound without changing canonical calls or drift.

Handle autoplay/context errors as a normal capability state. Attempt playback only when allowed; on blocked startup, suspended/interrupted contexts, unavailable WebAudio, or hardware failure, continue the complete silent aviary and default captions on. Surface a matter-of-fact sound-enabling affordance in accessibility settings/top-bar panel without an intrusive modal. A trusted gesture may retry `resume`; repeated failure stays silent. If the user explicitly opted out of captions, preserve that preference rather than repeatedly overriding it after each recoverable interruption, while first-time fallback defaults them on. Safari/interruption and device output changes are tested explicitly.

Captions are derived from the fully resolved descriptor that the synthesizer uses: note count, rise/fall, trill shape, pauses, intensity, and scene position. Generate lowercase observational phrases such as `a soft three-note rise` from these values, not one fixed caption per motif/species. In silence the same canonical descriptor still produces a caption at its scheduled time. An unavailable engine never substitutes a generic prerecorded sound or a generic text placeholder.

Place captions near the calling bird using responsive collision avoidance, a subdued opaque backing, and sufficient contrast at all day phases. Fade gently, with reduced-motion-safe opacity changes. Limit simultaneous overlapping text through packing/combined chorus phrasing based on actual calling bird descriptors, not by silently dropping all but the selected bird. Keep caption content out of the narration live queue by default to avoid duplicate screen-reader chatter; accessible narration can mention the call as part of the observation. Retain only the bounded current captions needed for display, not a second call-history feature.

At call end, release/disconnect nodes, handlers, and descriptor references. Pool only objects that actually reduce allocation cost; keep fixed limits for voices, noise buffers, decoded grammar tables, future descriptors, and recent-ID dedupe. No audio buffers containing ever-growing rendered calls, one-context-per-bird pattern, or retained closure per historical call. Stop/suspend hidden audio promptly and resume only the current/future calls. Validate that mute/listen transitions never click, clipping stays below the chosen headroom, and returning after suspend does not play a burst of missed calls.

## 10. Accessibility and product voice

### Semantic scene and narration

SVG art is decorative to assistive technology. Provide a scene container with one roving-tabindex semantic bird control per stable bird ID, accessible names such as `pip, warbler; listen in`, and a concise scene description. Do not announce `mood: wary`, perch indices, personality numbers, every frame change, or every motif parameter. Name and species are useful identification; prose supplies the living scene.

A narration composer consumes the same server facts/scene projection as the visual renderer. Compose one to three short naturalist sentences describing a distinctive bird action, another relevant bird, and environment. Use lowercase present tense and specific verbs. Reuse the editorial grammar with notebook writing, not raw event strings. Preserve factuality: a narration cannot say that a bird approached when its projected cue says it ignored an offer.

At idle, update a `role=status`, polite, atomic live region approximately every 45 seconds, within the required 30–60-second range. Do not clear/reinsert identical text to force speech. An owner greeting, accepted offer outcome, or settle gets a timely observation, generally within one to two seconds of its visual cue, but remains polite and concise. Keep a bounded queue, coalesce redundant ambient observations, and replace stale idle prose rather than accumulating speech while a screen reader reads another panel. Pause idle narration while settings/dialog controls are being read and on hidden; resume with a current observation, not a backlog.

Return/offer narration is observational (`pip looks up from the front rail`) rather than a system welcome or transaction announcement. System validation errors use direct matter-of-fact accessible error text and can have an appropriate alert role. Optional visible narration appears in the accessibility surface with full contrast. A user can pause narration/adjust its idle cadence within the allowed calm range without disabling keyboard access or drift.

### Keyboard, focus, and touch

Tab proceeds through the four top-bar items and into the first bird. Arrow keys traverse birds in stable adoption order, retaining focus if birds change perch. Enter engages/toggles listen-in; Escape exits listen-in and, where appropriate, closes the active panel. Moving focus outside birds disengages the mix. An offer shortcut works when the aviary is focused (for example Alt+O), with a visible alternative; no single-letter shortcut captures typing in name/email fields. Settle is reached in the same top-bar panel and has keyboard reversal.

Birds are semantic buttons with at least 44×44 CSS-pixel hit regions, layout-tested at seven birds without overlapping ambiguous targets. Use a soft high-contrast dual-tone focus outline against both bright and dark foliage. Focus rings are the accessibility exception to no scene chrome; there is no persistent hover label. Dialogs contain predictable tab order, accessible legends/labels, and focus return. Asynchronously receiving a snapshot, an invitation, or a notebook entry never steals focus.

Target text contrast is at least 4.5:1 for ordinary text and 3:1 for qualifying large text; focus/interactive boundaries are at least 3:1. Check actual top-bar/panel/caption/error/narration color combinations at morning, midday, evening, night, rain, and settle. Caption backing protects contrast independently of the underlying bird palette. Do not require color perception to find a bird or understand a focus/disabled state. Validate 200% text zoom and browser zoom/reflow without hiding controls or clipping captions.

Release requires manual VoiceOver/Safari, NVDA/Firefox or Chrome, keyboard-only, touch, and reduced-motion review, alongside automated markup/contrast checks. Test long listening sessions and notebook scroll rather than merely opening the first scene. Confirm the accessible aviary still communicates particular birds and quiet change, not a technical state list.

## 11. Field notebook generation

Generate entries in the tick from a bounded private observation accumulator, not every API request or session start. Candidates are actual aviary facts: an unusual greeting order, a lasting perch habit, a subdued morning posture, a rare response to a fragment, a passing rain with a bird reaction, or a long quiet stretch. No candidate may be a user attendance statistic, a personality delta, an achievement, or a feed item about a visitor.

Maintain enough private summaries for factual statements such as `first time this week` without replaying indefinite interaction logs. Track the week-local greeting-order facts and recent observation kinds; do not expose this as a visits calendar. For new accounts, allow one genuine initial observation after the birds have settled into their scene, not a signup transaction entry.

Default generation cadence is roughly one entry every three to four days for a regularly observed aviary. Set a minimum 48-hour ordinary spacing; allow a genuinely distinct notable event at most once per 24 hours. Active users do not increase the baseline linearly with event volume. Generate sparse environment/behavior observations while the aviary runs unobserved, but avoid filling long absences with dozens of repetitive entries. Limit candidate scores/priority so a weather event does not guarantee an entry each time.

Use editorially authored fact-constrained templates with variation slots, present-tense verbs, species/bird names, and scene particulars. No external language-model service receives account data. Templates generate natural prose instead of `session started` or `offer accepted`. Validate spelling, singular/plural, names, punctuation, lowercasing voice, and absence of forbidden numeric/stat language. Names remain references to the observed bird: store rendered historical prose immutable on rename, while current UI/narration uses the current name. Date headings reflect the observation's saved timezone, even after an account timezone change.

Keep notebook entries indefinitely for an active/recovered account. Index `(aviary_id, observed_at, id)`, page by cursor, and virtualize long notebook scrolling. DOM rows and page caches have a bounded window, but storage has no user-visible archival horizon. Account deletion purges the notebook as part of the account, which is distinct from an edit/delete-entry feature. The visitor scene does not receive notebook contents or a notebook browsing control.

## 12. Account lifecycle, visits, and privacy operations

### Account creation and identity

Successful initial magic-link consumption creates one account UUID and device session. Provision the two species server-side and present them as the birds that arrived, with default names the user may accept or edit. No catalog, rarity choice, avatar editor, inventory, or congratulatory modal. The adoption transaction creates both stable birds, one aviary, initial vector/filter state, and one-time arrival cues together. Retrying from another device returns the same starter identities.

Store account email encrypted with a managed key hierarchy. Only identity/mail code can decrypt it; browser/API logging cannot accidentally serialize the account object. Use keyed normalized-address lookup digests for uniqueness and rate limiting in identity storage only. Maintain short-lived email request envelopes until delivery/expiry, never a second permanent address database in queues or logs. Per-device cookies are opaque high-entropy secrets stored hashed server-side, Secure/HttpOnly/SameSite, with CSRF/origin protection for mutations. Start with 30-day device sessions, rotating/renewing securely when appropriate, and explicit user revocation.

Magic links expire after exactly 15 minutes and have atomic one-use consumption. The token GET landing is inert so email security scanners cannot sign users in or redeem visits. Never allow arbitrary external redirect paths. Email changes verify the new address with a purpose-bound single-use link while the old address remains active; the account UUID and aviary do not change. Revoked devices cannot fetch a cached private snapshot or append more events. Show current device and recent device activity only as security settings, not a product attendance log.

### Visits and notifications

The host explicitly creates each named invitation in account settings; the feature remains absent from onboarding. The emailed link is valid for 30 days until first redemption. Redeem atomically for one visitor-only session with a 24-hour maximum lifetime. This fixed active-session limit is a conservative implementation choice because the PRD specifies only unused-invite expiry. It does not create a permanent friend list or automatic future access. A visitor can resume in that browser within the active lifetime; another visit afterward requires a new deliberate invite. Explain the access window in the matter-of-fact invitation surface.

The visitor receives the same bird poses, mood expressions, call descriptors, weather, and host-time lighting as an owner viewing that revision. Use the identical scene/audio code with an ambient read-only capability flag; do not create a beautified visitor mode. Remove owner bird controls, offer/settle/notebook controls, return commands, and presence controller entirely. Local audio/caption/reduced-motion controls remain accessible but cannot change host settings or trigger listen-in. The host sees no visitor marker, cursor, greeting, new bird, or live co-presence state.

A visit pull verifies invitation status, visit-session expiry, and host status every time, including conditional requests. Revocation invalidates its active cookie server-side; the next pull (at most the ten-second polling interval while visible, sooner on restoration) replaces the scene with `This visit is no longer available.` No continued private snapshot stream. Expired/revoked unused links use that same surface. Do not promise instantaneous pixel removal from an already downloaded offline frame; local scene rendering stops when the next authoritative pull rejects access. This is the PRD's next-pull revocation semantics.

Begin the silent visit-log row at successful redemption and refine duration using authorized pulls plus optional close, ending at last observed activity plus at most one polling interval. Round to approximately the nearest minute, marked approximate. This is host transparency data, isolated from owner simulation and operational analytics. Revocation removes the item from active/outstanding invitations but preserves the historic `who/when/duration` row, avoiding destruction of the sharing audit. Historical log access is on demand with no icon badge or unread indicator.

If and only if the host has enabled visit email notifications, enqueue a single deduplicated visit-start email with a matter-of-fact statement and a settings link. Repeated pulls, reloads, retries, and resume do not send more messages. Honor a disabled toggle at delivery time, avoid batching reminders, and never include bird state, notebook content, host attendance, or encouragement to return. This narrow explicitly opted-in social exception does not establish a general notification service. The invite email and explicit requested export are transactional delivery, not aviary engagement mail.

### Export, deletion, and recovery

Exports take a consistent committed/projection snapshot and cursor-page notebook entries into a streaming JSON writer so an old aviary does not require the entire notebook in RAM. Include schema/engine versions, aviary creation time, stable bird IDs/species/names/adoption times, current mood labels, notebook prose/date history, and account settings. Do not export interaction/presence logs, visitor addresses, session tokens, private random seeds, or trait-derived rendering coefficients. Raw vector omission follows the explicit conflict decision in section 1; this limitation is stated clearly in export settings. An export is a snapshot, not a migration/import feature.

Write the export to encrypted storage, email a verified-owner download capability, and expire/delete after 24 hours. Never attach the JSON directly to mail, place it in a public bucket, or print its object key/token in observability. Hard account deletion immediately invalidates any outstanding download regardless of its nominal expiry.

Deletion marks the account immediately and records a 30-day UTC deadline. Stop owner mutations, exports, invitations, and visits; revoke existing visitor sessions. Device/auth access permits only the matter-of-fact deletion-pending surface and explicit recovery. Recovery before the cutoff atomically restores the account and its same birds/vectors/notebook/settings; canceled visits are not silently re-enabled. A final purge and recovery racing at the deadline serialize on the account lock, with the server deadline deciding the result.

At the cutoff, purge identity/email/digests, sessions/challenges, aviary/birds/filter state, raw and summarized events, notebook, visit references, export objects, mail jobs, private caches, and account-keyed diagnostic records. Erase the account data-encryption key so protected backup contents cannot resurrect its vectors or relationship. Use a deletion ledger with minimal opaque tombstones and bounded retention for restore exclusion, not an account history. Shared visitor identity addresses are deleted when no live host/account reference needs them; removing one host never erases another host's legitimately separate invite.

Choose backups with seven-day bounded physical retention, account-key encryption for private payloads, and deletion-aware restore automation. A restore must replay hard-deletion tombstones before becoming readable and must never restore erased encryption keys. Record and test the distinction between immediate live/crypto-erasure at day 30 and automatic physical expiry of encrypted backup blocks; do not claim an archived raw plaintext row remains acceptable. Where the provider cannot meet this, change backup design before launch. Run recurring drills for restoring the exact same vectors/IDs and for proving a hard-deleted account cannot recover them.

### Privacy as a data boundary

Owner interaction events serve only the owner's simulation. No use for training, recommendations, species popularity, cross-account drift tuning, social rankings, or cohort engagement. No third-party SDK reads scene state or event payloads. Synthetic schedules drive calibration. Human design studies collect explicit opinions/recognizability judgments, not actual customer interaction streams for population analysis.

Set raw simulation-event retention initially to seven days after consumption. Keep compact private filter/24-hour durations and observation summaries needed by that account's engine; retain notebook indefinitely. Events awaiting consumption are not purged, and a stalled tick/backlog blocks their purge until safely processed. Stable personality never depends on retained raw events for reconstruction. Retention maintenance may delete rows from the append-only log after consumption; ordinary clients/API never edit or delete an event.

Operational metrics have explicit schemas allowing route template, status class, duration, engine release version, browser family, and coarse synthetic geography/device class. Disallow account UUID, bird UUID, email, token, names, interaction kind/payload, vector values, notebook text, and invitation identities as metric dimensions. Client RUM sends timing buckets and capability error classes through first-party aggregation without a durable user identifier; discard transport IP after coarse handling and do not join measurements to simulation rows. Operational request counts use generic routes, not per-bird action popularity.

Limited support/security diagnostics may use a synthetic account UUID for a concrete error lookup, without bird/event payloads, for a short retention (start seven days), separate access controls, and deletion purging. Metrics exporters have no simulation-database read credentials. Request middleware and error reporters use field allowlists, never automatic body/object serialization. Redact emails/tokens in web access logs and disable full URL collection. No external error collector receives per-bird state or account interaction history.

The account privacy-policy link plainly names allowed aggregate request/latency/error/frame/audio metrics and excludes private interaction data. Include account lifecycle/export decisions and invitation sharing duration; write this as a system surface rather than naturalist prose.

## 13. Performance budgets and observability

Treat budgets as release gates with a defined device/network matrix, not targets to optimize after adding all features. The reference mobile test is a mid-tier Android device or calibrated equivalent, a stable 4G profile around 150ms RTT and 1.6Mbps downstream, and both cold and warm asset-cache navigations. The laptop target is a physical five-year-old mid-range machine with integrated graphics; record its exact configuration in engineering test fixtures. Browser support is the last two major versions of Chrome, Safari, Firefox, and Edge at release. Maintain that rolling matrix; show a clear unsupported-browser system surface outside it rather than shipping heavy compatibility shims.

| Budget | Implementation allocation and verification |
| --- | --- |
| Initial JS less than 2MB gzipped | Hard CI compressed-size gate over everything required by first bird. Internal target at most 200KB, with the critical scene controller around 35KB or less. Lazy-load account, notebook, invite, and accessibility panels; no sampled audio or large rendering framework. Report both critical and total route chunks to prevent moving required work out of accounting. |
| First bird visible less than 500ms | Aim authenticated bootstrap/first-byte within 200ms in reference geography; first HTML, small snapshot, and first-frame vector shapes within roughly 30–50KB gzipped combined; begin painting before full app hydration. Gate cold-cache and warm-cache controlled mobile navigations, with p95 below 500ms in the defined reachable-edge test matrix. Do not relabel first static sky paint as first bird. |
| 60fps idle on the old laptop | Frame budget 16.7ms; target scene scripting at most 4ms and paint/composite at most 8ms p95 for seven birds, rain, captions, and active audio over 30 minutes. Track missed frames and browser long tasks as well as averages. No per-frame component tree updates, broad SVG filter stacks, or per-leaf layout reads. |
| No client memory growth over 30 minutes | After warmup, run a seven-bird session with calls/offers, notebook scrolling, visibility cycles, and panel mounts. Compare repeated post-GC heap samples and object/resource counters; no monotonic retained growth, orphan audio nodes, workers, listeners, or DOM rows. Allow only a fixed bounded cache reaching a plateau, not an ever-increasing baseline. |
| Snapshot size | Initial internal target 5–15KB gzipped including seven birds and the horizon; p95 less than 20KB. Evaluate packing/descriptor IDs before shortening continuity or omitting accessibility facts. |
| Simulation tick health | Alarm if p99 computation latency exceeds five seconds. Also measure due-to-start scheduler lag; target p99 under ten seconds and alarm well before a full missed minute. Record transaction retries/backlog counts without per-account behavior dimensions. |
| Interaction responsiveness | First local listen-in gain change immediately, server-authored offer/greeting cue normally within 300–500ms receipt-to-render on the reference connection; greeting within two seconds of visibility. Cross-device changes within ten-second pull interval; personality commitment by next minute. |

The 2MB ceiling alone cannot meet a 500ms first-frame target on 4G. The much tighter critical-path targets and streamed inline bird are required. Authenticated state must not be put into a shared CDN cache to win speed. Test origin latency from common geographies early; if a single home region cannot satisfy the required matrix, add nearby authenticated rendering/state-serving replicas with version guarantees or account home-region placement before launch. Do not silently relax the target or substitute another account's/generic bird while state arrives.

Measure a `first-bird-frame` performance mark after critical SVG insertion and a paint opportunity, and correlate it with pixel/screenshot assertions in synthetic browsers. This client mark is an estimate of visible rendering, not proof from DOM insertion alone. Use synthetic pixel validation to distinguish sky, a placeholder, and an actual bird. Track initial download/TTFB, first-bird timing, frame distribution, long tasks, audio initialization/error classes, polling latency/error rates, tick computation, scheduler lag, job failures, and memory checks. Time intervals and counters never carry bird facts.

Run scheduled synthetics from several common geographies with controlled reference devices/networks. Tests use isolated synthetic accounts and may inspect their own private vectors to validate monotonicity; do not mix synthetic metrics with real-account relationship analytics. Aggregate RUM receives only performance/capability categories. Allowed anonymous session-duration histograms are coarse operational buckets without stable account/device dimensions or an interaction-history join. Avoid publishing product engagement goals from these histograms.

Apply metric cardinality/field checks at collection time and in CI. Reject an event containing an email, bearer secret, bird/account identifier, notebook field, or trait field. Scrub error payloads even when serialization fails. Collect no clicks-per-session, presence-per-account trends, listen-in popularity, offer conversion, adoption leaderboards, retention streaks, or average boldness; their absence is an architectural requirement, not an unbuilt dashboard.

## 14. Verification and acceptance suite

Implement tests around behavioral/correctness risks, using deterministic time and seeded simulation. Avoid asserting that every random action sequence is identical across all future engine versions; assert reproducibility within a version, safety constraints, identity continuity, and specific calibration fixtures.

| Area | Required evidence before release |
| --- | --- |
| Presence | All eight combinations of visibility/focus/recent activity, exact five-minute boundary, keyboard activity, blur/hidden/suspend, absent unload beacon, delayed ping, out-of-order replay, two-device overlapping intervals, and visitor access. Only the full conjunction earns time; background overnight earns none beyond a prior valid interval. No pointer/key contents transmitted. |
| Drift | Property tests of bounded nonnegative deltas across random valid inputs and clock segments; week-one measurable/three-week perceptual fixture; no visible single-session movement; residual positive tail on absence; zero negative drift after a month away; offers cannot overwhelm presence; client absolute vector fields rejected. |
| Tick and durability | Concurrent worker claims, crash before/after commit, lost acknowledgment, duplicate event retry, event arriving at tick boundary, cursor correctness, missed-minute catchup, and vector restore. Result equals one serial execution; no delta duplicated/lost and no vector reconstructed/reset. |
| Mood/continuity | Mood persists across reopen; daily timer versus timezone/DST; same revision on phone/laptop/visitor; nightjar-like calls at night; rare weather modifies expression but not traits; bounded bird-to-bird cascades. |
| Greeting | One initial noticing bird within two seconds; absence/boldness/mood materially change cue; subsequent greetings stagger; repeated greetings differ within identity; no spinner/arrival reset/welcome text on return; visitor causes none. |
| Interaction | Listen start/end under rapid focus changes; others remain audible; server-global per-bird offer cooldown across two devices; offer denial doesn't punish; settle ends the initiating presence; five-second reversal/late network/epoch mismatch; ordinary close has no penalty. |
| Rendering | Mid-action first frame, no hydration reset, phone/landscape/resizing and seven-bird bounds, day/night/rain text contrast, hidden pause/visible resume, no offscreen birds or scene scrolling, reduced-motion cross-fades without moving ornaments. |
| Audio | Distinct bird signatures in pair and seven-bird scenes, procedural variation without exact repeated calls, chorus clarity/headroom, ramp continuity, context-block/failure/cross-browser resume, bounded node disposal, no backlog burst on wake, zero prerecorded audio path. |
| Captions/narration | Resolved descriptor versus caption factual match in audible/silent modes; narrator uses current facts and lowercased prose; 30–60-second idle queue cadence, prompt user events, no duplicated speech storm, no vector values in DOM/ARIA/snapshot. |
| Notebook | Sparse synthetic month with both low/high activity, factual rare-order/week statements, no per-session feed, immutable historical prose on rename, cursor pagination over years, bounded virtualized memory, no user-behavior observations. |
| Auth/accounts | 15-minute expiry and atomic consume race, scanner-safe landing, device revocation, verified email switch, one account/aviary on concurrent creation, age eligibility independent of visits, seven-bird race guard, export capability expiry/omitted vectors, deletion/recovery deadline and irreversible purge. |
| Visits | Off by default, one-time redeem/30-day unused expiry, no owner write capability, scene parity, host timezone, no drift/greeting/listen caused by visitor, revocation on next pull including 304/hidden restoration, quiet logs, opt-in email exactly once, no implicit auto-reinvite. |
| Privacy | Trace all instrumentation/mail/error schemas; no simulation DB access for metrics; injected sensitive fields rejected; delete account and verify all live records/jobs/objects/diagnostics cleared; restore cannot recover erased data; no per-bird state forwarded externally. |

The engine calibration harness accelerates days/weeks from synthetic fixtures without changing production clock semantics. It can inspect private vectors in test infrastructure only. A design evaluation compares bird behavior and call recognition without showing trait numbers. For audio recognizability, ask evaluators to identify the same bird across mood/three-week drift and multi-bird chorus; use a predetermined launch criterion (start at at least 80% correct identity matching in controlled comparisons, adjust fixture difficulty before final sign-off). Do not train on customer histories or use customer telemetry to tune drift.

End-to-end tests use two independent browser contexts against the same synthetic account. Inject crashes and request loss between append, tick commit, and acknowledgment. Include a long-lived screen-reader/keyboard session, not just automated axe-style checks. Keep physical-device performance/audio/accessibility verification as a release requirement where simulated headless environments cannot establish quality.

## 15. Delivery sequence and rollout

The work packages are ordered by dependency. Frontend, audio, and accessibility engineering can develop against shared synthetic snapshots while backend durability is built; ship them together. Assign a backend/domain owner, a scene/frontend owner, an audio owner, and an accessibility/QA owner with design review. Do not add temporary generic graphics/recorded calls as a product alpha that later establishes the wrong experience.

| Milestone | Work and exit gate |
| --- | --- |
| 1 — contracts and feasibility | Freeze public/private schemas, ambiguity decisions, six species signature/silhouette briefs, three-perch responsive map, voice templates, and data-boundary rules. Prototype streamed mid-action first frame and procedural two-bird calls, including silent/reduced-motion/narration paths. Demonstrate 500ms feasibility and identity recognizability before building secondary panels. |
| 2 — canonical core | Implement account/aviary/bird schema, identity seed persistence, ordered event append/idempotency, reaction plans, locked minute tick, exact interval union, additive drift, mood/time/weather, snapshot projections, and job/outbox plumbing. Pass serial/concurrent/retry/crash tests and synthetic three-week calibration. |
| 3 — complete owner experience | Integrate actual species assets, smooth interpolation, listen-in, offer kinds/cooldowns, settle/undo, scene lifecycle, naming/adoption, small chrome, narration/captions/reduced motion, and notebook. Pass two-device continuity, keyboard/screen-reader design review, and mobile seven-bird layout even while real users begin at two. |
| 4 — lifecycle and quiet sharing | Finish device settings/revocation, verified email changes, export, deletion/recovery/purge/restore, invitation capabilities, read-only parity, visit log, optional off-by-default visit emails. Pass authorization, replay, revocation, and privacy-boundary tests. |
| 5 — hardening | Complete browser matrix, physical old-laptop 30-minute run, memory gate, cold/warm 4G first bird, audio listening study, reduced-motion contrast/zoom review, tick-load and scheduler backlog tests, deletion drill, and documentation for operators. No accessibility surface deferred to a later release. |
| 6 — guarded release | Internal synthetic/dogfood → small invited owner cohort → incremental availability → general release. Monitor operational-only signals and use qualitative opt-in feedback to judge charm, drift, and audio. Stop expansion on budget or identity/sync/privacy failures. |

Ship initially with two starters; adoption availability follows account age rather than a cohort's engagement. Staged bird-count rollout uses internal seven-bird synthetic accounts first, then enables real age-eligible third/fourth birds after verifying mix/layout/runtime budgets, then the full seven-bird policy. A prelaunch rollout flag may defer new adoptions up to a validated cap, but never removes a user's existing bird or presents locks/tiers. General v1 availability requires the seven-bird implementation proven, even if most accounts will take many months to reach it. Do not accelerate adoption because a user clicks more or pays; there is no payment tier.

Instrument from day one: first-bird performance marks, critical bytes, frame distributions/long tasks, audio capability errors, snapshot/event request status and latency, tick computation/scheduler delay, retry/backlog/job health, and privacy-schema rejections. Dashboards are service health only. Use synthetics to see actual bird/vector/call correctness; customer monitoring never reports private bird behavior.

Release engine versions through versioned schemas and deterministic fixture comparisons. Read old bird/signature versions, migrate additively and idempotently, and keep stable identifiers/vectors. Do not use trait reset as a rollback. Canary worker/frontend changes with compatible snapshots; back up canonical state before a migration. If a new drift mapping overexpresses birds, reduce future coefficients/presentation sensitivity while preserving accumulated vectors and identity. Rollback an engine writer only when compatible with already persisted state; otherwise deploy a forward repair.

Operational kill switches can stop new offers/adoptions/invites, disable a broken audio implementation into captioned silence, or slow environmental ornament rendering without erasing state. Do not globally disable accessibility or silently turn off canonical ticking to make a dashboard green. During a severe tick correctness incident, temporarily reject new mutations with matter-of-fact copy, preserve accepted events/vectors, fix and replay from the last proven cursor, then restore service. A stale client must never become the emergency source of truth.

### Practical scaling check

At `N` accounts, one-minute tick load is approximately `N/60` aviary ticks per second regardless of current viewers. Visible snapshot load is roughly `visible_views/10` per second; presence ingestion roughly `qualified_owner_views/15`, bounded and coalesced. Size storage from seven-day private event retention plus indefinite sparse notebooks, not hypothetical event replay forever. Load-test at the intended launch account count and at ten times that count using synthetic accounts. Partition due-tick indexes by UUID/time and tune batch sizes before adding services.

At one million accounts the tick rate is about 16,700 per second, which requires worker/database partitioning rather than assuming a small single PostgreSQL instance will suffice. V1 launches below a measured safe capacity and expands writer partitions by account UUID when needed; this is a sizing constraint, not a requirement to build a million-account platform before proving the product. No optimization changes absence semantics or reduces unconnected accounts to frozen-on-return simulation.

## 16. Risks, mitigations, and launch blockers

| Risk | Detection | Mitigation / stop condition |
| --- | --- | --- |
| Drift too fast, too slow, or dominated by gestures | Synthetic 7/21-day fixtures, single-session comparison, opt-in qualitative perception study | Keep presence dominant, cap offers/listen intervals, tune low-pass/coefficient and expressive curves. Block release if single sessions visibly move traits or weeks show no recognizable change. Never tune by aggregating actual owner bird histories. |
| Silent personality loss or double application | Concurrency/fault-injection/property tests, private checksums, backup/restore drill | Atomic tick/cursor/delta, single writer, server-only additive changes, stable IDs. Stop writes if invariants fail; repair from private proven state, never reset/reseed. |
| Canonical base and fast response projection diverge | Replay command plans across tick boundary/two devices | Store immutable reaction decisions and revision tuple; use one reducer and consistent snapshot transaction. Do not reroll an accepted offer/greeting in the tick. |
| Presence inflated by background/suspend/multiple devices | Conjunction tests, delayed/replay/union fixtures | Monotonic activity windows, short bounded intervals, terminal events, server union/expiry. No credit for open tabs, audio, visitor attention, or missing heartbeat intervals. |
| Birds sound synthetic, repetitive, or unrecognizable | Multiweek cross-mood identity listening tests, seven-bird chorus review | Narrow stable signature anchors, richer procedural contours/timbre, natural call spacing, headroom, bounded chorus. Silent-caption fallback for technical audio failure; do not replace with recordings. |
| Accessible experience loses the product's specificity | Manual narration/reduced-motion/caption/keyboard evaluations | Designed pose cross-fades, fact-constrained prose, grammar-derived captions, calm queue, visible focus. Accessibility failures block launch just like visual/audio failures. |
| 500ms target incompatible with private state latency | Cold 4G/geographic synthetic tests from milestone 1 | Stream a compact authenticated first-frame snapshot; reduce critical bytes, optimize home-region/edge path. Never leak private state into shared caches or hide a generic placeholder behind the metric. |
| Minute ticks miss load budget or drift during outage | Scheduling-lag and p99 tick alarms, synthetic mass-account tests | Spread ticks, bound work, partition UUID writer domains, analytic catchup for idle segments, ordered event handling. No client tick fallback or event-cursor skipping. |
| Visit credential changes host behavior or leaks data | Negative authorization tests, visitor-only integration tests | Separate capability/session type, no presence controller/owner event route, minimal projection, authorization before all cached reads. Stop invites if isolation fails. |
| Revocation looks successful but visitor keeps pulling | Test cached 304, active/hidden/resumed visits | Status check on every snapshot, short visible pull interval, no public snapshot cache. Preserve historic transparency logs while removing active access. |
| Numeric/personality or PII leaks through exports/debug/telemetry | Schema-level rejection tests, review snapshot/ARIA/export/log samples | Public projection allowlist, explicit export conflict decision, encrypted sole address references, token/URL redaction, isolated metrics credentials. Privacy regressions block rollout. |
| Scene accumulates audio nodes, notebook rows, or ornaments | Repeated 30-minute stress run and teardown counters | Bounded pools/horizons/page windows, deterministic disposal, one loop/context, listener lifecycle ownership. Release cannot pass merely by reloading before growth appears. |
| Timezone/DST and settle race produce snaps or divergent moods | Two-zone/multi-device/DST and settlement-epoch fixtures | One explicit account timezone, UTC integration, gentle palette retiming, epoch-specific undo/re-engagement. No device-local canonical day model. |
| Copy slips toward metrics, guilt, or announcements | Editorial snapshot reviews across all surfaces | Naturalist fact templates for product, direct system errors/settings, no attendance template source, no toast/badge framework on product events. Reject "harmless" welcome/streak/achievement additions. |

## 17. Definition of v1 completion

V1 is complete when a newly signed-in owner meets two identifiable birds, returns to the same continuing aviary on another device, receives a varied notice without a textual welcome, can watch/listen/offer/settle/read sparse observations, and sees mood today plus slow expressive drift across weeks without a stat or penalty. Additional adoption depends only on aviary age and never exceeds seven. A named invited visitor sees that same scene without influencing it, and access disappears at the next pull after revocation.

The same product must remain specific and alive in narration, captioned silence, keyboard use, and reduced-motion cross-fades. Canonical vectors and identities survive retries, migrations, restore, and device changes; private interactions remain private. The stated first-frame, bundle, long-session frame/memory, and tick health gates pass on the supported browser/device matrix. Account lifecycle/privacy operations and all quiet-sharing controls are delivered with the product. No launch depends on later adding accessibility, repairing a client-owned simulation, or stripping out gamification.
