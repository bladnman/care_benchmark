# Pocket Aviary v1 — implementation plan

## 1. Product boundary and decisions

Build a browser-only, single-user aviary with one canonical scene and one canonical state per account. A new account receives two server-selected starter birds, can name and later rename them, and may adopt additional birds at age-based intervals up to seven. The core session is observing the already-running scene, listening in on one bird, making an occasional offer, settling, and reading sparse field-notebook observations. Ship magic-link accounts, cross-device sync, privacy controls, export/deletion, per-invite read-only visits, captions, screen-reader narration, keyboard access, and a designed reduced-motion presentation in v1.

Treat presence as the main relationship signal, not clicks or session opens. Mood is visible and fast-changing; the persistent personality vector is slow, server-owned, monotonic toward expressive, and never numerically surfaced in product UI. Absence never reduces traits or creates distress. No scores, visit streaks, badges, counters, public discovery, profiles, shared aviaries, co-presence, user-placed birds, scene customization, native clients, payments, or push engagement loop. A visitor does not affect host presence or state.

Where the PRD leaves implementation choices open, use these defaults and tune only through product calibration: store an IANA timezone from the browser for local day/night and mood; select an offer recipient on the server from eligible birds based on current scene proximity, mood, and curiosity (never by clicking a bird); keep the notebook and account controls host-only while an invited visitor receives the scene snapshot and audio/render data only; consume an invite link once to mint a short-lived visitor session; and keep any optional visit notification off by default and confined to an in-product account surface. These choices preserve the described top-bar offer flow, private notebook, read-only ambient visit, and no-push policy.

## 2. Architecture and trust boundaries

Use a small web client plus a server-side account, aviary, and simulation service backed by a transactional database and a partitioned tick/event queue. The server owns accounts, identity, birds, personality vectors, moods, timestamps, notebook entries, invitation state, and the canonical snapshot version. Clients render snapshots and submit typed events; no client computes authoritative drift or writes absolute bird state. The renderer and WebAudio layer consume a versioned presentation snapshot and can be replaced without changing the simulation contract.

Suggested service boundaries:

- **Web shell and renderer:** responsive single-scene canvas renderer, thin top bar, keyboard and screen-reader surfaces, local interpolation, optional local procedural audio. Download the critical scene and rendering path up front; code-split settings, notebook, and invite management.
- **Identity/account API:** magic-link issuance and consumption, per-device sessions, verification, settings, export, deletion and restore.
- **Aviary API:** private snapshot reads, arrival/greeting requests, owner interaction-event intake, notebook reads, adoption and rename operations.
- **Simulation worker:** the sole writer of canonical bird behavior state. A partitioned scheduler advances every aviary on approximately one-minute ticks whether or not a client is connected. Owner actions may enqueue an immediate serialized simulation step for visible reactions; all state changes still go through this server writer.
- **Visit API:** issue, consume and revoke scoped invitations; provide visitors only a read-only scene snapshot stream; record visit start/end for the host's visit log.
- **Operational telemetry:** separate aggregate-only pipeline for request/tick latency, load/render timings, frame rates and audio errors. Do not join it to simulation events, bird fields, or account-level interaction histories.

Use TLS, secure same-site cookies or equivalent protected per-device session tokens, CSRF protection for cookie-authenticated writes, strict host-versus-visitor authorization, request schemas and payload limits. Hash one-time link and invite secrets at rest. Keep email encrypted on the account/invitation records where needed and never use email as an internal key, log identifier, partition key, or telemetry dimension. Use a generated synthetic account UUID for internal references.

## 3. Persistent model

Use relational records with explicit ownership and versioning; store timestamps in UTC and derive local daypart from the saved IANA timezone.

- **Account:** synthetic UUID, encrypted verified email, created/deletion timestamps, timezone, account settings (captions, reduced-motion override, optional visit-notification toggle), current snapshot version and one aviary reference. Soft deletion is immediately effective and recoverable for 30 days; hard deletion removes all account-owned data after that window.
- **Device session:** session UUID, account UUID, creation/last-seen, revocation and expiry state, device label if useful. Revoke a device session from account settings. Magic links expire after 15 minutes, are single-use, and issuance is rate-limited per email.
- **Aviary:** stable UUID, account UUID, created-at/age, canonical version, tick/event cursors, timezone, day/night phase, weather state and settled-until-reengagement marker. Enforce one aviary per account.
- **Bird:** stable UUID, aviary UUID, species from the six-species pool, user name, adoption timestamp and age-eligibility metadata. Identity and species remain stable across renames and migrations.
- **Personality vector:** five normalized server-only scalars (boldness, social warmth, vocal frequency, plumage saturation, curiosity), version and update time. Store the values as canonical state; update only by server-authored bounded deltas. Do not return the numeric vector in ordinary snapshots, APIs, narration, or UI. Include it only in the user's explicit JSON export, as required by the account-export scope.
- **Bird runtime state:** mood enum (wary, content, curious, drowsy, alert; allow a forward-compatible enum), mood start/next-transition timestamps, perch zone, current pose/action, next-call timing/grammar seed, and offer cooldown. Persist mood between sessions; no open-time reset.
- **Simulation event:** append-only per-aviary ordered event ID/sequence, event kind, server-received time, device-session ID, idempotency key, and minimal typed payload. Kinds include qualified-presence lease/heartbeat/end, listen-in begin/end, offer accepted, settle/undo, and arrival. Validate event order and size; compact processed raw records only after a retry/reconciliation horizon while retaining canonical state and cursor. Events are isolated from analytics.
- **Notebook entry:** UUID, aviary UUID, created time and naturalist prose, with internal source facts sufficient for regeneration/audit but no exposed trait values or visit-frequency claims. Entries are read-only, sparse, and retained while the account exists; do not archive or hide old entries.
- **Invite and visit:** invitation UUID, host account UUID, encrypted invited email, hashed bearer secret, issue/expiry/consume/revoke timestamps and state; visitor-session UUID with narrow scope and expiry; visit record with visitor email reference, start/end and approximate duration for the host's visit log. Do not grant a visitor account access to host records beyond the scene snapshot. Invites expire after 30 days unused and revocation blocks the next snapshot pull.
- **Export/deletion jobs:** job status and expiring download-token hash; deletion request date/recovery deadline. Export includes birds, names, vectors, current moods, notebook and account settings. Hard delete includes sessions, invites, visit records, vectors, notebook, interaction events, exports and any remaining identifiable data.

## 4. API and event contracts

Version the API and include canonical snapshot version plus server time in responses. Mutating requests take an idempotency key so retries cannot duplicate a greeting, offer, visit, or drift input. Return matter-of-fact errors for auth, sync, unsupported-browser and account surfaces.

- `POST /auth/magic-links` accepts email, rate-limits, stores only a hashed 15-minute single-use token, and sends the sign-in link. `POST /auth/magic-links/consume` atomically consumes it and issues a per-device session. Add session list/revoke, email-change verification, account settings, export request/download, delete request, and restore endpoints.
- `GET /v1/aviary/snapshot` returns the authenticated account's current presentation snapshot: birds by stable ID, names/species, mood and current action/pose, perch zone, active transitions and calls, scene daypart/weather, server timestamp, version and current adoption availability. Never include personality numbers or the raw event log. Mark responses private and version/ETag them; do not put authenticated personalized snapshots in a shared public CDN cache. The edge may cache only per-session/private snapshots keyed safely and invalidated by canonical version.
- `POST /v1/aviary/arrivals` is sent on fresh entry or return to a visible tab after meaningful hiding. The server uses last owner-presence time, absence length, boldness, mood and a per-arrival random seed to choose one greeting bird and an in-progress action. Stagger any secondary response. This event does not count as presence or drift. Return the schedule in the snapshot; do not show a welcome toast.
- `POST /v1/aviary/events` accepts typed owner events: qualified-presence heartbeat/end, listen-in begin/end, offer type, settle and settle undo. The server binds the account from the session rather than trusting a body account ID, validates bird/offer scope and per-bird cooldown, records the event, then queues an immediate serialized simulation step for responsive user-initiated reactions. Return acceptance and the new canonical presentation version/action where ready. Clients never send mood or personality values. A settle ends account-level presence; a later qualified owner interaction from any device re-engages. Undo is accepted for five seconds after settle.
- `GET /v1/notebook?cursor=...` pages the host's read-only entries with stable ordering. No visitor endpoint exposes notebook or account settings in v1.
- `POST /v1/birds/adoptions` accepts a name for a currently age-eligible server-selected species; `PATCH /v1/birds/{id}` allows rename only. The server enforces two starters, age-based availability, stable identity and the seven-bird cap. Availability must not depend on visits, interaction count or payment.
- `POST /v1/invites` creates one explicitly addressed invitation and emails its one-time URL. `POST /v1/visits/consume` exchanges it for a scoped read-only visitor session. `GET /v1/visits/{session}/snapshot` returns the same current host scene; it accepts no interaction writes and never emits owner presence. `DELETE /v1/invites/{id}` revokes unused or active access; the visitor is stopped on the next snapshot pull. Account settings provide invite status, outstanding invitations and recent visit log. No public discovery, visitor list or host badge.

For the first render, deliver the small personalized snapshot with the authenticated HTML shell where practical, or fetch it from the nearest private edge. A slow snapshot shows the quiet field, never a spinner; do not delay drawing on noncritical assets.

## 5. Server simulation and calibration

Keep a pure, deterministic transition function in the simulation service, versioned with its rules and fed explicit prior state, elapsed time, local-time inputs, weather and ordered events. Use a stable seed per bird/event for reproducible variation. Persist the new state and consumed event cursor in one transaction (or equivalent atomic compare-and-swap) per aviary. A unique tick/step ID plus version check makes retry and worker failover idempotent. Serialize all steps for one aviary so an immediate offer step cannot race the minute scheduler.

On each approximately one-minute background tick, advance all aviaries independent of browser connections: consume new events in sequence; accumulate only qualified owner presence; apply slow personality deltas; advance mood timers; calculate local daypart and rare ambient weather; model bird-to-bird calls/mood influence; choose current perch/action and call timing; update adoption-age availability; and generate a notebook entry only when a sparse noteworthy-observation rule qualifies. For long gaps, use elapsed-time transitions and deterministic catch-up rather than replaying every missed minute. Catch-up must preserve equivalent day/night and mood outcomes without inventing presence during the gap.

Presence is eligible only while all three client conditions hold together: `visibilityState === visible`, window focus, and pointer/key activity inside a configurable few-minute grace window. Use a lease/heartbeat from each device session containing sequence number and observed condition flags; the server validates freshness and caps credited duration at wall time since the previous accepted heartbeat. Opening a tab alone is never presence. Union overlapping valid intervals across devices for one account so two open clients do not double-count one minute. End a lease on hidden/unfocused/settle/logout when observable; server expiry closes abandoned leases. Choose the activity grace window during calibration, biased long enough to allow quiet watching. Visitors never create these leases.

Drift uses a low-pass filter over accumulated presence as dominant input, then listen-in attention for the focused bird's warmth/vocal frequency, and accepted offers for curiosity/boldness. Settle ends presence and quiets mood but has no positive or negative trait delta. Apply small nonnegative bounded deltas only; neglect does not lower any trait. Trait bounds and per-tick maxima prevent jumps, repeated retries and event bursts from saturating a vector. Mood is a separate enumerated state driven by recent owner interactions, local time, weather, nearby bird calls and personality-conditioned transition probabilities. It persists between sessions and can evolve during absence without default reset or distress state.

Call grammar runtime uses the species motif library and stable bird identity as its recognizable signature; mood and vector values alter timing, pitch range and expression only within limits that retain recognition. Vocal frequency governs call intervals and chorus likelihood. Server snapshots carry call schedule/seed and presentation events; the client synthesizes the audio. Generate arrival greetings as varied combinations of glance/perch/call and response, weighted by state and absence length, with only one first greeter and small randomized stagger for others.

Calibrate with seeded simulation cohorts, not population behavior analytics. Compare one-week regular-presence vectors for measurable instrument-level drift and three-week sequences for visible-but-subtle changes; verify one session cannot show visible numeric jumps, and two weeks away never lowers traits or creates distress. Keep exact trait bounds, filter constants, offer cooldown and age-to-adoption schedule in versioned simulation configuration, with safe rollout and rollback. Product review should assess bird-specific naturalist text and perceived call identity alongside numerical thresholds.

## 6. Canonical sync and conflict handling

The server is the only writer of canonical personality, mood and scene state. Clients send events, never absolute state; there is no client-to-client merge and no last-write-wins vector update. Store an aviary version and per-device event sequence; accept events transactionally in server order and deduplicate idempotency keys. A worker locks/compares the expected aviary version, applies deltas once, advances the consumed cursor, writes a new snapshot and publishes its version atomically. Concurrent devices therefore serialize into the same state instead of overwriting one another.

Clients interpolate between authoritative snapshots. Pull on initial open, tab becoming visible, long frame gaps/resume from sleep, after an accepted owner action, and at a low-frequency visible-tab keepalive. If a response version is older than the renderer's current version, ignore it. On timeout show a plain system message with retry; never ask a user to choose between two bird histories. On a retry, the idempotency key returns the prior outcome. If a server outage delays ticks, catch up before returning a current snapshot and preserve queued event order. Revoke device sessions centrally. Visitor snapshots use invite authorization at each pull so revocation takes effect no later than the next pull.

## 7. Frontend scene and interaction pipeline

Separate `Snapshot -> Presentation State -> Renderer` from `UI controls -> typed API event`. Keep all birds in a single horizontal composition with front/middle/back perch zones and no pan, zoom, or scene scroll. Use a responsive logical scene coordinate system and letterbox/scale it so all birds remain visible from narrow phone to wide desktop. Build the quiet sky/foliage/perch layers once; draw compact vector/procedural bird silhouettes and a small number of cached visual layers. The renderer owns no canonical state and never chooses behavior that would persist.

Start rendering as soon as the snapshot is available, using its current pose/action phase and server timestamp so the first visible bird is already mid-action. Idle pose choice and micro-motion are mood/personality keyed; client-only leaf/feather drift and subtle parallax use bounded render-time randomness and do not create simulation events. Birds themselves choose perch based on mood/personality; no drag-to-place. Day/night follows the account timezone, weather remains rare and quiet, and the nightjar-like species may call at night. After adoption, there is no empty-scene return; during initial account creation, the quiet field leads into the first two birds' soft fly-in.

Keep UI chrome to the sparse top bar: account/settings, accessibility, notebook and offer. Fade it nearly transparent after cursor stillness, and restore on pointer or keyboard activity without hiding keyboard focus. Listen-in is available by click, tap or keyboard on a bird; clicking it again, another bird, empty space, or moving focus away ramps back to ambient. Offers open from the top bar, select seed/song fragment/still pool, then show the server-chosen recipient's state-shaped response. Settle from the top bar warms the scene and quiets calls over seconds; any scene click within five seconds undoes it. Closing a tab is equivalent at the engine layer and never triggers a guilt surface.

## 8. Procedural audio

Build one bounded WebAudio graph per active tab: master ambience, per-bird buses, and a listen-in gain stage. Implement each species' call motifs with small oscillator/noise/filter/envelope primitives or reusable generated buffers; never download or loop recorded bird calls. Use parameter automation for gradual ramps, pitch/timing variation, and soft chorus mixing. On listen-in, smoothly raise the chosen bird and lower (but never mute) the others; disengage returns to ambient with the same ramp. Song-fragment offers use the small curated motif library, synthesized through the same graph.

Keep call identity tied to species and bird seed while mood, frequency trait, and grammar variation change expression. Reuse buffers/nodes where possible, dispose finished nodes, bound simultaneous voices and worklet/context count, and measure CPU and memory on the five-year-old laptop profile. The schedule and synthesized caption must derive from the same grammar choice. If WebAudio is unsupported, initialization fails, or autoplay policy leaves the context suspended, continue in graceful silence and turn captions on by default; resume audio on an ordinary user gesture without a blocking audio prompt. Never fall back to recorded audio.

## 9. Accessibility and language

Ship the accessible surfaces with v1. Provide semantic, keyboard-reachable controls for top-bar items and birds; Tab enters the first bird, arrow keys move among birds, Enter starts listen-in, Escape ends it; offer selection and settle are operable by keyboard. Ensure visible focus outlines contrast over both light and dark scene states. Test all user-copy text, caption, displayed narration and account surfaces at WCAG AA or better.

Create a screen-reader live narration surface that composes lowercase, present-tense naturalist prose from the same authoritative presentation state. Announce the initial return greeting promptly, user-triggered offer reactions and settle at a small priority bump; otherwise update around every 30–60 seconds at idle. Coalesce queued prose so state updates do not flood assistive technology. Never expose trait numbers or read out raw event changes such as “mood: content.” Notebook and narration use a shared voice and content vocabulary.

Honor `prefers-reduced-motion` and an account override. Render pose changes and flight as slow cross-fades, remove drifting leaves, slow ambient color transitions, and retain the scene, calls, mood and notebook. Captioning is user-selectable; captions are short naturalist descriptions generated from the actual runtime motif and appear near the calling bird. If audio cannot run, captions default on. Accessibility preferences sync with the account while OS preference remains respected.

## 10. Notebook, accounts and visits

Generate notebook entries on the server from real, stable observations: e.g. which bird greeted first, a perch/mood observation, or a passing weather effect. Keep entries rare (roughly every few days for ordinary use; more often for genuinely noteworthy aviary events) and avoid session-start logs, trait numbers, “you visited” claims, streaks or generic event text. Save final prose as read-only entries; allow indefinite chronological scrolling while account data remains active. The host's session and settings views use matter-of-fact copy.

First sign-in creates an account and two starter birds from the species pool, then offers naming. Support later renaming without changing IDs or traits. Age, not attention, controls quiet availability of new birds; start at two, expose no adoption counter or reward language, and enforce seven maximum. Settings support device-session revocation, verified email change, user-requested JSON export delivered via an expiring link, and soft delete/restore followed by hard deletion at 30 days.

Visits are off until the host explicitly creates a named email invite. A visitor gets a one-time link and a scoped read-only session, sees the true current aviary scene and calls, and can do nothing that writes state. Do not show a visitor cursor, avatar, notebook controls or special presentation. No presence, drift, interactions, greetings or co-presence are attributed to them. The host can see invitations and a recent visit log with visitor email, date and approximate duration in account settings; there is no new-visit badge or default notification. If the host opts in to visit notifications, keep delivery within the signed-in product surface, not push/email. Revocation blocks the next visitor snapshot request; unused invites expire after 30 days and cannot be revived.

## 11. Performance, privacy and observability gates

Treat these as release gates, measured on representative hardware and browser versions (last two major Chrome, Safari, Firefox and Edge):

- Initial JavaScript is below 2 MB gzipped, with settings/notebook/invites split from the critical path.
- First bird is visible under 500 ms on mid-tier mobile over 4G; the first frame has no spinner or fade-from-static.
- Idle scene sustains 60 fps on a five-year-old mid-range laptop with up to seven birds and a 30-minute session shows no client memory growth.
- Audio buffers, voices, audio contexts and workers are bounded; notebook items release references after scrolling away.
- Simulation tick latency p99 remains below the 5-second alarm threshold; event-to-offer reaction and snapshot refresh are measured separately.
- Synthetic browser fleet runs from common geographies; aggregate-only RUM records load and first-bird timings, frame timings, audio-context failures, API error rates and tick latency. No bird/personality fields, email, per-bird event or per-account interaction dimension enters analytics. Any operational log that must identify an account uses the synthetic UUID and carries no interaction payload; dashboard and warehouse exports remain aggregated.

Keep simulation/event storage out of the analytics warehouse at the infrastructure and permission level. Export access is explicit and user initiated. Enforce encryption, invite scoping, rate limits, magic-link expiration/single-use, one-time invite consumption and deletion jobs as data lifecycle guarantees. A privacy review should verify that hard deletion removes records from primary stores, queues, caches and export staging within its promised lifecycle.

## 12. Delivery sequence and release plan

1. **Foundation:** schema and migrations, synthetic UUID account model, magic-link/session flow, account deletion/export skeleton, simulation configuration/versioning, event idempotency, private snapshot endpoint and aggregate-only telemetry boundary.
2. **Engine vertical slice:** two stable starter birds, mood/personality persistence, one-minute server tick, exact presence leases, drift safeguards, return greeting and deterministic replay/catch-up. Seeded simulation calibration before visual polish.
3. **Scene and interaction slice:** one responsive scene, procedural idle actions, local day/night, weather, top bar, listen-in, offer reactions, settle/undo and sparse server-written notebook. Test two then seven birds for recognizable call and layout.
4. **Accessibility and reliability:** narration, keyboard model, reduced-motion presentation, runtime captions and WebAudio fallback; multi-device concurrent event serialization; export/delete and device revocation; visit invite/revoke and read-only path. Complete privacy/data-flow review.
5. **Performance hardening and v1 ramp:** synthetic perf baselines, 30-minute memory run, supported-browser review, load/tick capacity, dogfood with two birds, then controlled account cohorts. Release with two birds per new aviary; unlock the third and later birds only by aviary age using conservative configured intervals, gathering qualitative calibration through product review rather than behavioral analytics. Increase cohort and availability only after gates hold; rollback simulation config or release flag if state integrity, call identity, a11y or performance regresses.

## 13. Key risks and mitigations

- **Drift feels imperceptible or too fast:** run reproducible one-, three- and six-week presence profiles; review subtle visual changes blind to exact vector values; tune low-pass constants and event weights. Keep trait changes monotonic and bounded and prohibit neglect penalties.
- **Presence is overcounted:** test visibility/focus/activity combinations, sleeping laptop, long still watching, multiple devices and abandoned leases. Server caps heartbeat intervals, deduplicates overlap, and never equates page open with attention.
- **Canonical state diverges under concurrency or retries:** inject duplicate/out-of-order requests, worker restarts and concurrent laptop/phone actions. Transactional cursors, idempotency and per-aviary serialization must prove no lost deltas or duplicate offers.
- **Mood jumps or fails to continue during absence:** use deterministic time-zone/DST, long-gap catch-up and resume tests. Never reset to neutral at open; absence may make birds ambient but cannot create illness, distress or personality loss.
- **Procedural calls sound uncanny, repetitive or blur together:** blind-listening reviews at two and seven birds across moods; refine species motif range, envelope, pitch/timing limits and chorus levels. Preserve identity before adding more variation; cap concurrent voices.
- **Browser autoplay or WebAudio failure undermines the first impression:** treat suspended audio as a normal browser state; keep captions available/on by default on failure, never show an intrusive prompt, and verify calls begin after a normal gesture with no recorded fallback.
- **Accessibility announcements become noisy or flat:** review prose with screen-reader users, enforce cadence/coalescing, verify keyboard focus after top-bar fade, test caption timing against generated calls, and ship reduced-motion as a designed view rather than static fallback.
- **Scene/performance work competes with bundle and frame budgets:** profile seven birds on constrained devices, cache static layers, split rarely-used code and stop rendering when hidden while server simulation continues. Track memory over the full 30-minute window.
- **Invite leakage or revocation lag exposes private state:** scope signed invite sessions to scene reads, check revocation at every pull, hash secrets, expire unused tokens, test stale sessions and ensure visitor activity cannot write events or drift.
- **Notebook or telemetry accidentally gamifies or profiles behavior:** content rules ban visit-frequency narration and trait values; isolate simulation stores from analytics; review event schemas and generated prose at each release.
- **Account deletion leaves recoverable traces:** make deletion idempotent, test the 30-day restore boundary and hard deletion across database, queues, cache, invitation/visit data and exports, without retaining account-linked RUM.
