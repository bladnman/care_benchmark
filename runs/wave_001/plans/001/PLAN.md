# Pocket Aviary — v1 implementation plan

## 1. Product contract and scope

Ship one web aviary per magic-link account. Provision two stable-identity starter birds from a coherent pool of about six species; let the owner name or later rename them. Permit age-gated invitations to adopt additional birds, to a hard cap of seven. Ship presence-sensitive evolution, mood and bird-to-bird behavior, procedural calls, listen-in, seed/song-fragment/still-pool offers, settle with a five-second undo, a sparse read-only field notebook, local-time lighting and rare weather, opt-in read-only visits, account controls, export and deletion, and complete accessible render/audio alternatives.

The user-facing aviary is a single horizontal scene with three perch zones and a sparse top bar. The product voice is lowercase, present-tense naturalist prose in observations, narration, captions and offer copy. Identity, settings, errors and account flows use direct matter-of-fact copy. No textual return welcome, visit announcement, participation metric or numeric personality surface.

Reject native clients, additional aviaries, collaborative ownership, public discovery, profiles, comments, chats, feeds, rankings, payments, scores, streaks, badges, levels, hunger, death, distress, mandatory goodbye, scene customization and recorded call loops. Never gate new birds on engagement: aviary age alone controls eligibility. Keep a distinct product-design acceptance review for these exclusions, including hidden settings and analytics views.

## 2. System boundaries

Use a small web client, an authenticated HTTP API, a transactional primary database and server-side tick workers. The database is the sole canonical store of birds, their personality vectors, moods, positions, simulation clocks, account settings and notebook entries. An append-only, account-scoped interaction ledger carries commands and validated presence intervals into the tick. A transactional outbox can dispatch invite/export mail; mail delivery is not part of simulation consistency. A separate operational metrics pipeline receives only allowlisted aggregate counters, timings and errors, with no access to the simulation database or event payloads.

Serve the shell and a compact, authenticated initial snapshot through a low-latency edge path. Personal snapshots must be private/no-store at shared caches and keyed to a verified session; CDN delivery must not expose them across accounts. If an initial snapshot is not ready, paint the quiet field immediately, then enter the already-running scene at the snapshot's simulated phase. The empty field followed by a soft first-bird arrival is reserved for first adoption only. Code split settings, notebook history and invitation flows. Clients own rendering, procedural synthesis and local interaction state only; they never advance the canonical simulation or submit trait values.

Define a versioned snapshot schema shared by client and service. It contains server time, state version, next expected tick, owner timezone/day phase, weather state, per-bird stable ID/name/species, render-safe appearance parameters, mood, perch/pose and transition timestamps, a deterministic call schedule seed plus motif/voice parameters, and an event cursor. It does not expose raw personality numbers to the ordinary UI. Send derived behavior parameters needed for rendering/audio, bounded and validated by the server. The explicit account export is a separate owner-only data portability surface that includes vectors as required by the PRD; it is never presented as a stats panel.

## 3. Persistence and invariants

Use synthetic UUIDs as account, aviary and bird identifiers everywhere except the account's encrypted email field and the invitation's encrypted recipient field. Forbid email in partition keys, general logs, trace attributes and analytics. Suggested tables/records:

| Record | Key fields and rules |
| --- | --- |
| Account | UUID, encrypted verified email, timezone, created/deletion timestamps, notification preference, accessibility settings, optimistic version. One aviary per active account. |
| Session | Opaque token hash, account UUID, device label, issued/expiry/revoked timestamps; separately revocable. |
| Magic link | Random single-use token hash, email request reference, 15-minute expiry, consumed timestamp, request rate-limit metadata. |
| Aviary | UUID, account UUID unique, creation time, simulation tick cursor/version, weather/day state, last owner-presence end, adoption eligibility cursor. |
| Bird | Stable UUID, aviary UUID, species, mutable name, adopted time, five server-only normalized trait values, mood and mood timer, perch/pose, immutable call-signature seed, last offer time, record version. Never regenerate an existing bird on migration. |
| Interaction event | UUID/idempotency key, account/aviary UUID, actor session, server receipt time, client interval if relevant, type, validated bounded payload, tick consumption cursor. Append only. |
| Presence interval | Server-clamped start/end and originating session, derived from bounded qualifying heartbeats; deduplicated across devices so simultaneous owner tabs do not multiply time. |
| Notebook entry | UUID, aviary UUID, event/time anchors, authored naturalist text, generator version. Immutable, paginated indefinitely. |
| Invitation/visit | Host UUID, encrypted recipient email, token hash, 30-day unused expiry, redemption and revocation state, scoped visit-session hash, visit start/end and approximate duration. |
| Export/deletion job | Owner UUID, requested/expiry state, secure download artifact pointer or purge cursor; no email address outside the account record and mail handoff. |

Back up canonical records with point-in-time recovery and periodically restore a sample into a private test environment. Schema migrations must preserve every bird UUID, trait, mood and call signature. Test upgrade/downgrade paths against realistic long-lived records. On hard deletion, remove dependent records, event history, visit data, outbox references, exports and account-linked telemetry within the documented 30-day schedule; make deletion jobs resumable and auditable by synthetic ID only.

## 4. API and command contracts

Use HTTPS JSON endpoints with schema version, request ID and bounded payload size. CSRF-protect cookie sessions, set secure/httpOnly/sameSite attributes, and authorize every lookup by owner UUID or scoped visitor token. Mutations accept idempotency keys and return accepted event IDs or the current account/version where applicable. Do not accept client-supplied personality, mood, perch or tick state.

| Surface | Contract |
| --- | --- |
| `POST /auth/link`, `POST /auth/consume`, `POST /auth/logout` | Request, atomically consume single-use 15-minute link, issue/revoke per-device session. Generic request response prevents email enumeration; rate limit by email and source. |
| `GET /aviary/snapshot?after=<version>` | Owner snapshot or no-change response, ETag/version and server time. Pull on load, visibility restoration, suspension-sized frame gap and low-frequency visible keepalive. |
| `POST /aviary/events` | Append validated `listen_start`, `listen_end`, `offer`, `settle`, `settle_undo`, or presence interval/heartbeat events. Server checks bird ownership, offer cooldown, song-fragment library key and settle undo deadline. |
| `GET /notebook?cursor=...` | Reverse chronological paginated read, then historical scrolling; immutable entries. |
| `PATCH /birds/{id}` and `POST /adoptions` | Rename with limits; adopt only if server-side aviary age milestone is available and count <7, in a transaction. |
| `GET/PATCH /account`, `GET/DELETE /sessions/{id}` | Manage timezone, settings, verified email transition, device sessions and privacy-policy link. |
| `POST /account/export`, `POST /account/delete`, `POST /account/restore` | Email time-limited export link to verified address; mark deletion immediately, allow recovery within 30 days, then hard purge. |
| `POST /invitations`, `GET /invitations`, `DELETE /invitations/{id}` | Issue explicitly addressed one-time invitation, list outstanding/active grants and revoke. |
| `POST /visits/redeem`, `GET /visits/snapshot`, `POST /visits/end`, `GET /visits/log` | Atomically redeem token into a scoped read-only visit session; each snapshot rechecks grant and returns a clear unavailable response on revoke/expiry. Host sees on-demand log. |

The visitor endpoint returns the same canonical bird/day/weather projection as the host, with no private notebook, account data or owner-only command capability. Visitor presence is never sent to the simulation ledger. A redeemed link is single-use, while its issued visit session may continue until revoked or its bounded session expiry; this resolves the PRD's one-time-link/active-visit distinction. Keep visit snapshots frequent enough that revocation becomes visible on the next pull; bound pull interval in the client. If the host explicitly opts into visit notifications, send only the chosen notification and never enable the toggle in onboarding.

Offline commands are not speculative trait writes. The client can show the immediate local visual/audio reaction after server acceptance, and it queues a bounded retry with the same idempotency key for transient failures. On expired auth, stop submitting events, show a matter-of-fact sign-in path, and refresh the snapshot after reauthentication. A rejected offer or stale command gets a clear, quiet system error, not an invented bird response.

## 5. Presence and simulation engine

The browser's presence detector qualifies time only while `visibilityState === visible`, the window has focus, and a pointermove or keypress occurred within a calibrated few-minute window. Use a monotonic local clock to segment qualifying intervals; close an interval immediately on hidden/blur/settle/unload and send periodic bounded heartbeats while qualified. `sendBeacon` is best effort only: the server can close a stale interval from heartbeat expiry. Never infer presence from an open tab, a playing audio context or a visitor. Keep the idle-activity timeout configurable and test with people who watch without moving; start near the longer side of “a few minutes.” The server clamps claimed interval lengths to receipt-time bounds and deduplicates overlapping owner sessions. This is validation for drift integrity, not a public engagement counter.

Schedule a roughly one-minute tick for every active aviary, including those with no connected client. Partition jobs by synthetic aviary UUID, use per-aviary transactional locking or compare-and-swap versioning, and make tick execution idempotent on `(aviary_id, tick_time)`. In one transaction: read unconsumed ordered events and prior state; accrue deduplicated presence; apply bounded additive trait deltas; evolve moods, perches, weather and call schedule; select sparse notebook observations; persist new state and consumption cursor. Retry contention without double-applying events. During outages, replay missed tick windows in order with bounded batch processing; do not jump straight to a freshly initialized state. Alert when tick latency p99 exceeds five seconds and expose backlog age.

Normalize trait values internally to `[0,1]`. Keep a stable individual baseline and immutable species motif identity. For each trait, maintain a smoothed exposure accumulator from recent qualified presence and eligible interaction events. A concrete starting calibration is `exposure[t+1] = exposure[t] * exp(-Δt/τ) + bounded_signal[t]`, with `τ` on the order of several days. Apply `trait[t+1] = min(1, trait[t] + k_trait * max(0, exposure[t+1]) * Δt)` and per-day caps. Presence drives all expressive traits and carries most weight; listen-in adds modest warmth/vocal-frequency exposure for its bird; offers add small curiosity and proximity/boldness exposure only once per cooldown. Settle changes short-term mood and ends presence; it has no special drift reward. Never subtract from persisted traits for absence or negative mood. Let greeting probability and call activity soften temporarily through mood/recency, so a two-week absence reads as quiet without reversing personality or creating distress. Set coefficients using simulation harnesses for one-week instrument-detectable movement and approximately three-week user-perceptible change under representative regular attendance. Verify that a single long session or repeated offers cannot cause visible jumps.

Use a small mood state machine (wary, content, curious, drowsy, alert) with transition probabilities shaped by trait vector, owner interaction, local time and ambient events. Persist mood and timer across sessions; choose daily-ish equilibrium movement, never reset on page open. Encode a seasonal/timezone-independent weather random seed per aviary and rare events (a few short rains per week, occasional wind), with temporary mood/audio effects. Timezone comes from an explicitly stored IANA zone, initially detected on device and changeable in settings; use server time plus that zone for daylight and adoption age. Define safe behavior for timezone changes and daylight-saving transitions; a clock change must not produce extra adoption eligibility or drift.

Maintain one immutable per-bird call identity: species motif library plus individual seed, pitch contour and rhythmic fingerprint. Mood changes timbre, intensity and timing; vocal-frequency trait changes call probability/chorus participation, never the recognizable core motif. A seeded scheduler emits call intents and bird-to-bird responses, including occasional chorus and propagated wary/alert reactions. Record logical call timings in snapshots; clients synthesize actual waveforms. Do not persist per-sample audio or leaf positions. Keep per-bird offer cooldown at a server-enforced few minutes, with distinct mood/personality-shaped reaction branches for seed, song fragment and still pool.

Generate notebook entries from noteworthy state transitions with a sparsity budget around one entry per few days in a regular aviary. Use deterministic, reviewed naturalist templates that bind specific birds, times, perch/weather/call observations; reject generic status strings, trait numbers and statements about the user's visit frequency. Deduplicate by underlying observation and retain all entries for indefinite scrolling until account deletion. Review generated examples across species, moods and long absences for voice and factual consistency.

## 6. Session choreography and scene rendering

On navigation or return from hidden state, obtain the current snapshot and absence duration from the server. Choose exactly one greeting bird with a weighted draw using boldness, warmth, mood and elapsed absence, then choose a procedural glance/head tilt/step/call pattern appropriate to that bird; if a second bird responds, stagger it with a small seeded offset. For a brief absence prefer a glance, for a long absence allow a more deliberate call/reorientation. Prevent a duplicate greeting on rapid visibility flaps with a session-local debounce. Narrate the greeting promptly for screen readers. Never show a welcome toast or absence tally.

Compose one responsive, unscrollable scene: sky/foliage background, middle-plane front/middle/back perches and birds, occasional foreground leaves/feathers. Map server perch and pose to normalized coordinates and safe bounds that keep all seven birds visible on narrow phones and wide desktops. Use bird silhouettes/palette from compact SVG or procedural primitives. Identity, mood and personality select pose and low-rate idle actions (preen, scan, shuffle, tilt); use deterministic phase offsets so the first rendered frame is mid-action. The client interpolates timestamped transitions between authoritative snapshots, but never writes them back. On resumed visibility or a long frame gap, fetch a fresh snapshot before interpolation to avoid stale teleportation. Stop drawing while hidden; the server continues ticking.

The client computes gradual local-time color transitions from the snapshot's server-time anchor and timezone; settle overlays a slower evening lighting/call attenuation until the user re-engages or closes the tab. A click within five seconds reverses settle and emits idempotent undo; outside that window, re-engagement starts a normal new presence interval. Leaf and feather drift are bounded render-only ornaments with no tick events. Top-bar icons are account/settings, accessibility settings, notebook and offer; expose settle as a reachable top-bar action without adding a fifth always-visible icon if the design can place it in the account/control affordance. Resolve that top-bar placement in the design specification and usability test, preserving the PRD's sparse four-icon bar. Fade the bar after pointer stillness, restore it on pointer or keyboard input, and never fade a focused control beyond legibility.

Use a rendering adapter with two deliberate motion modes. Standard mode uses subtle transforms and slow parallax at a 60 fps target. Reduced-motion mode chooses the same poses/events but cross-fades still poses, cross-fades perch changes instead of flight paths, removes leaf drift and slows palette shifts. Detect `prefers-reduced-motion` and allow explicit override in accessibility settings; changing it applies without restarting the aviary. In both modes, mood, calls, notebook and drift remain intact.

## 7. Audio and accessible equivalents

Synthesize calls in an AudioWorklet/WebAudio pipeline from compact species motif grammars, using oscillators/noise/filter envelopes and bounded seeded variation in phrase rhythm, pitch, pauses and timbre. Preallocate/reuse voices and buffers, cap concurrent calls, smooth envelopes to avoid clicks and limit peak output. Preserve each bird's audible fingerprint across mood changes. Mix all birds into a gentle ambient chorus. Listen-in ramps the target bird up and others down over a perceptible interval; non-target birds retain an audible floor, and disengagement reverses the ramp. The offer song fragment comes from a small motif library and enters the same mixer. Validate polyphony and recognizability at two through seven birds by listening tests, including overlapping calls and nightjar-like nighttime activity.

Browser autoplay rules may prevent sound before a user gesture. Render the scene and scheduled calls immediately; start/resume the audio context at the first permitted gesture, preserving call phase rather than replaying a canned welcome. When WebAudio is missing or fails, run in silence and turn call captions on by default. Do not download recorded loops. Honor explicit mute and caption settings. Generate each caption from the actual scheduled motif, contour, timing and mood parameters used to synthesize the call, so text and sound correspond. Show short captions near the bird without obscuring other birds; retain accessible text equivalents independent of transient visual positioning.

Generate slow naturalist screen-reader narration from the same snapshot/event model as the scene: one coherent observation every 30–60 seconds at idle, with prompt prioritized observations after return greeting, offer and settle. Queue with coalescing so periodic updates do not interrupt user-initiated speech or flood live regions. Use meaningful bird names/species, perch and audible behavior, never trait numbers or raw state labels. Captions, notebook, focus and controls must be available to a screen-reader user. Test prose for specificity and sustained listening comfort with actual screen readers.

Give top-bar controls a logical Tab order, then focus the first bird on entering the scene; arrows move between birds, Enter toggles listen-in, Escape exits, and keyboard focus leaving a bird disengages. Offer menu and settle/undo are fully operable by keyboard. Keep visible focus rings legible in bright and dim scenes. Meet WCAG AA contrast for every user-copy surface, including captions and faded chrome while focused. Verify touch target size, zoom/reflow without clipped birds, no focus traps, and correct live-region behavior. Account and accessibility settings use clear system-language labels.

## 8. Delivery, measurement and acceptance

Build in vertical slices: (1) account/auth and two-bird snapshot/first frame, (2) tick, presence and mood with canonical multi-device reads, (3) rendering, calls and listen-in, (4) offers, settle, notebook and adoption age gates, (5) accessibility surfaces, (6) visits, export/deletion and operational hardening. Accessibility prototypes and voice review begin with the first slice, rather than waiting for the fifth. Gate every slice on stable bird IDs and no client personality writes.

Automated checks: event idempotency and simultaneous-device ordering; hidden/unfocused/inactive presence exclusion and overlapping-device deduplication; tick retries/outage replay; monotonic bounded trait drift; mood persistence across sessions; offer cooldown; adoption age/count; visit read-only/revocation; magic-link replay; deletion restoration/purge; snapshot schema upgrades. Use seeded multi-week simulation cases (regular, absent, high-offer, all-night-open, multi-device) to tune one-week measurable and three-week visible drift. Conduct blinded listening studies for call identity, repetition and chorus quality, and user studies of naturalist narration/reduced motion. Assert no gamification copy or frequency metrics on public surfaces.

Enforce initial compressed JS under 2 MB; target first bird visible within 500 ms on a mid-tier mobile device over 4G; keep 60 fps idle motion on a five-year-old mid-range laptop over a 30-minute run; require no sustained memory growth over that run. Measure navigation-to-first-bird, bundle weight, frame times, long tasks, audio-context failures, tick latency/backlog and snapshots' latency/size in synthetic browsers across common geographies and aggregate-only Real User Monitoring. Use release gates on device/network lab traces and a 30-minute heap/voice-count test. Time-to-first-bird must include auth/snapshot delivery for returning sessions, not only first local draw. If the 500 ms target fails, reduce critical-path code and snapshot latency before considering a loading animation.

Operational telemetry uses metric-name/dimension allowlists and privacy tests that reject account IDs, emails, bird IDs, event payloads and per-bird state. Aggregate request counts, status/errors, latency distributions, anonymized session-duration histograms, frame timing and audio errors; do not derive per-account engagement dashboards, average bird drift or population interaction analyses. Log transient request correlation IDs separately with short retention and no email. Alarm at simulation tick p99 >5 s, backlog age beyond one cadence, elevated snapshot errors, auth failures and audio failures. Monitor canonical state integrity with private invariant checks, never by exporting vectors to analytics.

Roll out to internal accounts, then a small opt-in cohort, then staged general availability. Start with two birds; enable age-based invitations to third and later birds behind a server flag after verifying multi-voice recognizability and mobile performance at three, five and seven. Keep the seven-bird hard cap in database/service validation regardless of flags. Ramp visit invitations after read-only authorization and revoke tests pass. Include a rollback path for client bundles and tick algorithm versions; data migrations must be forward-safe and must never reset birds. Review aggregate performance, tick integrity, privacy and accessibility gates at each stage. Instrument first-bird timing, tick p99/backlog, frame/memory, audio failures and auth/visit errors from day one.

## 9. Risks and decisions to close during build

| Risk | Mitigation / acceptance criterion |
| --- | --- |
| Drift too fast, too slow or inflated by background tabs | Conjunctive presence detector, server bounds/deduplication, per-day trait caps, multi-week seeded simulations and longitudinal observation. One session produces no perceptible trait change; regular visits show instrument drift around week one and visible character change around week three. |
| Canonical state lost or overwritten across devices | Single server writer, ordered append-only events, atomic tick cursor/version, idempotent retries, restore drills and migration tests. Two concurrent devices converge to the same snapshot without last-write-wins vector replacement. |
| Procedural calls sound synthetic, repetitive or indistinguishable | Immutable per-bird motif identity, varied grammar and envelopes, acoustic reviews at two to seven birds, chorus and listen-in listening tests, no loop fallback. |
| Accessibility turns the aviary into status messages or a static page | Naturalist narration/caption editorial review, dedicated cross-fade render mode, screen-reader and vestibular user tests, keyboard/contrast automated and manual gates before launch. |
| First frame appears as an app loading | Small edge snapshot, critical-path render, deterministic mid-action phase and quiet-field timeout; measure the real 4G path. |
| Visitor access leaks owner controls or survives revocation | Separate scoped visitor projection, no event endpoint scope, token redemption/recheck each pull, revocation integration tests. |
| Privacy data escapes into observability | UUID-only references, encrypted email only on account/invitation records, metric allowlists, pipeline separation and automated payload audits. |

Product decisions left for implementation calibration: precise presence activity window, tick cadence near one minute, trait coefficients and cap, offer cooldown within a few minutes, adoption age intervals, palette/contrast tokens and top-bar settle placement. Record chosen values in versioned design/engine configuration and validate them against the acceptance tests above. None may be tuned by adding scores, notifications, visible trait values or punitive absence behavior.
